## 二、static关键字

### 2.1 类变量（static / class variable）

**定义**：用`static`修饰的成员变量称为类变量（静态变量）。

**核心特点**：
- 在该类所有实例之间是**共享**的
- 在加载该类时，只分配**一次**空间，并初始化

**示例**：
```java
class Employee {
    static int com;
}
```
运行时，所有实例 e1、e2、e3 共享同一个 `com` 变量。

**类变量的用途**：
- 在实例之间进行**通信**
- 跟踪该类实例的**数目**

**示例——实例计数**：
```java
public class Count {
    private int serialNumber;
    private static int counter = 0;

    public Count() {
        counter++;
        serialNumber = counter;
    }
}
```

**访问方式**：
- 类变量有点类似于其他语言中的**全局变量**
- 对于非private类型的类变量，可以在类外**直接用类名调用**而不需要初始化实例

**示例**：
```java
public class StaticVar {
    public static int number;
}

public class OtherClass {
    public void method() {
        int x = StaticVar.number;
    }
}
```

### 2.2 类方法（static / class method）

**定义**：用`static`修饰的方法，可以直接被调用，而不需要生成任何实例。

**示例**：
```java
public class GeneralFunction {
    public static int addUp(int x, int y) {
        return x + y;
    }
}

public class UseGeneral {
    public void method() {
        int c = GeneralFunction.addUp(9, 10);
    }
}
```

**静态方法的重要规则**：

| 规则 | 说明 |
|------|------|
| **无this指针** | 静态方法中没有this指针，不能访问所属类的非静态变量和方法，只能访问方法体内定义的局部变量、自己的参数和静态变量 |
| **不能重写** | 子类不能重写父类的静态方法，但可以通过声明相同的方法将其**隐藏（hide）** |
| **不能跨类型重写** | 子类不能把父类的非静态方法重写为静态的 |
| **main()方法是静态的** | 如果要在main()方法中访问所在类的成员变量或方法，就必须首先创建相应的实例对象 |

### 2.3 静态初始化程序（Static Initialization Block）

**定义**：没有存在于任何方法体中的静态语句块，在加载该类时执行且**只执行一次**。

**示例**：
```java
public class StaticInitDemo {
    static int i = 5;
    static {
        System.out.println("Static code: i=" + i++);
    }
}

public class Test {
    public static void main(String args[]) {
        System.out.println("Main code: i=" + StaticInitDemo.i);
    }
}
```

**输出结果**：
```
Static code: i=5
Main code: i=6
```

## 三、final关键字

final关键字可以用来修饰类、方法和变量，各有不同的语义：

| 修饰对象 | 语义 | 说明 |
|----------|------|------|
| **final类** | 不能有子类 | 该类不能被继承 |
| **final方法** | 不能被重写 | 子类不能Override该方法 |
| **final变量** | 一经赋值就不能改变 | 实际上是**常量**，一般**大写**命名，且必须赋初值 |

**示例**：

```java
// final类——不能被继承
final class Employee {
    // ...
}
// class Manager extends Employee { ... }  // 错误！不能继承final类

// final变量——常量
final int NUMBER = 100;
```

## 四、抽象类（Abstract Class）

### 4.1 抽象方法与抽象类的定义

- 只有声明而**没有方法体**的方法称为**抽象方法**
- 包含一个或多个抽象方法的类称为**抽象类**
- 必须在声明中增加`abstract`关键字，在无方法体的方法前也要加上`abstract`

**示例**：
```java
public abstract class Drawing {
    public abstract void drawDot(int x, int y);

    public void drawLine(int x1, int y1, int x2, int y2) {
        // ... 调用 drawDot() 方法
    }
}
```

### 4.2 抽象类的特点

| 特点 | 说明 |
|------|------|
| **不能直接实例化** | 抽象类不能直接用来生成实例（即使是普通类前面添加abstract修饰），一般可通过定义子类进行实例化 |
| **可生成变量** | 可以生成抽象类的变量，该变量可以指向具体的一个子类的实例 |
| **可有构造方法** | 抽象类也可有构造方法、普通的成员变量或方法 |
| **可以派生子类** | 抽象类可以被继承 |

**示例——抽象类变量指向子类实例**：
```java
abstract class Employee {
    abstract void raiseSalary(int i);
}

class Manager extends Employee {
    void raiseSalary(int i) { /* ... */ }
}

Employee e = new Manager();  // 抽象类变量指向子类实例
```

### 4.3 抽象类的设计意义

- 抽象类往往用来表征对问题领域进行分析、设计中得出的**抽象概念**，是对一系列看上去不同、但本质上相同的具体概念的**抽象**
- 在面向对象方法中，抽象类主要用来进行**类型隐藏**：构造出一个固定的一组行为的抽象描述，但是这组行为却能够有任意个可能的具体实现方式。这个抽象描述就是抽象类，而这一组任意个可能的具体实现则表现为所有可能的派生类
- 模块可以操作一个抽象体。由于模块依赖于一个固定的抽象体，因此它可以是不允许修改的；同时，通过从这个抽象体派生，也可扩展此模块的行为功能
- 抽象类是面向对象设计最核心原则——**OCP（Open-Closed Principle，开闭原则）**的关键所在

## 五、接口（Interface）

### 5.1 接口的定义与属性

- 接口是在**抽象类概念的基础上演变**而来的
- 在接口中定义的**常量**默认具有 `public`、`final`、`static` 的属性
- 在接口中声明的**方法**默认具有 `public`、`abstract` 的属性

### 5.2 接口的含义

- 接口是一系列**方法的声明**，是一些方法特征的集合，一个接口只有方法的特征没有方法的实现，因此这些方法可以在不同的地方被不同的类实现，而这些实现可以具有不同的行为（功能）
  - 注：Java SE 8开始能在接口中实现方法（default方法）
- 接口定义了一组**行为的协议**，两个对象之间通过这个协议进行通信
- 接口在面向对象的Java程序设计中占有**举足轻重的地位**。事实上在设计阶段最重要的任务之一就是设计出各部分的接口，然后通过接口的组合，形成程序的基本框架结构
- 接口**不属于类层次结构**。不相关的类可以实现相同的接口

### 5.3 接口的实现

用 `implements` 代替 `extends` 声明子类，该子类中**必须实现接口（及其超类）中的所有方法**。

**示例**：
```java
interface SayHello {
    void printMessage();
}

class SayHelloImpl implements SayHello {
    public void printMessage() {
        System.out.println("Hello");
    }
}
```

### 5.4 接口作为数据类型

接口可以作为一种**数据类型**使用。

**示例**：
```java
interface StockWatcher {
    final String sunTicker = "SUNW";
    final String oracleTicker = "ORCL";
    final String ciscoTicker = "CSCO";
    void valueChanged(String tickerSymbol, double newValue);
}

class StockMonitor {
    public void watchStock(StockWatcher watcher,
            String tickerSymbol, double delta) {
        // ...
    }
}
```

### 5.5 接口与多态

一个接口可作为类名使用，实现**多态**。

**示例**：
```java
interface Human { /* ... */ }

class Chinese implements Human { /* ... */ }
class Germany implements Human { /* ... */ }

Human e = new Chinese();
Human e = new Germany();
e.showNameInNativeLanguage();
```

### 5.6 接口与多重继承

Java中可以通过接口实现**多重继承**：一个类只能继承一个父类，但可以实现**多个接口**。

**语法**：
```java
interface I1 { /* ... */ }
interface I2 { /* ... */ }
class E { /* ... */ }

class M extends E implements I1, I2 { /* ... */ }
```

**多重继承结构**：

```
              抽象或具体父类
                   │
    ┌──────────────┼──────────────┐
    │              │              │
interface_1   interface_2   ... interface_n
    │              │              │
    └──────────────┼──────────────┘
                   │
                 子类
```

**多重继承示例——交通工具**：

```
        Flyer              Vehicle            Sailer
      (接口)              (接口)              (接口)
    takeoff()                            dock()
    land()                               cruise()
    fly()
        │                   │                   │
        ├───────────────────┼───────────────────┤
        │                   │                   │
    Airplane            RiverBarge           SeaPlane
    takeoff()           dock()               dock()
    land()              cruise()             cruise()
    fly()                                    takeoff()
                                             land()
                                             fly()
        │
    Helicopter
```

### 5.7 接口中注意的问题

- **不能向接口定义中随意增加方法**。如果确实需要增加，应该通过**继承接口**来扩展：

```java
// 原接口
interface StockWatcher {
    final String sunTicker = "SUNW";
    final String oracleTicker = "ORCL";
    final String ciscoTicker = "CSCO";
    void valueChanged(String tickerSymbol, double newValue);
}

// 扩展接口
interface StockTracker extends StockWatcher {
    void currentValue(String tickerSymbol, double newValue);
}
```

## 六、包（Package）

### 6.1 包的概念

- 包（package）是**相关类与接口的一个集合**，它提供**访问控制**与**命名空间管理**
- Java平台中的类与接口都是根据功能以包组织的

**包机制的好处**：

| 好处 | 说明 |
|------|------|
| **易于定位** | 程序员容易确定包中的类是相关的，并且容易根据所需的功能找到相应的类 |
| **避免命名冲突** | 每个包都创建一个新的命名空间，因此不同包中的类名不会冲突 |
| **宽松访问控制** | 同一个包中的类之间有比较宽松的访问控制 |

### 6.2 包的定义

用`package`语句指定源文件中的类属于一个特定包。

**语法**：
```java
package 包名;
```

**规则**：
- 包定义语句在每个源程序中**只能有一条**，即一个类只能属于一个包
- 包定义语句必须在程序的**第一行**（之前可有空格及注释）
- 包名用 `.` 分隔

### 6.3 包的引入（import）

将package引入源程序的格式：

```java
import 包名.*;      // 引入包中所有类
import 包名.类名;   // 引入包中特定类
```

**源文件结构顺序**：
```java
[package ...;]        // 缺省是 package .
[import ...;]         // 缺省是 import java.lang.*
[类声明 ...]
```

**静态导入**：引入其他类的静态成员
```java
import static java.lang.Math.*;
```

### 6.4 包名与包的存储路径

- 包分隔符`.`相当于目录分隔符，包存储的路径由**包根路径**加上包名指明的路径组成
- 包的根路径由 **`CLASSPATH`** 环境变量指出

**示例**：
```
package abc.financeDept
对应路径：%CLASSPATH%\abc\financeDept
```

### 6.5 源文件与类文件的管理

- 源文件（.java）可以按照包名指明的路径放置
- 类文件（.class）也将放在反映包名的一系列目录下
- **推荐做法**：一般将源文件与类文件**分别存放**

## 七、枚举类型（Enum）

### 7.1 枚举的定义

一个枚举的声明实际上是定义了一个**类**。

**语法**：
```java
[public] enum 枚举类型名 [implements 接口名表] {
    枚举常量定义
    [枚举体定义]
}
```

### 7.2 枚举的特征

| 特征 | 说明 |
|------|------|
| **可实现接口** | 枚举类型与类一样，也可以实现接口 |
| **隐含继承Enum** | 所有的枚举类型都隐含地继承了`java.lang.Enum`类，由于Java不支持多继承，所以枚举类型的声明中不能再继承任何类 |
| **固定实例** | 枚举类型实际上是具有固定实例的特殊类 |
| **常量与整数对应** | 每个枚举常量都将与一个整数值相对应 |
| **构造方法私有** | 枚举类型的构造方法只能定义为private（默认） |

### 7.3 枚举类型的方法

| 方法 | 说明 |
|------|------|
| `equals` | 如果传入对象等于此枚举常量时，返回true |
| `name` | 返回此枚举常量的名称，在其枚举声明中对其进行声明 |
| `ordinal` | 返回枚举常量的序数（它在枚举声明中的位置，其中初始常量序数为零） |
| `toString` | 返回枚举常量的名称，它包含在声明中 |
| `values` | 返回一个包含该枚举类型所有常量的数组 |

**注意**：枚举类型的变量也属于一种**引用型变量**。

## 八、包装类（Wrapper Class）

### 8.1 包装类的概念

- Wrapper类将**基本类型表示成类**
- 每个Wrapper类对象都封装了基本类型的一个值

### 8.2 基本类型与对应的包装类

| 基本数据类型（Primitive Data Type） | 包装类（Wrapper Class） |
|-------------------------------------|-------------------------|
| boolean | Boolean |
| byte | Byte |
| char | Character |
| short | Short |
| int | Integer |
| long | Long |
| float | Float |
| double | Double |

### 8.3 包装类的常用方法和常量

- 数字型Wrapper类中的 `MIN_VALUE` 和 `MAX_VALUE` 常量，定义了该类型的最大值与最小值
- `byteValue`、`shortValue` 等方法进行**数值转换**
- `valueOf` 和 `toString` 实现**字符串与数值之间的转换**

**示例——Wrapper类对象的创建**：
```java
Integer quantity = new Integer(123456);
Double amount = new Double(345987.246);
```

### 8.4 自动装箱与拆箱（JDK 1.5+）

| 操作 | 说明 |
|------|------|
| **装箱（Box）** | 把基本类型的数据通过相应Wrapper类形成对象 |
| **拆箱（Unbox）** | 把一个Wrapper类对象中的基本数据类型提取出来 |

**自动装箱与拆箱示例**：
```java
Integer i = 10;    // 自动装箱：int → Integer
int j = i;         // 自动拆箱：Integer → int
```

## 九、泛型（Generics）

### 9.1 泛型的概念

泛型即**泛化技术（Generics）**，通过一种类型或方法操纵各种类型的对象，而同时又提供了**编译时的类型安全保证**。

泛型技术的基本思想是**类和方法的泛化**，是通过**参数化**实现的，因此泛型又被称为**参数化类型**。

### 9.2 泛型的优点

| 优点 | 说明 |
|------|------|
| **编译时严格类型检查** | 类型错误在编译期就能被发现，而非运行时 |
| **消除类型转换** | 消除了绝大多数的显式类型转换，代码更简洁安全 |

### 9.3 不使用泛型 vs 使用泛型对比

**不使用泛型**（需要强制类型转换，存在类型安全隐患）：
```java
List list = new ArrayList();
list.add("hello");
String s = (String) list.get(0);  // 需要强制类型转换
```

**使用泛型**（类型安全，无需强制转换）：
```java
List<String> list = new ArrayList<String>();
list.add("hello");
String s = list.get(0);  // 无需强制类型转换
```

### 9.4 泛型的定义

泛型的定义与普通类定义相比，在类名后增加了由尖括号`<>`标识的**类型变量**，一般用 `T` 表示：

```java
public class Box<T> {
    private T t;
    public void set(T t) { this.t = t; }
    public T get() { return t; }
}
```

### 9.5 泛型的使用

泛型在使用时，必须像方法调用一样执行"**泛型调用**"，将泛型中的类型变量 `T` 替换为具体的类、接口等：

```java
Box<Integer> intBox = new Box<Integer>();
intBox.set(100);
Integer value = intBox.get();
```

## 十、集合类（Collections）

### 10.1 集合类概述

- 一个集合类对象表示了一组对象，相当于一个**容器**
- Java Collections API的核心接口支持**泛型**，并且形成了两个独立的**树型结构**：

**集合框架两大接口体系**：

```
                        Collection                        Map
                       (接口)                          (接口)
                    /           \                    /        \
                 Set             List            HashMap    TreeMap
                (接口)          (接口)           ...        ...
               /    \          /     \
          HashSet  TreeSet  ArrayList  LinkedList
          ...                Vector
```

### 10.2 Set接口

**特点**：Set**不能包含重复的元素**。

**主要实现类**：
- `HashSet`
- `TreeSet`
- `LinkedHashSet`

**Set接口定义**：
```java
public interface Set<E> extends Collection<E> {
    // 基本操作
    int size();
    boolean isEmpty();
    boolean contains(Object element);
    boolean add(E element);
    boolean remove(Object element);
    Iterator<E> iterator();  // 返回当前集合元素的迭代器
    // ...
}
```

### 10.3 List接口

**特点**：List是**有序**的集合，元素**可以重复**。

**主要实现类**：
- `ArrayList`
- `LinkedList`
- `Vector`

**List接口定义**：
```java
public interface List<E> extends Collection<E> {
    // 按位置存取元素
    E get(int index);
    E set(int index, E element);
    Boolean add(E element);
    void add(int index, E element);
    E remove(int index);
    boolean addAll(int index, Collection<? extends E> c);

    // 查找
    int indexOf(Object o);
    int lastIndexOf(Object o);
    // ...
}
```

### 10.4 Map接口

**特点**：Map把**键（Key）映射到值（Value）**，一个键值最多只能映射一个值。

**主要实现类**：
- `HashMap`
- `TreeMap`
- `HashTable`

**Map接口定义**：
```java
public interface Map<K,V> {
    // 基本操作
    V put(K key, V value);
    V get(Object key);
    V remove(Object key);
    boolean containsKey(Object key);
    boolean containsValue(Object value);
    int size();
    boolean isEmpty();
    // ...
}
```

### 10.5 三大集合接口对比总结

| 集合类型 | 特点 | 元素是否有序 | 元素是否可重复 | 存储方式 | 常用实现类 |
|----------|------|:----------:|:----------:|----------|------------|
| **Set** | 不包含重复元素 | 无序（TreeSet有序） | ✗ | 单元素 | HashSet, TreeSet, LinkedHashSet |
| **List** | 有序集合 | ✓ | ✓ | 单元素，按索引访问 | ArrayList, LinkedList, Vector |
| **Map** | 键值对映射 | 无序（TreeMap有序） | Key不可重复 | Key-Value键值对 | HashMap, TreeMap, HashTable |

## 十一、本章小结

本章系统介绍了Java的高级特征，涵盖以下核心知识点：

1. **static关键字**：
   - **类变量**：所有实例共享，加载时分配一次空间，可用于实例间通信和跟踪实例数目
   - **类方法**：无this指针，不能访问非静态成员；子类不能重写父类静态方法（只能隐藏）；main()是静态方法
   - **静态初始化程序**：类加载时执行且只执行一次

2. **final关键字**：final类不能被继承、final方法不能被重写、final变量为常量（必须赋初值，一般大写）

3. **抽象类**：包含抽象方法的类，不能直接实例化，但可定义变量指向子类实例；用于类型隐藏，是OCP原则的关键

4. **接口（Interface）**：只有方法声明和静态常量的特殊抽象类；用`implements`实现；一个类可实现多个接口，以此实现多重继承；接口可作为数据类型实现多态；Java SE 8开始支持default方法

5. **包（Package）**：相关类与接口的集合，提供访问控制和命名空间管理；通过`package`定义、`import`引入；存储路径由CLASSPATH决定

6. **枚举类型**：特殊的类，隐含继承`java.lang.Enum`；每个常量对应一个整数值（ordinal）；提供name()、values()等内置方法

7. **包装类**：8种基本类型对应的Wrapper类；提供MIN_VALUE/MAX_VALUE常量和类型转换方法；JDK 1.5+支持自动装箱/拆箱

8. **泛型**：参数化类型，提供编译时类型安全，消除大多数类型转换；类名后加`<T>`定义类型变量

9. **集合类**：
   - **Set**：不包含重复元素（HashSet, TreeSet, LinkedHashSet）
   - **List**：有序集合，元素可重复，按索引访问（ArrayList, LinkedList, Vector）
   - **Map**：键值对映射，Key不可重复（HashMap, TreeMap, HashTable）
