## 二、为什么需要JDBC

### 2.1 ODBC的局限性

ODBC可能是使用最广的、用于访问关系数据库的编程接口，它能在几乎所有平台上连接几乎所有的数据库。但ODBC**不适合直接在Java中使用**：

| 局限 | 说明 |
|------|------|
| **语言不匹配** | ODBC API是C的库函数，在Java程序中调用本地C代码有较大的局限性 |
| **安全性问题** | 调用本地代码带来安全隐患 |
| **健壮性问题** | C与Java的内存管理机制不同 |
| **可移植性问题** | 破坏了Java的平台无关性 |
| **指针问题** | Java没有指针，而ODBC对指针使用很广泛，字面翻译不可取 |

### 2.2 JDBC的优势

- JDBC以ODBC为基础，采用了与ODBC**相同的标准**
- 使用JDBC使应用程序保持**"纯Java"**的可移植性等

## 三、JDBC简介

### 3.1 JDBC的定义

JDBC是为在Java程序中访问数据库而设计的**一组Java API**，是Java数据库应用开发中的一项**核心技术**。

### 3.2 JDBC的特点

| 特点 | 说明 |
|------|------|
| **独立于平台** | 跨操作系统的数据库访问 |
| **独立于数据库** | 统一的API访问不同的数据库 |
| **SQL数据库访问** | JDBC规范中成功地提供了SQL数据库访问的Java方法 |

### 3.3 JDBC与Hibernate

尽管JDBC在Java语言层面实现了统一，但不同数据库仍旧有许多差异。为了更好地实现跨数据库操作，于是诞生了**Hibernate**项目。Hibernate是对JDBC的**再封装**，实现了对数据库操作更宽泛的统一和更好的可移植性。

## 四、数据库访问模型

### 4.1 两层模型（Client/Server）

在两层模型中，Java Applet或应用程序将**直接与数据库进行对话**。这需要一个JDBC驱动程序来与所访问的特定数据库管理系统进行通讯。

**流程**：
```
Java应用程序 → JDBC驱动程序 → 数据库
           ←（SQL语句发送）      ↓
           ←（结果返回）    ←
```

- 用户的SQL语句被送往数据库中，其结果将被送回给用户
- 数据库可以位于另一台计算机上，用户通过网络连接
- 这就是**客户机/服务器配置**，用户的计算机为客户机，提供数据库的计算机为服务器
- 网络可以是Intranet，也可以是Internet

### 4.2 三层模型

在三层模型中，命令先被发送到服务的**"中间层"**，然后由它将SQL语句发送给数据库。数据库对SQL语句进行处理并将结果送回到中间层，中间层再将结果送回给用户。

**三层模型优点**：

| 优点 | 说明 |
|------|------|
| **访问控制** | 可用中间层来控制对公司数据的访问和可作的更新种类 |
| **API简化** | 用户可以利用易于使用的高级API，中间层将其转换为相应的低级调用 |
| **性能优化** | 许多情况下三层结构可提供一些性能上的好处 |

## 五、JDBC驱动类型

### 5.1 驱动体系结构

```
Java应用程序
    ↓
JDBC驱动管理器
    ↓
┌──────────────────┬──────────────────┐
│  JDBC-ODBC桥     │  JDBC网络驱动      │
│  ODBC和数据库驱动  │  JDBC中间协议      │
│  数据库驱动A/B    │  专用数据库协议     │
│  JDBC API         │  JDBC驱动API       │
│  JDBC实现         │                    │
└──────────────────┴──────────────────┘
```

### 5.2 四种驱动类型

| 类型 | 名称 | 工作方式 | 特点 |
|:----:|------|----------|------|
| **Type 1** | **JDBC-ODBC桥** (JDBC-ODBC Bridge) | JDBC调用 → ODBC调用 | 要求ODBC代码、Client端代码都要在客户机上安装 |
| **Type 2** | **本地API部分Java驱动** (Native-API Partly-Java Driver) | JDBC调用 → 数据库的Client端API | 也需要在客户机上安装代码 |
| **Type 3** | **网络协议完全Java驱动** (Net-Protocol Fully Java Driver) | JDBC调用 → 独立于任何DBMS的网络协议 | 该协议将由另外一个服务器转换为某种DBMS协议，无需客户端安装 |
| **Type 4** | **本地协议完全Java驱动** (Native-Protocol Fully Java Driver) | JDBC调用 → 特定DBMS的网络协议 | 纯Java实现，直接与数据库通信，性能最优 |

## 七、建立与数据库的连接

### 7.1 加载JDBC驱动程序

JDBC的`DriverManager`查找到相应的数据库Driver并加载。

**两种加载方式**：

| 方式 | 说明 |
|------|------|
| **系统属性自动加载** | 从系统属性`java.sql`中读取Driver的类名，并一一注册 |
| **程序中动态加载** | 使用`Class.forName()`方法动态装载并注册Driver |

**常见数据库驱动加载示例**：

```java
// JDBC-ODBC桥
Class.forName("sun.jdbc.odbc.JdbcOdbcDriver");

// SQL Server
Class.forName("com.microsoft.sqlserver.jdbc.SQLServerDriver");

// Oracle
Class.forName("oracle.jdbc.driver.OracleDriver");

// MySQL
Class.forName("com.mysql.jdbc.Driver");
```

### 7.2 建立数据库连接

通过 `DriverManager.getConnection()` 与数据库建立连接。

**方法签名**：
```java
public static Connection getConnection(String url, String user, String password)
        throws SQLException
```

**参数说明**：
- `url`：数据库连接串，指定数据库访问协议以及数据源
- 一般格式：`jdbc:<subprotocol>:<subname>`

**示例——通过JDBC-ODBC桥接驱动与wombat数据源建立连接**：
```java
Connection con = DriverManager.getConnection(
    "jdbc:odbc:wombat", "myUsername", "myPassword");
```

## 八、执行SQL语句

### 8.1 Statement（基本语句对象）

在数据库连接上创建`Statement`对象，将各种SQL语句发送到所连接的数据库执行。

**创建与执行**：
```java
Statement stmt = con.createStatement();
ResultSet rs = stmt.executeQuery("SELECT a, b, c FROM Table1");
```

**两个核心方法**：

| 方法 | 返回类型 | 说明 |
|------|:--------:|------|
| `executeQuery(String sql)` | `ResultSet` | 执行查询语句（SELECT），返回结果集 |
| `executeUpdate(String sql)` | `int` | 执行更新语句（INSERT/UPDATE/DELETE/DDL），返回受影响行数 |

### 8.2 PreparedStatement（预编译语句对象）

由方法 `prepareStatement()` 所创建。

**特点**：
- 用于发送带有一个或多个输入参数（**IN参数**）的SQL语句
- 拥有一组方法，用于设置IN参数的值
- 执行语句时，这些IN参数将被送到数据库中
- 实例扩展了Statement，包括Statement的所有方法
- **效率更高**——因为已被预编译过并存放在那以供将来使用

**适用场景**：对于**多次执行但参数不同**的SQL语句。

```java
PreparedStatement pstmt = con.prepareStatement(
    "INSERT INTO Table1 VALUES (?, ?, ?)");
pstmt.setInt(1, 100);
pstmt.setString(2, "name");
pstmt.setFloat(3, 99.5f);
pstmt.executeUpdate();
```

### 8.3 CallableStatement（存储过程调用对象）

由方法 `prepareCall()` 所创建。

**特点**：
- 用于执行SQL**存储过程**——一组可通过名称来调用的SQL语句
- 从PreparedStatement中继承了用于处理IN参数的方法
- 增加了用于处理 **OUT参数** 和 **INOUT参数** 的方法

### 8.4 三种Statement对比

| 类型 | 创建方法 | 用途 | 特点 |
|------|----------|------|------|
| **Statement** | `createStatement()` | 基本SQL语句 | 每次执行都需要编译 |
| **PreparedStatement** | `prepareStatement()` | 带参数的预编译SQL | 预编译，效率高，防止SQL注入 |
| **CallableStatement** | `prepareCall()` | 调用存储过程 | 支持IN/OUT/INOUT参数 |

## 九、处理结果集（ResultSet）

### 9.1 结果集概念

- 结果集是查询语句返回的数据库记录的集合
- 在结果集中通过**游标（Cursor）**控制具体记录的访问
- SQL数据类型与Java数据类型的转换——根据SQL数据类型的不同，使用不同的方法读取数据

### 9.2 结果集处理示例

```java
/* 处理结果集 rs */
while (rs.next()) {
    int x = rs.getInt("a");      // 或 rs.getInt(1);
    String s = rs.getString("b");
    float f = rs.getFloat("c");
    // ...
}
```

### 9.3 常用的ResultSet getter方法

| getter方法 | 返回的Java类型 |
|-----------|:------------:|
| `getInt()` | int |
| `getString()` | String |
| `getFloat()` | float |
| `getDouble()` | double |
| `getBoolean()` | boolean |
| `getDate()` | Date |
| `getLong()` | long |
| `getShort()` | short |
| `getByte()` | byte |
| `getObject()` | Object |

**两种指定列的方式**：
- 通过**列名**：`rs.getInt("a")`
- 通过**列索引**（从1开始）：`rs.getInt(1)`

### 9.4 关闭数据库连接

```java
stmt.close();
con.close();
```

**重要**：使用完毕后必须关闭资源，释放数据库连接。

## 十、JDBC层次结构与基本构成分析

### 10.1 JDBC层次结构

```
Java应用程序
    ↓
JDBC API（java.sql包）
    ↓
JDBC Driver Manager（java.sql.DriverManager）
    ↓
JDBC Driver（各数据库厂商或第三方实现）
    ↓
数据库（MySQL / Oracle / SQL Server / ...）
```

### 10.2 Driver角色

所谓驱动加载进内存，其实就是实现了`java.sql.Driver`接口的类。

**加载过程**：使用 `Class.forName()` 将对应的驱动类加载到内存中，然后执行内存中的static静态代码段，代码段中会创建一个驱动Driver的实例，放入`DriverManager`中，供DriverManager使用。

### 10.3 DriverManager角色

一般我们操作Driver、获取Connection对象都是交给DriverManager**统一管理**的。

**DriverManager功能**：
- 可以注册和删除加载的驱动程序
- 可以根据给定的URL获取符合URL协议的驱动Driver
- 建立Connection连接，进行数据库交互

### 10.4 Connection角色

表示与特定数据库的连接，可以获取到数据库的一些信息，包括：
- 表信息
- 应该支持的SQL语法
- 数据库内的存储过程
- 此链接功能的信息等

### 10.5 Statement角色

根据传入的SQL语句，将其整理组合成数据库能够识别的SQL语句，然后传递SQL请求，之后会得到返回的结果。

- 对于查询SQL，结果会以`ResultSet`的形式返回

### 10.6 ResultSet角色

查询SQL执行后会得到ResultSet对象，作为数据库结果的映射。ResultSet对从数据库返回的结果进行了封装，使用**迭代器模式**逐条取出结果集中的记录。

## 十二、零基础补充：JDBC 完整运行图

### 12.1 JDBC 应用框架图示说明

JDBC 的作用是让 Java 程序用统一方式访问不同数据库。

```text
Java程序
  ↓ 调用 JDBC API
DriverManager
  ↓ 找到合适数据库驱动
JDBC Driver
  ↓ 转换为数据库能理解的协议
数据库
```

如果没有 JDBC，每一种数据库都可能需要一套完全不同的访问代码；有了 JDBC，Java 代码面对的是统一接口。

### 12.2 两层模型和三层模型再比较

| 模型 | 结构 | 优点 | 缺点 |
|------|------|------|------|
| 两层模型 | Java程序 ↔ 数据库 | 简单直接 | 客户端直接连数据库，安全和维护压力大 |
| 三层模型 | 客户端 ↔ 中间层 ↔ 数据库 | 易维护、易控制权限、可复用业务逻辑 | 结构更复杂 |

三层模型中的“中间层”通常就是 Web 服务或业务服务器。

### 12.3 JDBC 核心对象协作流程

```text
Class.forName 加载驱动
    ↓
DriverManager.getConnection 获取连接
    ↓
Connection 创建 Statement/PreparedStatement
    ↓
执行 SQL
    ↓
ResultSet 保存查询结果
    ↓
遍历 ResultSet
    ↓
关闭 ResultSet、Statement、Connection
```

### 12.4 Statement、PreparedStatement、CallableStatement

| 类型 | 用途 | 适合场景 |
|------|------|----------|
| `Statement` | 直接执行普通 SQL | SQL 固定且无用户输入 |
| `PreparedStatement` | 预编译 SQL，可设置参数 | 常用；更安全，能减少 SQL 注入风险 |
| `CallableStatement` | 调用存储过程 | 数据库中已有存储过程 |

推荐初学者优先掌握 `PreparedStatement`：

```java
String sql = "SELECT * FROM users WHERE name = ?";
PreparedStatement ps = conn.prepareStatement(sql);
ps.setString(1, username);
ResultSet rs = ps.executeQuery();
```

### 12.5 ResultSet 的游标模型

`ResultSet` 可以理解为查询结果表，但它内部有一个游标。刚查询出来时，游标在第一行之前。

```java
while (rs.next()) {
    String name = rs.getString("name");
}
```

每调用一次 `next()`，游标移动到下一行；如果没有下一行，返回 `false`。

### 12.6 JDBC 初学者注意事项

1. 数据库驱动 jar 必须在项目依赖中。
2. URL、用户名、密码要写对。
3. 查询用 `executeQuery()`，增删改用 `executeUpdate()`。
4. 资源要关闭，实际项目推荐 `try-with-resources`。
5. 有用户输入时优先使用 `PreparedStatement`。

## 十三、本章小结

本章系统介绍了Java数据库连接（JDBC）技术，涵盖以下核心知识点：

1. **JDBC概述**：Java访问数据库的统一API，独立于平台和数据库，以ODBC为基础但保持"纯Java"特性；Hibernate是对JDBC的再封装，实现更宽泛的跨数据库统一

2. **数据库访问模型**：
   - 两层模型：应用程序直接连接数据库（Client/Server）
   - 三层模型：通过中间层转发，提供访问控制、API简化和性能优化

3. **四种JDBC驱动类型**：
   - Type 1：JDBC-ODBC桥（需安装ODBC和客户端代码）
   - Type 2：本地API部分Java驱动（需安装客户端代码）
   - Type 3：网络协议完全Java驱动（通过中间服务器转换协议）
   - Type 4：本地协议完全Java驱动（纯Java，直接通信，性能最优）

4. **JDBC核心API**：
   - `DriverManager`：管理驱动程序，建立连接
   - `Connection`：数据库连接，创建Statement对象
   - `Statement`/`PreparedStatement`/`CallableStatement`：执行SQL语句
   - `ResultSet`：结果集，通过游标迭代获取数据

5. **三种Statement**：Statement（基本）、PreparedStatement（预编译，效率高，防SQL注入）、CallableStatement（存储过程，支持IN/OUT/INOUT参数）

6. **结果集处理**：游标机制，通过列名或列索引使用getter方法读取数据

7. **JDBC编程流程**：加载驱动 → 建立连接 → 创建Statement → 执行SQL → 处理结果集 → 关闭资源
