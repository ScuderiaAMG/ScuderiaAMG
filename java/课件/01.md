## 二、Java的起源

### 2.1 Green项目

Java来自于**Sun公司**的一个叫**Green**的项目，其原先的目的是为家用消费电子产品开发一个分布式代码系统，可以把E-mail发给电冰箱、电视机等家用电器，对它们进行控制，和它们进行信息交流。

开始准备采用**C++**，但C++太复杂、安全性差，最后基于C++开发了一种新的语言——**Oak**（橡树）。Oak是一种用于网络的精巧而安全的语言。

Sun公司曾以Oak投标一个交互式电视项目，但结果被**SGI**打败，Oak几乎无家可归。恰巧这时**Mark Ardreesen**开发的**Mosaic**和**Netscape**启发了Oak项目组成员，他们用Java编制了**HotJava**浏览器，得到了Sun公司首席执行官**Scott McNealy**的支持，触发了Java进军Internet。

### 2.2 Java命名趣闻

有一天，几位Java成员组的会员正在讨论给这个新的语言取什么名字，当时他们正在咖啡馆喝着**Java（爪哇）咖啡**，有一个人灵机一动说就叫Java怎样，得到了其他人的赞赏，于是Java这个名字就这样传开了。

## 四、Java的编程环境

### 4.1 JDK（Java Development Kit）

JDK称为Java开发包或Java开发工具，是一个编写Java的Applet小程序和应用程序的程序开发环境。**JDK是整个Java的核心**，包括了：
- **Java运行环境（JRE）**
- 一些Java工具
- Java的核心类库（**Java API**）

不论什么Java应用服务器，实质都是内置了某个版本的JDK。主流的JDK是Sun公司发布的，除此之外还有很多公司和组织都开发了自己的JDK。

### 4.2 JRE（Java Runtime Environment）

可以把Java API类库中的**Java SE API子集**和**Java虚拟机**这两部分统称为**JRE**。JRE是支持Java程序运行的标准环境。

### 4.3 JDK与JRE的关系

- **JRE**是运行环境，**JDK**是开发环境
- 写Java程序时需要**JDK**，而运行Java程序时需要**JRE**
- **JDK里面已经包含了JRE**，因此只要安装了JDK，就可以编辑Java程序，也可以正常运行Java程序
- 但由于JDK包含了许多与运行无关的内容，占用的空间较大，因此运行普通的Java程序无须安装JDK，而只需要安装JRE即可

## 五、Java技术体系

Java技术体系分为三大平台：

### 5.1 Java SE（Java Standard Edition，标准版）
- 以**Web为中心**的客户端或服务器端的软件开发
- 以前称为**JDK 1.X**
- Java SE的实现：**Java Software Development Kit (SDK), Standard Edition** + **Java Runtime Environment, Standard Edition**

### 5.2 Java ME（Java Micro Edition，微型版）
- 针对**消费类电子设备**，如移动电话、电视置顶盒、汽车导航系统等
- 特点：**语言精简**、**运行环境高度优化**

### 5.3 Java EE（Java Enterprise Edition，企业版）
- 定义了**基于组件的多层企业级应用**的开发标准
- 面向**企业级和高端服务器**的Internet应用开发
- 构成：**Java SE + Enterprise JavaBeans (EJB) + Java Servlets API + Java Server Pages (JSP)**

## 七、Java的特征

Sun在Java白皮书中指出：Java是一种"**简单、面向对象、分布式、解释型、健壮、安全、体系结构中立、可移植、高性能、多线程和动态**"的编程语言。

### 7.1 特征1——简单性

- 类似C++，但进行成功改造：
  - 去掉**指针**
  - 取消**多重继承**和**运算符重载**
  - **自动内存回收**
- 语法和语义都比较单纯，容易学习和使用
- 提供大量功能丰富的**可重用类库**，简化了编程工作量

### 7.2 特征2——面向对象

Java是非常纯洁的面向对象语言，对面向对象方法学的支持也很全面：
- Java对象有**模块化性质**和**信息隐藏能力**，满足面向对象的**封装**要求
- 支持**继承**
- 通过**抽象类**与**接口**支持**多态**

### 7.3 特征3——分布式

**数据分布支持**：通过Java的URL类可以访问网上的各类信息资源，访问方式完全类似于本地文件系统。

**操作分布支持**：通过在WWW页面中的小应用程序（**Applet**）将计算从服务器分布至客户机，避免网络拥挤，提高系统效率。

### 7.4 特征4——半编译、半解释

**执行流程**：编译器编译Java源程序 → 字节码 → 解释器解释执行

**优点**：
- 兼具编译执行的**效率优势**和解释执行的**灵活性**
- 提高了应用程序的**可移植性**：源程序、中间代码

### 7.5 特征5——健壮性

- Java致力于检查程序在**编译时**和**运行时**的错误
- Java是一种**强类型**的语言，其类型检查比C++还要严格。类型检查帮助我们检查出许多开发早期出现的错误
- Java自己负责**内存管理**，提供了**垃圾内存回收机制**，有效地避免了C++中最头疼的**内存泄漏**问题

### 7.6 特征6——安全性

在语言和运行环境中引入了**多级安全措施**：

**第一级——内存安全**：
- Java的内存分配和引用模型对于程序员透明，完全由底层的运行系统控制
- 内存布局与C、C++不同，不是由编译器决定，而是运行系统根据所在的硬件平台的特性决定
- 取消了C、C++的指针，Java编译器通过**符号指针**来引用内存，由Java运行系统在运行时将符号指针具体解释为实际的内存地址

**第二级——字节码验证**：
运行系统引入**字节码验证器**，其中包含简单的规则验证程序，以确保遵循下列规则：
- 不存在伪造的指针
- 未违反访问权限
- 严格遵循对象访问规范来访问对象
- 合适的参数调用方法
- 没有栈溢出

### 7.7 特征7——体系结构中立

Java作为一种网络语言，其源代码被编译成一种**结构中立的中间文件格式**。只要有Java运行系统的机器都能执行这种中间代码。Java源程序被编译成一种与机器无关的**字节码**格式，在**Java虚拟机（JVM）**上运行。

### 7.8 特征8——可移植性

- **"一次编程，到处运行"**——WORA（Write Once, Run Anywhere）
- 可移植性源于两方面：
  - Java的**半编译、半解释**的特征
  - Java采用标准的**独立于硬件平台的数据类型**

**执行模型**：
```
Java源程序 → Java编译器 → Java字节码 → Java解释器
（可在Pentium、SPARC等不同平台上编译和运行）
```

### 7.9 特征9——高性能

- Java编译生成的**字节码与机器代码十分接近**
- 提供**即时编译（JIT）**等措施来提高性能

### 7.10 特征10——多线程

- Java在**语言级**嵌入对并发的支持功能，具体机制就是**多线程**
- **线程**是比进程更小、更经济的并发执行单位，不拥有单独的内存空间

**多线程类比**：例如做一张桌子。如果一个人完成这张桌子——就好像单线程，需要先做桌面，做完桌面后再依次做4个桌子腿。如果现在有5个人来做桌子——在程序中开辟5个线程，其中1个人做桌面，另外4个人分别做4个桌子腿，那么这两种方式效率高下立见。

### 7.11 特征11——动态特性

- Java程序的基本组成单元——**类**是运行时**动态装载**的，使Java可以动态地维护应用系统及其支持类之间的一致性
- 对比C++：在C++程序设计过程中，每当在类中增加一个实例变量或一个成员函数后，引用该类的所有子类都必须重新编译，否则将导致程序崩溃

### 7.12 Java特征总结

| 应用方向 | 对应特征 |
|----------|----------|
| 基于OO技术 | 面向对象 |
| 面向嵌入式应用 | 简单、安全可靠 |
| 面向网络应用 | 分布式、可移植（体系结构中立，半编译半解释）、高性能（多线程）、动态性 |

## 九、Java与C++不同的语法机制详解

### 9.1 类（Class）

类是Java最重要、最基本的语法设施。类的定义与继承和C++类似，主要区别：

**不允许多重继承**：多重继承必须通过**接口**实现。

**abstract修饰词**：
- 带abstract的类称为**抽象类**，只能作为父类使用，不能直接产生实例对象

**final修饰词**：
- 带final的类**不能**用作父类被继承
- 带final的属性在定义时**必须赋初值**并称为**常量**
- 带final的方法将**禁止子类重写（Overriding）**

### 9.2 接口（Interface）

- 接口是一种**抽象类**，其中只能出现**静态常量**或**抽象方法**定义
- 主要目的是实现**多重继承**功能，避免C++在多重继承语义上的复杂性
- 一个Java类可以**实现（继承）多个接口**

### 9.3 程序包（Package）

- 程序包是一些**相关类或接口的集合**
- Java提供包括可重用类标准程序包，用户可**自定义程序包**
- 通过**import**语句将程序包引入应用程序

### 9.4 自动内存回收

- Java**取消了指针类型**，所有动态内存请求均通过**new**运算符，并且得到的不是指针而是**引用**
- 系统自动进行**内存回收（垃圾回收）**

### 9.5 多线程

- 依赖操作系统提供的线程管理API：与平台绑定（传统方式）
- Java的**语言级支持多线程**：忽略操作系统多线程机制的差异，软件具有更好的**可靠性**和**可移植性**

## 十、Java运行系统

### 10.1 引入运行系统的必要性

- 将**字节码转化为本机代码**
- **类的装载**与**符号的消解**
- **控制执行代码**

### 10.2 运行环境的种类

- **Java Application**——Java解释器
- **Java Applet**——Java兼容的Web浏览器

### 10.3 Java运行系统的构成

Java运行系统由以下五个部分组成：
1. **类装配器**
2. **字节码验证器**
3. **解释器**
4. **代码生成器**
5. **运行支持库**

### 10.4 Java程序运行过程

```
Hello.java  →  javac Hello.java  →  Hello.class
                                        ↓
                                   网络类装配器
                                        ↓
                                   字节码验证器
                                        ↓
                             解释器 ← → 代码生成器
                                        ↓
                                   运行支持库
                                        ↓
                                   本地系统
                                 编译 → 运行
```

### 10.5 执行字节码的过程

执行字节码包含三个阶段：
1. **代码的装入**
2. **代码的验证**
3. **代码的执行**：有两种方式——**解释方式**、**即时编译（JIT）方式**

## 十一、Java虚拟机（JVM）

### 11.1 JVM的定义

> An imaginary machine that is implemented by emulating it in software on a real machine. Code for the Java Virtual Machine is stored in **.class files**.

JVM是一台通过在实际机器上仿真软件来实现的**虚拟机器**，Java虚拟机的代码存储在**.class文件**中。

### 11.2 JVM的组成部分

JVM规范定义了一组抽象的逻辑组件，包括：
1. **指令集**
2. **寄存器组**：程序计数器、栈顶指针等
3. **栈结构**：提供各种参数等
4. **存储区**：存放字节码的方法代码、符号表
5. **垃圾收集器**

### 11.3 JVM与Java运行系统的关系

- Java运行系统是各供应商对JVM的**具体实现**，JVM需要针对不同的软硬件平台做专门的实现
- **JVM的意义**：保证不同平台上的Java运行系统功能统一

**分层架构**：

| 层次 | 内容 |
|------|------|
| 应用程序层 | Java应用程序 |
| Java平台层 | Java虚拟机（JVM） |
| 操作系统层 | UNIX/Linux、Windows |
| 硬件层 | SPARC、X86 |

### 11.4 对运行系统的设计与实现的要求

对Java运行系统的设计与实现必须满足以下三个条件：
- 必须支持Sun的**.class文件结构**
- 必须支持**字节码定义**
- 必须支持**JVM规范**

这样使得Java运行系统功能是**统一的**，并且只能执行**统一格式的字节码**。

## 十四、Java应用程序示例

### 14.1 HelloWorld程序

```java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello World!");
    }
}
```

### 14.2 程序要点说明

**main声明——Java程序入口点**：
- 格式：`public static void main(String[] args) { ... }`
- main()方法是程序的入口

**源文件命名规则**：
- 源文件的名字与main()方法所在的类名相同
- 扩展名必须是**.java**

**编译**：
```bash
javac HelloWorld.java
```
生成 `HelloWorld.class`

**运行**：
```bash
java HelloWorld
```

## 十五、零基础补充：把本章知识串起来

### 15.1 Java EE Application Model 图示说明

PDF 中的 Java EE Application Model 是在说明：企业级应用通常不是一个单独程序，而是分成多层协作。

| 层次 | 作用 | 常见内容 |
|------|------|----------|
| 客户端层（Client Tier） | 用户直接接触的入口 | 浏览器、桌面客户端、移动端 |
| Web层（Web Tier） | 接收HTTP请求、生成网页或接口响应 | Servlet、JSP、Controller |
| 业务层（Business Tier） | 处理业务规则 | EJB、Service、业务对象 |
| 企业信息系统层（EIS Tier） | 保存和管理企业数据 | 数据库、ERP、遗留系统 |

理解方式：用户点击网页按钮后，请求先到 Web 层；Web 层调用业务层；业务层再访问数据库；最后把结果返回给用户。

### 15.2 Java Development Platform 图示说明

Java 开发平台可以理解为“写代码、编译代码、运行代码”的工具集合。

```text
源代码 .java
    ↓ javac 编译
字节码 .class
    ↓ JVM 加载与执行
程序运行
```

| 名称 | 零基础解释 |
|------|------------|
| JDK | 开发工具包，写 Java 程序必须安装它 |
| JRE | 运行环境，只负责运行 Java 程序 |
| JVM | 虚拟机，真正执行 `.class` 字节码 |
| API 类库 | Java 官方提前写好的类，比如输入输出、集合、网络、图形界面 |

### 15.3 Java 初学者必须先分清的几个概念

- **Java语言**：一套语法规则，用来写程序。
- **Java平台**：让 Java 程序能运行的一整套环境，包括 JVM、类库和工具。
- **源程序**：程序员写的 `.java` 文件。
- **字节码**：编译后得到的 `.class` 文件，不直接依赖某一种 CPU 或操作系统。
- **跨平台**：同一份字节码可以在不同系统上的 JVM 中运行。

### 15.4 本章易混点

| 易混点 | 正确理解 |
|--------|----------|
| JDK 和 JRE | JDK 包含开发工具；JRE 只负责运行 |
| JVM 和 JRE | JVM 是 JRE 的核心，但 JRE 还包含类库等运行支持 |
| 编译和解释 | Java 先编译成字节码，再由 JVM 解释或即时编译执行 |
| Java SE、ME、EE | SE 是基础，ME 面向受限设备，EE 面向企业应用 |
| `.java` 和 `.class` | `.java` 给人看和写；`.class` 给 JVM 执行 |
