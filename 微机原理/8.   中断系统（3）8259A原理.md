## 知识点详解

### 中断请求寄存器 IRR（Interrupt Request Register）

**定义**：8 位寄存器，用于寄存所有正在请求中断服务的中断源：当外部中断请求信号从引脚 IR0~IR7 进入 8259A 时，IRR 中与该引脚对应的位被置 1。

**理解**：IRR 是中断请求进入 8259A 后的第一级记录。8 个输入引脚与 IRR 的 8 个位一一对应：IR0 对应最低位，IR7 对应最高位。某引脚上有请求信号，其对应位即为 1；没有请求则对应位为 0。IRR 只记录"哪些中断源提出了请求"，不记录"哪些请求正在被服务"；它记录的是请求的到达，与 CPU 是否响应无关。

**作用**：8259A 内部结构的第一环节，为优先权电路 PR 提供判优输入，使 PR 能在所有待处理请求中按优先级排队。与 ISR 并列：IRR 记录"请求中"的中断源，ISR 记录"服务中"的中断源。

### 中断屏蔽寄存器 IMR（Interrupt Mask Register）

**定义**：8 位寄存器，用于存放程序员写入的中断屏蔽字；IMR 的每一位可对 IRR 中对应的中断请求位实施屏蔽：若 IMRi 位为 1，则 IRRi 位对应的中断请求被屏蔽，不可能进入优先权电路；若 IMRi 位为 0，则所对应的中断请求是开放的。

**理解**：IMR 的位与 IRR 的位一一对应。屏蔽的含义是阻止该请求参与判优——被屏蔽的请求不会进入优先权电路，也就不会触发中断响应过程；但屏蔽操作并不清除 IRR 中已置 1 的请求记录。程序员通过改写 IMR 的内容（经 OCW1）即可逐个开放或禁止 8 个中断源。

**作用**：提供对单个中断源的使能/禁止控制，是程序员在程序运行期间动态管理中断源的主要手段；操作命令字 OCW1 写入的内容即存入 IMR。

### 中断服务寄存器 ISR（In-Service Register）

**定义**：8 位寄存器，记录所有正在被服务的中断源：若某个中断请求 IRi 被响应、CPU 正在执行它的中断服务程序，则 ISR 的对应位 ISRi 为 1，并将保持到该中断请求被处理完毕后，该位复位为 0。

**理解**：ISR 与 IRR 的位序相同，但含义不同：IRR 记录"已提出、尚未被选中的请求"，ISR 记录"已被 CPU 响应、正在执行服务程序的请求"。在中断嵌套情形下（第 5 页思考题，见例题 1），被打断的较低级中断尚未处理完毕，其 ISR 位保持为 1，同时较高级中断的 ISR 位也被置 1，因此 ISR 中可同时有多个位为 1；各位置 1 位各自保持到对应中断处理完毕（收到中断结束命令 EOI）时才清 0。

**作用**：为优先权电路 PR 提供"CPU 正在服务的中断级别"信息，使 PR 能将新进入的请求与正在服务的级别进行比较，从而封锁同级或低级请求、只放行更高级别的请求，实现中断嵌套控制。ISR 位的清除时刻即"中断结束方式"（EOI 管理）的控制对象。

### 优先权电路 PR（Priority Resolver）

**定义**：8259A 内部负责中断判优的电路：比较、判断保存在 IRR 中的各个中断请求的优先级别，并选出优先权最高的中断请求存储在中断服务寄存器 ISR 中；PR 还比较、判断 CPU 正在服务的中断级别和新进入 IRR 的中断请求级别。

**理解**：PR 完成两类比较。第一类比较的对象是 IRR 中所有未被 IMR 屏蔽的请求：按预先设定的优先级规则（如固定优先级 IR0 最高、IR7 最低，或循环优先级）选出其中优先级最高的一个。第二类比较的对象是"刚选出的最高优先级请求"与"ISR 中记录的正在服务的中断级别"：只有新请求的级别高于正在服务的级别时，该请求才被允许打断当前服务并向 CPU 发出中断请求；否则不予发出。"存储在 ISR 中"对应第 9 页的机制：当 CPU 以第一个 INTA 负脉冲响应后，被选中的中断源在 ISR 中的对应位被置 1。

**作用**：8259A 中断优先级排队功能的执行核心。两类比较分别实现"多个同时请求的排队"和"中断嵌套的允许/禁止"，其判别结果决定 8259A 是否经 INT 引脚向 CPU 发出中断请求信号。

### 控制逻辑

**定义**：8259A 内部的控制电路，有两组可编程的命令字寄存器，分别存储初始化命令字 ICW1~ICW4 和操作命令字 OCW1~OCW3；这些命令字经译码后产生内部控制信号，根据中断请求和中断优先级的判别结果，向 CPU 发出中断请求信号 INT，并接受来自 CPU 的中断响应信号 INTA，控制 8259A 进入中断服务。

**理解**：控制逻辑的功能分两层。第一层是命令字的存储与译码：把 CPU 写入的 ICW、OCW 保存下来，翻译成对内部各部件（IRR、IMR、ISR、PR 等）的控制信号，从而决定 8259A 的优先权管理方式、屏蔽方式、结束方式、总线连接方式等。第二层是中断请求/响应交互：根据 PR 的判优结果，经 INT 引脚向 CPU 发出中断请求；接收 CPU 返回的 INTA 响应信号，并按 INTA 的节拍控制中断响应过程（第一个负脉冲置 ISR 位、清 IRR 位，第二个负脉冲送出中断类型号）。

**作用**：8259A 内部结构的核心控制部件，负责命令字的译码和中断请求/响应时序的控制；整个命令字系统（ICW/OCW）通过它实现对全片工作方式的设置。

### 数据总线缓冲器

**定义**：8 位双向三态缓冲器，是 8259A 与系统数据总线的接口；CPU 写入 8259A 的命令字及读取 8259A 的状态字都是通过数据总线缓冲器实现的。

**理解**：该缓冲器的宽度为 8 位，对应引脚 D0~D7。双向的含义是：CPU 写命令字时数据流入 8259A，CPU 读状态字（或 8259A 送中断类型号）时数据流出 8259A。三态的含义是：当 8259A 未被选中时，其输出端呈高阻状态，不占用数据总线。

**作用**：实现 8259A 内部总线与系统数据总线之间的电气连接与传输方向控制，是 CPU 与 8259A 交换命令字、状态字、中断类型号的必经通路。

### 读/写逻辑

**定义**：实现 CPU 对 8259A 的读/写操作的逻辑电路，根据片选信号 CS、端口选择信号 A0、读写控制信号 WR/RD 以及数据线标识位的组合，决定本次访问的目标寄存器与操作方向。

**理解**：CPU 访问 8259A 的任一内部寄存器，都由读/写逻辑译码出目标寄存器并开放相应通路：WR 有效（为 0）时执行写操作，命令字被送入指定寄存器；RD 有效（为 0）时执行读操作，寄存器内容被送上数据总线。7 个寄存器访问表（见补充知识点总结）就是读/写逻辑译码规则的形式化表述。

**作用**：8259A 与 CPU 之间寄存器级访问的译码执行部件；"两个端口地址访问 7 个命令字寄存器"正是由读/写逻辑配合 A0、D4、D3 标识位及写入顺序实现的。

### 级联/缓冲比较器

**定义**：用于多片 8259A 的主-从级联方式的比较器，可将中断优先级最多扩展到 64 级；与引脚 CAS0~CAS2 及 SP/EN 配合工作。

**理解**：该部件服务于 8259A 的两种工作状态。级联状态下，它配合双向级联信号 CAS2~CAS0 实现主片与从片之间的联系（主片经 CAS 线输出信号，从片经 CAS 线接收信号）；缓冲状态下，它与 SP/EN 引脚配合，参与 8259A 至 CPU 之间数据总线缓冲器的选通控制。

**作用**：把单片 8 级中断管理扩展为多片级联最多 64 级中断优先权管理，是级联结构的关键部件。

### 8259A 的中断处理过程（第 7–10 页，跨页连续）

**定义**：从外部中断源提出请求到 CPU 转入中断服务程序的完整硬件流程，依次为：
1. 中断请求信号由引脚 IR0~IR7 进入中断请求寄存器 IRR，使其对应位置 1。
2. 未被中断屏蔽寄存器 IMR 所屏蔽的中断请求被送到优先权电路 PR。
3. 优先权电路对同时送达的中断源进行判优，还与中断服务寄存器 ISR 中正在服务的中断级别进行比较、判别，优先权最高的中断源将被服务，8259A 由引脚 INT 向 CPU 发出中断请求信号。
4. 如果 CPU 处于开中断状态，则在执行完当前指令后，CPU 向 8259A 发出中断响应信号 INTA（两个负脉冲）。
5. 8259A 在接受了第一个中断响应信号（即 INTA 的第一个负脉冲）后，优先权最高的中断源在 ISR 中的对应位置 1，并且相应的 IRR 位清 0。
6. 8259A 在接受了第二个中断响应信号（即 INTA 的第二个负脉冲）后，向 CPU 的数据总线发出 8 位的中断类型号 n。
7. CPU 将 n 乘以 4，在中断向量表中地址为 $4n \sim 4n+3$ 的存储单元中取出中断服务程序入口地址送 IP 和 CS，CPU 转入中断服务程序。

**理解**：该过程分三段。第一段（步骤 1–2）是请求的登记与筛选：IRR 记录请求到达，IMR 过滤被屏蔽的请求。第二段（步骤 3–4）是判优与请求：PR 完成排队与嵌套比较，经 INT/INTA 与 CPU 进行请求/响应交互。第三段（步骤 5–7）是响应与转向：ISR 位标记服务状态、IRR 位清除请求记录，中断类型号送上数据总线，CPU 经中断向量表取得入口地址。两个 INTA 负脉冲的作用不同：第一个负脉冲完成 ISR 置位与 IRR 清零的状态更新，第二个负脉冲触发中断类型号的输出。

**作用**：本章的核心主线。该过程把内部各部件（IRR、IMR、PR、ISR、控制逻辑）与各引脚（IR0~IR7、INT、INTA、D0~D7）串成一个完整的中断响应时序，是分析中断系统硬件工作过程与后续编程内容的基础。

### 8259A 的编程结构：初始化命令字 ICW 与操作命令字 OCW

**定义**：8259A 有 7 个 CPU 可访问的寄存器，分两组：初始化命令字 ICW1~ICW4，在系统初启时设定，规定优先权管理方式、中断结束方式及级连方式等基本工作方式，其决定的工作方式在 8259A 的整个工作过程中不变，写入顺序不能改变（ICW1→ICW2→[单片判断]→ICW3→ICW4）；操作命令字 OCW1~OCW3，在系统运行时由应用程序设定，动态改变其操作和控制方式，实现对中断处理的动态管理和控制，OCW1~OCW3 无写入顺序要求。

**理解**：两类命令字的差别在于设置时机和作用时效。ICW 只在系统初启时写入一次，写入后不再改变，故用于规定不可变的工作骨架（触发方式、单片/级连、级连结构、缓冲方式、嵌套方式、结束方式）；ICW1~ICW4 的写入顺序不能改变，其初始化流程为：先写 ICW1，再写 ICW2；判断是否为单片 8259A——非单片（级联）时写 ICW3，然后写 ICW4；单片时跳过 ICW3 直接写 ICW4。OCW 在运行期间可反复写入、随时改写，故用于动态管理（屏蔽、EOI、优先级循环、特殊屏蔽、查询、读状态）；写入顺序约束只存在于 ICW 内部（由 8259A 内部状态机按序接收），OCW 之间无顺序约束。

**作用**：8259A 编程结构的顶层概念，统领 ICW1~ICW4 与 OCW1~OCW3 全部命令字知识点，是理解后续全部命令字内容（优先级方式、屏蔽方式、结束方式、总线连接方式）的框架。"初始化时静态配置（ICW）、运行期动态调整（OCW）"的分工也是全部 8259A 编程题目的基础。

### 端口选择（标识位）机制

**定义**：8259A 只有两个端口地址（由 A0 区分偶地址与奇地址），却要访问多个寄存器；其解决方法是采用专门的"标识位"：ICW1 用偶地址写入且 D4=1；ICW2、ICW3、ICW4 紧接着 ICW1 用奇地址写入；OCW1 也用奇地址写入，但不紧跟 ICW1；OCW2、OCW3 也用偶地址写入，但 D4=0（再由 D3 区分：D3=0 为 OCW2，D3=1 为 OCW3）。这样可节省输入地址的引脚数（仅用了 A0）。

**理解**：由于片内选择只用 A0 一根地址线，8259A 采用"地址位 + 数据位标识 + 写入顺序"三重信息区分寄存器：A0 区分偶地址端口与奇地址端口；数据总线上的 D4、D3 作为标识位参与译码（D4=1 标志 ICW1，D4=0 且 D3=0 标志 OCW2，D4=0 且 D3=1 标志 OCW3）；ICW2~ICW4 与 OCW1 都写奇地址端口，靠"是否紧跟 ICW1"的写入次序区分。7 个寄存器访问表中 CS、RD、WR、A0、D4、D3 各列的组合含义即来源于此。

**作用**：解决"两个端口地址访问 7 个寄存器"的寻址矛盾，节约地址引脚数；是整个命令字系统的寻址基础，也是编程时选择偶/奇端口地址的直接依据。

### 全嵌套方式（Fully Nested Mode）

**定义**：8259A 中断优先权管理的 4 种方式之一，是默认方式（也称固定优先级方式）：由 IRi 引入的中断请求具有固定的优先级，IR0 最高，IR7 最低。

**理解**：全嵌套方式下 8259A 的行为分两方面。其一，当一个中断请求被响应时，ISR 中的对应位 ISn 被置 1，8259A 把中断类型码放到数据总线上，然后 CPU 进入中断服务程序；一般情况下（除"中断自动结束"方式外），在 CPU 发出中断结束命令（EOI）前，此对应位一直保持为 1。其二，该置 1 位封锁同级或低级的中断响应——新到的同级或低级请求不会被响应；但并不禁止比本级优先级高的中断响应——更高级别的请求可以打断当前服务，实现中断嵌套。

**作用**：8259A 初始化后的默认优先权管理方式，是后续比较其余三种方式（特殊全嵌套方式、自动循环方式、优先级特殊循环方式）差异的基准；其 ISR 置位保持规则是理解中断嵌套与中断结束管理的基础。

### 特殊全嵌套方式（SPECIAL FULLY NESTED MODE，SFNM）

**定义**：8259A 的一种中断优先权管理方式。在处理某一级中断时，不但允许优先级更高的中断请求进入，也允许同级的中断请求进入。通过 ICW4 的 SFNM 位（D4）设置，D4=1 即指定特殊完全嵌套方式。用于主从结构的 8259A 系统中，将主片设置为特殊全嵌套方式。

**理解**：全嵌套方式下，某中断被响应后其 ISR 对应位保持为 1，该位会封锁同级中断请求；特殊全嵌套方式取消了这一封锁条件，使同级请求也能进入。采用它的原因与主从级连结构有关：从片的 INT 输出接在主片的某一个 IR 输入端（例如 IR2）上，因此从片任何一路中断对主片而言都表现为同一级（同一 IR 端）。若主片采用全嵌套方式，当从片正在服务其中断时主片该 IR 端对应的 ISR 位为 1，从片随后产生的更高优先级中断到达主片时会被当作同级请求而封锁，从片内部便无法实现嵌套。主片改为特殊全嵌套方式后，同级请求放行，从片内部的高优先级中断即可正常嵌套。

**作用**：中断优先权管理的 4 种方式之一，是全嵌套方式的补充扩展。与主从级连结构（ICW3、CAS 信号、从片识别）配套使用，是全嵌套方式与中断嵌套原理在主从系统中的应用。

### 自动循环方式（AUTOMATIC ROTATION）

**定义**：8259A 的一种中断优先权管理方式。优先级循环变化，不保持固定的优先级差别：一个设备的中断服务完成后，其优先级自动降为最低，而将最高优先级赋给原来比它低一级的中断请求。是否采用自动循环优先级由操作命令字 OCW2 设定。

**理解**：该方式用"服务完成后优先级轮转"的规则取代固定的 IR0>IR1>…>IR7 次序。轮转规则由两部分构成：刚服务完的 IR 端降为最低优先级；其余 IR 端按原来的顺序依次前移一位（比它低一级的升为最高）。例如初始队列为 IR0→IR7，IR0 服务完成后队列变为 IR1，IR2，IR3，IR4，IR5，IR6，IR7，IR0；随后若 IR4 服务完成，队列变为 IR5，IR6，IR7，IR0，IR1，IR2，IR3，IR4。轮转保证各中断源轮流获得最高优先级，避免固定优先级下低级设备长时间得不到服务。

**作用**：中断优先权管理的 4 种方式之一，与全嵌套方式（固定优先级）构成对比。设置依赖 OCW2 命令字，是 OCW2 中 R 位功能的前置应用实例，与"优先级特殊循环方式"并列。

### 优先级特殊循环方式

**定义**：8259A 的一种中断优先权管理方式，优先级循环过程与自动循环方式相同；区别在于自动循环方式的初始优先级是确定的（复位后为 IR0 最高、IR7 最低），而特殊循环方式的初始最低优先级由程序决定，其余各级优先级随最低优先级的指定而相应确定。

**理解**：该方式与自动循环方式的差别只在于初始状态由谁决定：自动循环方式的起始队列固定，特殊循环方式允许程序员通过 OCW2 的 L2~L0 指定初始的最低优先级编码，从而得到不同的起始优先级队列。起始队列确定之后，两者按同一条规则轮转：某中断服务完成，其优先级降为最低，低一级者升为最高。

**作用**：中断优先权管理的 4 种方式之一，是自动循环方式的变体。其初始最低优先级的指定功能与 OCW2 的 L2~L0 编码直接相关。

### 利用中断屏蔽功能管理优先级

**定义**：中断优先级管理除全嵌套、特殊全嵌套、自动循环、特殊循环 4 种方式外，还存在另一种方法：利用中断屏蔽功能（即通过对 IMR 相应位置 1 屏蔽指定中断请求）来实现优先级管理。

**理解**：该方法不改变 8259A 内部的优先权判决规则，而是把不希望参与响应的中断请求在进入优先权电路之前通过 IMR 屏蔽掉，使它们暂时退出优先级竞争。屏蔽位可随时通过 OCW1 写入或修改，因此可动态改变实际参与响应中断源的集合，达到按需要管理优先级的目的。

**作用**：中断优先权管理的补充方法，与 4 种硬件优先级方式并列。前置概念是 IMR（中断屏蔽寄存器），具体操作依赖 OCW1 命令字，与"普通屏蔽方式"知识点直接衔接。

### 普通屏蔽方式

**定义**：通过对中断屏蔽寄存器 IMR 的设定实现对中断请求的屏蔽：IMR 相应位为 1 时，对应 IR 端的中断请求被屏蔽（不可能进入优先权电路）；为 0 时对应中断请求开放。可通过 OCW1 使 IMR 的一位或几位置 1，可以在主程序和中断服务程序中设置。

**理解**：屏蔽的机理是 IMR 位于 IRR 与优先权电路之间的通路上，某位为 1 时该路请求在进入优先权电路前就被截断，因此被屏蔽的请求不参与判优、不会被响应，但请求仍保留在 IRR 中。设置位置可以是主程序（初始化阶段屏蔽某些设备）或中断服务程序（运行中改变屏蔽状态），设置手段为向奇地址端口写入 OCW1。

**作用**：中断屏蔽方式之一，与特殊屏蔽方式并列。是 OCW1 命令字的使用场景，也是 IMR 寄存器知识点的直接应用，为中断系统的动态控制提供手段。

### 特殊屏蔽方式（SPECIAL MASK MODE）

**定义**：一种使低优先级的中断能够进入正在服务的高优先级中断的中断屏蔽方式。设置方法：先输出 OCW3（ESMM=1，SMM=1）允许设置特殊屏蔽方式，再输出 OCW1 使 IMR 对应于本级中断的位为 1（同时 ISR 的对应位清 0），此时本级中断"级无效"；撤销方法：先输出 OCW1 使 IMR 对应于本级的位为 0，再输出 OCW3（ESMM=1，SMM=0）。一般在中断服务程序中设置，目的是实现中断优先权的动态管理。

**理解**：全嵌套方式下，正在服务的中断级别记录在 ISR 中，ISR 会封锁所有级别不高于本级的中断请求，因此低级中断无法打断高级中断服务。特殊屏蔽方式通过两步操作解除该封锁：第一步用 OCW3 的 ESMM、SMM 两位打开 8259A 的"特殊屏蔽"开关，第二步用 OCW1 屏蔽正在服务的本级中断（本级被屏蔽后其 ISR 对应位自动清 0，8259A 中不再有该级正在服务的记录），于是低级中断请求可以正常通过优先权电路进入响应。服务完后按相反顺序恢复：先开放本级屏蔽位，再关闭特殊屏蔽开关。

**作用**：中断屏蔽方式之一，用于中断优先权的动态管理，是中断嵌套规则（高级可打断低级）的一种受控例外。前置概念为 OCW1、OCW3 命令字，与中断结束方式（ISR 位清 0）在机理上相关联。

### 中断结束与中断结束方式

**定义**：中断结束指一个中断过程处理完成；中断结束要做的事情是处理中断服务寄存器 ISR 的对应位，即将处理完的中断对应位清 0。ISR 记录当前"正在处理"的中断，包括被高级中断打断、还未处理完的中断。何时将 ISR 中对应位清 0，就是中断结束方式。

**理解**：ISR 某位为 1 表示该级中断尚未处理完，此记录具有两种作用：供中断响应时封锁同级和低级请求（用于嵌套控制）、供中断结束命令确定应清除的位置。中断服务程序执行完毕并不自动清除 ISR 位，必须由中断结束机制完成清除；清除时机和清除位置的确定方法不同，构成不同的中断结束方式。该知识点同时回答了两个问题：为什么需要中断结束（不清除则同级、低级中断永远被封锁）和中断结束要做何事（清 ISR 对应位）。

**作用**：中断结束方式三种具体方式（自动、一般、特殊）的总括概念，是中断嵌套和中断服务程序返回（IRET）之间的必要环节。前置概念为 ISR 寄存器，后置概念为三种 EOI 方式及 OCW2 命令字。

### 中断自动结束方式（AUTOMATIC EOI，AEOI）

**定义**：在第二个 INTA 信号的下降沿，即完成使对应的 ISR 位复位（清 0）。即 AEOI 方式是在中断响应后而不是在中断处理程序结束后将 ISR 位清 0。通过 ICW4 的 AEOI 位（D1）设置，AEOI=1 为自动中断结束方式。

**理解**：该方式的清 0 时机早于中断服务程序的结束时刻。其直接后果是：中断处理过程中，8259A 中已没有"正在处理"的标识，此时若有中断请求出现且 IF=1，则无论其优先级比本级高、低或相同，都将得到响应；尤其当某一中断请求信号被 CPU 响应后若未及时撤销，该请求会再次被响应，产生"二次中断"。因此 AEOI 方式仅适合中断请求信号持续时间有一定限制以及不出现中断嵌套的场合。

**作用**：中断结束方式之一，特点是无需软件发送 EOI 命令。与一般、特殊中断结束方式并列，其局限（不能嵌套、二次中断风险）是理解"为何多数场合不用 AEOI"的依据。设置依赖 ICW4 的 D1 位。

### 一般（常规）中断结束方式

**定义**：在中断服务程序结束时，CPU 向 8259A 发送常规中断结束命令（OCW2：EOI=1、SL=0、R=0），将 ISR 中最高优先级的置 1 位清 0，完成当前正在处理中断的结束操作。适合全嵌套方式。

**理解**：该方式不指明要清除 ISR 中哪一位，而是依赖全嵌套方式的一条性质：ISR 中优先级最高的置 1 位正对应当前正在处理的中断。中断服务程序结束前，CPU 执行一条 OUT 指令向偶地址端口写入 OCW2=20H（0010 0000B，D5(EOI)=1、D6(SL)=0、D7(R)=0），8259A 据此找到 ISR 最高优先级的置 1 位并清 0。发送该命令的指令必须放在 IRET 指令之前，使中断返回前 ISR 记录已清除。

**作用**：中断结束方式之一，是全嵌套方式下最常用的中断结束手段。与特殊中断结束方式对比：无需指定具体中断级别。前置概念为 ISR、全嵌套方式，操作依赖 OCW2 命令字。

### 特殊中断结束方式（SPECIFIC EOI，SEOI）

**定义**：在非全嵌套方式下（如使用设置优先权命令或特殊屏蔽方式时），无固定的优先级序列，根据 ISR 的内容无法确定刚刚响应（处理）的中断，此时必须使用特殊的中断结束命令 SEOI：OCW2 的 EOI=1、SL=1、R=0，由 L2~L0 指定清除 ISR 中的哪一位，即 ISR 位的清零由程序员指定。

**理解**：常规 EOI 依赖"ISR 最高优先级位=当前正在处理的中断"这一性质，该性质只在固定优先级的全嵌套方式下成立。在非全嵌套方式（自动/特殊循环方式改变了优先级别，或特殊屏蔽方式清除了 ISR 位）下该性质不成立，8259A 无法自行判断应清哪一位，因此改为由程序员在命令字的 L2~L0 字段中直接给出中断级别编码，8259A 清除指定编号的 ISR 位。

**作用**：中断结束方式之一，覆盖常规 EOI 不适用的工作方式。与常规 EOI 并列，两者构成 OCW2 命令字的两类中断结束应用。前置概念为 ISR、OCW2 及非全嵌套方式。

### 中断触发方式

**定义**：8259A 对中断请求信号进入请求触发器的条件的规定，共两种。电平触发方式：由 IRi 上的有效电平来触发中断请求触发器；边沿触发方式：由 IRi 上由低电平向高电平的跳变来触发中断请求触发器。由 ICW1 的 LTIM 位（D3）设置：LTIM=0 为上升沿边缘触发，LTIM=1 为高电平触发。

**理解**：同一路中断请求信号存在电平变化和跳变沿两个不同特征，触发方式规定以哪个特征作为"请求到来"的判定条件：电平触发以信号处于有效电平（高电平）为准，边沿触发以信号发生低到高的跳变时刻为准。选择依据是外设请求信号的电气特性；在 PC 系列微机系统中采用边沿触发方式。该方式在初始化时由 ICW1 设定，属初始化决定的静态工作方式。

**作用**：8259A 中断管理方式之一（课程要求掌握的内容），是 ICW1 命令字 LTIM 位的应用场景。与中断请求信号的硬件特性直接相关，是正确配置 8259A 初始化的前置知识。

### 连接系统总线的方式（缓冲方式与非缓冲方式）

**定义**：8259A 与系统数据总线之间的两种连接方式，由 ICW4 的 BUF 位（D3）选择。
- 缓冲方式（BUF=1）：8259A 通过总线驱动器（如 8286）和数据总线相连；此时 8259A 的 SP/EN 引脚作为输出（EN 有效），在 8259A 与 CPU 间传送数据时启动（选通）数据总线缓冲器；由 ICW4 的 M/S 位（D2）定义本片是主片还是从片（M/S=1 为主片，M/S=0 为从片）。
- 非缓冲方式（BUF=0）：8259A 直接与数据总线相连；此时 SP/EN 引脚作为输入（SP 有效），由 SP/EN 端的电平标识本片是主片（=1）还是从片（=0）；此时 ICW4 的 M/S 位无意义。

缓冲的目的：提高总线驱动能力。

**理解**：两种方式的选择取决于总线上负载的数量：负载较多时 8259A 的输出驱动能力不足，需经 8286 等总线驱动器放大后再驱动数据总线，此为缓冲方式；负载少时直接相连即可，为非缓冲方式。两种方式下 SP/EN 引脚功能不同（输入 SP 定主从 / 输出 EN 选通缓冲器），主从标识也由不同来源决定（引脚电平 / ICW4 的 M/S 位）。这一配置属于初始化静态设置，写于 ICW4 中。

**作用**：8259A 中断管理方式之一，是 8259A 硬件连线与 ICW4（BUF、M/S 位）之间的衔接知识点。前置概念为 SP/EN 双向双功能引脚和级连主从概念，是 8259A 系统组建（硬件设计）的必要知识。

### ICW1（初始化命令字 1）

**定义**：8259A 初始化命令字 1，用偶地址（A0=0）写入。格式：D7、D6、D5、D2 为任意值（×）；D4 恒为 1，是 ICW1 的标志位；D3（LTIM）设置中断请求信号触发形式，D3=0 为上升沿边缘触发，D3=1 为高电平触发；D1（SNGL）设置单片/级连工作方式，D1=0 为多片级连，D1=1 为单片工作；D0（IC4）标示是否设置 ICW4，在 80X86 系统中该位为 1（要设置）。

**理解**：ICW1 在初始化流程中承担三项任务：以 D4=1 作为身份标志，使 8259A 在写入偶地址端口的多个命令字（ICW1、OCW2、OCW3 共用偶地址）中识别出这是 ICW1；以 D3、D1 设置触发方式和单片/级连方式；以 D0 预告后面是否还有 ICW4（80X86 系统固定写 1）。其余 4 位（D7、D6、D5、D2）内容不影响芯片工作，可任取。

**作用**：初始化命令字之一，是所有初始化程序的第一条命令字。其 D0（IC4）位还用于修改初始化流程（见补充知识点总结）；D3、D1 是触发方式、级连方式两个知识点的设置入口。

### ICW2（初始化命令字 2）

**定义**：8259A 初始化命令字 2，用奇地址（A0=1）写入，用以设置中断类型号。格式：D7~D3 为用户指定的中断类型号的高 5 位（区分其他中断号）；D2~D0 由 8259A 中断请求端 IR7~IR0 的编码确定——IR0 的编码是 000、IR1 的编码是 001、…、IR7 的编码是 111。当 8259A 有某个中断源的中断请求时，对应的编码自动填入 D2~D0，这样 D7~D0 就构成 8 位中断类型号。

**理解**：ICW2 只预先规定中断类型号的高 5 位；低 3 位不在初始化时固定，而是留给硬件在响应中断时按提出请求的 IR 端编号自动填充。高 5 位由程序员选择（例如 PC 机主片取 08H 的高 5 位 00001），低 3 位即 IR 编码（IR0=000 到 IR7=111），因此同一片 8259A 的 8 级中断类型号是 8 个连续值：高 5 位值×8 + 0 到 +7。该机制使中断类型号与中断源一一对应，且无需为每个中断源单独编程。

**作用**：初始化命令字之一，是"中断类型号→中断向量表"链路的起点：CPU 将收到的中断类型号 n 乘以 4，在中断向量表中 $4n \sim 4n+3$ 单元取入口地址。是 8086 中断向量表知识与 8259A 硬件之间的连接点。

### ICW3（初始化命令字 3，主片格式与从片格式）

**定义**：8259A 多片级连时需设置的初始化命令字，用奇地址（A0=1）写入。主、从片的 ICW3 格式不同：
- 主片 ICW3：D0~D7 位（S0~S7）指出主片的哪个中断请求输入端 IR 连接有从片——D0 对应 IR0、D1 对应 IR1、…、D7 对应 IR7，某 IR 端接有从片则该位为 1，无从片则为 0。
- 从片 ICW3：D2（ID2）~D0（ID0）位指出该从片接入主片中断请求输入端 IR 的编码，例如从 8259A 接到主 8259A 的 IR6，则从片 8259A 的 D2=1、D1=1、D0=0，其余以此类推。
- 级连工作时过程：当 CPU 第一个 INTA 脉冲到来时，主片通过 CAS0~CAS2 向从片发送编码 ID2~ID0，从片收到后与自身 ICW3 中的值进行比较，如果相等，则在第二个 INTA 脉冲到来时将自己的中断类型号发送到数据总线上。

**理解**：级连系统的 8259A 不止一片，各片的身份和连接位置必须预先登记。主片的 ICW3 登记"哪几根 IR 上挂有从片"（位置位图）；从片的 ICW3 登记"我接在主片的哪一根 IR 上"（3 位编码）。响应中断时，主片须先判断请求来自直连设备还是从片：若是从片，主片用 CAS0~CAS2 广播该从片的编码，只有编码与自身 ICW3 匹配的从片才在第二个 INTA 脉冲时送出类型号，保证一次只有一片 8259A 向数据总线放数据。原文勘误（第 36、37 页）：教材原文此处写"只有 ICW1 的 D1=1 时才需设置 ICW3"，与 ICW1 中"D1=0 为多片级连、D1=1 为单片"的定义矛盾，应为原文笔误（级连即 D1=0 时才需设置 ICW3），以 ICW1 位定义为准。

**作用**：初始化命令字之一，仅在多片级连系统中使用，是级连结构（主从 8259A、CAS0~CAS2、SP/EN）的编程登记。与特殊全嵌套方式（主片设置）、中断优先级扩展至 64 级等知识点直接关联。

### ICW4（初始化命令字 4）

**定义**：ICW1 的 D0（IC4）=1 时（表示要设置 ICW4）必须设置的初始化命令字，用奇地址（A0=1）写入。格式：D7~D5 为 ICW4 的特征位，总是设置为 0；D4（SFNM）专用于指定多片 8259A 级连方式是否采用特殊完全嵌套方式进行中断优先权管理，D4=0 为非特殊完全嵌套方式，D4=1 为特殊完全嵌套方式；D3（BUF）指出 CPU 的数据总线是否需增加缓冲器，D3=0 为非缓冲方式，D3=1 为缓冲方式（此时引脚 SP/EN 为输出端，当 8259A 与 CPU 间传送数据时它启动数据总线缓冲器）；D2（M/S）指出在缓冲方式下本片是主片还是从片，它与 D3 位配合使用——D3=0 时 D2 位不起作用，D3=1 时 D2=0 为从片、D2=1 为主片；D1（AEOI）指定 8259A 是否采用自动中断结束方式，D1=0 为正常中断结束方式，D1=1 为自动中断结束方式；D0 恒为 1，为 ICW4 的特征位。

**理解**：ICW4 是初始化命令字中的工作方式综合设置字，把前述多个管理方式的选择集中到一条命令字中：嵌套方式（SFNM）、总线连接方式（BUF 与 M/S 配合）、中断结束方式（AEOI）。其写入条件是 ICW1 的 D0=1，即 ICW1 事先预告要设置 ICW4。D7~D5 恒为 0 作为该命令字的特征标志，与 D4 标志位为 1 的 ICW1 形成区分（两者都经偶地址/奇地址写入过程区分，ICW1 走偶地址、ICW4 走奇地址）。

**作用**：初始化命令字之一，是特殊全嵌套方式、缓冲/非缓冲方式、自动/正常中断结束方式三个知识点的编程入口，把各管理方式的知识落实到具体位的设置。

### OCW1（操作命令字 1，中断屏蔽命令字）

**定义**：8259A 的操作命令字 1，即中断屏蔽命令字，其内容被存入中断屏蔽寄存器 IMR 中。格式：D7~D0 位（M7~M0）对应 IR7~IR0 的中断请求，某位为 1 时对应该位的中断请求被屏蔽，为 0 时表示对应位的中断请求开放。用奇地址（A0=1）写入。

**理解**：OCW1 的每一位与一条 IR 中断请求线一一对应，其值直接写入 IMR 寄存器。OCW1 是运行期命令字，无写入顺序限制，可在主程序或中断服务程序中随时写入，从而动态改变各中断源的开放/屏蔽状态。它与普通屏蔽方式、特殊屏蔽方式的知识点是对应关系：前者是命令字格式，后两者是其应用场景。

**作用**：操作命令字之一，是中断屏蔽（普通屏蔽方式、特殊屏蔽方式）与"利用屏蔽功能管理优先级"的全部软件操作载体，也是 8259A 动态控制中断系统的基本手段。

### OCW2（操作命令字 2）— 优先权循环与中断结束方式设置命令字

**定义**：OCW2（操作命令字 2）是 8259A 的一组操作命令字之一，通过偶地址端口（A0=0）写入；其格式为：D7=R、D6=SL、D5=EOI、D4=0、D3=0、D2~D0=L2~L0。D4、D3 均为 0 是 OCW2 的标志位。OCW2 用于设置优先权循环的方式和中断结束的方式。

**理解**：OCW2 共 8 位，由五个位段构成。D4、D3 两位恒为 0，只用于区分本命令字是 OCW2 而不是 ICW1（ICW1 用偶地址写入且 D4=1，OCW3 的标志位是 D4=0、D3=1）。其余位按功能分组：D7 单独控制优先权是否循环；D6 单独控制 D2~D0 三位是否有效；D5 单独控制是否执行中断结束操作；D2~D0 三位在 D6 有效时提供附加信息。D7、D6、D5 各自具有独立功能，组合起来构成复合功能，因此一个 OCW2 可同时完成"设置循环方式 + 中断结束"两件事。该设计的原因：8259A 的偶地址端口要复用于 ICW1、OCW2、OCW3 三个命令字，靠 D4、D3 两位的组合区分三个命令字。

**作用**：OCW2 是 8259A 操作命令字体系的一部分（与 OCW1 的中断屏蔽、OCW3 的特殊屏蔽/查询/读寄存器并列），用于在系统运行期动态改变优先权管理方式（固定或循环）和完成中断结束处理（一般 EOI 或特殊 EOI）。它是 4 种优先权管理方式中"自动循环方式"和"优先级特殊循环方式"的设定手段，也是"一般中断结束方式"和"特殊中断结束方式"的实现手段。

### OCW2 的 D4、D3 标志位

**定义**：OCW2 中 D4=0、D3=0，为 OCW2 的标志位（恒定为 0）。

**理解**：D4、D3 固定取 0、0。写入偶地址端口（A0=0）的命令字靠这两位区分：D4=1 为 ICW1，D4=0 且 D3=0 为 OCW2，D4=0 且 D3=1 为 OCW3。ICW1 用偶地址写入且 D4=1；OCW2、OCW3 也用偶地址写入但 D4=0，再由 D3 区分二者。

**作用**：基础概念，独立知识点。它解释 8259A 为何仅用 A0 一条地址线就能访问多个寄存器——采用专门的标识位以节省输入地址的引脚数。

### OCW2 的 D7（R）位 — 优先权循环控制

**定义**：OCW2 中 D7（R）用于优先权控制。D7=0，为固定优先权方式（IR0 最高，IR7 最低）；D7=1，为优先权循环方式。

**理解**：R 位只有两个取值。取 0 时 8259A 保持复位后自动设置的固定优先级序列 IR0>IR1>…>IR7 不变；取 1 时采用循环优先级——一个中断源被服务完成后，其优先级自动降为最低，原来比它低一级的中断请求获得最高优先级。取 1 时若配合 SL=1，则 L2~L0 指定循环的初始最低优先级，即"优先级特殊循环方式"；R=1 而 SL=0 时从固定序列出发循环，即"自动循环方式"。

**作用**：是 OCW2 复合功能的一部分，与 D6、D5 组合使用；实现运行期对优先权管理方式的动态改变（对应 4 种优先权管理方式）。

### OCW2 的 D6（SL）位 — L2~L0 有效控制

**定义**：OCW2 中 D6（SL）用于决定 OCW2 中的 L2、L1、L0 是否有效。D6=0，表示无效；D6=1，表示有效。

**理解**：SL 位是一个使能开关。当 SL=0 时，D2~D0 三位的内容不被采用，此时 OCW2 的循环/结束功能按默认规则执行；当 SL=1 时，D2~D0 三位的取值才参与操作——在循环方式中指定最低优先级编号，或在特殊中断结束中指定要清除的 ISR 位。

**作用**：是 OCW2 复合功能的一部分，作为 L2~L0 的使能控制位，与 D7（R）、D5（EOI）组合使用。

### OCW2 的 D5（EOI）位 — 中断结束命令

**定义**：OCW2 中 D5（EOI）用于中断结束命令。D5=1，使中断服务寄存器 ISR 的对应位置 0。

**理解**：EOI 位取值 1 表示执行一次中断结束操作，即把 ISR 中的相应位置 0。它与 SL、R 组合出三种中断结束命令：EOI=1、SL=0、R=0 为一般（常规）中断结束命令，由 8259A 自动选择 ISR 中优先级最高的置 1 位清 0（如 MOV AL,20H; OUT 20H,AL，OCW2=20H，放在 IRET 指令之前）；EOI=1、SL=1、R=0 为特殊中断结束命令，由 L2~L0 指定清 ISR 的哪一位；EOI=0 则不执行中断结束。

**作用**：是 OCW2 复合功能的一部分；是"中断结束方式"中一般中断结束方式与特殊中断结束方式的实现手段。中断结束时必须执行，否则 ISR 对应位保持 1，会封锁同级或低级中断的响应。

### OCW2 的 D2~D0（L2~L0）位 — 最低优先级编码 / 特殊 EOI 指定

**定义**：OCW2 中 D2~D0（L2~L0）有两个作用：1、用于决定 8259A 优先级循环中的最低优先级编码，以此改变 8259A 复位后自动设置的固定优先级（IR0 最高，IR7 最低）；2、当 OCW2 给出特殊中断结束命令时（即 EOI=1、SL=1、R=0），D2~D0 指出应使 ISR 中的对应位清 0。

**理解**：L2~L0 是三位二进制编码，编码值与 IR 序号对应（000=IR0，001=IR1，…，111=IR7）。作用 1 的应用：设 L2、L1、L0 分别为 1、1、0，即设置 IR6 为最低优先级；原来比 IR6 低一级的 IR7 变为最高。由此，指定一个最低优先级后，其余优先级按循环规则依次排列，整个初始序列即被确定（这就是"优先级特殊循环方式"中"初始最低优先级由程序决定"的含义）。作用 2 的应用：在非全嵌套方式下 ISR 内容无法确定当前处理的是哪一级时，由程序通过 L2~L0 明确指出要清除的 ISR 位。

**作用**：是 OCW2 复合功能的一部分，在 SL=1 时向优先级循环和特殊中断结束操作提供编码参数；与循环优先级和 SEOI 的内容对应。

### OCW3（操作命令字 3）— 特殊屏蔽、中断查询、寄存器状态读出命令字

**定义**：OCW3（操作命令字 3）是 8259A 的一组操作命令字之一，通过偶地址端口（A0=0）写入；其格式为：D7=0（不起作用）、D6=ESMM、D5=SMM、D4=0、D3=1、D2=P、D1=RR、D0=RIS。D4、D3 分别为 0 和 1，是 OCW3 的标志位。OCW3 用于设置特殊屏蔽方式、中断查询方式、读出 8259A 内部寄存器的状态。

**理解**：OCW3 的 8 位分为四组：标志位 D4=0、D3=1 区分本命令字为 OCW3；D7 恒为 0 不起作用；D6、D5 两位组合控制特殊屏蔽方式；D2 单独控制查询方式；D1、D0 两位组合控制寄存器读出。一个控制字实现三个功能依靠位的分组：不同功能占用互不重叠的位，各组位的取值互不干扰，因此一次写入可同时设定三组功能。

**作用**：是 8259A 操作命令字体系的一部分（与 OCW1、OCW2 并列），实现中断处理过程的动态管理：优先权的动态管理（特殊屏蔽）、无 INTR 引脚参与的中断查询、以及 IRR/ISR/IMR 状态的读出。

### OCW3 的 D6（ESMM）位与 D5（SMM）位 — 特殊屏蔽方式控制

**定义**：OCW3 中 D6（ESMM）为 1，表示允许设置或取消设置特殊屏蔽；D5（SMM）为 1 则选择特殊屏蔽方式。D6 和 D5 位组合使用：当 ESMM=1，SMM=0，取消设置特殊屏蔽方式；当 ESMM=1，SMM=1，允许设置特殊屏蔽方式。当 ESMM=0 时，无论 SMM 为何值，均不能设置或取消特殊屏蔽方式。

**理解**：ESMM 是"特殊屏蔽使能"开关，SMM 是"特殊屏蔽方式"选择位。两者组合出三种状态：ESMM=1、SMM=1 为设置特殊屏蔽方式；ESMM=1、SMM=0 为清除特殊屏蔽方式；ESMM=0 时 SMM 不起作用，特殊屏蔽状态保持不变。设置特殊屏蔽方式的完整操作是两步：先用 OCW1 命令字屏蔽正在运行的高级中断（使 IMR 对应位置 1，同时 ISR 对应位清 0），再设置 OCW3 的 ESMM=1 及 SMM=1。经过这两步后，"中断级无效"——8259A 在中断服务过程中不再封锁低级中断，低优先级中断源可以中断正在服务的高优先级中断源，从而实现对中断优先权的动态管理。撤销时先撤销屏蔽（OCW1 对应位清 0），再输出 ESMM=1、SMM=0 清除特殊屏蔽方式。

**作用**：是 OCW3 复合功能的一部分，与 OCW1 配合实现"特殊屏蔽方式"；作用对象是 IMR 与优先权判别，解决固定优先级下高级中断服务期间低级中断无法响应的问题。

### OCW3 的 D1（RR）、D0（RIS）位 — IRR / ISR 读出选择

**定义**：OCW3 中 D1（RR）、D0（RIS）两位组合使用，用于读取中断请求寄存器或中断服务寄存器的内容。RR=1、RIS=0，表示下一个操作读取中断请求寄存器 IRR 的内容；RR=1、RIS=1，表示下一个操作读取中断服务寄存器 ISR 的内容。若要读取屏蔽寄存器 IMR 的内容，则应用输入指令从奇地址端口（A0=1）读取。

**理解**：RR 是"读寄存器"使能位，RIS 是"读 ISR 选择"位。RR=0 时不进行寄存器读出；RR=1 时下一个读操作从偶地址端口读 IRR（RIS=0）或读 ISR（RIS=1）。IMR 不需通过 OCW3 选择，因为 IMR 与写入命令字共用奇地址端口：奇地址端口的写方向通向 ICW2、ICW3、ICW4、OCW1，读方向固定通向 IMR，所以读 IMR 直接 IN 奇地址端口即可。

**作用**：是 OCW3 复合功能的一部分；用于程序运行期检测 8259A 内部状态（哪些中断在请求、哪些在服务、哪些被屏蔽），是第 45 页读出 ISR 例题（见例题 5）的依据。

### OCW3 的 D2（P）位 — 中断查询方式

**定义**：OCW3 中 D2（P）为查询位。通过设置 P 位为 1，中断系统工作在中断查询状态下，一般用于多于 64 级中断的 8259A 级联系统中。此时，CPU 不是靠接收中断请求信号（INTR）来进入中断过程，而是靠发送查询命令 OCW3（P=1）来获得外部设备的中断请求信息。

**理解**：P=1 时 8259A 进入查询方式，P=0 时退出（不查询）。查询方式的区别在于信息获取路径：正常方式下 8259A 通过 INT 引脚向 CPU 发出 INTR 请求，CPU 以 INTA 响应；查询方式下 CPU 主动向 8259A 发出 P=1 的 OCW3，然后读偶地址端口取得中断状态字，从状态字获知是否有中断请求及其最高优先级。查询方式用于超过 64 级中断的级联系统，因为此时级联片数超过 8 片、INTR 引脚资源不足，改用查询方式获取中断信息。

**作用**：是 OCW3 复合功能的一部分；提供与 INTR/INTA 中断响应机制并列的另一种中断信息获取途径，扩展级联规模。

### 中断查询操作过程与中断状态字

**定义**：中断查询操作过程：通过置 P=1 向 8259A 发出查询命令，接着通过读取 8259A 的中断状态字获知外部是否有中断请求正在被处理，并给出当前处理的最高优先级。中断状态字格式：D7=IR、D6~D3=×、D2~D0=W2~W0。D7（IR）=0，表示 8259A 外部无中断请求；D7（IR）=1，表示 8259A 外部有中断请求，且 W2、W1、W0 为请求服务中断源的最高优先级编码。在置 P=1 后，马上读取偶端口即获得中断状态字。

**理解**：查询操作分两步。第一步：CPU 向偶地址端口输出 P=1 的 OCW3，此时 8259A 执行一次与判优相同的操作，把当前状态冻结进中断状态字。第二步：CPU 从偶地址端口输入中断状态字。状态字只用 4 位承载信息：D7 是"有无中断请求"标志；D2~D0 是三位二进制编码，000~111 对应 IR0~IR7，指出请求服务中断源中的最高优先级。若 D7=0，则 W2~W0 无意义。

**作用**：是 OCW3 P 位功能的配套操作，构成完整的中断查询方式。

### 特殊屏蔽方式的应用（IR4 服务程序）

**定义**：特殊屏蔽方式应用于允许低级中断源中断高级中断源的场合：在高级中断源（如 IR4）的服务程序中，先关中断，写入 OCW1 屏蔽本级（使 IMR 中对应位为 1、ISR 对应位清 0），再写入 OCW3（ESMM=1、SMM=1）设置特殊屏蔽方式，然后开中断；此后有低级中断源请求时 CPU 可响应并执行其服务程序。低级中断服务完成后，关中断，写入 OCW3（ESMM=1、SMM=0）清除特殊屏蔽方式，写入 OCW1 开放本级，再开中断。

**理解**：操作序列分设置与撤销两段。设置段：CLI 关中断防止设置过程被干扰；OCW1=00010000B 使 IMR 的 M4=1，屏蔽 IR4；OCW3=01101000B（ESMM=1、SMM=1）设置特殊屏蔽方式；STI 开中断。设置完成后，8259A 失去"正在服务 IR4"的封锁依据，低级中断请求可通过优先权电路被响应。撤销段：CLI 关中断；OCW3=01001000B（ESMM=1、SMM=0）清除特殊屏蔽方式；OCW1=00000000B 开放 IR4；STI 开中断。指令均放在 IR4 的中断服务程序内，特殊屏蔽方式一般在中断服务程序中设置。完整程序与逐指令分析见例题 6。

**作用**：特殊屏蔽方式原理的直接应用，是考试与程序设计的常见考查点。

### 完全嵌套方式下高级中断嵌套低级中断的流程（IR2 中断 IR3）

**定义**：对 8259A 写入初始化命令字后，若不再写入操作命令字，8259A 自动进入完全嵌套方式。在完全嵌套方式下，IR0~IR7 具有固定优先级（IR0 最高，IR7 最低）；8259A 封锁同级或低级的中断响应，但不禁止比本级优先级高的中断响应，实现中断嵌套。

**理解**：系统只有一片 8259A，8259A 初始化后执行 STI，若有 IR3 请求中断，CPU 响应并进入 IR3 的中断服务，此时 ISR3=1。在为 IR3 服务期间，IR2 又请求中断；CPU 在响应中断时自动关中断（IF=0），若 IR3 的服务程序未再次开中断，IR2 的请求得不到响应。只有 IR3 的服务程序执行了 STI 后，CPU 才会响应 IR2 的中断请求（IR2 的优先级高于 IR3，完全嵌套方式不禁止高级中断进入）。此时 IR3 中断服务程序暂时挂起，转入对 IR2 的中断处理，ISR2=1、ISR3=1，表示两级中断都未处理完毕。要使被中断的较低级中断程序能继续执行，较高级的服务程序结束时必须执行中断结束命令和中断返回命令：先使较高级中断的 ISRi=0（一般 EOI，OCW2=20H），再执行 IRET 使 CPU 返回执行较低级的中断服务程序。逐步分析见例题 7。

**作用**：是 8259A 默认工作方式（完全嵌套方式）下中断嵌套的完整时序描述，综合"全嵌套方式"、"一般 EOI"、"中断响应过程"的知识。

### 80286 以上微机中两片 8259A 级连的 15 级硬件中断系统

**定义**：在 80286 以上微机系统中，使用两片 8259A 级连管理硬件中断，共 15 级。主要特点：主片的端口地址是 20H 和 21H，从片的端口地址是 A0H 和 A1H；主、从片的中断请求信号均采用边沿触发方式；主、从片均采用完全嵌套方式管理中断优先级，从片的 INT 端接主片的 IR2 端，因此从片的中断请求都是经由主片的 IR2 发出，15 个中断源中断优先权由高至低的级别是：主 8259A 的 IR0、IR1、从 8259A 的 IR0~IR7（处在主 8259A IR2 的位置）、主 8259A 的 IR3~IR7；采用非缓冲方式，主片的 SP/EN 连 +5V，从片的 SP/EN 连 0V；主、从片均采用一般中断结束方式；主片 0~7 级的中断号是 08H~0FH，从片 8~15 级的中断号是 70H~77H。

**理解**：该结构是单片 8259A 各项功能在真实 PC 中的综合应用。级连方式：从片 INT 接主片 IR2，主片通过 CAS0~CAS2 向从片发送编码，从片与自身 ICW3 中的 ID 比较相等后在第二个 INTA 脉冲时送出自己的中断类型号。从片占用了主片的一个 IR 输入（IR2），所以 15 级中断优先级序列中从片整体插入主片 IR2 的位置；主片设置特殊全嵌套方式（由 ICW4 的 SFNM 位设置），使从片内部的更高级中断能打断从片的同级嵌套。非缓冲方式下 SP/EN 作为输入决定主从：主片 SP/EN=1（+5V），从片 SP/EN=0（0V）。中断号分配上，主片 IR0~IR7 依次对应中断号 08H~0FH，从片 IR0~IR7 依次对应 70H~77H。

**作用**：8259A 级连能力的实际应用实例；是级连扩展、特殊全嵌套方式、非缓冲方式、ICW3 内容的综合。

### 8259A 级连硬件结构图（第 51 页图片关键特征）

**定义**：第 51 页为图片页，展示 8259A 级连硬件结构图，IRQ0~IRQ15 为微机系统的硬件中断源。

**理解**：结构图中两片 8259A 通过 CAS0~CAS2 级连线相连（主片的 CAS0~CAS2 为输出、从片的 CAS0~CAS2 为输入）；从片 INT 接主片 IR2，主片 INT 接 CPU 的 INTR；两片均接 INTA（CPU 中断响应）、IOR、IOW（经总线控制器）以及各自地址 A0 与片选（片选 1、片选 2）；主片 SP/EN 接 +5V，从片 SP/EN 接 0V。中断源分配：IRQ0—日时钟、IRQ1—键盘、IRQ3—串行口 2、IRQ4—串行口 1、IRQ5—并行口 2、IRQ6—软盘、IRQ7—并行口 1（以上接主片，IRQ2 被从片占用未列出独立外设）；IRQ8—实时时钟、IRQ9—用户中断、IRQ10—保留、IRQ11—保留、IRQ12—保留、IRQ13—协处理器、IRQ14—硬盘、IRQ15—保留（以上接从片）。另有 NMI 与 NMI 屏蔽寄存器屏蔽位，NMI 用于 I/O 通道检查错、RAM 奇偶错。

**作用**：以图示形式呈现 80286 以上微机中断系统的硬件连接，是第 50 页文字描述的图形对应。

### 2. 简单中断接口逻辑电路的回顾与 8259A 的引入（第 2–3 页）

**简单中断接口逻辑电路**（第 2 页）完成三项任务：产生中断、处理中断响应、中断号存取。其组成器件：

| 器件 | 功能 |
| --- | --- |
| 74LS74 | 触发器 |
| 74LS244 | 三态缓冲器 |
| 74LS148 | 优先编码器 |

80X86 只有 INTR 和 NMI 两个引脚接受外部硬件发出的中断请求，不便于管理多个中断源。

**为何要采用中断控制器构成外部中断系统**（第 3 页）：Intel 8259A 用于管理外部可屏蔽中断源，完成**中断优先级排队、中断源识别、产生中断号及进行中断屏蔽**等功能。Intel 8259A 具有可编程能力，可以灵活组建中断系统，功能强大。

### 3. 8259A 的管理规模（第 4 页）

- 每一片 8259A 可管理 **8 级**优先级中断；
- 两片 8259A 级联可管理 **15 个**中断（$8+8-1=15$，其中 1 个用于主从连接）；
- 多片级联最多可构成 **64 级**优先权管理系统。

本页图为两种连接方式的结构图：**单片方式**——IR0~IR7 共 8 路中断请求输入单片 8259A，其 INT 输出接 CPU 的 INTR，INTA 与 CPU 的 INTA 相连；**级联方式**——主 8259A 的 IR 端接从 8259A（图中示出两个从片，各带 IR0~IR7 输入），主片的 INT/INTA 接 CPU 的 INTR/INTA。

### 4. 8259A 内部结构框图的关键连接关系（第 5–6 页图）

该图为 8259A 内部结构框图（两页重复出现，第 5 页用于配合讲解 ISR/PR/控制逻辑/IMR，第 6 页用于讲解其余部件）。图中标注的关键连接关系为：

- 外部中断请求经 **IR0~IR7** 输入**中断请求寄存器 IRR**；
- **IRR → 优先权电路 PR → 中断服务寄存器 ISR** 依次连接，构成判优通道；
- **中断屏蔽寄存器 IMR** 接于 IRR 与 PR 之间，对 IRR 的输出实施屏蔽；
- **控制逻辑**分别经 **INT、INTA** 与 CPU 相连，并连接内部总线；
- **数据总线缓冲器**连接 **D0~D7** 与内部总线；
- **读/写逻辑**连接 **RD、WR、A0、CS**；
- **级联/缓冲比较器**连接 **CAS0、CAS1、CAS2** 与 **SP/EN**。

| 引脚 | 名称 | 方向/性质 | 功能说明 |
| --- | --- | --- | --- |

| IR0~IR7 | 中断请求输入 | 输入 | 外设中断请求输入，共 8 级 |
| INT | 中断请求输出 | 输出 | 向 CPU 发出的中断请求信号 |

| A0 | 端口选择信号 | 输入 | 8259A 具有两个端口地址，A0 用于内部端口地址选择；一般直接连到 CPU 的地址线 A0 或其它地址线上 |

### 6. 8259A 中断管理方式总览（第 16 页）

8259A 的编程结构包括四个方面：**中断优先权管理、中断源屏蔽方式、中断结束管理、系统总线的连接方式**。其中：

- **中断优先权管理（4 种方式）**：A、全嵌套方式；B、特殊全嵌套方式；C、自动循环方式；D、优先级特殊循环方式（另有一种补充方法：利用中断屏蔽功能管理优先级）。
- **中断源屏蔽方式**：普通屏蔽方式、特殊屏蔽方式。
- **中断结束管理**：中断自动结束方式（AEOI）、一般（常规）中断结束方式、特殊中断结束方式（SEOI）。
- **系统总线的连接方式**：缓冲方式、非缓冲方式。

各方式的定义与设置见"知识点详解"。

### 8. 初始化命令字与操作命令字的写入规则（第 18–19 页，第 32 页重述流程示意）

**初始化命令字 ICW1~ICW4**：在 8259A 工作之前，必须进行初始化编程，规定优先权管理方式、中断结束方式及级连方式等。由初始化命令字 ICW1~ICW4 所决定的工作方式在 8259A 的整个工作过程中不变，**写入顺序不能改变**。

**操作命令字 OCW1~OCW3**：在操作过程中可写入，定义操作方式，并可进行改写，改变 8259A 的操作方式，实现对中断处理过程的动态控制；OCW1~OCW3 **无写入顺序**。

**初始化流程图**：ICW1 → ICW2 → 判断"单片 8259A？"——否（N）则写 ICW3 后写 ICW4；是（Y）则直接写 ICW4。（第 32 页再次以框图自上而下呈现同一流程：ICW1 → ICW2 →"单片 8259A？"判断 → 否（N）则 ICW3 → ICW4；是（Y）则跳过 ICW3 直接到 ICW4。）

| 命令字 | 端口地址 | 附加条件 |
| --- | --- | --- |
| ICW1 | 偶地址（A0=0） | D4=1（标志位） |
| ICW2、ICW3、ICW4 | 奇地址（A0=1） | 紧接着 ICW1，按顺序写入 |
| OCW1 | 奇地址（A0=1） | 但不紧跟 ICW1 |
| OCW2、OCW3 | 偶地址（A0=0） | D4=0；再以 D3 区分（OCW2 的 D3=0，OCW3 的 D3=1） |

### 9. 中断优先权管理相关图示与补充事实（第 20–23 页）

- 第 21 页含主从级连结构示意：上方为 CPU（引出 INTR、INTA 两条线），中间为主片 8259（IR0、IR1、IR7 三根请求输入端，其 INT 接 CPU 的 INTR、INTA 接 CPU 的 INTA），下方为从片 8259（IR0、IR1、IR7 三根请求输入端，其 INT、INTA 连到主片的 IR7 等端）。该图说明从片的中断请求经主片 IR 端转交，故对主片而言从片全体中断为同级。
- 第 22 页含自动循环方式示意图：一串标注 IR0~IR7 的方块/端子序列（提取文本中为两列纵向排布的 IR0 至 IR7 标注），表示优先级队列的轮转顺序。
- 自动循环方式的优先级队列变化实例（第 22 页）：
  - 初始队列（高→低）：IR0，IR1，IR2，IR3，IR4，IR5，IR6，IR7；
  - IR0 请求被响应并处理完成后，队列变为：IR1，IR2，IR3，IR4，IR5，IR6，IR7，IR0；
  - 随后 IR4 请求处理完成后，队列变为：IR5，IR6，IR7，IR0，IR1，IR2，IR3，IR4。
- 优先级特殊循环方式与自动循环方式的比较：相同点——优先级循环过程相同；不同点——自动循环方式初始优先级确定（复位后 IR0 最高、IR7 最低），特殊循环方式的初始最低优先级由程序决定（其他优先级也随之决定）。

### 11. 中断结束方式补充事实（第 26–29 页）

- 中断结束的含义：一个中断过程处理完成；要做的事情是处理 ISR 的对应位，即将处理完的中断对应位清 0。ISR 记录当前"正在处理"的中断，包括被高级中断打断、还未处理完的中断。
- 自动结束方式（AEOI）要点：
  - 清位时刻：第二个 INTA 信号的下降沿（即中断响应后而非服务程序结束后）；
  - 后果：处理过程中 8259A 无"正在处理"标识，IF=1 时任何优先级（高、低、相同）的请求都会得到响应；请求信号若不及时撤销会再次被响应，产生"二次中断"；
  - 适用场合：中断请求信号持续时间有一定限制、不出现中断嵌套的场合；
  - 设置：ICW4 的 AEOI 位=1。
- 一般（常规）中断结束方式要点：
  - 适合全嵌套方式；
  - 命令格式：OCW2 的 EOI=1、SL=0、R=0；示例指令 MOV AL,20H / OUT 20H,AL（20H=0010 0000B，D5=1 为 EOI 位；端口 20H 为偶地址），且这段指令放在 IRET 指令前；
  - 机理：全嵌套方式下 ISR 中最高优先级的置 1 位正对应当前正在处理的中断，清 0 该位即完成结束操作。
  - 第 28 页含 ISR 位序列示意：标注 IR0（最高优先）至 IR7（最低优先）的一行位，中间某位置"1"，表明清 0 对象是 ISR 中优先级最高的置 1 位。
- 特殊中断结束方式（SEOI）要点：
  - 适用：非全嵌套方式（设置优先权命令、特殊屏蔽方式等无固定优先级序列的场合），此时据 ISR 内容无法确定刚响应的中断；
  - 命令格式：OCW2 的 EOI=1、SL=1、R=0，由 L2~L0 指定清除 ISR 中的哪一位；ISR 位的清零由程序员指定。

### 12. 中断触发方式与总线连接方式的补充事实（第 30–31 页）

- 中断触发方式（第 30 页，课件标注"要求掌握"，为课程重点）：
  - 电平触发：由 IRi 上的有效电平触发中断请求触发器（ICW1 的 LTIM=1）；
  - 边沿触发：由 IRi 上低电平向高电平的跳变触发中断请求触发器（ICW1 的 LTIM=0）。

## 解题方法汇总

### 方法 1：由中断类型号确定中断向量表地址与 ICW2 的取值

- **适用场景**：CPU 收到 8259A 在第二个 INTA 负脉冲后送出的 8 位中断类型号 n 之后，确定中断服务程序入口地址在中断向量表中的存放位置；或已知 8259A 某级中断类型号反推 ICW2 的值；或已知 ICW2 求各级中断类型号。
- **已知条件**：8 位中断类型号 n（十进制或十六进制），或 ICW2 的写入值；IR 端编号（IR0=000 ~ IR7=111）。
- **计算步骤**：
  1. 若已知 8 位中断类型号 n：取 n 的高 5 位（n ÷ 8 取整）作为 ICW2 的 D7~D3；取 n 的低 3 位（n mod 8）即该中断对应的 IR 编码（响应时由硬件自动填入 ICW2 的 D2~D0）。若已知的是 ICW2：其高 5 位与低 3 位 IR 编码合起来即各 IR 端的中断类型号（IR0 的类型号为高 5 位值×8+0，IR7 的为高 5 位值×8+7）。
  2. 将 n 乘以 4，得到中断向量表起始地址 $4n$（例如 n=8 时起始地址为 32）。
  3. 确定读取区间：内存地址 $4n \sim 4n+3$，共 4 个连续存储单元。
  4. 从该区间取出中断服务程序入口地址：低地址两个字节（单元 $4n$、$4n+1$）送 IP（偏移地址），高地址两个字节（单元 $4n+2$、$4n+3$）送 CS（段地址）。
  5. 结果：CPU 获得 CS:IP，转入中断服务程序。
- **常见错误**：把"类型号×4"误算为"类型号+4"或"类型号×2"；只取 2 个字节而漏掉段地址/偏移地址的 4 字节结构；把低 16 位与高 16 位赋给 IP、CS 的顺序写反；忘记低 3 位是 IR 编码而非用户设定，把类型号低 3 位直接写进 ICW2（初始化时 ICW2 低 3 位恒为 000）；把 IR 编号与类型号高低位的对应关系搞反。

### 方法 2：8259A 中断响应流程分析

- **适用场景**：分析或叙述从外部中断请求产生到 CPU 进入中断服务程序的完整硬件过程；用于理解各寄存器与引脚在响应时序中的作用。
- **已知条件**：某 IRi 引脚上有中断请求信号；IMR 对应位的状态；CPU 的中断允许标志 IF 状态。
- **计算步骤**（按时间顺序）：
  1. 请求登记：IR0~IR7 上的请求信号进入 IRR，使 IRR 对应位置 1。
  2. 屏蔽过滤：未被 IMR 屏蔽（IMR 对应位为 0）的请求被送到 PR。
  3. 判优：PR 对同时送达的中断源判优，并与 ISR 中正在服务的中断级别比较，选出优先权最高的中断源。
  4. 请求 CPU：8259A 由 INT 引脚向 CPU 发出中断请求信号。
  5. CPU 响应：若 CPU 开中断（IF=1），执行完当前指令后向 8259A 发出 INTA（两个负脉冲）。
  6. 第一个 INTA 负脉冲：8259A 将被选中中断源在 ISR 中的对应位置 1，并将其 IRR 位清 0。
  7. 第二个 INTA 负脉冲：8259A 向 CPU 数据总线发出 8 位中断类型号 n。
  8. 取入口：CPU 将 n 乘 4，从中断向量表 $4n \sim 4n+3$ 单元取出入口地址送 IP、CS，转入中断服务程序。
- **常见错误**：混淆两个 INTA 负脉冲各自的作用（第一个更新 ISR/IRR 状态，第二个送中断类型号）；认为 IMR 屏蔽会同时清除 IRR 中的位（实际 IRR 位保留）；认为 PR 只比较请求之间而不与正在服务的级别比较；漏掉"CPU 处于开中断状态"这一响应前提。

### 方法 3：8259A 初始化编程（ICW1~ICW4 的逐字计算与写入）

- **适用场景**：给定 8259A 工作条件（触发方式、单片/级连、中断类型号高 5 位、嵌套方式、缓冲方式、中断结束方式、端口地址），编写初始化程序或计算各命令字数值。
- **已知条件**：单片还是多片级连；触发方式（边沿/电平）；中断类型号高 5 位（或 8 位类型号）；是否自动结束（AEOI）；是否缓冲、主从；8259A 端口地址（偶/奇）。
- **计算步骤**：
  1. 按初始化顺序列出需写入的命令字：ICW1 → ICW2 →（级连时）ICW3 → ICW4，并确定各命令字的端口地址（ICW1 写偶地址端口，ICW2~ICW4 写奇地址端口）。
  2. 计算 ICW1：从 D0 到 D7 逐位填写。80X86 系统 D0（IC4）=1；D1（SNGL）单片=1、级连=0；D3（LTIM）边沿=0、电平=1；D4（标志位）=1；D2、D5、D6、D7 任取（通常写 0）。如单片、边沿触发、要设 ICW4：D7~D0=0001 0011B=13H。写入偶地址端口。
  3. 计算 ICW2：高 5 位 = 给定的类型号高 5 位，低 3 位写 000（响应时由硬件自动按 IR 编码填入）。如高 5 位 00011：00011 000B=18H。写入奇地址端口。
  4. 判断 ICW1 的 SNGL：若 SNGL=1（单片），跳过 ICW3；若 SNGL=0（级联），级连时计算 ICW3：主片按"哪几根 IR 接从片"置对应位为 1；从片按"接入主片第几号 IR"的 3 位编码填 D2~D0。写入奇地址端口。
  5. 判断 ICW1 的 IC4：若 IC4=1，计算 ICW4：D0=1；D1（AEOI）自动结束=1、正常=0；D2（M/S）缓冲方式下主片=1、从片=0（非缓冲时无意义，常写 0）；D3（BUF）缓冲=1、非缓冲=0；D4（SFNM）特殊完全嵌套=1、否则 0；D5~D7=0。如 AEOI=1 其余 0：0000 0011B=03H。写入奇地址端口。
  6. 结果：得到各命令字的 8 位二进制/十六进制数值及对应 OUT 指令序列；初始化完成后若不再写操作命令字，8259A 自动进入完全嵌套方式工作。
- **常见错误**：
  - 忽略 ICW1 的 D4=1 标志位，导致写入偶地址端口的字节被当作 OCW2/OCW3；
  - 把 ICW2 的低 3 位也按"类型号低 3 位"计算（低 3 位由硬件填入，初始化时写 000 即可）；
  - 混淆写入顺序（ICW 顺序固定不可颠倒）或把 ICW 写到错误的地址（ICW1 偶地址，ICW2~ICW4 奇地址）；
  - 单片系统仍写 ICW3，或级连系统漏写 ICW3；
  - ICW1 的 D0（IC4）漏写 1 导致 ICW4 不被接收；
  - 混淆 ICW4 的 D0（恒 1 特征位）与 ICW1 的 D0（IC4 位）。

### 方法 4：8259A 命令字写入与寄存器状态读出的端口/标识位选择访问法

- **适用场景**：CPU 对 8259A 进行初始化编程（写 ICW）、运行期操作编程（写 OCW）以及状态读取（读 IRR/ISR/IMR）。
- **已知条件**：8259A 的两个端口地址（偶地址 A0=0、奇地址 A0=1）；要访问的寄存器名称。
- **计算步骤**（写方向，CS=0、WR=0、RD=1）：
  1. 写 ICW1：选偶地址（A0=0），且写入数据的 D4=1。
  2. 写 ICW2：紧跟 ICW1，选奇地址（A0=1）。
  3. 写 ICW3：仅级联方式（ICW1 的 SNGL=0）时进行，仍选奇地址。
  4. 写 ICW4：ICW1 的 IC4=1 时进行，仍选奇地址。
  5. 写 OCW1：选奇地址，且该次写入不紧跟 ICW1。
  6. 写 OCW2：选偶地址，写入数据的 D4=0、D3=0。
  7. 写 OCW3：选偶地址，写入数据的 D4=0、D3=1。
  8. 读 IRR：先向偶地址端口写 OCW3 使 RR=1、RIS=0（D1D0=10，OCW3=00001010B=0AH），随后 IN 偶地址端口，读入内容即 IRR。
  9. 读 ISR：先向偶地址端口写 OCW3 使 RR=1、RIS=1（D1D0=11，OCW3=00001011B=0BH），随后 IN 偶地址端口，读入内容即 ISR。
  10. 读 IMR：不需 OCW3 选择，直接 IN 奇地址端口（A0=1）即得 IMR 内容。
  11. 结果：所有命令字/状态寄存器均可经两个端口地址访问；当 CS=1 或 RD=WR=1 时数据线呈高阻态。
- **常见错误**：写 ICW1 时忘记置 D4=1，导致与 OCW2/OCW3 冲突；将 OCW1 与 ICW2~ICW4 的奇地址写入混淆（OCW1 必须不紧跟 ICW1）；OCW2 与 OCW3 的 D3 位写反；初始化时打乱 ICW1~ICW4 的顺序；读 IMR 时先写 OCW3（多此一举且可能改变 P、SMM 等状态）；写 OCW3 与读寄存器之间插入其他访问 8259A 端口的指令（OCW3 仅对下一个读操作有效）；RIS、RR 组合写错（RR=0 时不发生读出）。

### 方法 5：OCW1 中断屏蔽字（IMR）的计算与写入

- **适用场景**：给定"开放/屏蔽哪些 IR 端"的要求，计算 OCW1（IMR 屏蔽字）并写出指令；或已知 IMR 值判断哪些中断开放。
- **已知条件**：需要开放（或屏蔽）的 IR 端编号清单；OCW1 端口地址（奇地址）。
- **计算步骤**：
  1. 按 D7~D0 对应 IR7~IR0 写出位图：开放的 IRi 对应位 Mi=0，屏蔽的 IRi 对应位 Mi=1。
  2. 把位图转成 8 位二进制（或十六进制）数。
  3. 用 OUT 指令写入奇地址端口（例：MOV AL,11100111B / OUT 21H,AL）。
  4. 结果：IMR 寄存器内容为该屏蔽字，屏蔽位=1 的请求不可能进入优先权电路。
- **常见错误**：
  - 1/0 含义写反（把"1=屏蔽、0=开放"记成相反）；
  - 位序颠倒（把 IR0 对应 D7、IR7 对应 D0）；
  - 写入偶地址端口（OCW1 必须奇地址）。

### 方法 6：特殊屏蔽方式的设置与撤销序列（OCW3 与 OCW1 配合）

- **适用场景**：固定优先级（完全嵌套）方式下，在高级中断服务程序中需要临时允许低级中断进入（中断优先权动态管理）。
- **已知条件**：OCW1 端口地址（奇地址，如 21H）与 OCW3 端口地址（偶地址，如 20H）；当前服务的中断级别（其 IMR 对应位）。
- **计算步骤**：
  1. CLI 关中断，防止设置序列被其他中断打断。
  2. 写 OCW1 屏蔽本级：仅本级对应位置 1（屏蔽 IR4：MOV AL,00010000B; OUT 21H,AL），使 IMR 对应位=1、ISR 对应位清 0。
  3. 写 OCW3 设置特殊屏蔽方式：ESMM=1、SMM=1，其余位为 0，OCW3=01101000B，输出到偶地址端口（OUT 20H,AL）。
  4. STI 开中断；此后有低级中断源请求时 CPU 可响应并执行其服务程序。
  5. 低级服务完成、返回本服务程序后：CLI 关中断。
  6. 写 OCW3 撤销特殊屏蔽方式：ESMM=1、SMM=0，OCW3=01001000B（OUT 20H,AL）。
  7. 写 OCW1 开放本级：本级对应位清 0（IR4：MOV AL,00000000B; OUT 21H,AL）。
  8. STI 开中断。结果：本级中断恢复原优先级地位，正常嵌套规则恢复。
- **常见错误**：
  - 两步顺序颠倒（先屏蔽后开允许，或恢复时先关开关后开放；必须先 OCW1 后 OCW3 设置、先 OCW3 后 OCW1 撤销）；
  - 只写 OCW1 屏蔽而不设置 ESMM/SMM（此时只是普通屏蔽，ISR 位不清 0，低级中断仍被封锁）；
  - ESMM=0 时试图用 SMM 设置特殊屏蔽方式（无效）；
  - 把撤销条件写成"SMM=1、SMM=0"（教材第 25 页原文笔误，正确为 ESMM=1、SMM=0）；
  - 忘记在设置与撤销前后执行 CLI/STI，或忘记在特殊屏蔽期间结束后恢复 IMR 位。

### 方法 7：常规（一般）中断结束命令 EOI 的发送

- **适用场景**：全嵌套方式下，中断服务程序结束前清除 ISR 中当前中断对应位，使被嵌套的低级中断可继续执行。
- **已知条件**：OCW2 端口地址（偶地址）；中断系统工作于全嵌套（固定优先级）方式。
- **计算步骤**：
  1. 构造 OCW2 值：EOI=1（D5）、SL=0（D6）、R=0（D7），D4=D3=0（OCW2 标志位）→ 0010 0000B = 20H。
  2. 执行 MOV AL,20H；OUT 20H,AL（写入偶地址端口）。
  3. 该指令放在 IRET 指令之前执行。
  4. 结果：ISR 中最高优先级的置 1 位被清 0，当前中断结束。
- **常见错误**：
  - 把 EOI 指令放在 IRET 之后（返回后 ISR 位仍为 1，同级/低级中断被永久封锁）；
  - 在非全嵌套方式（循环优先级、特殊屏蔽）下仍用常规 EOI（无法确定清哪位，应改用 SEOI）；
  - 把 OCW2=20H 写成 21H 或写入奇地址端口。

### 方法 8：特殊中断结束命令 SEOI 的发送

- **适用场景**：非全嵌套方式（特殊屏蔽方式、设置优先权命令等无固定优先级序列）下结束中断。
- **已知条件**：刚服务完毕的中断级别编码（其 IR 编号 0~7）；OCW2 端口地址（偶地址）。
- **计算步骤**：
  1. 构造 OCW2：EOI=1（D5）、SL=1（D6）、R=0（D7）、D4=D3=0，L2~L0 = 待清除中断级别的 3 位编码。
  2. 例：清除 IR6 对应 ISR 位，L2 L1 L0 = 110，OCW2 = 0110 0110B = 66H。
  3. 执行 OUT 指令写入偶地址端口。
  4. 结果：ISR 中由 L2~L0 指定的位被清 0。
- **常见错误**：
  - 忘记置 SL=1（L2~L0 无效，命令退化为常规 EOI）；
  - L2~L0 编码与 IR 编号不一致（IR0=000 到 IR7=111）；
  - 在全嵌套方式下无必要地使用 SEOI。

### 方法 9：用 OCW2 设置优先权循环方式 / 中断结束方式（含 L2~L0 最低优先级编码计算）

- **适用场景**：需要在运行期改变 8259A 优先权管理方式（固定改循环、指定循环初始最低优先级），或发出中断结束命令（一般 EOI / 特殊 EOI）。
- **已知条件**：8259A 偶地址端口地址（如 20H）；目标优先权方式；需结束时待清位的中断级别编号（特殊 EOI 时）。
- **计算步骤**：
  1. 写标志位：D4=0、D3=0。
  2. 确定 D7（R）：固定优先权方式取 0；优先权循环方式取 1。
  3. 确定 D6（SL）：不需使用 L2~L0 时取 0；需使用 L2~L0 时取 1。
  4. 确定 D5（EOI）：执行中断结束取 1，否则取 0。
  5. 确定 D2~D0（L2~L0）：SL=0 时置 000；SL=1 时写入目标级别编码（IR6 写 110、IR7 写 111 等），循环方式中该编码为初始最低优先级，特殊 EOI 中该编码为待清 ISR 位序号。
  6. 将 8 位拼成二进制字节，换算为十六进制，经偶地址端口输出（如一般 EOI：R=0、SL=0、EOI=1、L2~L0=000，OCW2=20H，指令为 MOV AL,20H; OUT 20H,AL）。
- **常见错误**：把 L2~L0 理解为"最高优先级"编码——它表示的是循环中的最低优先级（指定最低后其余按 IR0→IR7 循环规则顺延，原比它低一级者成为最高）；SL=0 时仍写入 L2~L0 导致无意义；漏写标志位 D4=D3=0；特殊中断结束命令（EOI=1、SL=1、R=0）与优先级特殊循环（R=1、SL=1、EOI=0）组合混淆。

### 方法 10：中断查询方式操作

- **适用场景**：多于 64 级中断的 8259A 级联系统；或不用 INTR/INTA 引脚而以软件查询方式获取中断信息。
- **已知条件**：8259A 偶地址端口（如 20H）。
- **计算步骤**：
  1. 写 OCW3 使 P=1（D2=1，其余按需设置），OUT 到偶地址端口，发出查询命令。
  2. 立即 IN 偶地址端口，取得中断状态字。
  3. 检查 D7（IR）：IR=0 表示无中断请求；IR=1 表示有请求，取 D2~D0（W2~W0）即请求服务中断源的最高优先级编码。
  4. 按 W2~W0 编码转去对应中断服务处理。
- **常见错误**：置 P=1 后不立即读偶端口（中间被其他端口操作破坏）；把 W2~W0 当成中断类型号（它是 IR 序号编码，须与 ICW2 的高 5 位拼成中断类型号）；IR=0 时仍使用 W2~W0。

### 方法 11：完全嵌套方式下中断嵌套流程分析（以 IR2 中断 IR3 为例）

- **适用场景**：分析或编写单片 8259A 默认（完全嵌套）方式下的中断嵌套响应次序。
- **已知条件**：8259A 已初始化（未写操作命令字即自动进入完全嵌套方式）；各中断源请求时刻；固定优先级 IR0 最高、IR7 最低。
- **计算步骤**：
  1. 初始化后执行 STI，CPU 开中断。
  2. IR3 请求：CPU 响应并进入 IR3 服务程序，ISR3=1（响应中断时 CPU 自动关中断，IF=0）。
  3. IR3 服务期间 IR2 请求：因 IF=0，IR2 请求不被响应（请求保持在 IRR 中挂起）。
  4. IR3 服务程序执行 STI（IF=1）：IR2 优先级高于 IR3，完全嵌套方式不禁止高级中断，CPU 响应 IR2。
  5. IR3 服务挂起，转入 IR2 处理，ISR2=1、ISR3=1（两级中断均未处理完毕）。
  6. IR2 服务程序结束：执行一般中断结束命令（OCW2=20H，MOV AL,20H; OUT 20H,AL，放在 IRET 前）使 ISR2=0，再执行 IRET 返回 IR3 服务程序。
  7. IR3 服务程序结束：执行 EOI 使 ISR3=0，IRET 返回主程序。
- **常见错误**：认为 CPU 响应 IR3 后 IF 仍为 1（实际响应中断时自动关中断，IR2 需等 IR3 服务程序 STI 才被响应）；认为完全嵌套方式也禁止高级中断（实际只封锁同级或低级）；漏掉较高级服务程序结束时的 EOI 命令，导致 ISR2 不清 0 且低级程序无法恢复执行。

### 方法 12：PC（80286 以上）级连 8259A 系统的参数确定

- **适用场景**：确定 80286 以上微机中断系统的端口地址、优先级顺序、中断号分配等参数（读图、写初始化程序的基础）。
- **已知条件**：两片 8259A 级连结构（从片 INT 接主片 IR2）。
- **计算步骤**：
  1. 端口地址：主片 20H（偶）/21H（奇）；从片 A0H（偶）/A1H（奇）。
  2. 优先级顺序：主片 IR0 → 主片 IR1 → 从片 IR0~IR7（整体处于主片 IR2 位置）→ 主片 IR3~IR7。
  3. 中断号：主片第 i 级（i=0~7）中断号 = 08H+i（08H~0FH）；从片第 i 级（i=0~7）中断号 = 70H+i（70H~77H）。
  4. 其余参数：边沿触发（ICW1 LTIM=0）、完全嵌套（主片配合级连用特殊全嵌套，ICW4 SFNM 位；从片全嵌套）、非缓冲方式（ICW4 BUF=0，主片 SP/EN=+5V、从片 SP/EN=0V）、一般中断结束（ICW4 AEOI=0，服务程序末尾 OCW2=20H）。
- **常见错误**：把从片 8 级看作整体插在主片 IR2 之后，漏掉"主片 IR1 之后、主片 IR3 之前"的位置；从片中断号误用 08H~0FH 延续；非缓冲方式下误用 ICW4 的 M/S 位定义主从（非缓冲方式下 M/S 无意义，由 SP/EN 引脚决定）。

## 例题汇总

### 例题 1：中断嵌套时 ISR 的状态（第 5 页思考题）

**题干**：
中断服务寄存器 ISR（8 位）记录所有正在被服务的中断源，即若某个中断请求 IRi 被响应，CPU 正在执行它的中断服务程序，则 ISR 的对应位 ISRi 也为 1，并将保持到该中断请求被处理完毕后，该位复位为 0。（思考：中断嵌套时会怎么样？）

**解**：

第 1 步：依据 ISR 的定义（第 5 页），CPU 响应中断请求 IRi 后，ISR 中对应位 ISRi 置 1；该位在 IRi 被处理完毕之前不会复位。

第 2 步：依据全嵌套方式下的保持规则（第 20 页），一般情况下（除"中断自动结束"方式外），在 CPU 发出中断结束命令（EOI）前，ISRi 一直保持为 1。

第 3 步：在 CPU 为 IRi 服务期间，若更高级别的请求 IRj 到达且 CPU 已开中断，则 IRj 得到响应，ISR 中对应位 ISRj 也被置 1。

第 4 步：此时 IRi 尚未处理完毕，其 ISR 位不复位，于是 ISR 中同时有两位为 1（ISRj=1 且 ISRi=1），分别对应"正在处理的高级中断"和"被打断、尚未处理完的低级中断"。

第 5 步：两个置 1 位各自保持，直到各自对应的中断被处理完毕并执行中断结束命令后才分别复位为 0。

**答案**：中断嵌套时，ISR 中可同时有多个位为 1；每个置 1 位对应一个尚未处理完毕的中断，被打断而暂停的低级中断也属于"正在被服务"之列，其 ISR 位保持为 1。嵌套的层数对应 ISR 中同时为 1 的位数。

**验证**：用原定义代回检验——ISR 定义为"记录所有正在被服务的中断源"，被打断的中断其服务程序尚未结束，仍属"正在被服务"，故其位为 1，符合定义；第 20 页全嵌套方式"在 CPU 发出中断结束命令（EOI）前，此对应位一直保持为 1"的规则与上述结论一致。

### 例题 2：两个端口地址如何访问多个寄存器（第 13 页思考题）

**题干**：
8259 有多个寄存器需要访问：ICW1~ICW4，OCW1~OCW3，IRR、ISR、IMR 等，而端口地址只有两个，如何实现对它们的访问？

**解**（答案依据第 17、19 页的访问表与标识位规则）：

第 1 步：8259A 的两个端口地址由 A0 区分：A0=0 为偶地址端口，A0=1 为奇地址端口。

第 2 步：在此基础上采用专门的标识位——数据总线的 D4、D3 参与寄存器译码。偶地址端口（A0=0）上：D4=1 时写入 ICW1；D4=0 且 D3=0 时写入 OCW2；D4=0 且 D3=1 时写入 OCW3。

第 3 步：奇地址端口（A0=1）上可写 ICW2、ICW3、ICW4 或 OCW1，靠写入顺序区分：紧跟 ICW1 之后依次写入的是 ICW2（级联时再写 ICW3、ICW4）；不紧跟 ICW1 的奇地址写访问为 OCW1。

第 4 步：读操作（RD=0）：偶地址端口读 IRR 或 ISR（由 OCW3 指定读哪个）；奇地址端口读 IMR。

第 5 步：由此，ICW1~ICW4、OCW1~OCW3 共 7 个命令字寄存器及 IRR/ISR/IMR 三个状态寄存器，仅用 A0 一根片内选择线（两个端口地址）即可全部访问。代价是占用数据线上的 D4、D3 两位作标识位并规定固定的写入顺序——这正是第 19 页所述"采用了专门的'标识位'，以节省输入地址的引脚数（仅用了 A0）"的设计含义。

**答案**：采用"地址位 A0 + 数据位 D4、D3 标识位 + 写入顺序"三者结合的方式，实现两个端口地址对全部寄存器的访问。

**验证**：对照第 17 页访问表逐行核查：ICW1 行 CS=0、WR=0、A0=0、D4=1，与第 2 步一致；OCW2 行 A0=0、D4=0、D3=0，与第 2 步一致；OCW3 行 A0=0、D4=0、D3=1，与第 2 步一致；ICW2/ICW3/ICW4/OCW1 行 A0=1，与第 3 步一致；IRR/ISR 行与 IMR 行 RD=0，与第 4 步一致。全部行均吻合，结论成立。

### 例题 3：8259A 初始化编程（ICW1=13H、ICW2=18H、ICW4=03H，第 39 页）

**题干**：
将 8259A 按以下条件初始化：单片 8259A 工作，中断请求信号为边沿触发方式，中断类型号的高 5 位为 00011，采用自动中断结束方式。设 8259A 的端口地址为 20H 和 21H。
初始化程序如下：

```asm
MOV  AL，13H
OUT  20H，AL       ；设置ICW1
MOV  AL，18H
OUT  21H，AL       ；设置ICW2
MOV  AL，03H
OUT  21H，AL       ；设置ICW4
```

**解**：

第 1 步：确定初始化流程。系统为单片工作（SNGL=1），因此写入顺序为 ICW1 → ICW2 →（跳过 ICW3）→ ICW4；ICW1 写入偶地址端口 20H（A0=0），ICW2、ICW4 写入奇地址端口 21H（A0=1）。

第 2 步：验证 ICW1=13H。13H 展开为二进制 0001 0011B，逐位核对：D7=0、D6=0、D5=0、D2=0（任意值位，取 0）；D4=1，满足 ICW1 标志位要求；D3（LTIM）=0，对应边沿触发方式；D1（SNGL）=1，对应单片工作；D0（IC4）=1，表示要设置 ICW4。13H 经 OUT 20H,AL 写入偶地址端口 20H。

第 3 步：验证 ICW2=18H。18H 展开为二进制 0001 1000B：D7~D3 = 00011，与题干给定的中断类型号高 5 位 00011 一致；D2~D0 = 000，为初始化时的低 3 位（响应中断时由 8259A 按提出请求的 IR 端编码自动填入：IR0=000、IR1=001、…、IR7=111）。18H 经 OUT 21H,AL 写入奇地址端口 21H。

第 4 步：验证 ICW4=03H。03H 展开为二进制 0000 0011B：D7~D5=000，满足 ICW4 特征位要求；D4（SFNM）=0，非特殊完全嵌套方式；D3（BUF）=0，非缓冲方式；D2（M/S）=0，非缓冲方式下该位无意义；D1（AEOI）=1，对应题干要求的自动中断结束方式；D0=1，ICW4 特征位。03H 经 OUT 21H,AL 写入奇地址端口 21H。

第 5 步：用原始条件验证。题干四项条件逐一对应：(1) 单片工作 → ICW1 的 D1=1，13H 的 D1=1，符合；(2) 边沿触发 → ICW1 的 D3（LTIM）=0，13H 的 D3=0，符合；(3) 中断类型号高 5 位为 00011 → ICW2 的 D7~D3=00011，18H 高 5 位为 00011，符合；(4) 自动中断结束 → ICW4 的 D1（AEOI）=1，03H 的 D1=1，符合。端口地址使用正确：ICW1 写入偶地址 20H，ICW2、ICW4 写入奇地址 21H。

**答案**：
初始化程序为：

```asm
MOV  AL，13H    ；ICW1=0001 0011B：D4=1 标志位，LTIM=0 边沿触发，SNGL=1 单片，IC4=1
OUT  20H，AL
MOV  AL，18H    ；ICW2=0001 1000B：中断类型号高 5 位=00011
OUT  21H，AL
MOV  AL，03H    ；ICW4=0000 0011B：AEOI=1 自动中断结束方式
OUT  21H，AL
```

单片系统不需写 ICW3；初始化后各 IR 端的中断类型号为 18H~1FH（高 5 位 00011 加低 3 位 IR 编码 000~111）。

### 例题 4：用 OCW1 开放 IR4、IR3 并屏蔽其余中断请求（第 40 页）

**题干**：
OCW1 中某位为 1 时，对应该位的中断请求就被屏蔽，为 0 时，表示对应位的中断请求是开放的。
例如，以下指令开放了 IR4 和 IR3，而屏蔽了其余中断请求：

```asm
MOV  AL，11100111B
OUT  21H，AL
```

**解**：

第 1 步：确定 OCW1 各位与中断请求的对应关系：D7（M7）对应 IR7，D6（M6）对应 IR6，D5（M5）对应 IR5，D4（M4）对应 IR4，D3（M3）对应 IR3，D2（M2）对应 IR2，D1（M1）对应 IR1，D0（M0）对应 IR0；位值为 1 表示屏蔽，0 表示开放。

第 2 步：将 AL=11100111B 逐位展开并标注含义：D7=1（M7=1，屏蔽 IR7）；D6=1（M6=1，屏蔽 IR6）；D5=1（M5=1，屏蔽 IR5）；D4=0（M4=0，开放 IR4）；D3=0（M3=0，开放 IR3）；D2=1（M2=1，屏蔽 IR2）；D1=1（M1=1，屏蔽 IR1）；D0=1（M0=1，屏蔽 IR0）。

第 3 步：汇总位图结果。被开放的中断请求：IR4（M4=0）、IR3（M3=0）；被屏蔽的中断请求：IR7、IR6、IR5、IR2、IR1、IR0（对应位均为 1）。

第 4 步：确认写入地址。OUT 21H,AL 写入 21H（奇地址，A0=1），符合 OCW1 用奇地址写入的规定，内容存入中断屏蔽寄存器 IMR。

第 5 步：用原始条件验证。题干要求"开放 IR4 和 IR3，屏蔽其余中断请求"：11100111B 中 M4=0、M3=0，与开放 IR4、IR3 一致；M7、M6、M5、M2、M1、M0 均为 1，与屏蔽其余 6 级请求一致。验证通过。

**答案**：

```asm
MOV  AL，11100111B   ；OCW1：M4=M3=0（开放 IR4、IR3），其余位=1（屏蔽 IR0~IR2、IR5~IR7）
OUT  21H，AL         ；写入奇地址端口 21H，屏蔽字存入 IMR
```

执行后 IMR=11100111B：IR4、IR3 的请求开放，可进入优先权电路；IR0~IR2、IR5~IR7 的请求被屏蔽。

### 例题 5：用 OCW3 读出 8259A 中断服务寄存器 ISR 的内容（第 45 页）

**题干**：
例：用 OCW3 读出 8259A 中断服务寄存器 ISR 的内容。程序如下：

```asm
MOV  AL，00001011B     ；设置OCW3，准备读ISR的值
OUT  20H，AL
NOP
IN  AL，20H            ；读出ISR的内容
MOV  AH，AL            ；保存正在服务的中断源
OR  AL，AH             ；是否为0？
JNZ  HW_INT            ；否，转硬件中断处理程序
MOV  AH，0FFH          ；是，非硬件中断，设FFH标志
JMP  RW_INT            ；转非硬件中断处理程序
```

**解**：

第 1 步：写出命令字字节。MOV AL,00001011B 将二进制 00001011B 送入 AL。逐位分解 00001011B：D7=0、D6=0、D5=0、D4=0、D3=1、D2=0、D1=1、D0=1。其中 D4=0、D3=1 为 OCW3 标志位；D6（ESMM）=0、D5（SMM）=0，不改变特殊屏蔽方式；D2（P）=0，不查询；D1（RR）=1、D0（RIS）=1，即 RR=1、RIS=1，含义为"下一个操作读取中断服务寄存器 ISR 的内容"。00001011B = 0BH。

第 2 步：输出命令字。OUT 20H,AL 把 0BH 写入偶地址端口 20H（A0=0），8259A 接受 OCW3，准备好在下一个读操作时送出 ISR 内容。

第 3 步：等待一拍。NOP 空操作，保证命令字写入完成后 8259A 内部状态稳定。

第 4 步：读出 ISR。IN AL,20H 从偶地址端口 20H 读入一个字节到 AL，AL 即中断服务寄存器 ISR 的内容；ISR 的每一位对应一个中断请求端（D0 对应 IR0、…、D7 对应 IR7），某位为 1 表示对应中断源正在被服务。

第 5 步：保存与判零。MOV AH,AL 将 ISR 内容复制到 AH 保存正在服务的中断源；OR AL,AH 执行 AL←AL∨AH，将 AL 与自身按位或，结果影响标志位 ZF（仅当 AL=0 时结果全 0，ZF=1）。

第 6 步：分支。JNZ HW_INT 判断 ZF：ZF=0（ISR 内容非 0）说明有硬件中断正在服务，转硬件中断处理程序 HW_INT；ZF=1（ISR 内容为 0）说明没有正在服务的中断源，顺序执行。

第 7 步：非硬件中断处理。MOV AH,0FFH 把 0FFH 送入 AH 作为"非硬件中断"标志；JMP RW_INT 无条件转非硬件中断处理程序 RW_INT。

第 8 步：验证。00001011B 中 D4=0、D3=1 与 OCW3 标志位定义一致；RR=1、RIS=1 与"下一个 RD 读 ISR"的组合（11）一致；偶地址端口 20H 与"读 IRR/ISR 用偶地址端口"一致。原题条件与程序指令完全吻合。

**答案**：程序先向偶地址端口 20H 写 OCW3=00001011B（RR=1、RIS=1），再从端口 20H 读入 ISR 内容；若 ISR 非 0 转硬件中断处理程序 HW_INT，若 ISR 为 0 置 AH=0FFH 作标志并转非硬件中断处理程序 RW_INT。

### 例题 6：利用 OCW3 实现低级中断源中断高级中断源（IR4 服务程序，第 48 页）

**题干**：
例：CPU 正在处理 IR4 引入的中断请求，一般 CPU 不响应低级别的中断请求，但利用写入 OCW3 可实现低级中断源中断高级中断源的服务。IR4 的中断服务程序如下：

```asm
；IR4的中断服务程序
CLI                    ；关中断
MOV  AL，00010000B     ；写入OCW1，屏蔽IR4
OUT  21H
MOV  AL，01101000      ；写入OCW3，SMM=1，设置特殊屏蔽方式
OUT  20H，AL
STI                    ；开中断
；此时，有低级中断源请求，CPU可响应，并执行低级中断源的服务程序
CLI                    ；关中断
MOV  AL，01001000B     ；写入OCW3，SMM=0，清除特殊屏蔽方式
OUT  20H，AL
MOV  AL，00000000B     ；写入OCW1，开放IR4
OUT  21H
STI                    ；开中断
```

**解**：

第 1 步：关中断。CLI 使 IF=0，防止设置特殊屏蔽方式的过程中被其他中断请求打断。

第 2 步：写 OCW1 屏蔽 IR4。MOV AL,00010000B 将 00010000B 送入 AL。逐位分解：D4=1，其余位 0；OCW1 的 D4 即 M4，对应 IR4。OUT 21H,AL 把 00010000B 写入奇地址端口 21H（A0=1，写方向为 OCW1），中断屏蔽寄存器 IMR 的 M4 位置 1，IR4 被屏蔽，同时 ISR 的对应位被清 0。此时 8259A 中不再有"IR4 正在服务"的标识。

第 3 步：写 OCW3 设置特殊屏蔽方式。MOV AL,01101000 将 01101000B 送入 AL。逐位分解：D7=0、D6=1、D5=1、D4=0、D3=0、D2=0、D1=0、D0=0，即 ESMM=1、SMM=1。OUT 20H,AL 写入偶地址端口 20H。D6D5=11，为"设置特殊屏蔽方式"组合；D4D3=00，命令字为 OCW2 格式的字节值 68H，但此端口写操作由 ESMM/SMM 字段生效（原文程序如此书写，指令注释标明"写入 OCW3"）。

第 4 步：开中断。STI 使 IF=1。

第 5 步：进入允许低级中断的窗口。此后若有低级中断源（IR5、IR6、IR7）请求，由于 ISR 中 IR4 对应位已被清 0、特殊屏蔽方式已设置，优先权电路不再封锁低级中断，CPU 可响应并执行低级中断源的服务程序。

第 6 步：低级中断处理完毕，开始撤销。CLI 关中断（IF=0），防止撤销过程中被打断。

第 7 步：写 OCW3 清除特殊屏蔽方式。MOV AL,01001000B 送入 AL。逐位分解：D7=0、D6=1、D5=0、D4=0、D3=0、D2=0、D1=0、D0=0，即 ESMM=1、SMM=0。OUT 20H,AL 写入偶地址端口 20H。D6D5=10，为"清除特殊屏蔽方式"组合。

第 8 步：写 OCW1 开放 IR4。MOV AL,00000000B 将全 0 送入 AL；OUT 21H,AL 写入奇地址端口 21H，IMR 全部位清 0，M4=0 使 IR4 重新开放。

第 9 步：开中断。STI 使 IF=1，IR4 服务程序继续执行直至结束。

第 10 步：验证。OCW1=00010000B 中 M4=1 与"屏蔽 IR4"的目标一致；OCW3 设置字 01101000B 中 ESMM=1、SMM=1 与"设置特殊屏蔽方式：11"的组合一致；OCW3 撤销字 01001000B 中 ESMM=1、SMM=0 与"清除特殊屏蔽方式：10"的组合一致；OCW1=00000000B 与"开放 IR4"一致。指令对端口的分配（OCW1 用奇地址 21H、OCW3 用偶地址 20H）与 8259A 端口约定一致。

**答案**：IR4 服务程序中先关中断，以 OCW1=00010000B 屏蔽 IR4，再以 OCW3（ESMM=1、SMM=1）设置特殊屏蔽方式后开中断，此后低级中断源可中断 IR4 的服务；低级服务完成后关中断，以 OCW3（ESMM=1、SMM=0）清除特殊屏蔽方式，再以 OCW1=00000000B 开放 IR4，最后开中断。

### 例题 7：单片 8259A 完全嵌套方式下 IR2 嵌套 IR3 的中断流程（第 49 页）

**题干**：
应用举例：系统只有一片 8259A，当 CPU 执行主程序时，8259A 的 IR3 请求中断，在 CPU 为 IR3 中断服务时，IR2 又发出中断请求，若 8259A 采用完全嵌套方式工作，试说明该中断方式流程。

**解**：

第 1 步：确定工作方式。对 8259A 写入初始化命令字后，若不再写入操作命令字，则 8259A 自动进入完全嵌套方式；完全嵌套方式下 IR0~IR7 具有固定优先级，IR0 最高、IR7 最低，故 IR2 的优先级高于 IR3。

第 2 步：初始化后执行 STI，CPU 开中断（IF=1）。

第 3 步：IR3 请求中断。CPU 响应，进入 IR3 的中断服务程序，此时 ISR3=1。CPU 在响应中断时自动关中断（IF=0）。

第 4 步：IR3 服务期间 IR2 又请求中断。由于 CPU 未再次开中断（IF=0），IR2 的请求不会得到响应，IR2 的请求保持在 IRR 中挂起。

第 5 步：IR3 的服务程序执行 STI，IF=1。此时 IR2 的请求有效且 IR2 优先级高于 IR3（完全嵌套方式只封锁同级或低级中断，不禁止高级中断），CPU 响应 IR2 的中断请求。

第 6 步：IR3 中断服务程序暂时挂起，转入对 IR2 的中断处理。此时 ISR2=1、ISR3=1，表示两级中断都未处理完毕。

第 7 步：IR2（较高级）服务程序结束时，执行中断结束命令和中断返回命令：先执行一般中断结束命令（OCW2 中 EOI=1、SL=0、R=0，即 OCW2=20H，指令 MOV AL,20H; OUT 20H,AL，放在 IRET 指令之前），使较高级中断的 ISR2=0；再执行 IRET，使 CPU 返回执行较低级的中断服务程序（IR3 的服务程序）。

第 8 步：IR3 服务程序继续执行，完成后同样执行 EOI 使 ISR3=0，再 IRET 返回主程序。

第 9 步：验证。用原题条件验证：IR3 先请求、IR2 后请求，流程中 ISR3 先置 1、ISR2 后置 1，与请求先后一致；IR2（优先级 2）高于 IR3（优先级 3），满足"较高级中断打断较低级中断"的嵌套条件；完全嵌套方式的规定"封锁同级或低级、不禁止高级"解释了第 4 步 IR2 不被立即响应（因 IF=0）与第 5 步 STI 后被响应的原因。全部流程与原题条件一致。

**答案**：8259A 初始化后自动进入完全嵌套方式；执行 STI 后 IR3 请求被响应，ISR3=1；IR3 服务期间 IR2 请求因 CPU 响应中断时自动关中断而不被响应；IR3 服务程序执行 STI 后，IR2（优先级高于 IR3）被响应，IR3 服务挂起，ISR2=1、ISR3=1；IR2 服务结束后执行中断结束命令（OCW2=20H）使 ISR2=0 并 IRET 返回，IR3 服务继续执行直至完成并返回主程序。
