## 知识点详解

### 1. 机器指令（机器码）

**定义**：机器指令——微处理器中指令以二进制编码的形式出现，称为指令的机器码，或称机器指令。8086 的指令连续存放在存储器中，其第一个字节所在的存储器地址为该指令的地址。

**理解**：机器码是指令在存储器中的实际存在形式，每条指令由若干个字节组成，书写时通常用十六进制表示。符号指令（汇编助记符形式）经汇编后转换为对应的机器码，二者的对应关系是确定的。举例：符号指令 MOV AX,1234H 汇编为机器码 B8 34 12，共 3 字节，其中 B8 是操作码，34H、12H 是立即数 1234H 的编码，低字节 34H 存放在低地址单元、高字节 12H 存放在高地址单元。符号指令 ADD AX,BX 汇编为机器码 01 D8，共 2 字节。指令连续存放的直接结果：若第一条指令从 2000:0100 开始，占 3 个字节（2000:0100、2000:0101、2000:0102），则第二条指令从 2000:0103 开始，占 2 个字节（2000:0103、2000:0104）。

**作用**：基础概念，独立知识点。它是理解汇编（符号指令到机器码）、反汇编（机器码到符号指令）以及 CPU 取指执行过程的出发点。

### 2. 8086 指令系统的六大类

**定义**：8086 的指令共有六大类：数据传送指令、算术运算指令、逻辑运算和移位指令、字符串处理指令、控制转移指令、处理器控制指令。

**理解**：六大类按指令功能划分。§3.3 依次展开为：3.3.1 数据传送指令、3.3.2 算术运算指令（其中 BCD 码运算不要求掌握）、3.3.3 逻辑运算和移位指令、3.3.4 字符串处理指令（不要求掌握）、3.3.5 控制转移指令、3.3.6 处理器控制指令。标注 × 的表示不要求掌握。

**作用**：本章内容的总框架，为后续各节提供分类定位；属于顶层总览知识。

### 3. 数据传送指令的总性质（对标志位的影响）

**定义**：3.3.1 数据传送指令（见表 3.3），除 SAHF 和 POPF 指令外，对标志位均没有影响。

**理解**：执行数据传送指令后，标志寄存器中的各标志（CF、PF、AF、ZF、SF、OF 等）保持执行前的值不变。两个例外是 SAHF 和 POPF，这两条指令的功能本身就是把数据写入标志寄存器，因此执行后会改变标志位。

**作用**：程序设计时的依据——在影响标志位的运算指令之后，可以安全地插入数据传送指令而不破坏标志状态。属于 3.3.1 节的总体性质，为条件转移类指令的使用提供前提。

### 4. MOV 传送指令

**定义**：指令格式：MOV 目的，源；指令功能：目的操作数 ← 源操作数。约束：(1) CS 不能做目的操作数；(2) 立即数不能做目的操作数；(3) 指令中至少要有一项能明确说明传送的是字节还是字；(4) 目的操作数和源操作数不能同时为存储器单元。

**理解**：MOV 把源操作数的内容复制到目的操作数中，源操作数内容保持不变。各约束的原因：(1) CS 是代码段寄存器，其内容由系统管理，程序中不能任意改写；(2) 立即数是写在指令中的常数，不具备存储能力，不能作为被写入的对象；(3) 若源和目的都未表明字节或字，汇编程序无法确定传送位数。例如 MOV AX,[2000H] 中 AX 表明字操作，MOV AL,[2000H] 中 AL 表明字节操作；(4) 对"目的操作数和源操作数同时为存储器单元可不可以"的回答是：不可以。8086 指令系统没有提供存储器到存储器的直接传送指令——一条指令的机器码只能对一个存储单元寻址，内存到内存的传送需要中间暂存，所以两个存储单元之间的数据传送必须先经寄存器（先用 MOV 取到寄存器，再用 MOV 存入另一单元）。另外，若两个操作数中一方是寄存器、另一方是存储单元或立即数，则寄存器同时明确了传送的位数和方向。

**作用**：数据传送指令中最基本、使用频率最高的指令；是 PUSH/POP/XCHG/XLAT 等指令学习的前置知识，也是给段寄存器赋值（经通用寄存器中转）的基础。

### 5. 数据段定义（SEGMENT/ENDS 伪指令）

**定义**：在汇编语言程序中，数据通常存放在数据段中。数据段以伪指令 SEGMENT 开始、ENDS 结束，格式为：段名 SEGMENT …… 段名 ENDS，其中 DATA（段名）为标识符。

**理解**：SEGMENT 与 ENDS 成对出现，构成一个逻辑段；二者是不产生机器码的伪指令，只在汇编时划定段的范围。段内定义的变量按书写顺序从偏移地址 0000H 开始依次分配存储单元。与高级语言变量定义的区别：高级语言中变量由编译系统分配地址，程序员一般不关心具体地址；汇编语言中程序员可以直接确定并知道每个变量在段内的偏移地址。

**作用**：组织程序中数据的结构单位；汇编后段名被赋予具体的段地址，为段内变量的寻址提供段基址。

### 6. DB 伪操作符（定义字节变量）

**定义**：DB 伪操作符定义字节变量，每个操作数占 1 个字节；定义的变量可以给定初值。

**理解**：DB 后跟的操作数每个占 1 个字节；操作数可以是常数、字符（按 ASCII 码存放）或字符串（每个字符占 1 字节）。例：AREA1 DB 14H,3BH 定义 AREA1 占 2 个字节单元，初值分别为 14H、3BH；STRING DB 'GOOD' 定义 4 个字节单元，存放字符 G、O、O、D 的 ASCII 码。

**作用**：定义字节型数据的工具；与 DW 并列，是查表法建表的基础（七段码表格即用 DB 建立）。

### 7. DW 伪操作符（定义字变量）

**定义**：DW 伪操作符定义字变量，每个操作数占 2 字节；字存放规则为低字节在前（低地址单元），高字节在后（高地址单元）。

**理解**：DW 后跟的每个操作数占 2 个字节。8086 对字的存放规则是低字节存放在低地址、高字节存放在高地址。例：ARRAY DW 3100H,01A6H 定义两个字符单元；3100H 存放时，00H 在低地址单元、31H 在高地址单元；01A6H 存放时，A6H 在低地址单元、01H 在高地址单元。

**作用**：定义字型数据；低字节在前的存放规则是 8086 存储组织的基本规定，读取字单元时必须据此区分高、低字节。

### 8. DUP 复制操作符

**定义**：DUP 是复制操作符，格式为：重复次数 DUP(初值)。如 3 DUP(0) 说明在存储器中保留 3 个单元，初值均为 0。

**理解**：DUP 前面的数字是重复次数，括号内是被重复的操作数。3 DUP(0) 展开后等价于 0,0,0，即连续 3 个单元、每个单元初值为 0。DUP 与 DB/DW 配合使用：DB 3 DUP(0) 是 3 个字节单元初值 0；若为 DW 3 DUP(0) 则是 3 个字单元初值 0。

**作用**：批量定义初值相同的连续存储区（缓冲区、数组）时避免逐个书写；与 DB、DW 配合使用。

### 9. 变量的偏移地址（有效地址）

**定义**：汇编后，段名（如 DATA）被赋予具体的段地址，各变量自偏移地址 0000H 开始依次存放，各符号地址也被赋予确定的值，等于它们在数据段中的偏移量。偏移地址亦称有效地址。

**理解**：偏移地址是变量相对其所在段首地址的字节距离。变量按定义顺序依次分配单元，某个变量的偏移地址等于它前面所有变量占用字节数之和。图 3.13 实例：AREA1 DB 14H,3BH 占 0000H、0001H 两个单元；AREA2 DB 3 DUP(0) 占 0002H～0004H 三个单元；ARRAY DW 3100H,01A6H 占 0005H～0008H 四个单元；STRING DB 'GOOD' 占 0009H～000CH 四个单元。因此：AREA1 的偏移地址为 0000H，AREA2 的偏移地址为 0002H，ARRAY 的偏移地址为 0005H，字符串 'GOOD' 从 0009H 开始存放。

**作用**：汇编语言变量寻址的基础。指令中出现的变量名（存储器操作数）在汇编时被替换为其偏移量；符号地址的值等于偏移量，也是 OFFSET 操作符所取值的对象。

### 10. OFFSET 属性操作符

**定义**：OFFSET 为属性操作符，表示应把其后的符号的地址（而不是内容）作为操作数。

**理解**：OFFSET 作用于变量名时，取该变量在段内的偏移地址。MOV DX,OFFSET ARRAY 与 MOV DX,ARRAY 的区别：前者 DX 得到 ARRAY 的偏移地址 0005H（一个常数）；后者 DX 得到 ARRAY 字单元的内容 3100H（一次内存读）。OFFSET 取的是"地址"，直接取数是"内容"。

**作用**：建立地址指针的基本方法；在查表技术中用于把表格首地址送入寄存器（MOV BX,OFFSET TABLE），与基址变址寻址配合使用。

### 11. PUSH 进栈指令

**定义**：指令格式：PUSH 源；指令功能：将源操作数推入堆栈。源操作数可以是 16 位通用寄存器、段寄存器或存储器中的数据字，但不能是立即数。执行 PUSH 操作时，先使 $SP \leftarrow SP - 2$，再把源操作数压入 SP 指示的位置上。

**理解**：堆栈以字为单位操作，栈顶由 SS:SP 指示。PUSH 分两步执行：第一步 SP 减 2（一个字占 2 字节，8086 堆栈的栈顶指针随数据入栈向低地址方向移动）；第二步把源操作数字写入新的栈顶单元（SS:SP 指向的地址）。源不能是立即数的原因：立即数直接写在指令中即可使用，无需压栈保存。

**作用**：保存寄存器现场数据（子程序调用、中断处理前保护数据）和传递参数；与 POP 配对，构成堆栈后进先出的存取机制。

### 12. POP 出栈指令

**定义**：指令格式：POP 目的；指令功能：把当前 SP 所指向的一个字送到目的操作数中。目的操作数可以是 16 位通用寄存器、段寄存器或存储单元，但不能是 CS。每执行一次出栈操作，先将 SP 指向的数据送到目的操作数，再 $SP \leftarrow SP + 2$，SP 向高地址方向移动，指向新的栈顶。

**理解**：POP 是 PUSH 的逆操作，分两步执行：第一步把 SS:SP 当前指向的字单元内容读出，送到目的操作数；第二步 SP 加 2，栈顶指针向高地址方向移动。目的不能是 CS 的原因与 MOV 相同：CS 由系统管理，不能随意改写。

**作用**：恢复由 PUSH 保存的数据；与 PUSH 配对使用，共同实现堆栈的后进先出（后进栈的数据先出栈）存取。

### 13. XCHG 交换指令

**定义**：指令格式：XCHG 目的，源；指令功能：源操作数和目的操作数相交换。交换可以在寄存器之间、寄存器与存储器之间进行，但段寄存器不能作为操作数，也不能直接交换两个存储单元中的内容。

**理解**：XCHG 一次完成两个方向的数据移动：目的操作数得到源的值，源操作数同时得到目的的原值，两个操作数的内容互换，这与 MOV 的单向复制不同。约束的原因：(1) 段寄存器不能作为操作数，因段寄存器受系统管理；(2) 两个存储单元不能直接交换，因 8086 一条指令不能同时对两个存储单元寻址（与 MOV 的限制相同）。可用的组合为：寄存器与寄存器、寄存器与存储单元。

**作用**：需要互换两个数据时（例如排序中交换两个元素）一条指令即可完成，不需要中间寄存器暂存。

### 14. XLAT 表转换指令与查表技术

**定义**：指令格式：XLAT 转换表（"转换表"为表格首地址）；或 XLAT（"转换表"可省略不写）。指令功能：将 1 个字节从一种代码转换成另一种代码。教学要求：不要求掌握查表指令，但需要了解什么是查表以及如何实现查表。

**理解**：查表是用预先建立的表格完成代码转换：待转换代码的值作为表格的位移量，从表格中取出对应单元的内容作为转换结果。实现步骤分三部分：(1) 建表——用 DB 伪指令建立表格，第 n 项数据存放在相对表首地址位移量为 n 的单元中；(2) 取表首地址——用 MOV BX,OFFSET TABLE 将表格起始地址送入 BX；(3) 查表——把待转换代码值送入变址寄存器（如 MOV SI,5），再用基址变址寻址 MOV AL,[BX+SI] 取出表项。代码值与表格位移量的一一对应关系使代码转换自动完成。

**作用**：代码转换类问题的通用解法（数字到七段显示码、ASCII 码到其他编码等）；是 OFFSET 操作符、DB 建表、基址变址寻址的综合应用。

### 15. IN 输入指令

**定义**：IN 是 8086 的输入指令，功能为把指定端口的输入数据读入累加器。指令格式有两种：格式① `IN AL，端口地址`（AL←从 8 位端口读入 1 字节）或 `IN AX，端口地址`（AX←从 16 位端口读入 1 个字），此时端口地址（00~FFH）直接包含在 IN 指令里，共允许寻址 256 个端口；格式② `IN AL，DX` 或 `IN AX，DX`，端口地址先存放在 DX 寄存器中，DX 允许范围 0000~FFFFH，当端口地址大于 FFH 时必须用格式②寻址。

**理解**：IN 指令由三个要素构成：读取方向（从端口设备读入 CPU）、数据宽度（AL 对应 1 字节即 8 位端口，AX 对应 1 个字即 16 位端口）、端口地址的给出方式（立即数直接给出，或由 DX 寄存器间接给出）。端口地址是 16 位空间（0000~FFFFH），但直接编码在指令里的立即数形式只有 8 位（00~FFH），因此大于 FFH 的端口号无法直接写在指令中，必须先送入 DX 再执行 IN。16 位端口读入时，一次读入 2 字节，低地址端口的内容进入 AL，高地址端口的内容进入 AH。

**作用**：输入输出指令是 CPU 与外部 I/O 设备交换数据的两条通道之一，IN 负责"读入"方向。它是"数据传送指令"大类中的第 2 类，与 OUT 指令并列，二者共同构成 8086 的 I/O 端口寻址体系（端口独立编址，与存储器寻址分开）。后续接口课程中的 8255A、8253/8254、8259A 等接口芯片的端口读写均以 IN/OUT 为基础。

### 16. OUT 输出指令

**定义**：OUT 是 8086 的输出指令，功能为把累加器的内容送到指定端口。指令格式有两种：格式① `OUT 端口地址，AL`（8 位端口←AL 内容）或 `OUT 端口地址，AX`（16 位端口←AX 内容）；格式② `OUT DX，AL` 或 `OUT DX，AX`，端口地址由 DX 给出。

**理解**：OUT 与 IN 方向相反，把 CPU 累加器中的数据送到外部设备端口。其端口地址的给出方式与 IN 完全相同：立即数形式覆盖 00~FFH 共 256 个端口，DX 间接形式覆盖 0000~FFFFH 全部 64K 个端口。数据宽度同样由累加器决定：AL 传送 1 字节，AX 传送 1 个字（低地址端口接收 AL 内容，相邻高地址端口接收 AH 内容）。

**作用**：与 IN 并列，完成 CPU 对 I/O 设备的"写出"方向。二者共同构成 8086 的输入输出指令体系，是数据传送指令的第 2 类。输出指令用于向接口芯片的控制端口写入控制字、向数据端口送出数据等。

### 17. LEA 取有效地址指令

**定义**：LEA（Load Effective Address）取有效地址指令，指令格式 `LEA 目的，源`，指令功能为：取源操作数地址的偏移量，送到目的操作数。源操作数必须是存储单元，目的操作数是一个除段寄存器之外的 16 位寄存器。

**理解**：LEA 传送的是"地址"而非"地址里的内容"。操作分两步理解：先计算源存储单元的偏移地址（有效地址 EA），再把这个偏移量的数值送入目的寄存器。同一存储单元可以通过 LEA 得到其地址、通过 MOV 得到其内容，这是两条指令的本质区别：`LEA BX，[SI]` 使 BX 得到 SI 的值（即偏移地址本身），`MOV BX，[SI]` 使 BX 得到内存单元中的内容。

**作用**：属于地址目标传送指令（数据传送指令的第 3 类），用于在程序中获得某个存储单元（变量、表格）的偏移地址，为后续的间接寻址、查表等操作做准备。它与 MOV/OFFSET 方式功能等价，是后续数据段变量寻址、字符串处理（SI/DI 指针设置）的前置知识点。

### 18. LDS 将双字指针送到寄存器和 DS 指令

**定义**：LDS（Load Pointer using DS）指令，格式 `LDS 目的，源`，功能为：从源操作数指定的存储单元中，取出 1 个 4 字节地址指针，送进目的寄存器 DS 和指令中指定的目的寄存器中。源操作数必须是存储单元，目的操作数必须是 16 位寄存器（常用 SI），但不能是段寄存器。

**理解**：LDS 一次传送一个完整的"双字指针"（段地址 + 偏移地址共 4 字节）。指针在存储器中的存放规则是：低地址 2 字节为偏移量部分，高地址 2 字节为段基址部分。执行时把低 2 字节送入指定的 16 位目的寄存器（偏移量），把高 2 字节送入 DS（段地址）。指令中 DS 是隐含目的操作数，写指令时只写一个目的寄存器。LDS 与 LES 的操作规则完全相同，区别仅在于段寄存器是 DS 还是 ES。

**作用**：地址目标传送指令之一，用于把预先存放在内存中的远指针（far pointer，段：偏移形式）一次装入段寄存器和偏移寄存器，为跨段数据访问做准备。与 LES 并列，二者分别对应数据段指针和附加段指针。

### 19. LES 将双字指针送到寄存器和 ES 指令

**定义**：LES（Load Pointer using ES）指令，格式 `LES 目的，源`，指令功能与 LDS 指令的操作基本相同，但段寄存器为 ES，目的操作数常用 DI。

**理解**：LES 与 LDS 的拆解结构完全一致：从源存储单元取 4 字节指针，低 2 字节送入目的寄存器（常用 DI），高 2 字节送入 ES。唯一区别是段寄存器由 DS 换成 ES。源操作数必须是存储单元，目的操作数不能是段寄存器。

**作用**：与 LDS 并列的地址目标传送指令，用于装入指向附加段（ES）的远指针，常用于字符串操作指令中 ES:DI 的目标串指针设置。

### 20. LAHF 标志送到 AH 指令

**定义**：LAHF（Load AH from Flags），指令格式 `LAHF`，指令功能：把标志寄存器的 SF、ZF、AF、PF 和 CF 传送到 AH 寄存器的相应位。

**理解**：FLAGS 寄存器中的 5 个状态标志（SF、ZF、AF、PF、CF）按各自在标志寄存器中的固定位位置，对应复制到 AH 的相应位中。指令无操作数，源和目的都是隐含的。只传送这 5 个标志，不涉及 OF、DF、IF、TF。

**作用**：标志传送指令之一（数据传送指令的第 4 类）。用于把标志寄存器的内容保存到通用寄存器中，便于程序检查标志状态。与 SAHF 配对使用，构成"标志→AH→标志"的传递通道。是 PUSHF/POPF 之外的另一种标志保存方式，但只覆盖 5 个状态标志。

### 21. SAHF AH 送标志寄存器

**定义**：SAHF（Store AH into Flags），指令格式 `SAHF`，指令功能：把 AH 内容存入标志寄存器，指令功能与 LAHF 的操作相反。

**理解**：SAHF 是 LAHF 的逆操作，把 AH 中相应位的内容写回标志寄存器的 SF、ZF、AF、PF、CF 五个标志位。执行 LAHF 后再执行 SAHF，标志寄存器中这 5 个标志恢复到 LAHF 时刻的值。由于 SAHF 会改变标志位，所以数据传送指令中"除 SAHF 和 POPF 指令外，对标志位均没有影响"。

**作用**：与 LAHF 配对，构成用通用寄存器中转保存/恢复状态标志的手段。属于标志传送指令，用于程序需要临时改动标志位后再恢复原标志状态的场合。

### 22. PUSHF 标志入栈指令

**定义**：PUSHF（Push Flags onto Stack），指令格式 `PUSHF`，指令功能：把整个标志寄存器的内容推入堆栈，并使 SP←SP−2。

**理解**：PUSHF 把整个 FLAGS 寄存器（16 位，含全部标志位）压入堆栈保存。执行顺序是先 SP 减 2（栈顶向低地址方向移动一个字），再把 FLAGS 内容写入新栈顶指向的字单元。与 PUSH 指令机制相同，区别在于源操作数固定为 FLAGS，指令中无需写出。

**作用**：标志传送指令之一。与 POPF 配对，用于进入子程序或中断处理前保存完整的标志状态，处理后恢复，保证主程序标志不被破坏。数据传送指令中 PUSHF 对标志位没有影响。

### 23. POPF 标志出栈指令

**定义**：POPF（Pop Flags off Stack），指令格式 `POPF`，指令功能：把 SP 所指的一个字，传送给标志寄存器 FLAGS，并使 SP←SP+2。

**理解**：POPF 是 PUSHF 的逆操作。执行顺序是先取当前 SP 指向的栈顶字送入 FLAGS，再把 SP 加 2（栈顶向高地址方向回退一个字）。因为 POPF 直接用栈中数据改写全部标志位，所以它是数据传送指令中会影响标志位的两条指令之一（另一条是 SAHF）。

**作用**：与 PUSHF 配对完成标志寄存器的完整保存与恢复。在中断服务程序返回前用 POPF 恢复中断前的标志状态，是中断系统和子程序调用的基础指令。

### 24. 算术运算指令处理的 4 种类型数

**定义**：8086 算术运算指令可处理 4 种类型的数：无符号二进制整数、带符号二进制整数、无符号压缩十进制整数（Packed Decimal）、无符号非压缩十进制整数（Unpacked Decimal）。二进制数可以是 8 位或 16 位，如果是带符号数，则用补码表示。压缩十进制数在一个字节中存放两个 BCD 码十进制数；非压缩十进制数低半字节存放一个十进制数，高半字节为全零（译为 ASCII 码数）。

**理解**：同一条算术指令的操作数可能代表四种不同意义的数，指令本身按二进制编码运算，不区分类型，类型由程序员解释。二进制类（有/无符号）直接用二进制补码运算；十进制类用 BCD 码表示，运算后需配合十进制调整指令校正。压缩 BCD 每字节放两位十进制数（高、低半字节各一位），非压缩 BCD 每字节只放一位十进制数（低半字节），高半字节为 0。

**作用**：是 3.3.2 算术运算指令的总前提，规定了后续加减乘除及调整指令所处理数据的所有可能形式，决定"加减法不分有符号/无符号而乘除法要分"这一问题的答案基础。

### 25. ADD 加法指令

**定义**：ADD 加法指令，指令格式 `ADD 目的，源`，指令功能：目的←源+目的。源操作数可以是寄存器、存储器或立即数；目的操作数只能用寄存器和存储单元（存储单元可以有表 3.2 中所示的 24 种表示方法）；源和目的操作数不能同时为存储器，而且它们的类型必须一致，即都是字节或字。指令执行后影响标志位 CF、OF、PF、SF、ZF 和 AF。

**理解**：ADD 执行两操作数相加，结果写回目的操作数，源操作数不变。操作数规则由 8086 总线结构决定：一条指令不能同时读写两个存储器单元，故源、目的不能同为存储器；数据宽度必须一致（字节配字节、字配字），因为寄存器与存储器的宽度由操作数本身隐含确定。加法结果的标志影响是本指令的核心学习点：CF 反映无符号进位，OF 反映有符号溢出，AF 反映低 4 位向高 4 位的进位（半进位），ZF/SF/PF 反映结果本身特征。

**作用**：加法指令的基本形式，是算术运算指令的第一条。与 ADC 配合构成多字节加法的基础，是所有算术运算学习的前置知识点。

### 26. ADC 带进位的加法指令

**定义**：ADC（Addition with Carry）带进位的加法指令，指令格式 `ADC 目的，源`，指令功能：目的←源+目的+CF。操作数规则与 ADD 相同：源操作数可以是寄存器、存储器或立即数；目的操作数只能用寄存器和存储单元；源和目的不能同时为存储器，类型必须一致。指令影响标志位 CF、OF、PF、SF、ZF 和 AF。

**理解**：ADC 与 ADD 的区别仅在于多加了当前进位标志 CF 的值。加法结果本身会产生新的 CF，供下一次 ADC 继续使用。多字节数相加时，低位字节用 ADD 相加（此时没有来自更低位的进位），高位字节用 ADC 相加（把低位字节相加产生的进位一并加进来），依次从低字节向高字节逐段进行。

**作用**：与 ADD 组成加法指令对，解决"怎么做多字节的加减法"这一 3.3.2 开篇问题——多字节加法靠 ADD（最低字节）+ ADC（其余字节）实现。是理解 CF 进位标志作用的关键知识点。

### 27. INC 增量指令（Increment）

**定义**：指令格式 `INC 目的`；指令功能：目的 ← 目的 + 1。目的操作数可以是通用寄存器或内存单元。指令执行后影响 AF、OF、PF、SF 和 ZF，但进位标志 CF 不受影响。

**理解**：该指令把指定寄存器或内存单元中存放的数加 1，再把结果写回原位置。它不改变 CF，因此在多字节数加 1 的场合，低字节加 1 产生的进位不会经 CF 传递给高字节，这一点与 ADD 不同。指令只有一个操作数；若操作数是内存单元，必须用 PTR 操作符说明是字还是字节（如 `INC BYTE PTR[BX]` 对字节单元增 1，`INC WORD PTR[BX]` 对字单元增 1）。

**作用**：属于加法指令组（ADD、ADC、INC）的成员；常用作循环计数器、地址指针的递增操作，是程序设计中高频使用的单操作数算术指令。

### 28. SUB 减法指令（Subtraction）

**定义**：指令格式 `SUB 目的，源`；指令功能：目的 ← 目的 − 源（注意相减顺序是目的减源，结果回送目的操作数）。源操作数可为寄存器、立即数或内存单元。

**理解**：该指令执行二进制减法，方向固定为"目的操作数减源操作数"，减得的结果写回目的操作数，源操作数不变。例如 `SUB DX,1850H` 是 DX 减去立即数 1850H 后结果存回 DX；`SUB BL,[BX]` 是 BL 中的内容减去物理地址 DS:BX 处字节的内容，结果存入 BL。减法结果按二进制补码解释，并据结果设置状态标志。

**作用**：减法指令组（SUB、SBB、DEC、NEG、CMP）中的基本指令；两个数相减的主要手段，也是 SBB、CMP 等指令实现的基础。

### 29. SBB 带借位的减法指令（Subtract with Borrow）

**定义**：指令格式 `SBB 目的，源`；指令功能：目的 ← 目的 − 源 − CF，即在"目的减源"的基础上再减去进位（借位）标志 CF 的值。SBB 主要用于多字节减法中。

**理解**：做多位宽（多字节或多字）减法时，低位部分相减产生的借位保存在 CF 中；高字节部分相减时必须把低位借位一起减去，SBB 在减源操作数的同时再减 CF 的值，从而把借位正确地传递到高位部分。例如 `SBB AL,CL` 执行 AL ← AL − CL − CF。

**作用**：与 SUB 配合构成多字节/多字减法的高位部分减法指令，使处理器能够实现超过寄存器宽度的任意位宽减法；它是"带进位加法 ADC"在减法方向上的对应指令。

### 30. DEC 减量指令（Decrement）

**定义**：指令格式 `DEC 目的`；指令功能：目的 ← 目的 − 1。目的操作数可为寄存器或内存单元（如 `DEC BX`；`DEC WORD PTR[BP]` 对堆栈段中位于 [BP] 偏置处的字减 1）。

**理解**：该指令把指定寄存器或内存单元中存放的数减 1，再把结果写回原位置。指令只有一个操作数；内存操作数需用 PTR 操作符说明宽度（字节或字）。

**作用**：减法指令组中的单操作数减量指令；常用作循环计数器、地址指针的递减操作，与 INC 形成对称。

### 31. NEG 取负指令（Negate）

**定义**：指令格式 `NEG 目的`；指令功能：目的 ← 0 − 目的（即对目的操作数取负，也就是"取反加一"，改变数的符号位）。例如 `NEG AX` 将 AX 中的数取负；`NEG BYTE PTR[BX]` 对数据段中位于 [BX] 偏置处的字节取负。

**理解**：对一个补码表示的数取负，等价于用 0 减去该数，也等价于对该数逐位取反后在最低位加 1。这一"取反加一"过程正是求补码的运算规则，因此 NEG 直接体现补码转换。课件在此处标注"为什么？补充补码知识——和 IMUL 和 IDIV 串联起来"，即：掌握取反加一是理解后面有符号乘法 IMUL 和有符号除法 IDIV 的准备知识。

**作用**：求一个数的相反数（符号取反）；同时是补码运算体系的组成部分，与 IMUL、IDIV 构成有符号数运算的知识链条。

### 32. CMP 比较指令（Compare）

**定义**：指令格式 `CMP 目的，源`；指令功能：目的 − 源，实际执行的是减法运算，但结果不回送到目的操作数，只根据结果改变标志位。比较指令主要用在希望比较两个数的大小、而又不破坏原操作数的场合，一般紧跟条件转移指令实现跳转。

**理解**：CMP 内部完成的动作与 SUB 相同，差别仅在于减得的结果被丢弃、不写回目的操作数，因此两个操作数在比较后都保持原值。程序根据该减法结果设置的标志位（如 ZF 表示相等、CF 表示无符号大小、SF/OF 表示有符号大小）判断两数的大小关系，随后用条件转移指令跳转。例如 `CMP AL,80H` 把 AL 与立即数 80H 比较；`CMP BX,DATA1` 把 BX 与数据段中偏移量为 DATA1 处的字比较。

**作用**：程序分支（条件转移）的判据来源，是比较两个数大小而不破坏原操作数的标准手段；在控制结构中与条件转移指令成对使用。

### 33. MUL 无符号数乘法指令（Multiply）

**定义**：指令格式 `MUL 源`；指令功能：把源操作数和累加器中的数都当成无符号数，然后将两数相乘。两个操作数中一定有一个是累加器：若源操作数是 1 个字节，则 AX ← AL × 源；若源操作数是 1 个字，则 (DX, AX) ← AX × 源。源操作数可以是寄存器或存储单元，不能是立即数；当源操作数是存储单元时，应在操作数前加 BYTE 或 WORD（或者用 BYTE PTR/WORD PTR）说明是字节还是字。MUL 指令执行后影响 CF 和 OF 标志：如果结果的高半部分不为零，则 CF、OF 均置 1；否则 CF、OF 均清 0。通过测试这两个标志，可检测并去除结果中的无效前导零。

**理解**：乘积的位宽是乘数位宽的两倍：8 位乘 8 位得 16 位积存入 AX（AL 存低 8 位、AH 存高 8 位）；16 位乘 16 位得 32 位积存入 DX:AX（AX 存低 16 位、DX 存高 16 位）。乘积的高半部分是否为零，决定了乘积能否仅用低半部分表示；CF/OF 同时置 1 即表示高半部分含有有效数值位，CF/OF 同时清 0 即表示高半部分全为 0、可以丢弃。由于累加器固定作为被乘数，指令只需写出一个源操作数。

**作用**：无符号数乘法基本指令；CF/OF 提供乘积高半部分是否有效的信息，用于决定是否需要保存积的高半部分。

### 34. IMUL 整数乘法指令——有符号数乘法（Integer Multiply）

**定义**：指令格式 `IMUL 源`；指令功能：把源操作数和累加器中的数都作为带符号数进行相乘，存放结果的方式与 MUL 相同，最后给乘积赋予正确的符号。指令执行后，如果乘积的高半部分不是全 0 或全 1，则置 CF=1、OF=1；若结果高半部分为全 0 或全 1，则使 CF=0、OF=0，以此决定是否需要保存积的高半部分。

**理解**：与 MUL 的区别仅在于操作数的解释方式：MUL 按无符号数解释，IMUL 按补码带符号数解释。有符号乘积的高半部分按符号扩展规则取值：乘积为正时高半部分应为全 0，乘积为负时高半部分应为全 1；因此高半部分只有"全 0 或全 1"与"其他"两种情形，前者表示高半部分仅是符号位的重复、不含有效数值位，后者表示高半部分含有有效数值位，需要保存。

**作用**：带符号数乘法指令；CF/OF 用于判断有符号乘积的高半部分是否有效，从而决定是否需要保存积的高半部分。

### 35. DIV 无符号数除法指令（Division, unsigned）

**定义**：指令格式 `DIV 源`；指令功能：对两个无符号二进制数进行除法操作。若源操作数为字节，被除数必须放在 AX 中，且 AL ← AX/源(字节) 的商、AH ← AX/源(字节) 的余数；要是被除数只有 8 位，必须把它放在 AL 中并将 AH 清 0，然后相除。若源操作数为字，被除数必须放在 DX 和 AX 中，且 AX ← (DX,AX)/源(字) 的商、DX ← (DX,AX)/源(字) 的余数；要是被除数只有 16 位、除数也是 16 位，则必须将 16 位被除数送入 AX、再将 DX 清 0，然后相除。与被除数和除数一样，商和余数都是无符号数。

**理解**：除法指令对被除数寄存器的使用是隐含固定的：被除数位宽必须是除数位宽的两倍（字节除数对应 16 位被除数 AX，字除数对应 32 位被除数 DX:AX）。当被除数实际位宽与除数相同（8 位除 8 位、16 位除 16 位）时，必须先把高半部分寄存器（AH 或 DX）清零，构成位宽正确的无符号被除数，再执行 DIV。商存低半部分寄存器（AL 或 AX），余数存高半部分寄存器（AH 或 DX）。

**作用**：无符号除法基本指令；被除数位宽准备规则（清 AH/DX）是正确使用该指令的前提。

### 36. IDIV 整数（有符号数）除法指令（Integer Division）

**定义**：指令格式 `IDIV 源`；指令功能：功能与 DIV 相同，但操作数都必须是带符号数，商和余数也都是带符号数，而且规定余数的符号和被除数的符号相同。进行除法操作时，如果商超过了目标寄存器 AL 或 AX 所能存放数的范围，计算机会自动产生除法错中断，相当于执行了除数为 0 的运算，所得的商和余数都不确定。

**理解**：IDIV 与 DIV 的区别在于按补码带符号数解释操作数和结果，并强制余数与被除数同号（例如 −38÷3 的商为 −12、余数为 −2，而不是商 −13 余 +1）。当商的绝对值超出目标寄存器 AL（字节除法）或 AX（字除法）的表示范围时，处理器不给出错误结果，而是转入除法错中断处理，此时商和余数的值均不可使用。带符号数除法字节操作要求被除数为 16 位、字操作要求被除数为 32 位；被除数位宽不足时不能简单将高位置 0，须先用符号扩展指令 CBW、CWD 转换格式。

**作用**：带符号除法指令；商溢出保护机制（除法错中断）保证不会把错误结果当作有效结果继续执行。

### 37. CBW 把字节转换为字指令（Convert Byte to Word）

**定义**：指令格式 `CBW`（无操作数）；指令功能：把 AL 中字节的符号位扩充到 AH 的所有位，此时 AH 被称为是 AL 的符号扩充。如果 AL 中的 D7=0，就将这个 0 扩展到 AH 中去，使 AH=00H；若 AL 中的 D7=1，则将这个 1 扩展到 AH 中去，使 AH=FFH。CBW 指令执行后不影响标志位。

**理解**：该指令在不改变数值的前提下，把一个 8 位补码数扩展为 16 位补码数：正数（D7=0）高位补 0，负数（D7=1）高位补 1。补码表示下负数必须高位补 1 才能保持数值不变，因此符号扩展后的 16 位数与原 8 位数代表同一个值。字节操作的有符号除法要求 16 位被除数，故 8 位带符号被除数在 IDIV 之前必须先经 CBW 扩展。

**作用**：带符号除法（IDIV 字节操作）的被除数格式准备指令；是符号扩展规则在字节到字方向的具体实现。

### 38. CWD 把字转换成双字指令（Convert Word to Double Word）

**定义**：指令格式 `CWD`（无操作数）；指令功能：把 AX 中字的符号位扩充到 DX 寄存器的所有位中去。若 AX 中的 D15=0，则 DX←0000H；若 AX 中的 D15=1，则 DX←FFFFH。

**理解**：该指令在不改变数值的前提下，把一个 16 位补码数扩展为 32 位补码数：正数（D15=0）高位补 0，负数（D15=1）高位补 1，扩展后 DX:AX 表示的值与原来 AX 的值相同。字操作的有符号除法要求 32 位被除数，故 16 位带符号被除数在 IDIV 之前必须先经 CWD 扩展。

**作用**：带符号除法（IDIV 字操作）的被除数格式准备指令；是符号扩展规则在字到双字方向的具体实现，与 CBW 成对。

### 9. 复习问题解答（第 8 页及例 3.27、例 3.28 后）

- 例 3.27 后："复习：这是什么寻址方式？"——AREA1、AREA2 为存储器符号地址，其偏移量直接写在指令中，属直接寻址。
- 例 3.28 的寻址方式：MOV AX,TABLE[BP][DI] 属基址变址寻址（BP 为基址寄存器、DI 为变址寄存器、TABLE 为 16 位位移量；因使用 BP，段寄存器默认 SS）。
- 第 8 页提问："目的操作数和源操作数同时为存储器单元可不可以？为什么？"——不可以。8086 指令不允许两个操作数同时为存储器单元：一条指令的机器码只能对一个存储单元寻址，内存到内存的直接传送需要中间暂存，故两个存储单元间的数据传送必须经寄存器中转。

### 10. IN 指令的端口寻址规则（第 21 页）

- 格式①：端口地址（00~FFH）直接包含在 IN 指令里，共允许寻址 256 个端口；
- 格式②：当端口地址大于 FFH 时，必须先将端口号送入 DX，再执行输入操作，DX 允许范围 0000~FFFFH。
- 8 位端口：`IN AL，端口地址` / `IN AL，DX`；16 位端口：`IN AX，端口地址` / `IN AX，DX`。
- 例 3.33 表明端口地址可以用符号表示（`ATOD EQU 54H` 定义符号后 `IN AL，ATOD` 即可），该符号地址是立即数寻址（复习点）。

### 11. OUT 指令格式汇总（第 24 页）

- 格式①：`OUT 端口地址，AL`（8 位端口←AL 内容）或 `OUT 端口地址，AX`（16 位端口←AX 内容）；
- 格式②：`OUT DX，AL` 或 `OUT DX，AX`（DX=端口地址）。
- 16 位端口输出时低地址端口接收 AL、相邻高地址端口接收 AH（例 3.34：`OUT DX，AX`，DX=300H 时 300H 端口←AL 内容，301H 端口←AH 内容）。

### 12. 地址目标传送指令要点（第 26–29 页）

- LEA：取源操作数地址的偏移量送到目的操作数；源必须是存储单元，目的必须是除段寄存器之外的 16 位寄存器。
- LDS：从源存储单元取 4 字节地址指针，低地址 2 字节→目的寄存器（常用 SI），高地址 2 字节→DS；源必须是存储单元，目的必须是 16 位寄存器，不能用段寄存器。
- LES：与 LDS 基本相同，但段寄存器为 ES，目的操作数常用 DI。
- 原文勘误：例 3.39 注释中"前 2 字节内容为 0300H，SI←0300H"按指令与后文应为"DI←0300H"（原文笔误），本笔记例题中按 DI 表述。

### 13. 标志传送指令要点（第 30–32 页）

- LAHF：把标志寄存器的 SF、ZF、AF、PF 和 CF 传送到 AH 寄存器的相应位（操作示意图见图 3.15）。
- SAHF：把 AH 内容存入标志寄存器，与 LAHF 操作相反。
- PUSHF：把整个标志寄存器的内容推入堆栈，并使 SP←SP−2。
- POPF：把 SP 所指的一个字传送给标志寄存器 FLAGS，并使 SP←SP+2。

（"数据传送指令中除 SAHF 和 POPF 外，对标志位均没有影响"承接第 7 页表 3.3，见上文第 6 条。）

### 18. 标志位解释的原则（第 41 页）

对运算后的标志位（ZF、AF、CF、SF、PF、OF 等）如何解释，取决于编写的程序，由程序员决定，因为程序员知道参加运算的是何种类型的数据。同一组标志位对无符号数与带符号数的含义不同（CF 用于无符号数运算，OF 用于带符号数运算），只有结合数据类型的约定才能作出正确解释。

### 19. MUL 与 IMUL 的选用（第 53 页）

MUL 指令和 IMUL 指令的使用条件是由数的格式决定的。例如 (11111111b) × (11111111b)：当把它看作无符号数时应为 $255 \times 255 = 65025$（十进制），而把它看作带符号数时则为 $(-1) \times (-1) = 1$。指令本身不知道操作数是有符号数还是无符号数，关键是程序员要给数据赋予意义。这就是需要两条乘法指令 MUL 和 IMUL 的原因。

### 20. 补码知识串联（第 47 页）

NEG 的"取反加一"与补码的求法一致；该知识为 IMUL 和 IDIV 两类有符号运算指令的学习提供准备。

### 21. 带符号除法被除数的格式要求（第 58 页）

对于带符号数除法指令：字节操作时要求被除数为 16 位，字操作时要求被除数为 32 位。如果被除数不满足这个条件，不能简单地将高位置 0（那样会改变负数的值），而应该先用符号扩展指令（Sign Extension）CBW、CWD 将被除数转换成除法指令所要求的格式，再执行除法指令。

### 22. 除法错中断（第 56 页）

进行除法操作时，如果商超过了目标寄存器 AL 或 AX 所能存放数的范围，计算机会自动产生除法错中断，相当于执行了除数为 0 的运算，所得的商和余数都不确定。

## 解题方法汇总

### 方法 1：给段寄存器（DS）赋值的两段传送法

- **适用场景**：需要把数据段的段地址（汇编后为 16 位常数）送入 DS 等段寄存器时；立即数不能直接送入段寄存器。
- **已知条件**：数据段的段名（如 DATA），或已知的段地址常数。
- **计算步骤**：
  1. 第一步：执行 MOV AX，DATA——汇编时 DATA 被替换为具体段地址常数，AX ← DATA 段地址值；
  2. 第二步：执行 MOV DS，AX——DS ← AX，段寄存器从通用寄存器获得段地址。
  3. 结果：DS = DATA 的段地址值。
- **常见错误**：写成 MOV DS，DATA——立即数直接送段寄存器，非法；误以为段寄存器可以像通用寄存器一样直接用立即数赋值；漏掉中转寄存器这一步。

### 方法 2：获取符号地址的偏移地址（OFFSET 属性操作符与 LEA 指令）

- **适用场景**：程序需要取某个变量、表格首地址的偏移量（有效地址 EA）送入 16 位寄存器，而不是取该符号所在单元的内容。
- **已知条件**：符号（变量名/表格名）在数据段中的偏移量（可由变量定义顺序与各变量占用字节数累加求得）。
- **计算步骤**：
  1. 若用 OFFSET 操作符：第一步，依次累计前面各变量的字节数，得到目标符号的偏移地址（如 AREA1 占 2 字节、AREA2 占 3 字节，则 ARRAY 偏移 = 0000H+2+3 = 0005H）；第二步，执行 MOV DX，OFFSET ARRAY——OFFSET 使操作数取符号的地址（偏移量）而非内容；结果 DX = 0005H（16 位偏移量）。
  2. 若用 LEA 指令：写 `LEA 目的寄存器，符号地址`（如 `LEA BX，TABLE`），执行后目的寄存器 = 该符号的偏移地址；目的寄存器不能是段寄存器。
  3. 二者等价：`MOV BX，OFFSET TABLE` 与 `LEA BX，TABLE` 的执行结果完全相同，BX 都得到 TABLE 的偏移地址（OFFSET"取地址而非内容"的语义与 LEA"取有效地址"的功能一致）。
  4. 与内容传送区分：`MOV BX，[SI]` 取的是 SI 指向内存单元的内容，`LEA BX，[SI]` 取的是偏移地址本身（例 3.35 中分别为 1234H 与 1000H）。
- **常见错误**：漏写 OFFSET，写成 MOV DX，ARRAY——此时取的是 ARRAY 单元的内容 3100H 而非地址；用 MOV 直接送变量名（会取出内存内容而不是地址）；LEA 的目的操作数写成段寄存器（不允许）；把"取地址"与"取内容"混淆。

### 方法 3：判断 MOV/XCHG 等双操作数指令的合法性

- **适用场景**：判断一条给定的数据传送/交换指令是否合法，并说明原因。
- **已知条件**：指令中各操作数的类型（通用寄存器/段寄存器/存储器/立即数）及操作数位数（字节/字）。
- **计算步骤**：
  1. 第一步：检查目的操作数是否为 CS（是则非法）或立即数（是则非法）；
  2. 第二步：检查源与目的是否同为存储器单元（是则非法，8086 不允许）；
  3. 第三步：检查两个操作数是否至少有一个能表明字节或字（都不表明则非法）；
  4. 第四步：检查段寄存器使用（XCHG 中段寄存器不能作操作数；MOV 中 CS 不能作目的，DS、ES、SS 可经通用寄存器赋值）；
  5. 结果：全部通过则该指令合法，否则逐条列出违反的规则。
- **常见错误**：只背格式不背约束，漏查"两个存储单元"与"字节/字必须明确"两条；误以为立即数可作目的操作数；认为 POP CS、MOV CS,AX 合法（CS 不能作目的操作数）。

### 方法 4：手工模拟堆栈操作（PUSH/POP 序列后 SP 与栈内容）

- **适用场景**：给定 SS、SP 与各寄存器初值，依次执行若干 PUSH/POP 指令，求每一步及最终的 SP 值、堆栈各单元内容和寄存器值。
- **已知条件**：SS 段基址、SP 初值、被压入数据的值、指令序列。
- **计算步骤**（以例 3.29 为例：SS=2000H、SP=40H、AX=25FEH、BX=3120H，依次执行 PUSH BX、PUSH AX、POP BX）：
  1. 第一步（PUSH BX）：SP ← 40H − 2 = 3EH；把 BX=3120H 写入 2000:3EH 字单元（低字节 20H → 3EH 单元，高字节 31H → 3FH 单元）。执行后栈顶 = 3EH。
  2. 第二步（PUSH AX）：SP ← 3EH − 2 = 3CH；把 AX=25FEH 写入 2000:3CH 字单元（低字节 FEH → 3CH，高字节 25H → 3DH）。执行后栈顶 = 3CH。
  3. 第三步（POP BX）：BX ← (2000:3CH) = 25FEH；然后 SP ← 3CH + 2 = 3EH。执行后栈顶 = 3EH。
  4. 结果：SP=3EH，BX=25FEH（原 BX 值 3120H 被覆盖），AX 仍为 25FEH；3CH、3EH 单元内容不变（出栈不擦除数据，仅 SP 移动）。
- **常见错误**：PUSH 与 POP 中 SP 加减顺序颠倒（PUSH 必须先减 2 后写入，POP 必须先读出后加 2）；SP 一次变化按 1 字节计算（正确为 2）；误认为出栈会清除栈中数据。

### 方法 5：计算存储器操作数的物理地址并完成数据传送/交换

- **适用场景**：指令中操作数带位移量与寄存器分量，如 [BX+200H]、TABLE[BP][DI]，需确定实际访问的存储单元并说明执行结果。
- **已知条件**：所用段寄存器的值（默认段规则：含 BP 用 SS，不含 BP 一般用 DS）、基址/变址寄存器的值、位移量、存储单元原内容。
- **计算步骤**（以例 3.30 为例：AX=2000H，DS=3000H，BX=1800H，(31A00H)=1995H，指令 XCHG AX,[BX+200H]）：
  1. 第一步：确定段寄存器为 DS（操作数不含 BP），段基址 = DS × 16 = 30000H；
  2. 第二步：计算偏移地址 = BX + 200H = 1800H + 200H = 1A00H；
  3. 第三步：计算物理地址 = 段基址 + 偏移 = 30000H + 1A00H = 31A00H；
  4. 第四步：读出该单元内容 1995H，与 AX 交换：AX ← 1995H，(31A00H) ← 2000H。
- **常见错误**：物理地址 = 段址 × 16 + 偏移，误把段址与偏移直接相加（漏乘 16）；操作数含 BP 时仍按 DS 计算（含 BP 默认段为 SS）；十六进制加法进位错误（如 30000H+1800H+200H 算成 30A00H 或漏加 200H）。

### 方法 6：查表法（XLAT 实现代码转换）

- **适用场景**：把一种代码值转换为对应的另一种代码（如数字 0~9 转为 LED 七段码），且输入代码值连续、可直接作为表格位移量。
- **已知条件**：代码对照表（输入代码 → 输出代码）、表首地址。
- **计算步骤**（以例 3.31 求数字 5 的七段码为例）：
  1. 第一步：用 DB 伪指令建表，第 n 项存放在相对表首位移量为 n 的单元：TABLE DB 40H,79H,24H,30H,19H；DB 12H,02H,78H,00H,18H（数字 5 的七段码 12H 位于位移量 5 的单元）；
  2. 第二步：MOV SI，5——把数字 5 的值（位移量 5）送入 SI；
  3. 第三步：MOV BX，OFFSET TABLE——把表格首地址送入 BX；
  4. 第四步：MOV AL，[BX+SI]——基址变址寻址访问 TABLE+5 单元，AL ← 12H。
  5. 结果：数字 5 的七段码 = 12H。
- **常见错误**：取表首地址时漏写 OFFSET（写成 MOV BX,TABLE 取到的是表内第一个字节 40H 而非地址）；位移量与表项错位（数字 5 应给 SI 赋值 5，误赋值 4 或 6）；表格用 DB 建时每项占 1 字节，位移量按字节计而误按字计。

### 方法 7：I/O 端口地址的寻址方式选择

- **适用场景**：编写或分析 IN/OUT 指令，需要确定端口地址的给出形式。
- **已知条件**：要访问的端口号数值。
- **计算步骤**：
  1. 判断端口号大小：若端口号 ≤ FFH（十进制 ≤ 255），进入第 2 步；若端口号 > FFH，跳到第 3 步。
  2. 端口号可直接写在指令中，用格式① `IN/OUT 累加器，端口号`，例如 0F1H 端口读入：`IN AL，0F1H`。
  3. 端口号 > FFH 时必须先把端口号送入 DX（如 `MOV DX，310H`），再用格式② `IN/OUT 累加器，DX` 执行。
  4. 按数据宽度选择累加器：1 字节用 AL，1 个字用 AX（16 位端口读入时 AL←低地址端口、AH←高地址端口）。
  5. 结果：读出或写出对应端口的数据。
- **常见错误**：端口号大于 FFH 仍直接写在指令中（指令编码只给 8 位立即数，无法表示）；DX 未赋值就执行 IN/OUT；字节操作误用 AX 或字操作误用 AL。

### 方法 8：二进制加法竖式与全部标志位的判定（ADD/ADC 执行后的标志位分析）

- **适用场景**：已知参与 ADD/ADC 的两个操作数，分析（或预测）执行后 CF、OF、AF、SF、ZF、PF 六个标志位的值。
- **已知条件**：两个操作数的二进制值（8 位或 16 位）及操作前 CF（ADC 时）。
- **计算步骤**（以例 3.41 为例：5EH + 3CH）：
  1. 第一步：把两个操作数写成同位数二进制：5EH = 0101 1110B，3CH = 0011 1100B。
  2. 第二步：按二进制逐位相加得结果（ADD 为 目的+源；ADC 为 目的+源+CF），从最低位 b0 到最高位 b7 记录每位和与进位：b0: 0+0=0 进位 0；b1: 1+0=1 进位 0；b2: 1+1=0 进位 1；b3: 1+1+1=1 进位 1；b4: 1+1+1=1 进位 1；b5: 0+1+1=0 进位 1；b6: 1+0+1=0 进位 1；b7: 0+0+1=1 进位 0。得结果 1001 1010B = 9AH。
  3. 第三步：判断 ZF：结果 = 0 则 ZF=1，否则 ZF=0（9AH ≠ 0 → ZF=0）。
  4. 第四步：判断 SF：结果最高位 = 1 则 SF=1（D7=1 → SF=1）。
  5. 第五步：判断 PF：结果中 1 的个数为偶数则 PF=1，为奇数则 PF=0（9AH 含 4 个 1 → PF=1）。
  6. 第六步：判断 AF：低 4 位向高 4 位有进位则 AF=1（b3 向 b4 的进位为 1 → AF=1）。
  7. 第七步：判断 CF：最高位产生进位（超出 8/16 位）则 CF=1（b7 向前进位 0 → CF=0）。
  8. 第八步：判断 OF：次高位向最高位的进位与最高位向外的进位不同（一个有进位一个无进位）则 OF=1，相同则 OF=0（b6→b7 有进位 1、b7→外无进位 0，相异 → OF=1）。
  9. 第九步：解释：CF 按无符号数解释，OF 按有符号数（补码）解释。
- **常见错误**：把 b7 向前的进位同时当作 CF 和 OF；把 OF 误当成"最高位有进位"；判断 OF 时不比较次高位的进位而只看结果是否超出范围；把 AF（半进位）与 CF 混淆；PF 数错结果中 1 的个数。

### 方法 9：CMP 比较大小 + 条件转移实现分支

- **适用场景**：需要比较两个数的大小、又不允许破坏原操作数，并依据比较结果跳转。
- **已知条件**：两个待比较的操作数（寄存器/立即数/内存）。
- **计算步骤**：
  1. 执行 `CMP 目的，源`：内部完成目的 − 源，只设置标志位，不写回结果；
  2. 紧接着执行条件转移指令，根据标志位（如 ZF、CF、SF、OF）判断相等、无符号大小或有符号大小并跳转。
- **常见错误**：期望 CMP 把差值存回目的操作数；在 CMP 与条件转移之间插入其他会改变标志位的指令，破坏判据。

### 方法 10：无符号乘法 MUL 求积并判定 CF/OF

- **适用场景**：已知 AL 或 AX 与源操作数的值，求 MUL 指令执行后的乘积及其 CF、OF 值。
- **已知条件**：被乘数（累加器内容）、乘数（源操作数）及其位宽（字节或字）。
- **计算步骤**（以例 3.57 为例：AL=55H，BL=14H）：
  1. 第一步：确定乘法类型：源为字节则积存 AX（16 位），源为字则积存 DX:AX（32 位）。
  2. 第二步：把两个操作数换算为十进制：55H=85，14H=20。
  3. 第三步：十进制相乘：85 × 20 = 1700。
  4. 第四步：换算为十六进制并放入目标寄存器：1700 = 06A4H → AX=06A4H（AH=06H，AL=A4H）。
  5. 第五步：判定 CF/OF：高半部分（字节乘的 AH、字乘的 DX）是否非零。AH=06H ≠ 0 → CF=1、OF=1；若高半部分为 0 则 CF=0、OF=0。
- **常见错误**：字节乘法只写 AL 而忽略 AH；源操作数误用立即数；把 MUL 的"高半部分非零"与 IMUL 的"非全 0 或全 1"判据混用。

### 方法 11：有符号乘法 IMUL 求积并判定 CF/OF

- **适用场景**：操作数为带符号数（补码表示）时求乘积并判定 CF/OF。
- **已知条件**：累加器与源操作数的带符号数值。
- **计算步骤**（以例 3.59 为例：AL=−28，BL=59）：
  1. 第一步：按十进制带符号数相乘：(−28) × 59 = −1652。
  2. 第二步：把乘积写成目标宽度补码：−1652 的 16 位补码为 F98CH → AX=F98CH。
  3. 第三步：判定 CF/OF：检查高半部分 AH=F9H=1111 1001B，既非全 0 也非全 1 → CF=1、OF=1；若高半部分为全 0 或全 1，则 CF=0、OF=0。
- **常见错误**：把补码结果当作无符号数读出；判据用"是否非零"代替"是否非全 0 且非全 1"；忘记给乘积赋予正确符号。

### 方法 12：无符号除法 DIV 的被除数准备与商、余数定位

- **适用场景**：执行 DIV 指令前准备被除数，以及执行后读取商和余数。
- **已知条件**：被除数、除数的位宽（字节除法或字除法）。
- **计算步骤**：
  1. 字节除法：被除数放 AX（8 位被除数则送入 AL，并把 AH 清 0）；执行后商在 AL、余数在 AH。
  2. 字除法：被除数放 DX:AX（16 位被除数则送入 AX，并把 DX 清 0）；执行后商在 AX、余数在 DX。
  3. 确认商和余数按无符号数解释。
- **常见错误**：忘记清 AH 或 DX，使被除数高位残留旧值；商与余数的寄存器位置记反；对带符号数误用高位清 0 的方式准备被除数。

### 方法 13：有符号除法 IDIV 的符号扩展与符号规则

- **适用场景**：被除数是带符号数且位宽不足（8 位被除数做字节除法、16 位被除数做字除法）时。
- **已知条件**：被除数的补码值（8 位在 AL、16 位在 AX）。
- **计算步骤**（以例 3.62 为例：求 −38/3 的商和余数）：
  1. 第一步：字节除法前执行 CBW：AL 的 D7=0 则 AH=00H，D7=1 则 AH=FFH，得到 16 位被除数 AX。
  2. 第二步：字除法前执行 CWD：AX 的 D15=0 则 DX=0000H，D15=1 则 DX=FFFFH，得到 32 位被除数 DX:AX。
  3. 第三步：执行 IDIV 源：商存入 AL（字节除）或 AX（字除），余数存入 AH 或 DX。
  4. 第四步：按带符号数读出商和余数；余数的符号必须与被除数相同（如 −38÷3 商 −12、余 −2）。
- **常见错误**：对带符号被除数把高位置 0（正数无碍、负数出错）；忘记执行 CBW/CWD 直接 IDIV；余数符号规则记反（余数应与被除数同号）。

### 方法 14：除法溢出（除法错中断）的判断

- **适用场景**：判断一次 DIV/IDIV 除法能否正常完成，商是否会溢出。
- **已知条件**：被除数、除数的值及目标寄存器（AL 或 AX）的表示范围。
- **计算步骤**（以例 3.61 为例：7A86H ÷ 04H）：
  1. 第一步：算出真正的商（7A86H ÷ 04H 的商为 1EA1H）。
  2. 第二步：与目标寄存器上限比较：字节除法商须 ≤ FFH（无符号）；1EA1H > FFH，超出 AL 所能存放的范围。
  3. 第三步：结论：商超范围时 CPU 自动产生除法错中断（相当于除数为 0 的运算），商和余数均不确定。
- **常见错误**：只把除数为 0 当作出错条件，忽略"商超出目标寄存器范围"这一溢出情形；把溢出后的结果当作有效商继续使用。

### 方法 15：十进制负数与补码的相互转换

- **适用场景**：把负数十进制数写成二进制补码参与运算，或把补码形式的运算结果读回十进制。
- **已知条件**：负数的绝对值及其目标位宽（8 位或 16 位）。
- **计算步骤**（以 −38 与 F98CH 为例）：
  1. 第一步：求绝对值二进制：38 = 0010 0110B。
  2. 第二步：逐位取反：1101 1001B。
  3. 第三步：最低位加 1：1101 1010B，即 −38 的 8 位补码。
  4. 第四步：反向换算：最高位为 1 的补码，其值 = −(2^n − 码值)，如 F98CH 的值为 −(10000H − F98CH) = −0674H = −1652。
- **常见错误**：只取反不加 1；取反时把符号位排除在外；反向换算时忘记加负号。

### 例题 1：例 3.24 —— 字符立即数传送（MOV AL,'B'）

**题干**：
MOV AL，‘B’ ；AL←将字符 B 的 ASCII 码 (42H)

**解**：

第 1 步：单引号括起的 'B' 是字符常数，汇编程序将其转换为字符 B 的 ASCII 码，即 42H。
第 2 步：指令等效为 MOV AL,42H，把立即数 42H 送入 AL；字节操作由 8 位寄存器 AL 明确。
第 3 步：结果 AL = 42H。

**答案**：执行后 AL = 42H，即字符 B 的 ASCII 码。

**验证**：字符 B 的 ASCII 码为 42H，与指令注释一致；操作数位数由 AL 明确，指令合法。

### 例题 2：例 3.25 —— 给段寄存器 DS 赋值（MOV AX,DATA / MOV DS,AX）

**题干**：
MOV AX，DATA
MOV DS，AX
DATA 表示数据段的段址，编译后是一个 16 位常数，不能被直接送进 DS，需要先送进另一个数据寄存器（如 AX），再传到 DS 中，这是对段寄存器的保护。

**解**：

第 1 步：执行 MOV AX，DATA。DATA 是段名，汇编时被替换为具体的段地址常数；AX ← DATA 段地址值。
第 2 步：执行 MOV DS，AX。DS ← AX，DS 获得与 AX 相同的段地址值。
第 3 步：两条指令完成后，DS 指向 DATA 段，程序可用 DS 作为默认数据段访问 DATA 段中的变量。

**答案**：执行后 DS = DATA 所代表的段地址值（经 AX 中转）。

**验证**：若直接写 MOV DS，DATA 属于立即数送段寄存器，非法。本题经 AX 中转，DS 最终值等于 DATA 段地址值，符合"立即数不能直接送段寄存器、段寄存器经通用寄存器赋值"的规则。

### 例题 3：例 3.26 —— 用 OFFSET 取偏移地址（MOV DX,OFFSET ARRAY）

**题干**：
MOV DX，OFFSET ARRAY
将 ARRAY 的偏移地址送到 DX。其中，OFFSET 为属性操作符，表示应把其后的符号的地址（而不是内容）作为操作数。
若 ARRAY 的值如图 3.13，则指令执行后，符号地址 ARRAY 的偏移量 0005H 被送到了 DX 中。

**解**：

第 1 步：确定 ARRAY 的偏移地址。由图 3.13：AREA1 占 2 字节（0000H、0001H），AREA2 占 3 字节（0002H～0004H），故 ARRAY 从 0005H 开始，偏移地址 = 0000H + 2 + 3 = 0005H。
第 2 步：OFFSET 操作符使源操作数取 ARRAY 的偏移量（0005H），而不是 ARRAY 单元的内容（3100H）。
第 3 步：DX ← 0005H。

**答案**：执行后 DX = 0005H（ARRAY 的偏移地址）。

**验证**：0000H + 2 字节 + 3 字节 = 0005H，与图 3.13 中 ARRAY 的偏移地址标注一致；DX 得到的是地址 0005H 而非内容 3100H，符合 OFFSET 的定义。

### 例题 4：例 3.27 —— 变量单元之间的字节传送（MOV AL,AREA1 / MOV AREA2,AL）

**题干**：
设 AREA1 和 AREA2 的值如图 3.13，说明以下指令功能：
MOV AL，AREA1 ；AL←AREA1 中的内容 14H
MOV AREA2，AL ；0002H 单元←14H
（复习：这是什么寻址方式？）

**解**：

第 1 步：执行 MOV AL，AREA1。AREA1 的偏移地址为 0000H（图 3.13），该字节单元内容为 14H（AREA1 DB 14H,3BH 的第一字节）；AL ← 14H。
第 2 步：执行 MOV AREA2，AL。AREA2 的偏移地址为 0002H（图 3.13）；把 AL 的内容 14H 写入 0002H 字节单元，即 (0002H 单元) ← 14H。
第 3 步：执行后 AL = 14H，0002H 单元 = 14H。AREA2 原值 00H（3 DUP(0) 的第一个单元）被 14H 覆盖。

**答案**：执行后 AL = 14H，(0002H 单元) = 14H。寻址方式为直接寻址（操作数符号的偏移量直接写在指令中）。

**验证**：AREA1 单元原值 14H 与 AL 的结果一致；AREA2 起始单元 0002H 原值 00H，执行后被 AL 中的 14H 覆盖，与"0002H 单元←14H"的注释一致。

### 例题 5：例 3.28 —— 基址变址寻址的字传送（MOV AX,TABLE[BP][DI]）

**题干**：
MOV AX，TABLE［BP］［DI］
；将地址为 16×SS+BP+DI+TABLE 的字单元中的内容送进 AX。

**解**：

第 1 步：确定操作数大小：目的为 AX（16 位），操作数按字处理。
第 2 步：确定段寄存器：操作数中含 BP，默认段寄存器为 SS，段基址 = 16 × SS。
第 3 步：计算物理地址 = $16 \times SS + BP + DI + TABLE$（TABLE 为 16 位位移量，BP 为基址、DI 为变址）。
第 4 步：从该物理地址的字单元读出内容送入 AX（低字节来自低地址单元，高字节来自高地址单元）。

**答案**：执行后 AX = 地址为 16×SS+BP+DI+TABLE 的字单元的内容。

**验证**：与指令注释完全一致；寻址方式为基址变址寻址，含 BP 故默认 SS 段，与物理地址公式一致。

### 例题 6：例 3.29 —— 堆栈操作序列（PUSH BX / PUSH AX / POP BX）

**题干**：
设 SS=2000H，SP=40H，AX=25FEH，BX=3120H。
依次执行指令：
PUSH BX
PUSH AX
POP BX
求堆栈中的数据和 SP 的变化情况（原图 3.14）。

**解**：

第 1 步（初始状态）：SS=2000H，SP=40H，AX=25FEH，BX=3120H。栈顶由 2000:0040 指示。
第 2 步（执行 PUSH BX）：先 SP ← 40H − 2 = 3EH；再把 BX 的内容 3120H 写入 SP 指示的字单元 2000:3EH：低字节 20H 写入 3EH 单元、高字节 31H 写入 3FH 单元。执行后 SP=3EH，栈顶单元内容为 3120H。
第 3 步（执行 PUSH AX）：先 SP ← 3EH − 2 = 3CH；再把 AX 的内容 25FEH 写入 2000:3CH：低字节 FEH 写入 3CH 单元、高字节 25H 写入 3DH 单元。执行后 SP=3CH，栈顶单元内容为 25FEH。
第 4 步（执行 POP BX）：先把 SP 指向的字单元 2000:3CH 的内容 25FEH 送到 BX，BX ← 25FEH；再 SP ← 3CH + 2 = 3EH。执行后 SP=3EH。
第 5 步（最终结果）：SP=3EH；BX=25FEH（原 BX 值 3120H 被覆盖，BX 等于原 AX 值）；AX=25FEH 不变。存储器 2000:3CH 处仍保留 25FEH、2000:3EH 处仍保留 3120H（出栈只移动 SP，不擦除数据）。

**答案**：最终 SP=3EH，BX=25FEH，AX=25FEH；栈中 3EH 单元为 3120H（原 BX 值）、3CH 单元为 25FEH（原 AX 值，已被弹出）。

**验证**：POP BX 弹出的值 25FEH 与原始数据中最后压入的 AX=25FEH 一致，符合堆栈后进先出规则；SP 变化序列 40H→3EH→3CH→3EH，每次变化 2，与"每个字占 2 字节、PUSH 先减 2、POP 后加 2"的规则一致。

### 例题 7：例 3.30 —— XCHG 寄存器与存储器交换（XCHG AX,[BX+200H]）

**题干**：
设 AX=2000H，DS=3000H，BX=1800H，(31A00H)=1995H，执行指令
XCHG AX，［BX+200H］

**解**：

第 1 步：确定源操作数的物理地址。操作数含 BX 不含 BP，段寄存器为 DS。
第 2 步：段基址 = DS × 16 = 3000H × 16 = 30000H。
第 3 步：偏移地址 = BX + 200H = 1800H + 200H = 1A00H。
第 4 步：物理地址 = 30000H + 1A00H = 31A00H，与已知条件 (31A00H)=1995H 对应。
第 5 步：执行 XCHG：AX 与 31A00H 字单元内容互换。AX ← 1995H；(31A00H) ← 2000H。

**答案**：指令执行后，AX=1995H，(31A00H)=2000H。

**验证**：原 AX=2000H 现存放于 31A00H 单元，原 (31A00H)=1995H 现存放于 AX，两个原始数据正好互换位置，与 XCHG 的功能一致。

### 例题 8：例 3.31 —— XLAT 查表求数字 5 的七段码

**题干**：
表 3.4 是十进制数字 0~9 的 LED 七段码对照表，试用 XLAT 指令求数字 5 的七段码值。
（表 3.4 数据：数字 0~9 对应七段码 40H、79H、24H、30H、19H、12H、02H、78H、00H、18H）

**解**：

第 1 步：用 DB 伪指令建表，表格起始地址为 TABLE，数字 0~9 的七段码存放在相对于 TABLE 的位移量为 0~9 的单元中：
TABLE DB 40H，79H，24H，30H，19H ；七段码表格
DB 12H，02H，78H，00H，18H
建表后各单元内容：TABLE+0=40H（数字 0）、TABLE+1=79H（数字 1）、TABLE+2=24H（数字 2）、TABLE+3=30H（数字 3）、TABLE+4=19H（数字 4）、TABLE+5=12H（数字 5）、TABLE+6=02H（数字 6）、TABLE+7=78H（数字 7）、TABLE+8=00H（数字 8）、TABLE+9=18H（数字 9）。

第 3 步：MOV BX，OFFSET TABLE——把表格首地址送入 BX。

### 例题 9：例 3.32 —— 用 IN 指令从输入端口读取数据

**题干**：用 IN 指令从输入端口读取数据的例子，指令序列为：
```
IN    AL，0F1H
IN    AX，80H
MOV   DX，310H
IN    AL，DX
```

**解**：

第 1 步：执行 `IN AL，0F1H`。端口地址 0F1H ≤ FFH，可直接写在指令中（格式①），数据宽度为 1 字节。结果：AL←从 F1H 端口读入 1 字节。

第 2 步：执行 `IN AX，80H`。端口地址 80H ≤ FFH，格式①，数据宽度为 1 个字。结果：AL←80H 端口内容，AH←81H 端口内容（16 位端口连续占用 80H、81H 两个端口号，低地址 80H 端口内容进 AL，高地址 81H 端口内容进 AH）。

第 3 步：执行 `MOV DX，310H`。端口地址 310H > FFH，不能直接写在 IN 指令里，先送 DX。结果：DX=310H。

第 4 步：执行 `IN AL，DX`。格式②，从 DX 指示的端口读 1 字节。结果：AL←310H 端口内容。

**答案**：AL 依次得到 0F1H 端口、80H 端口（IN AX 时 AL=80H 端口内容）、310H 端口的内容；AH 得到 81H 端口内容。验证：0F1H、80H 均 ≤ FFH 用直接寻址，310H > FFH 用 DX 间接寻址，与 IN 指令端口寻址规则一致。

### 例题 10：例 3.33 —— IN 指令用符号表示端口地址

**题干**：IN 指令中也可用符号表示地址。例如，要求从一个模/数（A/D）转换器读入 1 字节数字量到 AL 中：
```
ATOD  EQU   54H
IN    AL，ATOD
```
其中 A/D 转换器端口地址为 54H。复习：这是什么寻址方式？

**解**：

第 1 步：伪指令 `ATOD EQU 54H` 定义符号 ATOD 等于常数 54H，即 A/D 转换器端口地址的符号名。

第 2 步：执行 `IN AL，ATOD`。汇编时符号 ATOD 被替换为其值 54H，等效于 `IN AL，54H`。54H ≤ FFH，属格式①直接端口寻址。结果：将 54H 端口的内容读入 AL 中。

第 3 步：回答复习问题：端口地址 54H 作为立即数直接写在指令中，属于立即数寻址（直接端口寻址）；若端口地址在 DX 中（格式②），则属于寄存器间接寻址。

**答案**：AL = 54H 端口的内容（1 字节数字量）。验证：符号 ATOD 的值为 54H 且在 00~FFH 范围内，可直接寻址，符合规则。

### 例题 11：例 3.34 —— 用 OUT 指令对输出端口进行操作

**题干**：用 OUT 指令对输出端口进行操作的例子，指令序列为：
```
OUT   85H，AL
MOV   DX，0FF4H
OUT   DX，AL
MOV   DX，300H
OUT   DX，AX
```

**解**：

第 1 步：执行 `OUT 85H，AL`。端口地址 85H ≤ FFH，格式①，8 位端口。结果：85H 端口←AL 内容。

第 2 步：执行 `MOV DX，0FF4H`。结果：DX 指向端口 0FF4H。

第 3 步：执行 `OUT DX，AL`。格式②。结果：FF4H 端口←AL 内容。

第 4 步：执行 `MOV DX，300H`。结果：DX 指向 16 位端口 300H。

第 5 步：执行 `OUT DX，AX`。格式②，16 位端口输出。结果：300H 端口←AL 内容，301H 端口←AH 内容。

**答案**：85H 端口得到 AL；FF4H 端口得到 AL；300H 端口得到 AL、301H 端口得到 AH。验证：85H ≤ FFH 用直接寻址；0FF4H、300H > FFH 均先送 DX 再输出，符合 OUT 端口寻址规则；AX 为字输出时低地址端口 300H 收 AL、相邻高地址端口 301H 收 AH。

### 例题 12：例 3.35 —— LEA 与 MOV 的对比

**题干**：设 SI=1000H，DS=5000H，(51000H)=1234H，指令执行结果如下：
```
LEA   BX，[SI]
MOV   BX，[SI]
```

**解**：

第 1 步：分析源操作数。SI=1000H 为偏移地址，DS=5000H 为段地址，物理地址 = 16×DS+SI = 16×5000H+1000H = 50000H+1000H = 51000H，该单元内容为 1234H。

第 2 步：执行 `LEA BX，[SI]`。LEA 取的是源存储单元的偏移地址（有效地址），即 SI 的值。结果：[SI] 的偏移地址为 1000H，BX←1000H。

第 3 步：执行 `MOV BX，[SI]`。MOV 取的是内存单元的内容。偏移地址为 1000H 的单元内容为 1234H。结果：指令执行后，BX←1234H。

**答案**：`LEA BX，[SI]` 执行后 BX=1000H（地址）；`MOV BX，[SI]` 执行后 BX=1234H（内容）。验证：物理地址 51000H 的计算结果与题设 (51000H)=1234H 一致，说明 MOV 读出的正是该单元内容，而 LEA 只取偏移量 1000H 本身。

### 例题 13：例 3.36 —— LEA 与 MOV+OFFSET 的等价性

**题干**：下面两条指令是等价的，它们都取 TABLE 的偏移地址，送到 BX 中：
```
LEA   BX，TABLE
MOV   BX，OFFSET TABLE
```

**解**：

第 1 步：执行 `LEA BX，TABLE`。LEA 取源操作数 TABLE 的偏移地址送目的寄存器。结果：BX←TABLE 的偏移地址。

第 2 步：执行 `MOV BX，OFFSET TABLE`。OFFSET 为属性操作符，作用是把其后符号的地址（而不是内容）作为操作数。结果：BX←TABLE 的偏移地址。

第 3 步：对比。两条指令的操作数形式不同（LEA 的源直接写符号；MOV 的源用 OFFSET 操作符修饰），但执行结果完全相同。

**答案**：两条指令执行后 BX 都等于 TABLE 的偏移地址，二者等价。验证：OFFSET 操作符"取地址而非内容"的语义与 LEA"取有效地址"的功能一致。

### 例题 16：例 3.40 —— 加法指令实例（ADD/ADC 用法列举）

**题干**：列举上述两加法指令的实例，说明其用法：
```
ADD        AL，18H
ADC        BL，CL
ADC        AX，DX
ADD        AL，COST[BX]
ADD        COST[BX]，BL
```
它们影响标志位：CF、OF、PF、SF、ZF 和 AF。

**解**：

第 1 步：`ADD AL，18H`。字节加法，源为立即数 18H。结果：AL←AL+18H。

第 2 步：`ADC BL，CL`。字节加法，源为寄存器 CL，并加当前进位标志。结果：BL←BL+CL+CF。

第 3 步：`ADC AX，DX`。字加法。结果：AX←AX+DX+CF。

第 4 步：`ADD AL，COST[BX]`。目的为寄存器 AL，源为存储字节，物理地址 = DS:(COST+BX)。结果：将 AL 内容和物理地址 = DS:(COST+BX) 的存储字节相加，结果送到 AL 中。

第 5 步：`ADD COST[BX]，BL`。目的为存储字节（物理地址 = DS:(COST+BX)），源为寄存器 BL。结果：将 BL 与物理地址 = DS:(COST+BX) 的存储字节相加，结果留在该存储单元。

第 6 步：注意操作数规则：各指令源、目的操作数均不同时为存储器（寄存器与存储器搭配或寄存器与立即数搭配），类型一致（AL/BL/COST[BX] 为字节，AX/DX 为字）。

**答案**：5 条指令分别演示了 ADD/ADC 的立即数、寄存器、存储器操作数的各种合法组合。验证：存储器操作数 COST[BX] 的物理地址均为 DS:(COST+BX)，与 8086 存储器寻址规则一致；每条指令执行后 CF、OF、PF、SF、ZF、AF 六个标志位均被影响。

### 例题 17：例 3.41 —— 加法运算及标志位影响分析（第 40–41 页，跨页）

**题干**：
试用加法指令对两个 8 位 16 进制数 5EH 和 3CH 求和，分析指令执行后对标志位的影响。
程序如下：
```
MOV  AL, 5EH      ；AL=5EH (94)
MOV  BL, 3CH      ；BL=3CH (60)
ADD  AL, BL       ；结果 AL=9AH
```
相加过程的算式表示（第 41 页图片：二进制竖式）。

**解**：

第 1 步：执行 MOV AL，5EH。结果：AL=5EH（十进制 94）。

第 2 步：执行 MOV BL，3CH。结果：BL=3CH（十进制 60）。

第 3 步：执行 ADD AL，BL，即计算 5EH+3CH。把两个操作数写成 8 位二进制：5EH = 0101 1110B，3CH = 0011 1100B。

第 4 步：从最低位 b0 到最高位 b7 逐位相加，记录每位和与进位：
- b0：0 + 0 = 0，进位 0
- b1：1 + 0 = 1，进位 0
- b2：1 + 1 = 0，进位 1
- b3：1 + 1 + 1 = 1，进位 1
- b4：1 + 1 + 1 = 1，进位 1
- b5：0 + 1 + 1 = 0，进位 1
- b6：1 + 0 + 1 = 0，进位 1
- b7：0 + 0 + 1 = 1，进位 0

第 5 步：写出结果：0101 1110B + 0011 1100B = 1001 1010B = 9AH，与程序执行结果 AL=9AH 一致。
也可按十六进制逐位验算（算式分解）：E 位 + C 位 = 14+12 = 26 = 1AH，即本位 A、向高位进位 1（低 4 位向高 4 位有进位）；高 4 位：5 + 3 + 低 4 位来的进位 1 = 5+3+1 = 9，即 1001B，无最高位向外进位。结果：AL=9AH（十进制 154）。

第 6 步：判 ZF。结果 9AH 不为 0 → ZF=0。

第 7 步：判 SF。结果最高位 D7 = 1 → SF=1。

第 8 步：判 PF。结果 1001 1010B 中 1 的个数为 4（b7、b4、b3、b1），为偶数 → PF=1。

第 9 步：判 AF。b3 向 b4 的进位为 1（E+C=1AH，本位 A、进位 1）→ AF=1。

第 10 步：判 CF。b7 向更高位的进位为 0，即最高位向前无进位 → CF=0。

第 11 步：判 OF。次高位（b6）向最高位（b7）有进位（为 1），最高位向前无进位（为 0），两者相异 → OF = 1 ⊕ 0 = 1。

第 12 步：对这些标志如何解释，取决于编写的程序（程序员决定），因为程序员知道参加运算的是何种类型的数据。

**答案**：两数之和为 9AH（十进制 154）；标志位 ZF=0，AF=1，CF=0，SF=1，PF=1，OF=1。按无符号数解释，94+60=154 正确（CF=0）；按有符号数解释，+94 与 +60 之和超出 +127，产生溢出（OF=1）。

**验证**（用原始数据验证）：
- 十进制验证和：5EH = 94，3CH = 60，94 + 60 = 154 = 9AH，与结果一致。
- 无符号解释：154 ≤ 255，无进位，CF=0 正确。
- 有符号解释：94 与 60 均为正，之和 154 超出 8 位带符号数上限 +127，发生溢出，OF=1 正确；结果 9AH 若按带符号解释为 9AH − 100H = −102，符号出错，恰好与 OF=1 一致。
- AF：E+C 的二进制 1110+1100 = 11010，第 4 位向第 5 位进位 1，与 AF=1 一致。
- SF：结果 D7=1 → SF=1，与 9AH=1001 1010B 最高位相符。
- PF：9AH 中 1 的个数 4（偶）→ PF=1，正确。
- ZF：结果非零 → ZF=0，正确。

### 例题 18：例 3.42 —— INC 指令的例子（第 43 页）

**题干**：
```
INC  BL      ；BL寄存器中内容增1
INC  CX      ；CX寄存器中内容增1
```

**解**：

第 1 步：`INC BL` 把 BL 寄存器中内容加 1，结果写回 BL，即 BL ← BL + 1。

第 2 步：`INC CX` 把 CX 寄存器中内容加 1，结果写回 CX，即 CX ← CX + 1。

第 3 步：指令中只有一个操作数；该两条指令目的操作数均为寄存器，无需 PTR 说明宽度；执行后影响 AF、OF、PF、SF、ZF，CF 不受影响。

**答案**：BL 与 CX 内容各增 1；CF 保持不变。

### 例题 19：例 3.43 —— INC 指令内存操作数的例子（第 43 页）

**题干**：
指令中只有一个操作数，如果是内存单元，则要用 PTR 操作符说明是字还是字节。

```
INC  BYTE PTR[BX]    ；内存字节单元内容增1
INC  WORD PTR[BX]    ；内存字单元内容增1
```

**解**：

第 1 步：`INC BYTE PTR[BX]` 中 BYTE PTR 说明 [BX] 指向的内存单元按字节处理，该字节单元内容加 1 后写回原单元。

第 2 步：`INC WORD PTR[BX]` 中 WORD PTR 说明 [BX] 指向的内存单元按字处理，该字单元内容加 1 后写回原单元。

第 3 步：没有 PTR 说明时汇编程序无法确定内存操作数宽度，因此内存操作数必须显式给出 BYTE PTR 或 WORD PTR。

**答案**：内存字节/字单元内容分别增 1。

### 例题 20：例 3.48 —— SUB 指令的例子（第 44 页）

**题干**：
```
SUB  AX, BX       ；AX←AX-BX
SUB  DX, 1850H    ；DX←DX-1850H
SUB  BL, [BX]     ；BL中内容减去物理地址=DS:BX
                  ；处的字节，结果存入BL
```

**解**：

第 1 步：`SUB AX,BX` 执行 AX ← AX − BX，注意顺序是目的（AX）减源（BX），结果写回 AX。

第 2 步：`SUB DX,1850H` 执行 DX ← DX − 1850H，源操作数为立即数 1850H。

第 3 步：`SUB BL,[BX]` 执行 BL ← BL − [BX]，[BX] 指物理地址 = DS:BX 处的字节（内存操作数），BL 中的内容减去该字节内容，结果存入 BL。

**答案**：三条指令分别完成寄存器减寄存器、寄存器减立即数、寄存器减内存字节三种形式，结果均回送目的操作数。

### 例题 21：例 3.49 —— SBB 指令的例子（第 45 页）

**题干**：
```
SBB  AL, CL    ；AL←AL – CL - CF
```
SBB 主要用于多字节减法中。

**解**：

第 1 步：`SBB AL,CL` 执行 AL ← AL − CL − CF：先算 AL − CL，再减去当前进位（借位）标志 CF 的值，结果写回 AL。

第 2 步：CF 的参与使低位部分减法产生的借位被纳入高位部分的减法运算，故 SBB 用于多字节减法中高位字节（或高位字）的相减。

**答案**：AL ← AL − CL − CF，实现带借位减法，配合 SUB 完成多字节减法。

### 例题 23：例 3.51 —— NEG 指令的例子（第 47 页）

**题干**：
```
NEG  AX                 ；将AX中的数取负(改变数的符号位)
NEG  BYTE PTR[BX]       ；对数据段中位于[BX]偏置处的字节取负
```
（课件批注：为什么？补充补码知识——和 IMUL 和 IDIV 串联起来）

**解**：

第 1 步：`NEG AX` 执行 AX ← 0 − AX，即将 AX 中的数取负，结果写回 AX；运算等价于对 AX 逐位取反后在最低位加 1（取反加一），因此数的符号位被改变。

第 2 步：`NEG BYTE PTR[BX]` 对数据段（默认段寄存器 DS）中位于 [BX] 偏置处的字节取负，即该字节单元内容 = 0 − 原内容，结果写回原单元。

第 3 步：取反加一是补码的求法，掌握该运算为后续 IMUL（有符号乘法）和 IDIV（有符号除法）的学习提供基础。

**答案**：AX 中的数改变符号；DS:[BX] 字节单元内容改变符号。

### 例题 24：例 3.52 —— CMP 指令的例子（第 48 页）

**题干**：
```
CMP  AL, 80H     ；AL与80H作比较
CMP  BX, DATA1   ；BX与数据段中偏移量
                 ；为DATA1处的字比较
```
比较指令主要用在希望比较两个数的大小，而又不破坏原操作数的场合；一般紧跟条件转移指令实现跳转。

**解**：

第 1 步：`CMP AL,80H` 内部执行 AL − 80H 的减法，结果不回送 AL，只按结果设置标志位；AL 与立即数 80H 的内容在比较后均保持不变。

第 2 步：`CMP BX,DATA1` 内部执行 BX − (DS:DATA1 处字) 的减法，结果不回送，只设置标志位；DATA1 为数据段中的偏移量。

第 3 步：随后紧跟条件转移指令，依据标志位（如 ZF=1 表示相等）决定跳转去向，实现两个数大小的比较与分支。

**答案**：两条 CMP 完成 AL 与 80H、BX 与内存字的大小比较，操作数不变，标志位供条件转移使用。

### 例题 25：例 3.56 —— MUL 指令的例子（第 50 页）

**题干**：
```
MUL  DL                ；AX←AL*DL
MUL  CX                ；(DX，AX)←AX*CX
MUL  BYTE PTR [SI]     ；AX←AL*(内存中某字节)，
                       ；BYTE说明字节乘法
MUL  WORD PTR [BX]     ；(DX，AX)←AX*(内存
                       ；中某字)，WORD说明字乘法
```

**解**：

第 1 步：`MUL DL` 中源为 8 位寄存器 DL，执行字节乘法：AX ← AL × DL，16 位积存 AX。

第 2 步：`MUL CX` 中源为 16 位寄存器 CX，执行字乘法：(DX,AX) ← AX × CX，32 位积存 DX:AX。

第 3 步：`MUL BYTE PTR [SI]` 中 BYTE（BYTE PTR）说明内存操作数为字节，执行字节乘法：AX ← AL × [SI] 处字节。

第 4 步：`MUL WORD PTR [BX]` 中 WORD（WORD PTR）说明内存操作数为字，执行字乘法：(DX,AX) ← AX × [BX] 处字。

第 5 步：各条 MUL 执行后影响 CF 和 OF：结果高半部分（字节乘的 AH、字乘的 DX）不为零则 CF=OF=1，否则 CF=OF=0；据此可检测并去除结果中的无效前导零。

**答案**：四条指令分别演示字节乘法（寄存器源、内存字节源）与字乘法（寄存器源、内存字源）的用法；源操作数不能是立即数。

### 例题 26：例 3.57 —— MUL 无符号字节乘法求积（第 51 页）

**题干**：
设 AL=55H，BL=14H，计算它们的积。只要执行下面这条指令：
```
MUL  BL
```
结果：AX=06A4H。由于 AH=06H≠0，高位部分有效，所以置 CF=1 和 OF=1。

**解**：

第 1 步：把两操作数换算为十进制：AL=55H = 5×16+5 = 85；BL=14H = 1×16+4 = 20。

第 2 步：执行 MUL BL，字节乘法：AX ← AL × BL = 85 × 20 = 1700。

第 3 步：把 1700 换算为十六进制：1700 = 6×256 + 164，164 = 10×16 + 4，故 1700 = 06A4H，即 AX=06A4H（AH=06H，AL=A4H）。

第 4 步：判定 CF/OF：高半部分 AH=06H ≠ 0，高位部分有效 → CF=1、OF=1。

**答案**：AX=06A4H（十进制的 1700）；CF=1，OF=1。

**验证**（用原始数据验证）：
- 0x06A4 = 6×256 + 10×16 + 4 = 1536 + 160 + 4 = 1700 = 85 × 20，与 55H × 14H 一致。
- AH=06H≠0，符合"高半部分不为零则 CF、OF 均置 1"的规则。

### 例题 27：例 3.59 —— IMUL 有符号数乘法求积（第 52 页）

**题干**：
设 AL=−28，BL=59，试计算它们的乘积。
```
IMUL  BL     ；AX=F98CH = -1652，CF=1，OF=1
```

**解**：

第 1 步：按带符号十进制相乘：AL=−28，BL=59，(−28) × 59 = −1652。

第 2 步：执行 IMUL BL，字节乘法，16 位积存 AX。

第 3 步：把 −1652 写成 16 位补码：1652 = 0674H（6×256+7×16+4 = 1536+112+4 = 1652）；−1652 的补码 = 10000H − 0674H = F98CH，即 AX=F98CH。

第 4 步：判定 CF/OF：高半部分 AH=F9H = 1111 1001B，既不是全 0 也不是全 1 → CF=1、OF=1。

**答案**：AX=F98CH，即 −1652；CF=1，OF=1。

**验证**（用原始数据验证）：
- F98CH 作为 16 位带符号数 = −(10000H − F98CH) = −0674H = −(6×256+7×16+4) = −1652 = (−28)×59，正确。
- AH=F9H 非全 0 且非全 1，故 CF=1、OF=1 符合 IMUL 规则。

### 例题 28：例 3.61 —— 除法指令溢出举例（第 57 页）

**题干**：
两个无符号数 7A86H 和 04H 相除的商，应为 1EA1H。若用 DIV 指令进行计算，即
```
MOV  AX, 7A86H
MOV  BL, 04H
DIV  BL
```
这时，由于 BL 中的除数 04H 为字节，而被除数为字，商 1EA1H 大于 AL 中能存放的最大无符号数 FFH，结果将产生除法错误中断。

**解**：

第 1 步：确认除法类型：除数 BL=04H 为字节，字节除法被除数应为 16 位，放 AX 中；AX=7A86H。

第 2 步：计算真正的商：7A86H = 7×4096 + 10×256 + 8×16 + 6 = 28672 + 2560 + 128 + 6 = 31366；31366 ÷ 4 = 7841 余 2（4 × 7841 = 31364，31366 − 31364 = 2）。

第 3 步：把商换算为十六进制：7841 = 1×4096 + 14×256 + 10×16 + 1 = 1EA1H，与题给商 1EA1H 一致。

第 4 步：比较商与目标寄存器范围：字节除法商应存入 AL，AL 能存放的最大无符号数为 FFH = 255；1EA1H = 7841 > 255，商超出 AL 所能存放数的范围。

第 5 步：结论：执行 DIV BL 时产生除法错误中断，相当于执行了除数为 0 的运算，所得的商和余数都不确定。

**答案**：该除法产生除法错误中断，得不到有效商和余数。

**验证**（用原始数据验证）：
- 7A86H ÷ 04H = 31366 ÷ 4 = 7841 余 2，商 7841 = 1EA1H 与题给一致。
- 商 1EA1H > FFH，超出字节除法商寄存器 AL 的范围，故按"商超过目标寄存器所能存放数的范围将自动产生除法错中断"的规则，结论正确。

### 例题 29：例 3.62 —— 编程求 −38/3 的商和余数（第 61 页）

**题干**：
编程求 −38/3 的商和余数。
```
MOV  AL, 11011010B     ；被除数-38
MOV  CH, 00000011B     ；除数+3
CBW                    ；将AL符号扩展到AH中
                       ；使AX=1111 1111 1101 1010B
IDIV CH                ；AX/CH
                       ；AL=1111 0100B = -12 (商)
                       ；AH=1111 1110B = -2 (余数)
```

**解**：

第 1 步：求 −38 的 8 位补码：38 = 0010 0110B；逐位取反得 1101 1001B；最低位加 1 得 1101 1010B。故 MOV AL,11011010B 把 −38 送入 AL。

第 2 步：把 +3 写成 8 位二进制：3 = 0000 0011B。MOV CH,00000011B 把除数 +3 送入 CH。

第 3 步：执行 CBW：AL 的 D7=1，将 1 扩展到 AH 的所有位，使 AH=FFH，于是 AX=1111 1111 1101 1010B = FFDAH。

第 4 步：验证 FFDAH = −38：10000H − FFDAH = 26H = 38，故 FFDAH = −38，符号扩展未改变数值。

第 5 步：执行 IDIV CH（字节除法，除数 CH 为 8 位）：AX ÷ CH = (−38) ÷ 3 = −12 余 −2；商存入 AL，余数存入 AH。

第 6 步：把商 −12 写成 8 位补码：12 = 0000 1100B；取反得 1111 0011B；加 1 得 1111 0100B，故 AL=1111 0100B = −12。

第 7 步：把余数 −2 写成 8 位补码：2 = 0000 0010B；取反得 1111 1101B；加 1 得 1111 1110B，故 AH=1111 1110B = −2。

第 8 步：检查符号规则：余数 −2 与被除数 −38 同号，符合 IDIV"余数的符号和被除数的符号相同"的规定；余数绝对值 2 < 除数 3，正确。

**答案**：AL=1111 0100B = −12（商）；AH=1111 1110B = −2（余数）。

**验证**（用原始数据验证）：
- 商 × 除数 + 余数 = (−12) × 3 + (−2) = −36 + (−2) = −38，等于被除数，正确。
- 被除数 −38（11011010B）经 CBW 后为 FFDAH=−38，数值未变；除数 00000011B=+3。
- 商 −12 与余数 −2 均为 8 位带符号数，余数符号（负）与被除数符号（负）一致，符合 IDIV 规定。
