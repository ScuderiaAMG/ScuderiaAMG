## 知识点详解

### 知识点 1：中断的定义

**定义**：当CPU执行当前程序时，外部发生某随机事件，CPU暂停（中断）当前程序的执行，转而执行为该事件服务的程序（中断服务程序），服务完毕再继续原来程序的执行。其特点是：随机性、优先级。关键要素是断点信息——CPU 须记下被暂停处的位置与状态，才能在服务结束后正确返回原程序。

**理解**：中断的构成要素有三个：第一个要素是触发条件，即外部随机事件发生，事件何时发生不由主程序决定；第二个要素是转移执行，CPU 暂停主程序、转去执行专门为该事件编写的中断服务程序；第三个要素是恢复执行，服务程序结束后 CPU 回到主程序被暂停的位置继续执行。为了恢复执行，CPU 必须事先保存断点信息（当前执行位置及其状态）。"随机性"来自事件发生时刻不可预测，"优先级"来自多个事件可能同时发生而 CPU 一次只能执行一个程序，必须规定响应次序。

**作用**：本章最基础的顶层概念，是中断请求、响应、处理、返回等全部后续内容的前提。**基础概念，独立知识点**。

### 知识点 2：断点信息

**定义**：CPU 被中断时主程序的暂停位置及现场状态信息，具体包括断点地址（当前 CS:IP 值）和标志寄存器（FR）的内容。CPU 在响应中断时将它们压入堆栈保存，中断返回时再恢复。

**理解**：断点信息由两部分构成。断点地址记录主程序被暂停在哪一条指令处，保证返回后从下一条指令继续；标志寄存器内容记录暂停时刻程序状态标志（如进位、零、符号等标志）的取值，保证返回后程序状态与中断前一致。保存手段是压入堆栈（PUSH），恢复手段是弹出堆栈（POP），后进先出的堆栈特性保证恢复顺序与保存顺序相反且一一对应。

**作用**：中断机制区别于"丢下不管、重新开始"的关键。没有断点信息的保存与恢复，中断返回后主程序将无法从原位置正确继续执行。

### 知识点 3：中断的主要用途——故障处理

**定义**：利用中断处理计算机运行中出现的各种故障，包括硬件错误、掉电、存储出错、运算溢出等。故障发生时通过中断机制转入相应处理程序。

**理解**：计算机运行中的故障发生时刻随机且不可预期，若不在故障发生时立即处理，系统可能产生错误结果或损坏数据。通过中断，故障事件一旦出现即打断当前程序，转去执行故障处理程序，处理完再返回。举例：电源掉电事件触发中断，CPU 在电压完全消失前的短暂时间内保存关键数据。

**作用**：说明中断机制解决的第一个实际问题。与分时操作、实时处理并列，三者共同构成中断用途的完整列表。

### 知识点 4：中断的主要用途——分时操作

**定义**：利用中断实现 CPU 和各外设间的分时操作。CPU 命令多个外设同时工作，CPU 执行主程序的过程中可随时处理外设的中断请求。

**理解**：多个外设速度远慢于 CPU，若 CPU 逐一等待每个外设完成，效率极低。分时操作的方法是：CPU 启动多个外设同时工作，自己继续执行主程序；外设完成准备后发出中断请求，CPU 暂停主程序处理该外设，处理完返回主程序，从而在多个外设之间轮流服务，也在主程序与外设服务之间交替。

**作用**：说明中断机制解决的第二个实际问题，是 CPU 与多外设并行工作（分时）得以实现的基础。

### 知识点 5：中断的主要用途——实时处理

**定义**：利用中断保证实时处理外设的请求。外设要求的服务通常是随机的，外设要求 CPU 随时响应请求。

**理解**：某些外设的数据或事件具有时效性，出现后必须尽快被处理。中断的响应过程短、不依赖主程序主动查询，因此外设请求出现的时刻虽然随机，CPU 仍能在事件发生后及时转入服务，满足"随时响应"的要求。

**作用**：说明中断机制解决的第三个实际问题，是实时控制系统（如数据采集、过程控制）的技术基础。

### 知识点 6：中断分类——外部中断与内部中断

**定义**：按中断源分类，中断分为两类。（1）外部中断（硬件中断）：由外部事件引起的中断。外部中断源包括：一般 I/O 设备（键盘、显示器、鼠标、打印机等）、存储设备（软盘、硬盘、光盘、磁带等）、实时时钟（各种定时器、计数器等）、故障源（电源故障、存储出错、I/O 通道错误等）。（2）内部中断：由 CPU 内部指令引起的中断。内部中断源包括：CPU 内部异常（除法错、运算溢出、单步运行、断点运行等）、CPU 执行中断指令（如"INT n"指令等）。

**理解**：分类依据是中断请求的来源位置。外部中断的请求信号来自 CPU 芯片之外，由外部硬件设备或事件产生；内部中断的请求来自 CPU 内部，包括执行指令时检测出的异常情形（如除数为零、结果溢出）以及程序主动执行的中断指令（INT n）。这两类中断的响应条件、优先级处理方式不同，后续 8086 中断系统中外部中断经 INTR/NMI 引脚进入，内部中断由指令执行过程产生。

**作用**：按中断源分类是组织后续全部中断内容的框架——8086 系统对外部中断与内部中断分别规定了不同引脚、响应条件和中断号来源。

### 知识点 7：中断过程总框架（五个阶段）

**定义**：一次完整的中断过程分为五个阶段：中断请求 → 中断排队 → 中断响应 → 中断处理 → 中断返回。各阶段任务依次为：中断源发出中断请求信号，请求中断响应；多个中断请求时，响应优先级最高的中断；CPU 响应中断请求，保存断点，调用中断服务程序；处理中断任务（中断服务程序）；结束中断服务程序，返回断点执行主程序。

**理解**：五阶段是按时间顺序对一次中断全过程的分解。请求阶段解决"事件如何通知 CPU"；排队阶段解决"多个请求同时到来先处理谁"；响应阶段解决"CPU 满足什么条件才应答、应答时自动做什么"；处理阶段解决"服务程序本身做什么"；返回阶段解决"如何回到主程序"。五个阶段首尾相接，前一个阶段的完成是后一个阶段开始的前提。

**作用**：中断过程是本章重点内容，五个阶段是各页逐段展开的骨架；每个阶段在下方作为独立知识点进一步详解。

### 知识点 8：中断请求过程

**定义**：中断请求过程包括三项内容。（1）中断源发出中断请求信号：中断源配置有中断请求触发器，当外设准备就绪时发出"准备好"信号，即将中断触发器置 1，发出中断请求；该信号应能保持，直到得到响应。（2）CPU 清除已响应的中断请求信号：CPU 已响应某中断时，清除其中断请求，为该设备下一次中断请求作好准备。（3）中断屏蔽的控制：为了对中断请求进行灵活的控制，对可屏蔽中断源配置有中断屏蔽触发器，只有当触发器相应位为 0 时，外设的中断请求才能送到 CPU。

**理解**：中断请求是五阶段中的第一阶段，回答"外设如何把请求送到 CPU"。外设用中断请求触发器记录请求状态（置 1 表示有请求），信号必须保持直到被响应，防止请求丢失；CPU 响应后清除该请求，使触发器复位以便下一次请求；中断屏蔽触发器提供控制手段——置 1 时阻断请求信号送往 CPU（屏蔽），置 0 时放行。注意屏蔽针对的是可屏蔽中断源。

**作用**：五阶段之一。是排队、响应阶段的前提；请求触发器的保持特性直接解释了排队阶段"CPU 响应完高级中断后还可响应低级中断"的原因。

### 知识点 9：中断排队过程

**定义**：按优先级排队。多中断源同时请求中断，CPU 辨别和比较它们的优先权，进行中断排队，先响应优先级别最高的中断请求。注：由于中断请求信号是保持的，所以 CPU 响应完高级中断后还可响应低级中断。

**理解**：多个中断请求可能同时出现，而 CPU 一次只能为一个中断服务，因此必须先排序再响应。排队的内容是给同时到达的请求按优先级高低排序，CPU 选择优先级最高的先响应。由于各中断请求信号在被响应前一直保持，未被选中的低级中断请求不会消失，等高级中断处理完成后 CPU 仍能响应它。

**作用**：五阶段之一。是"优先级"特点的具体实现环节，直接引出 §1.3"中断优先权与中断嵌套"中的中断优先级内容（第 26 页）。

### 知识点 10：中断响应的条件

**定义**：中断请求发生时 CPU 并不能立即响应，必须满足一定条件。非屏蔽中断需要满足两个条件：① 无总线请求；② CPU 执行完现行指令。可屏蔽中断需要满足三个条件：① 无总线请求；② CPU 被允许中断；③ CPU 执行完现行指令。

**理解**：响应条件回答"CPU 何时才应答中断请求"。两类中断共同需要两个条件：系统总线当前未被其他设备请求占用（无总线请求），以及 CPU 已把正在执行的那条指令执行完毕（执行完现行指令）。可屏蔽中断还多一条：CPU 中断允许标志处于允许状态（IF=1，即 CPU 被允许中断）；非屏蔽中断不受该标志限制，故只要求两个条件。由此解释"外设中断请求发生时，CPU 不一定马上为其服务"。

**作用**：五阶段之"中断响应"的第一部分。两个条件与三个条件的区分是本知识点的关键点，也是解题判定题的常用考点。

### 知识点 11：CPU 响应中断自动完成的三项任务

**定义**：CPU 响应中断过程将自动完成三项任务。① CPU 自动关中断：在完成现场保护前，禁止 CPU 响应其他中断；② CPU 自动保护断点现场信息：保护标志寄存器（FR）和断点地址（当前 IP 和 CS 值），即将它们 PUSH 入堆栈；③ CPU 自动调用中断服务程序：获得中断程序入口地址，进入中断服务程序。

**理解**：这三项任务由 CPU 硬件自动完成，不需要服务程序中的任何指令。顺序与原因如下：先关中断，防止保护断点信息的过程中被其他中断插入而破坏保存过程；然后保护现场信息，把 FR、CS、IP 依次压入堆栈（保存顺序为 FR、CS、IP）；最后取得中断服务程序入口地址并转入执行。注意此处的"自动保护"只保护 FR、CS、IP 三个内容，不包括通用寄存器——通用寄存器由服务程序用 PUSH 保护。

**作用**：五阶段之"中断响应"的第二部分。与"中断处理"阶段中服务程序自行保护现场相衔接；自动保护的内容也是"中断返回"阶段 IRET 恢复内容的对应来源。

### 知识点 12：CPU 响应可屏蔽中断时序

**定义**：CPU 响应可屏蔽中断时，通过 INTA 引脚发出两个负脉冲（INTA 的负脉冲 ×2）构成响应时序，用于中断响应过程。

**理解**：课件中本页（第 14 页）为图片页，提取文本仅给出"INTA 的负脉冲×2"这一关键标注。INTA 是 8086 的中断应答信号引脚，低电平有效；CPU 响应可屏蔽中断时连续发出两个 INTA 负脉冲。这一时序属于"中断响应"阶段，具体脉冲用途（如从外设读取中断号）在后续 8086 中断系统章节展开。

**作用**：五阶段之"中断响应"的第三部分，是可屏蔽中断响应过程在总线时序层面的表现。

### 知识点 13：中断处理过程（中断服务程序的四个步骤）

**定义**：中断处理过程即中断服务程序的工作过程，共四个步骤。第 1 步保护现场：中断程序中要用到一些寄存器，若不保护这些寄存器在中断前的内容，中断服务程序会将其修改，这样返回主程序后主程序将不能正确执行；在中断服务程序中保护这些寄存器的工作称为"保护现场"，实际上就是用 PUSH 指令将有关寄存器的内容推入堆栈。执行完保护现场后要开中断，允许 CPU 响应更高级中断请求。第 2 步中断任务：执行具体的中断任务，比如将 A/D 转换器的值读入存储器中，或者将键盘的键值读入并处理。第 3 步恢复现场：将主程序断点的状态恢复，在中断返回前必须用 POP 指令将保存在堆栈中的各寄存器的值恢复到原来的位置；为了保证恢复现场过程不被高级中断所中断，在恢复现场前要关中断，恢复现场完成后要开中断。第 4 步调用 IRET：中断服务程序中至少包括一条 IRET 指令，调用 IRET 指令将启动中断返回过程。

**理解**：中断处理是五阶段中的第四阶段，全部工作由中断服务程序（软件）完成，四步按执行顺序排列。第 1 步保护现场的原因：服务程序使用寄存器会改写其原值，破坏主程序的运行状态，因此先把这些寄存器的原值用 PUSH 压栈保存；保护完成后开中断，使更高优先级中断能打断本服务程序。第 2 步执行本次中断的实际任务。第 3 步恢复现场的原因与第 1 步对应，用 POP 按相反顺序把寄存器的原值从堆栈取出放回；恢复前先关中断，防止恢复过程中被高级中断插入，恢复完再开中断。第 4 步执行 IRET，进入中断返回阶段。开中断与关中断的时机规则是：保护现场完成后开中断、恢复现场前关中断、恢复现场完成后开中断。

**作用**：五阶段之一，是"中断处理"阶段的全部内容。服务程序编写必须遵循这四步的框架，前三步（保护现场/任务/恢复现场/IRET）也是后续 8086 中断服务程序编写题的模板。

### 知识点 14：中断返回过程（IRET）

**定义**：中断服务程序中调用 IRET 便启动了中断返回过程。1、将堆栈中的标志寄存器的值送回原处（POP）；2、将断点地址重新送回原处（IP 和 CS 寄存器），CPU 继续执行主程序。

**理解**：中断返回是五阶段中的最后一个阶段。IRET 指令从堆栈中弹出三个内容并恢复：标志寄存器 FR、IP、CS——弹出顺序与响应时压入顺序（FR、CS、IP 依次压栈）正好相反，即先弹出 IP、CS 恢复断点地址，再弹出 FR 恢复标志状态，从而保证恢复值与保存值一一对应。恢复完成后 CS:IP 指向主程序断点处，CPU 继续执行主程序。

**作用**：五阶段之末，中断过程与主程序衔接的环节。IRET 与 RET 的区别（思考题，见例题 2）是常见考点：RET 只恢复 CS、IP 两个寄存器，IRET 恢复 FR、CS、IP 三个。

### 知识点 15：中断源的确定问题与两种识别方法

**定义**：问题的提出：CPU 在响应中断的时候如何知道是哪个中断源发出的请求呢？CPU 是如何找到中断服务程序入口地址的？本节（§1.2）的任务是：确定中断源，并找到该中断服务程序的入口地址。中断源的识别方法通常有两种：查询中断（软件查询法）、矢量中断（硬件识别法）。

**理解**：多个中断源可能共用一条中断请求信号到达 CPU，CPU 只收到"有中断请求"，但不知道具体是哪一个设备。因此需要一套机制回答两个问题：哪个设备请求中断、它的服务程序在哪里。两种方法的分工：查询中断由 CPU 用软件逐个检查中断源来识别；矢量中断由硬件（I/O 接口或中断控制器）直接提供中断源标识，CPU 凭标识查表获得服务程序入口地址。

**作用**：§1.2 的纲领性知识点，提出本节要解决的问题并给出两条技术路线，后续内容分别按两条路线展开。

### 知识点 16：查询中断（软件查询法）的定义

**定义**：查询中断（软件查询法）是用软件查询的方法识别中断源——在外设有中断请求时，从多个设备中查找请求中断的那个中断源。

**理解**：查询中断的识别工作完全由程序完成。当 CPU 得知有中断请求后，执行一段查询程序，按固定顺序逐个检查各中断源是否发出请求，查到发出请求的设备后转入它的中断服务程序。识别靠的是程序对中断请求信息的逐位检查，而不是硬件直接给出标识。

**作用**：两种中断源识别方法之一，与矢量中断并列。其接口组成、汇总电路、接口举例与优先级确定依次见知识点 17、18、19、20，共同构成软件查询法的完整内容。

### 知识点 17：查询中断接口电路的组成

**定义**：查询中断接口电路通常包括以下内容：1、每个外部中断源有一个中断请求线接入中断系统；2、向 CPU 的 INTR 引脚发出中断请求信号的"或"电路；3、中断请求锁存器及其译码电路：用于保存中断请求信息；4、程序读取中断请求信息，逐位查询是何中断源发出的中断请求，并调用其中断服务程序。

**理解**：接口电路按功能分四部分。第一部分为每个中断源提供独立的中断请求线；第二部分用"或"电路把所有请求线汇总成一条 INTR 信号送往 CPU，任一设备有请求即产生总请求；第三部分用中断请求锁存器保存各设备的请求状态（因为查询时刻可能晚于请求时刻，必须把请求信息锁存下来），译码电路使 CPU 能通过某个端口地址读取该锁存器的内容；第四部分是 CPU 执行的查询程序，读取锁存器内容、逐位判断、转入相应服务程序。

**作用**：查询中断的硬件支撑，解释查询中断"如何知道有请求"（或电路）与"如何查出是谁"（锁存器 + 查询程序）。

### 知识点 18：软件查询中断源（“或”电路汇总与逐位查询）

**定义**：1）软件查询中断源：把各个外设的中断请求信号"相或"，产生一个总的中断请求信号。

**理解**：各外设的中断请求信号接入"或"电路，任何一路为高电平（有请求），输出即为高电平，形成送往 CPU INTR 引脚的单一总请求信号。CPU 响应后，再通过查询程序逐位检查中断请求锁存器（如 D7、D6、D5、D4 …）判断具体是哪一路设备有请求——每一位对应一个中断源。第 20 页电路图中的中断源示例为：磁盘、磁带、CRT、键盘、打印等设备，其请求信号经"或"电路汇总，经锁存器由端口号 XXH 读出。

**作用**：查询中断识别流程的前半部分（汇总请求信号），与"查询中断接口举例"（第 21 页，含逐位查询程序）及"软件查询法的优先级确定"（第 22 页）共同构成软件查询法的完整内容。

### 知识点 19：查询中断接口举例（第 21 页）

**定义**：查询中断（软件查询法）的接口举例：8086CPU 经接口连接 4 个中断源 0#~3#，请求信号高电平有效，各中断源请求经与门送入中断请求锁存器保存，锁存器输出经或门合成一个总请求信号送到 CPU 的 INTR 引脚；锁存器输出分别接到数据总线 D7~D4（0# 对应 D7、1# 对应 D6、2# 对应 D5、3# 对应 D4，高电平表示有请求）；地址译码电路配合 M/IO、RD 信号，在端口 IPORT 选通锁存器。CPU 执行 `IN AL, IPORT` 读入请求信息后，用 TEST 指令从 D7 到 D4 逐位查询，JNZ 转入相应服务程序 SEV0、SEV1、SEV2、SEV3。图中提问：优先级顺序？

**理解**：接口电路的工作路径分四段。第一段是请求的汇总：各中断源（0#~3#）的请求信号经与门送入中断请求锁存器保存，锁存器输出经或门合成一个总请求信号送到 CPU 的 INTR 引脚，任何一个源有请求都会使 INTR 有效。第二段是请求信息的保存：锁存器把 4 路请求信号保持下来，0# 对应 D7、1# 对应 D6、2# 对应 D5、3# 对应 D4，高电平表示"有请求"。第三段是读取：CPU 执行 `IN AL, IPORT`，在地址译码电路配合 M/IO、RD 信号选通该锁存器端口（IPORT）时，把保存的请求信息读入 AL。第四段是逐位查询：`TEST AL,80H` 只测 D7（80H=1000 0000B），若 D7=1 则 ZF=0，`JNZ SEV0` 转去 0# 的服务程序；否则依次测 D6（40H）、D5（20H）、D4（10H），转入对应服务程序 SEV1、SEV2、SEV3。查询的先后次序同时决定了优先级：先测的 D7（0#）优先级最高。

**作用**：中断源识别两种方法（查询中断、矢量中断）中第一种方法的硬件实现样例。它把查询中断的一般定义落到具体电路与程序，是"软件查询法的优先级确定"和"中断优先级三种实现方式"两个知识点的前置实例。

### 知识点 20：软件查询法的优先级确定

**定义**：当 CPU 响应中断后，进入中断处理程序，在中断处理程序的开始部分安排一段带有优先级的查询程序；查询程序按优先级从高到低的次序依次测试各中断源对应的数据位，最先被查询（测试）到的中断源优先级最高。

**理解**：软件查询法的优先级不是由硬件电路决定，而是由查询程序中 TEST 指令的排列顺序决定。CPU 读入锁存器内容后，即使多个请求同时存在，也总是按固定顺序逐位测试：先测 D7（对应 0#），有请求就立即转入其服务程序，不再查询后面各位。因此排在前面的测试对象获得更高优先级。该方法的两个直接后果：优点——省硬件，只需锁存器和或门即可，优先级顺序可由软件任意调整（改查询程序顺序即可）；缺点——中断响应慢，CPU 必须逐位执行 TEST/JNZ 才能定位中断源，中断源数量越多，查询时间越长。

**作用**：中断优先级三种实现方式（软件查询法、硬件中断优先权电路、可编程中断控制器）之一，也是"查询中断接口举例"（第 21 页）中"问：优先级顺序？"这一问题的解答依据。后置关联：中断优先级（第 26 页，知识点 26）将其列为第一种实现方法。

### 知识点 21：矢量中断

**定义**：矢量中断（vector interrupt）是 CPU 要求通过 I/O 接口（通常是中断控制器，如 8259A）提供中断申请信号和中断矢量标志（通常称类型号或中断号），通过该标志在中断矢量（向量）表中获得中断服务程序入口地址的方法。

**理解**：矢量中断的识别路径分三步。第一步：接口电路（中断控制器）在向 CPU 提出中断申请的同时，提供一个标识"是哪个中断源"的数值，即中断号。第二步：CPU 以该中断号作为索引去访问中断向量表。第三步：从向量表中取出该中断对应的中断服务程序入口地址（中断向量），转去执行。与查询中断的差别在于中断源的确定方式：查询中断由 CPU 逐位查询锁存器内容来定位中断源；矢量中断由接口硬件直接提供中断号，CPU 不做逐位查询。

**作用**：识别中断源的第二种方法（硬件识别法），是 8086 系统实际采用的方式。本知识点统领其下的三个名词（中断号、中断向量、中断向量表）以及 8259A 中断控制器相关内容，是后续"8086 的中断系统"一章的前置基础。

### 知识点 22：中断号（中断类型号）

**定义**：标识中断源的一个数值。

**理解**：中断号是对中断源进行编号的结果：每个中断源被分配一个固定数值，CPU 依据该数值区分不同的中断源。在矢量中断中，中断号由接口（如 8259A）随中断申请信号一起提供给 CPU，CPU 获得中断号后即可确定中断源身份并计算该中断在中断向量表中的位置。中断号本身不含任何地址信息，它只起"标识与索引"的作用。

**作用**：矢量中断方法的核心数据，是连接"中断源"与"中断向量表"的索引值。后置关联：8086 系统中中断号 n 对应向量表地址 n×4，相关内容在"8086 的中断系统"部分展开。

### 知识点 23：中断向量

**定义**：中断服务程序的入口地址。

**理解**：中断向量是一个地址数据，指明某中断的服务程序在内存中的起始位置。CPU 响应中断后，依据中断号到中断向量表中取出的内容就是中断向量；CPU 把该地址装入相应寄存器后即转去执行中断服务程序。一个中断向量标识一个中断服务程序的存放位置，中断号与中断向量通过中断向量表一一对应。

**作用**：矢量中断三步路径（提供中断号 → 查表 → 取入口地址）的终点数据；与中断号、中断向量表共同构成矢量中断的完整机制。

### 知识点 24：中断向量表

**定义**：保存中断服务程序入口地址的表格。

**理解**：中断向量表集中存放所有中断服务程序的入口地址（中断向量），并按中断号组织。CPU 得到中断号后，以中断号为索引在该表中定位对应表项，读出其中保存的入口地址，从而转入中断服务程序。表的存在使"中断号 → 入口地址"的映射有统一的存放位置，CPU 不必知道各服务程序的实际位置，只要表的内容正确即可找到服务程序。

**作用**：矢量中断机制的存储载体，是中断号与中断向量之间的映射表。后置关联：8086 中断向量表的物理位置（00000H~003FFH）与 n×4 寻址规则在"8086 的中断系统"部分详述。

### 知识点 25：硬件中断优先权电路（74LS148 优先编码器）

**定义**：通过硬件实现中断请求信号的优先级编码，例如采用 74LS148 优先编码器。74LS148 的 8 路输入 I0~I7 低电平有效，I7 输入的请求具有最高优先级，I0 输入的请求具有最低优先级；E1 为使能端（低电平有效），A2A1A0 为三位编码输出，GS、E0 为状态输出。

**理解**：74LS148 的工作过程按三个环节拆解。第一是使能判定：E1=1 时芯片不工作，输出全部无效（A2A1A0=111，GS=1，E0=1）；E1=0 时进入编码状态。第二是请求判定：若 I0~I7 全为 1（无任何有效请求），输出 A2A1A0=111，GS=1、E0=0；只要有任一输入为 0（有请求），就进行编码。第三是优先级编码：从 I7 到 I0 检查，编号最大的有效输入（第一个遇到的 0）被编码，A2A1A0 输出其编号的二进制反码，例如 I5=0 且更高位均为 1 时输出 A2A1A0=010（5 的二进制 101 取反为 010），同时 GS=0 表示编码有效、E0=1。输入低电平有效意味着"0"表示有请求、"1"表示无请求，这与查询中断接口（第 21 页）"高电平有效"的约定相反，使用时需注意电平约定。

**作用**：中断优先级三种实现方式中的硬件方法（软件工作量小），是 8259A 内部判优电路的原理基础。其真值表是本知识点的核心数据，用于解题中由输入状态确定输出编码。

### 知识点 26：中断优先级

**定义**：系统中多个中断请求可能同时出现，CPU 只能按一定的次序（优先级策略）予以响应和处理，这个响应的次序称为中断优先级（interrupt priority）。

**理解**：中断优先级解决的是"多个请求同时到来时先处理谁"的问题。构成要素有二：一是多个中断请求同时存在的客观情况（中断是随机事件，随时可能多个源同时请求）；二是响应次序的规则（优先级策略），规定哪个中断先被响应、哪个后响应。实现该规则的方法有三种：软件查询法——只需少量硬件支持（靠查询程序顺序定优先级）；硬件中断优先权电路——软件工作量小（靠 74LS148 等编码电路定优先级）；可编程中断控制器（如 8259）——功能最强（硬件判优且可编程配置）。

**作用**：中断系统的基本概念，位于中断过程（请求 → 排队 → 响应 → 处理 → 返回）中"中断排队"环节的理论核心。前置关联：软件查询法（知识点 20）、硬件中断优先权电路（知识点 25）是它的两种实现；后置关联：中断嵌套规则以它为前提，8259A 的优先级管理是它的延伸。

### 知识点 27：中断嵌套

**定义**：当前中断服务程序只能被更高优先级的中断所打断，而低优先级的设备将等待，直到当前中断结束。

**理解**：中断嵌套描述的是中断处理过程中的一个规则及其执行结果。规则：正在执行某中断服务程序时，若出现新的中断请求，比较两者的优先级；新请求优先级高于当前中断时，CPU 暂停当前服务程序、转去执行更高优先级中断的服务程序，完成后返回继续执行被打断的服务程序；新请求优先级等于或低于当前中断时，CPU 不响应，该请求保持等待，直到当前中断服务结束。这个规则是"中断过程"中"中断排队"思想在处理阶段的应用：排队不仅在响应前进行，在处理过程中也持续生效。

**作用**：中断优先级概念的延伸应用，构成 §1.3"中断优先权与中断嵌套"的主题之一。后置关联：8259A 的完全嵌套方式即以此规则为工作基础。

### 猴子下山的故事（第 4–5 页，中断概念引入）

- Rev 1（无中断机制）：一只猴子下山，见到玉米好就掰玉米；看见了桃子就丢了玉米；看到了西瓜就丢了桃子；看到小兔就丢了西瓜；最后兔子跑了，猴子空手回家。
- Rev 2（有中断机制）：猴子掰完玉米看见了桃子，把玉米藏起来，记下藏点，摘下桃子；……把桃子拿回去后，回到藏玉米的地方把玉米找出来拿回家；猴子满载而归。

### 中断 VS 子程序（第 6 页提出的问题）

### 术语补充

- 中断源：发出中断请求的设备或事件（外设、故障、CPU 异常、中断指令）。
- 中断屏蔽：对可屏蔽中断源配置中断屏蔽触发器，仅当其相应位为 0 时，外设的中断请求才能送到 CPU（见知识点 8"中断请求过程"）。
- 中断号（中断类型号）：标识中断源的一个数值，见知识点 22（矢量中断需强调的三个名词之一）。
- 中断向量：中断服务程序的入口地址，见知识点 23。
- 中断向量表：保存中断服务程序入口地址的表格，见知识点 24（其物理位置 00000H~003FFH 与 n×4 寻址规则在"8086 的中断系统"部分展开）。
- 中断优先级：多个中断请求可能同时出现，CPU 只能按一定次序（优先级策略）予以响应和处理，这个响应的次序称为中断优先级（第 5、9、11 页作为特点与环节出现，正式定义见知识点 26，§1.3 第 26 页）。
- 可编程中断控制器（如 8259A）：矢量中断的典型硬件实现（见知识点 21 及第 24 页接口举例），其判优、嵌套等完整功能在后续 8086 中断系统与 8259A 章节展开。

## 解题方法汇总

### 方法 1：中断响应条件判定法

- **适用场景**：判断某个中断请求出现后 CPU 是否会响应、何时响应（课堂判断/选择类题目）。
- **已知条件**：中断请求的类型——非屏蔽中断（NMI）或可屏蔽中断（INTR）；系统当前有无总线请求；CPU 中断允许状态（IF）；当前指令是否执行完毕。
- **计算步骤**：
  1. 判断中断类型：若是非屏蔽中断，检查 2 个条件；若是可屏蔽中断，检查 3 个条件。
  2. 条件①检查：当前是否有总线请求，有则 CPU 不响应中断。
  3. 条件②检查（仅可屏蔽中断）：CPU 是否被允许中断（IF=1）；若被禁止（IF=0），可屏蔽中断不响应。
  4. 条件③检查：现行指令是否执行完毕，未执行完则等待，执行完后才响应。
  5. 结论：全部所需条件同时满足时 CPU 才进入中断响应。
- **常见错误**：把非屏蔽中断也要求"CPU 被允许中断"（实际上非屏蔽中断不受 IF 控制）；认为中断请求一出现 CPU 就立即响应（实际还受无总线请求与现行指令执行完毕两个条件约束）。

### 方法 2：中断服务程序编写四步法（框架题）

- **适用场景**：按标准框架编写中断服务程序，或给出一段中断服务程序要求补全/指出缺漏步骤。
- **已知条件**：中断任务内容；服务程序中需要使用的寄存器清单。
- **计算步骤**：
  1. 第 1 步保护现场：对服务程序中要用到的每个寄存器执行 PUSH 压栈；保护现场完成后执行 STI 开中断。
  2. 第 2 步中断任务：编写执行具体中断任务的指令（如把 A/D 转换器的值读入存储器、读取并处理键盘键值）。
  3. 第 3 步恢复现场：先执行 CLI 关中断，再按与保存相反的顺序对每个寄存器执行 POP；恢复现场完成后执行 STI 开中断。
  4. 第 4 步调用 IRET：以 IRET 指令结束服务程序，启动中断返回。
- **常见错误**：漏掉保护现场导致服务程序改写主程序寄存器内容；开/关中断时机颠倒（保护现场后未开中断、恢复现场前未关中断）；POP 顺序与 PUSH 顺序不一致导致寄存器内容错位；结尾用 RET 代替 IRET（RET 不恢复标志寄存器）。

### 方法 3：中断全过程串讲法（宏观叙述题）

- **适用场景**：要求完整叙述一次中断从发生到结束的全过程（简答/论述题）。
- **已知条件**：中断源、中断请求信号、CPU 状态、服务程序内容。
- **计算步骤**：
  1. 中断请求：外设准备就绪，中断请求触发器置 1，发出并保持中断请求信号（可屏蔽中断还需屏蔽触发器为 0 才能送达 CPU）。
  2. 中断排队：多个请求同时出现时按优先级排队，CPU 响应优先级最高的中断。
  3. 中断响应：满足响应条件（无总线请求、执行完现行指令；可屏蔽中断还须 CPU 允许中断）后，CPU 自动关中断、自动将 FR、CS、IP 压栈保护断点、取得服务程序入口地址并进入。
  4. 中断处理：服务程序执行 PUSH 保护现场 → 开中断 → 执行中断任务 → 关中断 → POP 恢复现场 → 开中断。
  5. 中断返回：执行 IRET，从堆栈恢复 IP、CS 与 FR，CPU 回到断点继续执行主程序。
- **常见错误**：遗漏中断排队阶段；把"保护现场"（服务程序中 PUSH 通用寄存器）与"自动保护断点现场"（CPU 自动压入 FR、CS、IP）混为一谈；遗漏各步的开/关中断时机。

### 方法 4：软件查询法识别中断源与确定优先级（编写查询程序）

- **适用场景**：多个外部中断源经"或"电路共用 CPU 一条 INTR 请求线，需靠软件确定是哪个中断源发出请求并按优先级服务；设备数量不多、对响应速度要求不高的场合。
- **已知条件**：中断请求锁存器的端口地址（IPORT，如 XXH）；各设备与锁存器数据位的对应关系（如 0#~3# 对应 D7~D4）；请求信号的有效电平约定（本接口为高电平有效）；各设备服务程序入口标号（SEV0、SEV1、…）。
- **计算步骤**：
  1. 读入请求信息：执行 `IN AL, IPORT`，把锁存器保存的请求信息读入 AL（0#~3# 的请求状态分别位于 D7~D4，高电平表示有请求）。
  2. 测试最高优先级位：执行 `TEST AL, 80H`（80H=1000 0000B，只测 D7 即 0#）；若 D7=1，TEST 结果非零使 ZF=0；若 D7=0，则 ZF=1。
  3. 条件转移：执行 `JNZ SEV0`——ZF=0（即 0# 有请求）则转到 0# 的服务程序 SEV0；ZF=1 则顺序执行下一条。
  4. 依次测试下一级：执行 `TEST AL, 40H`（测 D6 即 1#）后 `JNZ SEV1`；`TEST AL, 20H`（测 D5 即 2#）后 `JNZ SEV2`；`TEST AL, 10H`（测 D4 即 3#）后 `JNZ SEV3`；若还有更多中断源，按位权递减继续（80H 的一半 40H、再一半 20H、10H 之后为 08H、04H、02H、01H，依次测 D3~D0）。
  5. 结果：被查出的设备转入其服务程序；查询顺序即优先级顺序——最先被测试的位对应的中断源优先级最高，故本例优先级从高到低为 0#、1#、2#、3#。
- **常见错误**：查询顺序与要求的优先级次序不一致（把低优先级设备的测试排在前面；先查询的位即高位 D7 先查，优先级最高）；测试位号与设备编号对应关系弄错（80H 对应 D7 即 0# 设备）；有效电平约定理解反（本接口为高电平有效，锁存器位为 1 表示有请求；若为低电平有效则应改测"某位=0"并相应改变转移条件）；用 AND 指令代替 TEST（AND 会修改 AL 内容，TEST 只置标志位不改变 AL）；漏测某一位，导致对应设备有请求也永远查不到。

### 方法 5：74LS148 优先编码器查表确定输出编码

- **适用场景**：用硬件中断优先权电路确定多路中断请求的优先级编码；或在题目中给出 74LS148 的输入状态，求输出 A2A1A0、GS、E0。
- **已知条件**：使能端 E1 的电平；8 路输入 I0~I7 的电平（低电平有效，0 表示有请求）；74LS148 真值表。
- **计算步骤**：
  1. 判使能：若 E1=1，芯片不工作，输出 A2A1A0=111、GS=1、E0=1，结束；若 E1=0，进入第 2 步。
  2. 判有无请求：若 I0~I7 全为 1（无有效输入），输出 A2A1A0=111、GS=1、E0=0，结束；否则进入第 3 步。
  3. 找编码对象：从 I7 到 I0 依次检查，第一个为 0（有效）的输入即编码对象。例如 E1=0 且 I5=0、I6=I7=1，则编码对象为 I5。
  4. 查表得输出：按编码对象查真值表对应行。编码对象为 I7 时 A2A1A0=000；I6 时 001；I5 时 010；I4 时 011；I3 时 100；I2 时 101；I1 时 110；I0 时 111。存在有效编码时 GS=0、E0=1。
  5. 结果：例如 I5 被编码 → A2A1A0=010、GS=0、E0=1。A2A1A0 是被编码输入编号的二进制反码（编号 5=101B，取反得 010），GS=0 表示编码有效。
- **常见错误**：把 A2A1A0 直接读作优先级编号（输出是编号的反码，需对输出取反才是编号）；把输入当成高电平有效（74LS148 低电平有效，0 才表示有请求，与查询中断接口的高电平有效约定不同）；忽略 E1 使能条件，在 E1=1 时仍按编码表求输出；多个输入同时有效时取错对象（应取编号最大的有效输入，即 I7 优先）。

### 方法 6：中断优先级实现方式的选择

- **适用场景**：设计中断系统时，在软件查询法、硬件中断优先权电路、可编程中断控制器三种实现方式之间进行选择。
- **已知条件**：系统的中断源数量、对中断响应速度的要求、软硬件实现成本约束。
- **计算步骤**：
  1. 评估硬件约束：若希望硬件开销最小、可接受较慢的响应速度，选软件查询法（特点：只需少量硬件支持；代价：中断响应慢）。
  2. 评估软件约束：若希望软件工作量小、响应快，选硬件中断优先权电路（如 74LS148；特点：软件工作量小）。
  3. 评估功能要求：若需要功能最强、可灵活管理多级中断（如嵌套、屏蔽、级联），选可编程中断控制器（如 8259；特点：功能最强）。
  4. 结果：三种方式按功能强弱排序为 软件查询法 < 硬件中断优先权电路 < 可编程中断控制器；按硬件成本排序相反。
- **常见错误**：只比较硬件成本而忽略响应速度指标；在中断源多、实时性要求高的场合仍选用软件查询法（其响应慢的缺点会被放大）；认为三种方式功能等价、可随意互换。

## 例题汇总

### 例题 1：中断 VS 子程序有何不同点和相同点？（思考题，第 6 页）

**题干**：中断 VS 子程序，有何不同点和相同点？

**解**（依据课件范围内概念整理）：

- 不同点：
  1. 触发方式不同：中断由随机外部事件触发，发生时刻不可预测；子程序由主程序按程序流程用 CALL 指令调用，调用位置固定。
  2. 返回指令不同：中断服务程序用 IRET 返回，IRET 恢复 FR、CS、IP 三个寄存器；子程序用 RET 返回，RET 只恢复 CS、IP。
  3. 断点保存方式不同：中断响应时 CPU 自动把 FR、CS、IP 压入堆栈；子程序调用只自动保存 CS、IP。
  4. 开/关中断处理不同：中断服务程序需考虑保护现场后的开中断与恢复现场前的关中断；子程序一般无需此类处理。
- 相同点：二者都是转入另一段程序执行、执行完毕后返回原程序继续执行，返回后主程序从断点处继续。

**答案**：见上（课件本页未附参考答案）。

### 例题 2：IRET 与 RET 有何区别？（思考题，第 17 页）

**题干**：中断返回指令 IRET 和一般子程序返回指令 RET 有何区别？

**解**：

第 1 步：分析 RET 的恢复内容——RET 从堆栈弹出并恢复 CS、IP（共 2 个寄存器），用于子程序返回。

第 2 步：分析 IRET 的恢复内容——IRET 从堆栈弹出并恢复 IP、CS、FR（标志寄存器，共 3 个寄存器），弹出顺序与响应中断时 FR、CS、IP 的压入顺序相反。

第 3 步：指出 FR 恢复的意义——FR 的恢复使主程序中断前的标志状态还原，这是 IRET 相对 RET 多出的功能。

第 4 步：验证——中断响应时 CPU 自动压入 FR、CS、IP 三项（知识点 11），故返回时须弹出三项才能与保存内容一一对应；子程序调用只压入 CS、IP，故 RET 弹出两项即可。

**答案**：区别在于恢复的内容不同——IRET 比 RET 多恢复一个标志寄存器 FR。

### 例题 3：查询中断接口举例——求优先级顺序（第 21 页）

**题干**：
8086CPU 经查询中断接口连接 4 个外部中断源 0#~3#（注：中断信号高电平有效）。各中断源的请求信号经锁存器保存，分别接至数据总线的 D7、D6、D5、D4。CPU 通过端口 IPORT 读取中断请求信息，查询程序如下：

```
IN   AL,IPORT   ; 取中断请求信息
TEST AL,80H     ; 查询D7=1？
JNZ  SEV0       ; 不为0转SEV0
TEST AL,40H     ; 查询D6=1？
JNZ  SEV1       ; 不为0转SEV1
TEST AL,20H     ; 查询D5=1？
JNZ  SEV2       ; 不为0转SEV2
TEST AL,10H     ; 查询D4=1？
JNZ  SEV3       ; 不为0转SEV3
        …
```

问：优先级顺序？

**解**：

第 1 步：确定每条 TEST 指令测试的位与位权：80H=1000 0000B 只测 D7；40H=0100 0000B 只测 D6；20H=0010 0000B 只测 D5；10H=0001 0000B 只测 D4。

第 2 步：确定每个数据位对应的中断源：接口中 0# 接 D7、1# 接 D6、2# 接 D5、3# 接 D4（高电平表示该源有请求）。

第 3 步：按查询顺序定优先级：程序最先测试 D7（`TEST AL,80H`）。若 0# 有请求（D7=1），TEST 使 ZF=0，`JNZ SEV0` 立即转入 0# 的服务程序 SEV0，后面各位不再查询。因此最先被查询的 0# 优先级最高。

第 4 步：依次类推：第二次测试 D6（1#）次之；第三次测试 D5（2#）再次之；最后测试 D4（3#）优先级最低。

第 5 步：用原始数据验证：设 0# 与 3# 同时有请求，则 AL 的 D7=1、D4=1、其余位为 0，即 AL=1001 0000B=90H。执行 `TEST AL,80H` 时 90H AND 80H = 80H ≠ 0，ZF=0，`JNZ SEV0` 成立，CPU 先服务 0#；而 3#（D4=1）要到 0#、1#、2# 全部查完（均无请求）才会被 `TEST AL,10H` 查到。这与"0# 优先级最高、3# 优先级最低"的结论一致。

**答案**：优先级顺序（从高到低）：0# ＞ 1# ＞ 2# ＞ 3#。

说明：第 20 页"软件查询中断源"电路图只给出各外设请求信号经"或"电路汇总为总请求 INT（经端口 XXH 读取）的结构；优先级由查询程序的逐位测试顺序决定——先查的位优先级高（D7 → D6 → D5 → D4）。

### 例题 4：74LS148 优先编码器的编码计算（第 25 页）

**题干**：
74LS148 优先编码器用于硬件中断优先权电路。8 路输入 I0~I7 低电平有效（0 表示有请求），使能端 E1 低电平有效；I7 输入的中断请求具有最高优先级，I0 输入的中断请求具有最低优先级。已知 E1=0，且 I5=0、其余输入 I0~I4、I6、I7 均为 1，求输出 A2A1A0 以及状态输出 GS、E0 的值。

**解**：

第 1 步：判使能。E1=0，芯片处于使能（编码）状态，继续查表；若 E1=1 则直接得 A2A1A0=111、GS=1、E0=1。

第 2 步：判有无请求。输入中有 I5=0，即存在有效请求（输入不全为 1），芯片进行编码；若 I0~I7 全为 1，则 A2A1A0=111、GS=1、E0=0。

第 3 步：找最高优先级有效输入。按 I7→I0 的顺序检查：I7=1（无请求）、I6=1（无请求）、I5=0（有请求），第一个为 0 的是 I5，故编码对象为 I5。

第 4 步：查真值表。对应行：E1=0，I5=0、I6=1、I7=1，I0~I4 为 X（任意）→ 输出 A2A1A0=010。

第 5 步：查状态输出。该行 GS=0（编码有效），E0=1（芯片已使能且处于编码工作状态）。

第 6 步：用原始数据验证。I5 的编号为 5，二进制为 101B，其反码为 010B；查表所得 A2A1A0=010，等于编号 5 的反码，符合"输出为被编码输入编号的二进制反码"的规律。GS=0 与"存在有效编码"一致，E0=1 与"芯片使能且正在编码"一致。

**答案**：A2A1A0 = 010，GS = 0，E0 = 1。

补充验证（同一真值表）：若 E1=0 且 I7=0、其余任意，则编码对象为 I7，输出 A2A1A0=000（7=111B 的反码为 000B）、GS=0、E0=1，I7 为最高优先级输入；若 E1=0 且 I0=0、其余全 1，则输出 A2A1A0=111（0=000B 的反码为 111B）、GS=0、E0=1，I0 为最低优先级输入。两种边界情况均与真值表第 3 行、第 10 行一致。
