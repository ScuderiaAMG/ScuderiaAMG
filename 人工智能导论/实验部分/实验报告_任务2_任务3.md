## <a id="实验二"></a>实验二：基于 Q-Learning 的迷宫寻路强化学习系统

### 1. 问题分析

#### 1.1 任务描述

本实验要求基于 Q-Learning 强化学习理论，设计并实现一个迷宫寻路系统。智能体从迷宫中的 **Start** 位置出发，通过与环境交互不断学习，最终找到通往 **Goal** 位置的最优路径。系统需满足以下功能需求：

- 迷宫规模（行数、列数）可动态调整；
- 障碍物数量和位置随机生成；
- 提供图形化人机界面（GUI），支持参数调节、训练过程可视化与最优路径展示。

#### 1.2 问题建模

迷宫寻路问题可形式化为 **马尔可夫决策过程（Markov Decision Process, MDP）**，定义如下五元组 $\langle S, A, P, R, \gamma \rangle$：

| 符号 | 含义 | 本系统定义 |
|------|------|-----------|
| $S$ | 状态空间 | 迷宫中所有可行走格子坐标的集合，$S = \{(r, c) \mid 0 \le r < \text{rows},\ 0 \le c < \text{cols},\ (r,c) \notin \text{obstacles}\}$，外加终止状态 $\text{terminal}$ |
| $A$ | 动作空间 | $\{0, 1, 2, 3\}$，分别表示**上、下、左、右**四个方向移动 |
| $P$ | 状态转移概率 | 确定性转移，$P(s' \mid s, a) = 1$（动作执行后必然到达目标格；碰撞障碍物则留在原地） |
| $R$ | 奖励函数 | $R(s, a, s')$：到达目标 +100，撞障碍物 -10 并留在原地，空地每步 -1 |
| $\gamma$ | 折扣因子 | $\gamma = 0.9$，用于平衡即时奖励与未来奖励 |

#### 1.3 核心挑战

- **探索与利用（Exploration vs. Exploitation）的平衡**：智能体需在随机探索未知路径与利用已有知识之间做出权衡。
- **收敛性判定**：如何自动检测 Q 表已收敛至最优策略，从而停止训练。
- **最优路径提取**：收敛后如何从 Q 表中提取可视化最优路径。
- **高维状态空间**：随着迷宫尺寸增大，状态-动作组合急剧膨胀，考验 Q 表的存储与更新效率。

### 2. 算法原理

#### 2.1 Q-Learning 算法

Q-Learning 是一种经典的**无模型（model-free）**、**离策略（off-policy）** 时序差分（Temporal Difference, TD）强化学习算法。其核心思想是通过迭代更新状态-动作价值函数 $Q(s, a)$，使得智能体在任意状态 $s$ 下都能选择使期望累积奖励最大化的动作 $a$。

**Q 值更新公式（TD 更新规则）：**

$$Q(s, a) \leftarrow Q(s, a) + \alpha \left[ r + \gamma \cdot \max_{a'} Q(s', a') - Q(s, a) \right]$$

其中：
- $\alpha = 0.1$（学习率）：控制每次更新对误差的接纳程度，值越小学习越平稳但越慢；
- $\gamma = 0.9$（折扣因子）：$\gamma \to 1$ 表示智能体更关注长期回报，$\gamma \to 0$ 则更短视；
- $r + \gamma \cdot \max_{a'} Q(s', a')$ 为 **TD 目标（TD Target）**，即当前动作的"应有价值"；
- $r + \gamma \cdot \max_{a'} Q(s', a') - Q(s, a)$ 为 **TD 误差（TD Error）**，即"期望"与"现实"的差距。

**终止状态处理**：当 $s' = \text{terminal}$（智能体到达目标），不存在后续状态，因此：

$$Q(s, a) \leftarrow Q(s, a) + \alpha \left[ r - Q(s, a) \right]$$

#### 2.2 ε-贪心动作选择策略

智能体在每个状态下以概率 $\varepsilon$ 执行**利用（Exploitation）**，即选择当前 Q 值最大的动作；以概率 $1 - \varepsilon$ 执行**探索（Exploration）**，即从动作空间中随机选择。形式化表示为：

$$a = \begin{cases} \arg\max_{a} Q(s, a) & \text{以概率 } \varepsilon = 0.9 \\ \text{random}(A) & \text{以概率 } 1 - \varepsilon = 0.1 \end{cases}$$

当多个动作共享最大 Q 值时，从这些最优候选中等概率随机选择，避免确定性偏差。

#### 2.3 收敛检测机制

本系统引入了一种基于"步数稳定"的启发式收敛检测方法：

$$g_t = \begin{cases} g_{t-1} + 1 & \text{if } \text{steps}_t = \text{steps}_{t-1} \\ 0 & \text{otherwise} \end{cases}$$

其中 $g_t$ 为连续稳定回合计数器，$\text{steps}_t$ 为第 $t$ 个 episode 中智能体到达目标所需步数。当 $g_t \ge 3$（连续 3 个回合步数完全相同），判定 Q-Learning 已收敛至最优策略。

**理论依据**：在确定性环境中，若智能体已掌握最优策略，则每个 episode 将沿相同路径到达目标，步数不变。连续 3 次一致足以排除随机扰动。

### 3. 系统设计与实现

#### 3.1 系统架构

系统采用**三层解耦架构**，分别为算法层、环境层与表示层：

```
┌─────────────────────────────────────┐
│         MazeApp (表示层)              │
│  ┌───────────┐  ┌────────────────┐  │
│  │ MazeCanvas │  │ 控制面板/按钮   │  │
│  │ (迷宫渲染)  │  │ (参数调节/训练) │  │
│  └─────┬─────┘  └───────┬────────┘  │
│        │                │            │
│  ┌─────┴────────────────┴────────┐  │
│  │    QLearningAgent (算法层)      │  │
│  │  - choose_action()             │  │
│  │  - learn() (TD更新)            │  │
│  │  - Q表管理 (dict-based)        │  │
│  └────────────────────────────────┘  │
│              │                        │
│  ┌───────────┴─────────────────────┐ │
│  │    MazeCanvas (环境层)           │ │
│  │  - step() (状态转移 & 奖励)       │ │
│  │  - 碰撞检测 & 边界检查            │ │
│  │  - 障碍物随机生成                 │ │
│  └─────────────────────────────────┘ │
└─────────────────────────────────────┘
```

#### 3.2 核心类设计

**（1）`QLearningAgent` —— Q-Learning 智能体**

| 方法 | 功能 |
|------|------|
| `__init__(actions, lr=0.1, gamma=0.9, epsilon=0.9)` | 初始化超参数与空 Q 表（惰性初始化字典 `{(r,c): [Q_up, Q_down, Q_left, Q_right]}`） |
| `check_state_exist(state)` | 惰性初始化：首次遇到某状态时，在 Q 表中为其创建全零向量 |
| `choose_action(state, test_mode=False)` | ε-贪心策略选择；`test_mode=True` 时跳过探索（用于最优路径提取） |
| `learn(s, a, r, s_)` | 执行 TD 更新，区分终止状态（$Q_{\text{target}} = r$）与非终止状态（$Q_{\text{target}} = r + \gamma \cdot \max Q(s')$） |

Q 表采用字典存储而非完整矩阵，优势在于：
- **内存效率**：仅记录访问过的状态，适合稀疏迷宫；
- **状态泛化**：可自然扩展到非网格环境，状态键为任意可哈希元组。

**（2）`MazeCanvas(QWidget)` —— 迷宫画布**

| 方法 | 功能 |
|------|------|
| `reset_env()` | 重置起点 $(0,0)$、终点 $(\text{rows}-1, \text{cols}-1)$、障碍物列表、最优路径 |
| `generate_obstacles()` | 随机生成指定数量的障碍物，保证不覆盖起点和终点 |
| `step(action)` | 执行动作并返回 `(next_state, reward, done)`；包含边界检查和碰撞检测 |
| `paintEvent(event)` | 三层渲染：网格底色（起点蓝/终点绿/障碍灰/空地白）→ 金色最优路径线 → 红色智能体小球 |

**（3）`MazeApp(QMainWindow)` —— 主窗口控制器**

| 方法 | 功能 |
|------|------|
| `train_step()` | Q-Learning 单步迭代，由 `QTimer` 以 10ms 间隔驱动；执行 action → step → learn 循环 |
| `toggle_training()` | 训练启动/暂停切换 |
| `extract_and_draw_optimal_path()` | 收敛后从起点出发，使用 `test_mode=True` 的贪心策略提取完整路径 |
| `generate_new_maze()` | 重置迷宫参数、Q 表、训练计数器，重新生成障碍物 |

#### 3.3 奖励函数设计

奖励信号的精心设计是 Q-Learning 收敛性能的关键。本系统采用三层奖励结构：

| 事件 | 奖励值 | 设计意图 |
|------|--------|---------|
| 到达 Goal | **+100** | 稀疏但强烈的正向激励，驱动智能体克服每步 -1 的代价 |
| 撞障碍物 | **-10** | 惩罚无效移动，同时保留原地（不重置回合），使智能体学会避开障碍 |
| 空地行走 | **-1** | 每步微罚，驱动智能体寻找**最短路径**（步数越少，负累积越小） |

**Why 不设大负奖励？** 若撞墙给予过大的负奖励（如 -100），智能体可能因恐惧探索而永远学不会穿越狭窄通道。当前 -10 足以区分"无效"与"倒退"，但不会摧毁学习信号。

#### 3.4 关键实现细节

**（1）碰撞处理：原地停留**

```python
# maze_rl2.py, MazeCanvas.step(), line 92-96
elif next_state in self.obstacles:
    reward = -10   # 撞墙惩罚
    done = False
    next_state = s  # 留在原地
    self.agent_pos = list(s)
```

智能体碰撞障碍物后**不终止回合**，而是留在原地并承受 -10 惩罚。这样设计使智能体能从失败中学习——它将在 Q 表中将该格子→障碍物方向的动作价值降低，从而在后续回合中自然规避。

**（2）TD 目标的分情况处理**

```python
# maze_rl2.py, QLearningAgent.learn(), line 34-41
def learn(self, s, a, r, s_):
    self.check_state_exist(s_)
    q_predict = self.q_table[s][a]
    if s_ != 'terminal':
        q_target = r + self.gamma * np.max(self.q_table[s_])
    else:
        q_target = r  # 终点的TD目标（无未来）
    self.q_table[s][a] += self.lr * (q_target - q_predict)
```

终止状态 `terminal` 不在 Q 表中（它是哨兵值而非真实坐标），因此必须单独处理——其 Q 值恒为 0，TD 目标简化为即时奖励 $r$。

**（3）test_mode 在路径提取中的应用**

```python
# maze_rl2.py, QLearningAgent.choose_action(), line 22-32
def choose_action(self, state, test_mode=False):
    self.check_state_exist(state)
    if test_mode or np.random.uniform() < self.epsilon:
        # 纯贪心：选最大Q值动作
        ...
    else:
        action = random.choice(self.actions)  # 随机探索
```

收敛后调用 `extract_and_draw_optimal_path()` 时，以 `test_mode=True` 遍历所有状态，确保提取出的路径是**确定性最优策略**，不受 ε-贪心的随机性干扰。

**（4）收敛检测与自动停机**

```python
# maze_rl2.py, MazeApp.train_step(), line 248-263
if done:
    self.episode_count += 1
    if self.current_steps == self.last_episode_steps:
        self.stable_count += 1
    else:
        self.last_episode_steps = self.current_steps
        self.stable_count = 0
    if self.stable_count >= self.convergence_threshold:  # 3
        self.toggle_training()  # 自动暂停
        self.extract_and_draw_optimal_path()
```

每次 episode 结束时比较当前步数与上回合步数。若连续 3 个 episode 步数相同，触发自动停机、绘制金色最优路径并弹窗提示。

## <a id="实验三"></a>实验三：基于产生式系统的动物识别专家系统

### 1. 问题分析

#### 1.1 任务描述

本实验要求基于**产生式系统（Production System）** 理论，设计并实现一个动物识别专家系统。系统接收用户输入的动物特征观察，通过正向推理（数据驱动）识别出**虎、金钱豹、斑马、长颈鹿、鸵鸟、企鹅、信天翁**七种目标动物之一。核心功能需求：

- 提供图形化特征选择界面（复选框）；
- 实现完整的三层优先级产生式推理引擎；
- 支持推理过程的可视化追踪（解释机构）；
- 知识库支持外部 JSON 文件配置，可扩展至更多物种。

#### 1.2 产生式系统形式化定义

产生式系统由三个核心组件构成：

$$\text{Production System} = \langle \text{KB}, \text{WM}, \text{IE} \rangle$$

| 组件 | 符号 | 定义 |
|------|------|------|
| **知识库（Knowledge Base）** | KB | 规则集合 $\{R_1, R_2, \dots, R_{15}\}$，每条规则 $R_i = \langle P_i, C_i, \text{priority}_i \rangle$，其中 $P_i$ 为前提集，$C_i$ 为结论 |
| **工作内存（Working Memory）** | WM | 当前已知事实的动态集合，初始为用户选择的特征，逐步扩增推理结论 |
| **推理引擎（Inference Engine）** | IE | 执行正向链接（Forward Chaining）的匹配-选择-执行循环 |

#### 1.3 知识库结构分析

系统知识库包含 **15 条产生式规则**，分三个优先级层级：

**优先级 1（基础分类规则，4 条）**：将原始可观察特征映射到生物类别。

| 规则 ID | 前提条件 | 结论 |
|---------|---------|------|
| R1 | {有毛发} | 哺乳动物 |
| R2 | {产奶} | 哺乳动物 |
| R3 | {有羽毛} | 鸟类 |
| R4 | {会飞, 下蛋} | 鸟类 |

**优先级 2（中间推理规则，4 条）**：在类别基础上进一步细分。

| 规则 ID | 前提条件 | 结论 | 备注 |
|---------|---------|------|------|
| R5 | {吃肉} | 食肉动物 | |
| R6 | {有犬齿, 有爪, 眼盯前方} | 食肉动物 | 多条件合取 |
| R7 | {哺乳动物, 有蹄} | 有蹄类动物 | 依赖 P1 推理结果 |
| R8 | {哺乳动物, 反刍} | 有蹄类动物 | 依赖 P1 推理结果 |

**优先级 3（最终识别规则，7 条）**：组合多层级特征识别具体物种。

| 规则 ID | 前提条件 | 结论 |
|---------|---------|------|
| R9 | {哺乳动物, 食肉动物, 黄褐色, 黑色条纹} | 虎 |
| R10 | {哺乳动物, 食肉动物, 黄褐色, 暗斑点} | 金钱豹 |
| R11 | {有蹄类动物, 黑色条纹} | 斑马 |
| R12 | {有蹄类动物, 长脖子, 长腿, 暗斑点} | 长颈鹿 |
| R13 | {鸟类, 长脖子, 长腿, 不会飞, 黑白二色} | 鸵鸟 |
| R14 | {鸟类, 会游泳, 不会飞, 黑白二色} | 企鹅 |
| R15 | {鸟类, 善飞} | 信天翁 |

**规则的依赖关系图**：优先级 3 的前提中包含优先级 2 的结论（如"食肉动物"），优先级 2 的前提中又包含优先级 1 的结论（如"哺乳动物"），形成了**三层递进推理链**。这种分层设计是专家系统的典型知识工程实践——将复杂识别任务分解为"原始特征 → 中间类别 → 最终物种"的层级推理。

#### 1.4 关键挑战

- **冲突消解（Conflict Resolution）**：多条规则可能同时被满足（例如 R1 和 R2 均可推出"哺乳动物"），需确定触发顺序。
- **部分匹配处理**：当用户输入特征不足以唯一确定目标动物时，系统应给出部分匹配的候选列表。
- **可扩展性**：知识库应易于通过外部配置文件添加新物种和新规则，无需修改推理引擎代码。
- **推理可解释性**：完整记录推理链，使用户理解"系统为什么得出此结论"。

### 2. 算法原理

#### 2.1 正向链接（Forward Chaining）推理算法

正向链接是一种**数据驱动（data-driven）** 的推理策略：从已知事实出发，反复应用规则推导新事实，直至无法再推导或已识别出目标。算法伪代码如下：

```
Algorithm: ForwardChaining(KB, initial_facts)
Input:  KB = {R_1, ..., R_n} 知识库规则集
        initial_facts 用户提供的初始事实集
Output: (target, WM, explanation_log)

1.  WM ← initial_facts                    // 初始化工作内存
2.  used_rules ← ∅                        // 已触发的规则集（防止重复触发）
3.  step ← 1
4.  while True:
5.      conflict_set ← ∅
6.      for each R_i ∈ KB:
7.          if R_i.id ∉ used_rules AND R_i.premise ⊆ WM:
8.              conflict_set ← conflict_set ∪ {R_i}
9.      if conflict_set = ∅:
10.         break                           // 无可触发规则，推理终止
11.     selected ← ConflictResolution(conflict_set)
12.     used_rules ← used_rules ∪ {selected.id}
13.     WM ← WM ∪ {selected.conclusion}
14.     log(step, selected)
15.     step ← step + 1
16.     if selected.conclusion ∈ targets:
17.         return (selected.conclusion, WM, log)
18. return (None, WM, log)                 // 未能唯一识别
```

**时间复杂度分析**：每轮迭代扫描全部未使用规则，最坏情况下每条规则触发一次，总匹配次数为 $O(|R|^2)$。对于 15 条规则的小规模知识库，性能完全可接受。

**终止条件**：推理在两种情况下终止——(a) 推导出目标动物（成功）；(b) 冲突集为空且无目标命中（失败）。

#### 2.2 冲突消解策略

当冲突集中存在多条可触发规则时，需要选择一条优先执行。本系统采用**两级排序**策略：

$$\text{order}(R_i) = \big( \text{priority}(R_i),\ -\lvert P_i \rvert \big)$$

- **第一关键字**：$\text{priority}$ 升序（数字越小优先级越高，确保基础分类规则先于最终识别规则触发）；
- **第二关键字**：前提数量 $\lvert P \rvert$ 降序（在相同优先级下，前提更多、更具体的规则优先触发，符合"特殊性优先"原则）。

**示例**：若冲突集包含 $\{\text{R1}(P=1, |P|=1), \text{R2}(P=1, |P|=1)\}$，二者优先级与前提数均相等，排序稳定，先触发索引靠前者。这不会导致错误推理，因为 R1("有毛发") 和 R2("产奶") 的结论相同（均为"哺乳动物"），且`used_rules`机制阻止重复添加。

#### 2.3 部分匹配与依赖树递归

当精确正向链推推理失败（未能命中任一目标动物）时，系统提供**基于特征交集的候选推荐**：

**步骤 1：构建特征依赖树**

对于每个候选目标动物 $T$，递归展开其完整特征依赖树 $D(T)$：

$$D(T) = \{T\} \cup \bigcup_{R: \text{conclusion}(R)=T} \left( P(R) \cup \bigcup_{p \in P(R)} D(p) \right)$$

其中 $P(R)$ 为规则 $R$ 的前提集。递归过程通过 `visited` 集合防止循环依赖。

**步骤 2：计算交集**

对每个目标 $T$，计算 $D(T)$ 与当前工作内存 WM 的交集：

$$\text{match}(T) = D(T) \cap \text{WM}$$

**步骤 3：排序推荐**

按命中特征数量降序排列候选：

$$\text{candidates} = \text{sort}_{|\text{match}(T)| \downarrow} \big\{ (T, \text{match}(T)) \mid \text{match}(T) \neq \emptyset \big\}$$

向用户展示每个候选动物的名称及其命中特征列表，帮助用户判断还需补充哪些特征的观察。

#### 3.2 核心类设计

**（1）`Rule` —— 规则数据类**

```python
class Rule:
    def __init__(self, rule_id, premise, conclusion, priority=1):
        self.rule_id = rule_id       # 规则标识符 e.g. "R9"
        self.premise = set(premise)  # 前提集转为set支持快速子集判断
        self.conclusion = conclusion # 推理结论
        self.priority = priority     # 数字越小越优先
```

**（2）`KnowledgeBase` —— 知识库管理器**

| 方法 | 功能 |
|------|------|
| `load_from_json(json_path)` | 解析 JSON 知识库文件，加载规则列表并自动推导终端目标 |
| `get_all_premises()` | 提取仅由用户直接观察的特征（排除中间结论和目标），供 UI 复选框动态生成 |

**自动推导终端目标算法**：

```python
# animal_expert2.py, KnowledgeBase.load_from_json(), line 48-59
if "targets" in data:
    self.targets = set(data["targets"])
else:
    all_premises = set()
    all_conclusions = set()
    for r in self.rules:
        all_premises.update(r.premise)
        all_conclusions.add(r.conclusion)
    # 出现在结论里但从未作为前提的 → 即最终目标动物
    self.targets = all_conclusions - all_premises
```

此设计的关键优势：当添加新动物规则时，**无需手动声明 `targets`**——系统自动识别"仅作为结论出现、从未作为前提使用"的节点为终端目标。这使知识库的扩展异常简便：只需在 JSON 中添加新规则即可。

**（3）`InferenceEngine` —— 推理引擎**

| 方法 | 功能 |
|------|------|
| `forward_chaining(initial_facts)` | 执行正向链推推理，返回 `(target, final_WM, explanation_log)` |

核心数据结构：
- `working_memory: Set[str]` — 动态事实集（初始为用户选择）；
- `used_rules: Set[str]` — 已触发规则集，防止同一条规则被反复触发；
- `explanation_log: List[str]` — 逐步推理记录，实现推理可解释性。

**（4）`AnimalExpertSystem(QWidget)` —— 主界面**

| 方法 | 功能 |
|------|------|
| `initUI()` | 构建左右分栏布局：左侧 QScrollArea 特征选择 + 按钮区，右侧 QTextEdit 日志展示区 |
| `run_inference()` | 收集选中特征 → 调用 `forward_chaining` → 成功则展示推理链，失败则计算部分匹配候选 |
| `reset_features()` | 清除所有复选框勾选状态及日志区域 |

#### 3.3 关键实现细节

**（1）冲突消解的实现**

```python
# animal_expert2.py, InferenceEngine.forward_chaining(), line 103-104
conflict_set.sort(key=lambda r: (r.priority, -len(r.premise)))
selected_rule = conflict_set[0]
```

通过一次 `sort` 完成两级排序：`r.priority` 升序（优先级数字小者在前），`-len(r.premise)` 降序（前提多者在前）。取排序后首个元素即可。

**（2）推理可解释性（解释机构）**

```python
# animal_expert2.py, InferenceEngine.forward_chaining(), line 111-115
log_line = (f"-> 步骤 {step}: 触发规则 [{selected_rule.rule_id}]\n"
            f"   IF   {' AND '.join(selected_rule.premise)}\n"
            f"   THEN {selected_rule.conclusion}\n"
            f"   (事实库加入: '{selected_rule.conclusion}')\n")
self.explanation_log.append(log_line)
```

每步推理输出三个关键信息：(a) 触发了哪条规则，(b) 规则的前提（"因为什么"），(c) 规则的结论（"所以推导出什么"）。完整的推理链在右侧 QTextEdit 中逐行展示，实现了对用户透明的可解释 AI。

**（3）部分匹配的依赖树递归**

```python
# animal_expert2.py, AnimalExpertSystem.run_inference(), line 251-264
def get_all_dependencies(conclusion, visited=None):
    if visited is None:
        visited = set()
    if conclusion in visited:
        return set()  # 防环
    visited.add(conclusion)
    deps = set()
    for r in self.engine.kb.rules:
        if r.conclusion == conclusion:
            deps.update(r.premise)
            for p in r.premise:
                deps.update(get_all_dependencies(p, visited))
    return deps
```

递归搜索某结论的**完整前提依赖闭包**：对规则的每个前提，继续递归搜索其一级规则的前提，直至仅剩叶节点（用户可观察特征）为止。`visited` 集合防止在知识库存在循环依赖时的无限递归。

**（4）特征动态提取与 UI 生成**

```python
# animal_expert2.py, KnowledgeBase.get_all_premises(), line 64-71
def get_all_premises(self):
    all_conditions = set()
    for rule in self.rules:
        all_conditions.update(rule.premise)
    conclusions = {r.conclusion for r in self.rules}
    return sorted(list(all_conditions - conclusions - self.targets))
```

UI 的复选框从知识库中**动态计算**：取所有规则前提的并集，减去中间结论和最终目标。这意味着：
- 当在 JSON 中添加新动物和规则时，UI 会自动显示新特征；
- 不会在特征列表中显示"哺乳动物"、"虎"等推导结论（这些应由推理引擎得出，而非用户直接输入）。

## <a id="体会与建议"></a>体会与建议

### 实验收获

**实验二（Q-Learning 迷宫）的核心收获**：

1. **强化学习的直观理解**：通过亲手实现 TD 更新循环，深刻体会到"从试错中学习"的本质——每步奖励信号如同教师的批改，逐渐修正 Q 表使其逼近真实价值函数。
2. **探索-利用困境的工程权衡**：$\varepsilon$ 参数的调优直接影响收敛速度和最优性。$\varepsilon = 0.9$ 在本任务中表现良好，但在更复杂环境（如随机奖励、部分可观测）中可能需要衰减策略（如 $\varepsilon_t = \max(\varepsilon_{\min}, \varepsilon_{\text{init}} \cdot \text{decay}^t)$）。
3. **收敛判定的实践价值**：简单的"步数稳定"启发式比设定固定训练轮次更具工程实用性——避免过训（浪费计算）和欠训（未收敛即停机）。

**实验三（动物识别专家系统）的核心收获**：

1. **知识工程方法论**：将领域知识（15 条规则）从推理引擎（正向链接 + 冲突消解）中解耦，实现了"知识可配置"——这是专家系统的核心理念。JSON 知识库的设计让非编程人员也能维护和扩展知识。
2. **推理可解释性的重要性**：每步推理的完整日志（"因为 A，所以 B"）让用户信任系统的结论——这是现代 AI 可解释性（XAI）研究在专家系统中的早期实践。
3. **部分匹配的用户体验设计**：当精确推理失败时，基于特征交集提供候选建议，是一种优雅的"降级服务"——即使信息不完整，系统仍能提供有用输出。

### 改进方向

1. **迷宫 RL 系统**：
   - 引入 **ε-衰减策略**（$\varepsilon = 0.9 \to 0.01$），使训练后期更偏向利用；
   - 添加**随机起点/终点**选项，增强泛化能力；
   - 实现 **SARSA**（on-policy）与 Q-Learning（off-policy）的对比实验，直观对比两种 TD 方法的差异。

2. **动物专家系统**：
   - 引入**不确定性推理**（如确定性因子 CF），处理"可能"、"或许"等模糊特征；
   - 集成视觉感知模块（如 `vision_expert2.py` 中的 YOLOv8），实现"拍照→目标检测→特征映射→产生式推理"的端到端智能识别流水线；
   - 添加**反向链接（Backward Chaining）**模式，从目标动物出发反向询问缺失特征，实现交互式诊断。

### 对课程的建议

1. 实验指导书可增加对核心算法（Q-Learning TD 更新、正向链接冲突消解）的公式推导引导，帮助学生在编码前建立理论直觉；
2. 可增设"算法对比"环节——例如在迷宫任务中同时实现 Q-Learning 和 SARSA，在动物识别中同时实现正向链接和反向链接，通过实验数据对比不同方法的适用场景；
3. 引入轻量级基准测试（benchmark）——为迷宫任务设置标准格局（固定障碍物布局），对收敛步数和最优路径长度进行量化评估。
