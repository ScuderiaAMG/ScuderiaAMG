#### 🔹 第五步：切到代码，逐层讲解（60秒）

> *（切到代码编辑器，打开 maze_rl2.py）*

> "好，现在看代码是怎么实现的。整个文件大概三百行，分**三层**，我按从上到下的顺序讲。
>
> ---
>
> **第一层：智能体的大脑 —— QLearningAgent 类（第10行到第43行）**
>
> 这个类的核心就三个方法：
>
> **（1）Q 表是什么样的？（第11-16行初始化，第18行 check_state_exist）**
>
> Q 表是一个 Python 字典 `{}`——每个格子一张小抄。字典的**键**是智能体当前站在哪个格子，比如 `(0,1)` 表示第 0 行第 1 列（代码里行和列都是从 0 开始数的）。字典的**值**是一个列表 `[上方向的分数, 下方向的分数, 左方向的分数, 右方向的分数]`。
>
> 一开始字典是空的。智能体到达一个新格子时，`check_state_exist` 方法（第18行）会初始化这个格子的四个分数都为 0.0——四个方向都一视同仁。
>
> **（2）怎么选方向？ε-greedy 策略（第22行到第32行）**
>
> 这就像扔骰子。ε 设为 0.9，意思是 90% 的情况选当前分数最高的方向（这叫**利用**已有经验），10% 的情况随机选一个方向（这叫**探索**新可能）。
>
> 为什么要随机？因为如果只走分数最高的，可能永远困在一条次优路里走不出来。偶尔乱走一下，可能发现更好的路。
>
> 代码里 `np.random.uniform() < self.epsilon`（第25行）就是扔骰子——如果随机数小于 0.9，就找 Q 值最大的方向；否则就随机选。
>
> 注意这个方法还接受一个 `test_mode` 参数（第22行）。当 `test_mode=True` 时，直接跳过随机判断，永远选 Q 值最高的方向。这个参数**平时训练不用，只在最后提取最优路径时用**——因为那时已经学好了，不需要再探索。
>
> **（3）怎么更新 Q 表？（第34行到第41行）**
>
> 这是 Q-Learning 最核心的公式，写在 `learn` 方法里。我用大白话解释：
>
> `Q(s,a) += 学习率 × (目标值 - 当前值)`
>
> 展开就是：
>
> 当前值 = 这一步的 Q 分数（第36行 `q_predict`）
>
> 目标值 = 这一步的奖励 + 折扣因子 × 下一步所有方向里的最高分（第38行 `q_target`，走到终点时就是纯奖励，第40行）
>
> 最后第41行：`Q += lr × (target - predict)`，往目标方向挪一小步。
>
> 奖励 r 是环境给的（+100 到终点、-10 撞墙、-1 走一步）。
>
> 折扣因子 γ=0.9 的意思是'未来的奖励打九折'——鼓励智能体尽早到终点，不要绕远路。
>
> 学习率 α=0.1 的意思是'每次只改一点点'——防止一次学太多导致不稳定。
>
> ---
>
> **第二层：迷宫环境 —— MazeCanvas 类（第45行到第146行）**
>
> 这个类管三件事：
>
> **（1）随机生成障碍物（第65行到第74行）：** 用一个 while 循环，每次随机选一个格子，如果不是起点也不是终点、也没有和已有障碍物重复，就把它标为障碍物。数量和位置都是随机的。注意这里只检查了障碍物数量不超过总格子减 2，没有做连通性检测——如果障碍物排列恰好把路堵死，Q-Learning 可能永远无法收敛。这是一个已知限制，不过实际测试中随机生成基本不会遇到这种情况。
>
> **（2）执行动作 step 方法（第77行到第101行）：** 智能体告诉环境'我要往上走'，环境就检查：能走吗？走出边界就停在原地。走到终点给 +100 并标记完成。撞障碍物给 -10 并留在原地。走空地给 -1（每步扣一分，督促走最短路径）。
>
> **（3）绘制界面 paintEvent（第105行到第146行）：** 三层绘制——先画网格底色（起点蓝、终点绿、障碍物灰、空地白），再用金色线段画出最优路径，最上层画出红色的圆形智能体。
>
> ---
>
> **第三层：训练总控 —— MazeApp 类（第148行到第296行）**
>
> **（1）训练循环（第240行 train_step）：** 每一步 = 选动作 → 执行 → 学习 → 检查是否到终点。用 QTimer 定时器每 10 毫秒调用一次，训练跑得很快。
>
> **（2）迷宫生成时的安全检查（第215行）：** 在 `generate_new_maze` 方法里，如果障碍物数量 ≥ 格子总数减2，弹窗警告'障碍物过多，没有通道！'。这是一个基本防护——比如 4×4=16 格，放了 14+ 个障碍物，起点终点之间很可能完全堵死。
>
> **（3）收敛判定（第252-256行）：** 每回合结束时比较步数。如果连续三步步数不变，认为 Q 表在当前环境下已经稳定，自动停止训练。这是一个工程启发式方法，不是严格的数学收敛证明。
>
> **（4）最优路径提取（第270行 extract_and_draw_optimal_path）：** 收敛后从起点出发，每一步用 `test_mode=True` 纯贪婪选 Q 值最高的方向走，把路径存下来画金色线。同时带了一个 `visited` 集合（第274行）防止 Q 表中万一有环路导致死循环。另外如果走到障碍物也立刻停止——理论上收敛后不会，但这是防御性代码。"

#### 🔹 第五步：切到代码，逐层讲解（60秒）

> *（切到编辑器，先打开 knowledge.json，再打开 animal_expert2.py）*

> "好，现在看代码。整体分**三层架构**。在讲三层之前，先看一个承上启下的数据结构：
>
> **第零层：Rule 规则类（第10-16行）** —— 这是 JSON 和推理引擎之间的桥梁。PyQt5 从 JSON 加载每条规则后，不是直接用原始字典，而是包装成一个 `Rule` 对象。这个对象有四个字段：`rule_id`（规则编号）、`premise`（前提条件，存成 Python 的 set 集合，方便后面做子集判断）、`conclusion`（结论）、`priority`（优先级，数字越小表示越基础的规则，冲突消解时越优先触发）。用 set 集合的好处是，判断'当前事实是否满足规则前提'只需要一行 `premise.issubset(working_memory)`，一行搞定。
>
> ---
>
> **第一层：知识库 —— knowledge.json（打开这个文件）**
>
> 这是整个系统的'知识'部分，独立存储在一个 JSON 文件里，和 Python 代码分离。好处是**想加新动物，只改这个 JSON 文件就行，不用动推理引擎代码**。
>
> 文件里有一个 `targets` 列表，声明了 7 种目标动物。另外 `load_from_json` 方法（第36-61行）里还有一个兜底逻辑：如果 JSON 忘了写 `targets`，程序会自动扫描所有规则，找出那些**作为结论出现、但从不作为任何规则的前提条件**的概念——这些就是最终目标动物。当前 JSON 里显式声明了 targets 所以自动推导不会被触发，但留着这个机制可以让后续扩展更省事。
>
> 然后是 15 条 `rules`。每条规则有四个字段：
> - `id`：规则编号，R1 到 R15
> - `priority`：优先级，数字越小的越先触发（越基础的规则越先执行）
> - `premise`：前提条件列表，所有条件都满足才能触发
> - `conclusion`：结论，触发后把什么新事实加入工作内存
>
> 比如 R9（第52-57行）：
> ```json
> {"id": "R9", "priority": 3, "premise": ["哺乳动物", "食肉动物", "黄褐色", "黑色条纹"], "conclusion": "虎"}
> ```
> 翻译成人话：**如果**这个动物同时是哺乳动物、食肉动物、黄褐色、有黑色条纹，**那么**它就是虎。
>
> R14（第82-87行）识别企鹅：**如果**是鸟类、会游泳、不会飞、黑白二色，**那么**就是企鹅。
>
> 如果想加'鹰'，在 JSON 里加一条规则 `{"premise": ["鸟类", "善飞", "钩状喙"], "conclusion": "鹰"}`，确保'钩状喙'这个新特征能被 UI 自动提取到，不需要改 Python 代码。当然，前提是知识库里已经有规则能推出'鸟类'——对于鹰来说 R3 或 R4 已经可以做到。
>
> ---
>
> **第二层：推理引擎 —— InferenceEngine 类（第74行）**
>
> 这是系统的'大脑'。核心方法是 `forward_chaining`（正向推理，第79行）。
>
> 正向推理的过程就像**多米诺骨牌**，有三个阶段循环执行：
>
> **阶段1 — 匹配（第96-99行）：** 扫描所有规则，找出哪些规则的前提条件全部在当前工作内存中。关键细节——用 `used_rules` 集合（第87行）记录已触发的规则编号，匹配时跳过用过的规则（第97行 `rule.rule_id not in used_rules`），**防止同一条规则反复触发导致死循环**。比如 R1 '有毛发→哺乳动物'触发后，下一轮'哺乳动物'还在事实库里，没有这个机制 R1 又会再次匹配，无限循环。
>
> **阶段2 — 冲突消解（第104行）：** 如果同时有多条规则可以触发，选哪条？我的策略是：**priority 数字越小的先触发**（越基础的规则越优先，比如 R1 priority=1 先于 R5 priority=2），priority 相同时**条件多的先触发**（更具体的规则优先）。这样推理的自然顺序就是：先推出中间类别（哺乳动物、食肉动物），再推出具体动物（虎、金钱豹）。
>
> **阶段3 — 执行（第106-122行）：** 把选中的规则的结论加入工作内存，记录推理步骤。如果结论是 7 种目标动物之一就立刻停止。
>
> 然后回到阶段1，继续扫描。直到没有新规则能触发，或者找到了目标动物。
>
> ---
>
> **第三层：图形界面 —— AnimalExpertSystem 类（第127行）**
>
> 界面有两个关键设计：
>

>
> **（2）部分匹配推荐（run_inference 方法后半段，第243行起）：** 当精确匹配失败时，对每个目标动物，递归展开它的完整特征依赖树（`get_all_dependencies` 函数，第251行）。比如'虎'的依赖树展开后包括：有毛发、产奶（这两条通往哺乳动物）、吃肉（通往食肉动物）、黄褐色、黑色条纹。然后计算每个动物与当前已有事实的交集，交集不为空的就列为候选，按命中数降序推荐。递归函数带了一个 `visited` 集合（第252-256行）——如果知识库规则意外形成了环（比如 A→B 且 B→A），普通递归会爆栈，`visited` 就是防这种情况的安全网。"

### Q-Learning 公式速记（对应 maze_rl2.py 第34-41行）

```
第36行: q_predict = Q[s][a]              # 当前估计
第38行: q_target = r + γ·max Q[s']       # TD目标（非终点）
第40行: q_target = r                     # TD目标（终点）
第41行: Q[s][a] += α·(q_target - q_predict)   # 往目标挪一步
```

大白话：**实际拿到的分比预期好就加分，比预期差就扣分，每次只改一点点。**

### 产生式系统三阶段（冲突消解已修正）

```
循环 {
  匹配：找出所有前提被满足、且未用过的规则
  冲突消解：选 priority 数字最小的那条（越小越基础），同 priority 下条件多的优先
  执行：把结论加入工作内存
}
直到 找到目标动物 或 没有新规则可触发
```
