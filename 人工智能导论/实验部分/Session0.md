#### 🔹 第五步：切到代码，逐层讲解（60秒）

> *（切到代码编辑器，打开 maze_rl2.py）*

> "好，现在看代码是怎么实现的。整个文件 300 行，分**三层**，我按从上到下的顺序讲。
>
> ---
>
> **第一层：智能体的大脑 —— QLearningAgent 类（第12行到第43行）**
>
> 这个类的核心就三个方法：
>
> **（1）Q 表是什么样的？（第18行、第20-22行）**
>
> Q 表是一个 Python 字典 `{}`——可以理解为一个无限大的笔记本。字典的**键**是'智能体当前站在哪个格子'，比如 `(2,3)` 表示第 2 行第 3 列。字典的**值**是一个列表 `[上方向的分数, 下方向的分数, 左方向的分数, 右方向的分数]`。
>
> 一开始字典是空的。智能体到达一个新格子时，`check_state_exist` 方法（第20行）会初始化这个格子的四个分数都为 0.0——四个方向都一视同仁。
>
> **（2）怎么选方向？ε-greedy 策略（第24行到第34行）**
>
> 这就像扔骰子。ε 设为 0.9，意思是 90% 的情况选当前分数最高的方向（这叫**利用**已有经验），10% 的情况随机选一个方向（这叫**探索**新可能）。
>
> 为什么要随机？因为如果只走分数最高的，可能永远困在一条次优路里走不出来。偶尔乱走一下，可能发现更好的路。
>
> 代码里 `np.random.uniform() < self.epsilon`（第28行）就是扔骰子——如果随机数小于 0.9，就找 Q 值最大的方向；否则就随机选。
>
> 注意这个方法还接受一个 `test_mode` 参数（第24行）。当 `test_mode=True` 时，ε 相当于变成 1.0，永远选 Q 值最高的方向，不再随机探索。这个参数**平时训练不用，只在最后提取最优路径时用**——因为那时已经学好了，不需要再探索，直接走最佳路线就行。
>
> **（3）怎么更新 Q 表？（第36行到第43行）**
>
> 这是 Q-Learning 最核心的公式，写在 `learn` 方法里。我用大白话解释：
>
> `Q(s,a) += 学习率 × (目标值 - 当前值)`
>
> 展开就是（第39行和第42行的组合）：
>
> 当前值 = 这一步的 Q 分数（第42行 `q_predict`）
>
> 目标值 = 这一步的奖励 + 折扣因子 × 下一步所有方向里的最高分（第40行 `q_target`）
>
> 奖励 r 是环境给的（+100 到终点、-10 撞墙、-1 走一步）。
>
> 折扣因子 γ=0.9 的意思是'未来的奖励打九折'——鼓励智能体尽早到终点，不要绕远路。
>
> 学习率 α=0.1 的意思是'每次只改一点点'——防止一次学太多导致不稳定。
>
> ---
>
> **第二层：迷宫环境 —— MazeCanvas 类（第49行到第145行）**
>
> 这个类管三件事：
>
> **（1）随机生成障碍物（第69行到第78行）：** 用一个 while 循环，每次随机选一个格子，如果不是起点也不是终点、也没有和已有障碍物重复，就把它标为障碍物。数量和位置都是随机的。
>
> **（2）执行动作 step 方法（第80行到第104行）：** 智能体告诉环境'我要往上走'，环境就检查：这里能走吗？如果走出边界，就留在原地。如果走到终点，给 +100 奖励并标记完成。如果撞到障碍物，给 -10 惩罚并停留在原地。如果是空地，给 -1 奖励（每步扣一分，督促它走最短路径）。
>
> **（3）绘制界面 paintEvent（第106行到第145行）：** 两层绘制——先画网格底色（起点蓝、终点绿、障碍物灰、空地白），再用线段画出金色最优路径，最上层画出红色的圆形智能体。
>
> ---
>
> **第三层：训练总控 —— MazeApp 类（第151行到第299行）**
>
> **（1）训练循环（第242行 train_step）：** 每一步 = 选动作 → 执行 → 学习 → 检查是否到终点。用 QTimer 定时器每 10 毫秒调用一次，所以训练跑得很快。
>
> **（2）迷宫生成时的安全检查（第217-219行）：** 在 `generate_new_maze` 方法里，如果障碍物数量 ≥ 格子总数减2（即起点+终点以外的所有格子），系统会弹窗警告'障碍物过多，没有通道！'。这防止了死迷宫——比如 4×4=16 格，如果放了 14+ 个障碍物，起点到终点之间可能完全堵死，智能体永远走不到终点。
>
> **（3）收敛判定（第254-258行）：** 这是我自己加的。每回合结束时比较：这回合走了多少步？和上回合一样吗？用一个计数器 `stable_count` 记录连续相同的回合数，达到 3 就认为 Q 表已经稳定了，自动停止训练。
>
> **（4）最优路径提取（第273行 extract_and_draw_optimal_path）：** 收敛后，从起点出发，每一步都纯贪婪地选 Q 值最高的方向走（`test_mode=True` 关闭随机探索），一直走到终点，把路径存下来，然后画金色线。这里有一个细节：路径提取时带了一个 `visited` 集合（第277行），每走一个格子就记录，如果走到已经走过的格子就停止——这是防止极端情况下 Q 表有环路导致程序卡死，是一个防御性的安全措施。"

#### 🔹 第五步：切到代码，逐层讲解（60秒）

> *（切到编辑器，先打开 knowledge.json，再打开 animal_expert2.py）*

> "好，现在看代码。整体分**三层架构**。在讲三层之前，先看一个承上启下的数据结构：
>
> **第零层：Rule 规则类（第12-17行）** —— 这是 JSON 和推理引擎之间的桥梁。PyQt5 从 JSON 加载每条规则后，不是直接用原始字典，而是包装成一个 `Rule` 对象。这个对象有四个字段：`rule_id`（规则编号）、`premise`（前提条件，存成 Python 的 set 集合，方便做子集判断）、`conclusion`（结论）、`priority`（优先级，用于冲突消解）。用 set 集合的好处是，判断'当前事实是否满足规则前提'只需要一行 `premise.issubset(working_memory)`，时间复杂度 O(n)，非常高效。
>
> ---
>
> **第一层：知识库 —— knowledge.json（打开这个文件）**
>
> 这是整个系统的'知识'部分，独立存储在一个 JSON 文件里。不是写在 Python 代码里的，好处是**想加新动物，只改这个文件就行，不用改代码**。
>
> 文件里有一个 `targets` 列表，声明了 7 种目标动物：虎、金钱豹、斑马、长颈鹿、鸵鸟、企鹅、信天翁。这里我做了一个自动推导机制（`load_from_json` 方法第49-60行）：如果 JSON 里没写 `targets`，程序会自动扫描所有规则，找出那些**作为结论出现、但从不作为任何规则的前提条件**的概念——这些就是最终目标动物。比如'哺乳动物'既是 R1 的结论又是 R7 的前提，它不是目标；但'虎'只是 R9 的结论，从不当别人的前提，程序就能自动识别它是最终目标。这个设计让添加新动物时更省事——只要写好规则，目标动物会自动被识别出来。
>
> 然后是 15 条 `rules`。每条规则有四个字段：
> - `id`：规则编号，R1 到 R15
> - `priority`：优先级，数字越大越优先触发
> - `premise`：前提条件列表，所有条件都满足才能触发
> - `conclusion`：结论，触发后把什么新事实加入知识库
>
> 比如 R9（第53-57行）：
> ```json
> {"id": "R9", "priority": 3, "premise": ["哺乳动物", "食肉动物", "黄褐色", "黑色条纹"], "conclusion": "虎"}
> ```
> 翻译成人话：**如果**这个动物同时是哺乳动物、食肉动物、黄褐色、有黑色条纹，**那么**它就是虎。
>
> R14（第83-87行）识别企鹅：**如果**是鸟类、会游泳、不会飞、黑白二色，**那么**就是企鹅。
>
> 如果想加'鹰'，只需要加一行 JSON：`{"premise": ["鸟类", "善飞", "钩状喙"], "conclusion": "鹰"}`，完全不用动 Python 代码。
>
> ---
>
> **第二层：推理引擎 —— InferenceEngine 类（animal_expert2.py 第77行）**
>
> 这是系统的'大脑'。核心方法是 `forward_chaining`（正向推理，第82行）。
>
> 正向推理的过程就像**多米诺骨牌**，有三个阶段循环执行：
>
> **阶段1 — 匹配（第98-101行）：** 扫描所有规则，找出哪些规则的'前提条件'全部在当前已知事实中。这里有一个关键细节——代码里维护了一个 `used_rules` 集合（第90行），记录已经触发过的规则编号。匹配时会跳过用过的规则（第100行的 `rule.rule_id not in used_rules`），**防止同一条规则反复触发导致死循环**。比如没有这个机制，R1 '有毛发→哺乳动物'触发后，下一轮扫描时'哺乳动物'还在事实库里，R1 又会再次匹配上，无限循环。
>
> **阶段2 — 冲突消解（第106-108行）：** 如果同时有多条规则可以触发，选哪条？我的策略是：**优先级高的先触发**（priority 大的），优先级相同时**条件多的先触发**（更具体的规则优先）。这样 R9（priority=3）会在 R1（priority=1）之后才触发，保证先推出中间结论再推出最终结论。
>
> **阶段3 — 执行（第111-126行）：** 把选中的规则的结论加入工作内存，记录推理步骤到解释日志。如果结论是 7 种目标动物之一就立刻停止。
>
> 然后回到阶段1，继续扫描。直到没有新规则能触发，或者找到了目标动物。
>
> ---
>
> **第三层：图形界面 —— AnimalExpertSystem 类（第133行）**
>
> 界面有两个关键设计：
>
> **（1）特征复选框自动生成（第159-173行）：** 不是写死的。`get_all_premises` 方法（第65行）从知识库里提取所有基础特征——排除中间结论（比如'哺乳动物'是中间结论不是特征）和目标动物，只留下用户可以直接观察的特征（如'有毛发'、'吃肉'、'黑色条纹'）。这样改了 JSON，界面自动更新。
>
> **（2）部分匹配推荐（第252-298行）：** 当精确匹配失败时，对每个目标动物，递归展开它的完整特征依赖树（`get_all_dependencies` 函数，第257行）。比如'虎'的依赖树包括：有毛发、产奶（通往哺乳动物）、吃肉（通往食肉动物）、黄褐色、黑色条纹。然后计算每个动物与当前事实的交集，交集不为空的就列为候选，按命中数排序推荐。注意这个递归函数带了一个 `visited` 集合参数（第258-262行），每次递归前检查当前节点是否已经访问过——如果知识库规则形成了环，比如 A→B 且 B→A，普通递归会无限循环爆栈，`visited` 集合就是防止这种情况的安全网。"

### Q-Learning 公式记忆

```
新Q值 = 旧Q值 + 学习率 × ( 即时奖励 + 折扣因子 × 下一格最高分 - 旧Q值 )
```

大白话：**实际拿到的分比预期好就加分，比预期差就扣分，每次只改一点点。**

### 产生式系统三阶段

```
循环 {
  匹配：找出所有前提被满足的规则
  冲突消解：选优先级最高、条件最多的那条
  执行：把结论加入事实库
}
直到 找到目标动物 或 没有新规则可触发
```
