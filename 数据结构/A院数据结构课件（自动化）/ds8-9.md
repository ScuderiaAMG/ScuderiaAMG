# Data Structure

## DS8 查找

### 一、 查找的基本概念 (第1-4页)

>**通俗讲解：**
查找就像是“在茫茫人海中找特定的人”。我们通常根据人的“身份证号”（关键字）来找。评价一个找法好不好，主要看“平均需要找多少次”，也就是ASL（平均查找长度） 。

**严谨知识：**

* **关键字 (Keyword)：** 数据元素中某个数据项的值，用于标识一个数据元素 。


* **平均查找长度 (ASL)：** 为确定记录在表中的位置，需和给定值进行比较的关键字个数的期望值 。


* **ASL核心公式：** 对于含有n个记录的表， $ASL=\sum_{i=1}^{n}p_{i}c_{i}$（其中 $p_i$ 为查找第 $i$ 个元素的概率， $c_i$ 为找到该元素所需的比较次数） 。


* **评价维度：** 查找速度、占用存储空间、算法复杂程度 。



---

### 二、 顺序查找 (第3-4页)

>**通俗讲解：**
最笨但也最万能的方法——从头到尾挨个看。为了让电脑跑得快一点，有个小技巧叫“监视哨”：把你要找的目标先悄悄放在队伍的最前面（或最后面），这样电脑在遍历时就不需要每次都检查“有没有越界”，反正最后肯定能碰到它 。

**严谨知识：**

* **过程：** 从表的一端开始逐个进行记录的关键字和给定值的比较 。


* **监视哨 (Sentinel) 的作用：** 减少边界判断，优化常数时间的性能 。


* **性能：** 假设每个元素查找概率相等（$p_i = \frac{1}{n}$），则 $ASL = \frac{n+1}{2}$。查找失败时需要比较 $n+1$ 次 .



---

### 三、 折半查找 / 二分查找 (第5-9页)

>**通俗讲解：**
这就好比“猜数字游戏”。如果在1-100里猜一个数，你肯定先猜50，如果对方说“大了”，你就去1-49里猜，接着猜25……每次都能直接排除掉一半的选项。但前提是：队伍必须是**排好序**的，而且必须是**连续排队**（数组） 。

**严谨知识：**

* **适用条件：** 必须采用**顺序存储结构**且为**有序表** 。


* **判定树：** 描述折半查找过程的二叉树。具有 $n$ 个结点的判定树深度为 $\lfloor \log_{2}n\rfloor+1$ 。


* **性能：** 比较次数最多不超过判定树的深度 。满二叉树状态下， $ASL \approx \log_{2}(n+1)-1$ 。



---

### 四、 分块查找 / 索引顺序查找 (第10-13页)

>**通俗讲解：**
类似于“查字典”。字典的拼音目录是有序的（A-Z），这叫“块间有序”；但翻到特定拼音那一页后，里面的词语可能没有绝对排序，这叫“块内无序”。找的时候，先在目录里定位到哪个区块，然后再去那个区块里挨个找 。

**严谨知识：**

* **适用条件：** 分块有序表 。


* **结构：** 必须建立**索引表**。索引表结点包含：该块的最大关键字域、指向本块第一个结点的指针 。


* **性能：** $ASL_{bs}=L_{b}+L_{w}$（查找索引表的ASL + 块内查找的ASL）。如果表长 $n$，分 $b$ 块，每块 $s$ 个元素，顺序查找索引表时 $ASL_{bs}=\frac{1}{2}(\frac{n}{s}+s)+1$ 。

### 五、 哈希查找机制与哈希函数 (第14-22页)

>**通俗讲解：**
前三种查找本质上都在“比较”。哈希查找则是“对号入座”：给出一个人的名字，直接套用一个数学公式，算出来他应该坐在哪个座位上，一步到位！但是，如果两个人算出来的座位是同一个，这就发生了“冲突”。那些算出来同一个座位的不同关键字，互称为“同义词” 。

**严谨知识：**

* **哈希函数原理：** 是一种压缩映射， $addr(a_{i})=H(k_{i})$，由于关键字空间远大于存储空间，冲突不可避免 。


* **哈希函数的六大构造方法：**
1. **直接定址法：** $H(key)=a \cdot key+b$。不会发生冲突，但不常用 。


2. **数字分析法：** 选取关键字中分布均匀的若干位 。


3. **平方取中法：** 关键字平方后取中间几位，适用于不知全部关键字分布的情况 。


4. **折叠法：** 将关键字分割相加（移位叠加/间界叠加），适用于关键字极长的情况 。


5. **除留余数法（最核心）：** 取关键字被不大于表长 $m$ 的质数 $p$ 除的余数， $H(key)=key \pmod p$ ($p \le m$) 。


6. **随机数法：** $H(key)=random(key)$，适用于长度不等的情况 。

### 六、 哈希冲突的处理与性能分析 (第23-32页)

>**通俗讲解：**
如果算出来的座位上已经有人了怎么办？

* **开放定址法：** 脸皮厚一点，在现在的座位周围继续找空座。可以是依次看下一个（线性），也可以跳着看（二次探测）。
* **链地址法：** 原地拉一个“群”。所有算出来在这个座位的人，用一根链子串起来挂在这个位置上。
哈希表越满（装填因子越大），越容易撞车，查找越慢 。



**严谨知识：**

**方法一：开放定址法** 


* 公式： $H_i=(H(key)+d_i) \pmod m$ 。


* **线性探测再散列：** 增量序列 $d_i=1,2,3,...,m-1$ 。容易产生“二次聚集”现象。


* **二次探测再散列：** 增量序列 $d_i=1^2, -1^2, 2^2, -2^2...$ 。


* **伪随机探测：** $d_i$ 为伪随机序列 。



**方法二：再哈希法** 换不同的哈希函数重新算 。



**方法三：链地址法** 将所有同义词存储在一个单链表中，数组只存头指针 。


* **性能决定因素：** 哈希查找效率取决于三个核心——1. 哈希函数；2. 处理冲突的方法；3. **装填因子 $\alpha$**（$\alpha = \text{表中填入记录数} / \text{哈希表长度}$） 。



---

### 核心算法逻辑大总结

根据课件内容的描述，为您提炼以下核心算法的实现逻辑 ：

1. 折半查找算法逻辑 

```text
输入: 有序数组 r, 表长 n, 目标值 k
1. 初始化: low = 1, high = n
2. 只要 low <= high, 就循环执行以下操作:
   a. 计算中点: mid = ⌊(low + high) / 2⌋
   b. 如果 k == r[mid].key，查找成功，返回 mid。
   c. 如果 k < r[mid].key，说明目标在左半边，更新 high = mid - 1。
   d. 如果 k > r[mid].key，说明目标在右半边，更新 low = mid + 1。
3. 循环结束若仍未找到，查找失败。

```

2. 哈希查找流程控制 

```text
输入: 给定目标值 k
1. 计算初始哈希地址: addr = H(k)
2. 判断该地址状态:
   a. 如果地址为空: 查找失败。
   b. 如果地址不为空且 关键字 == k: 查找成功。
   c. 如果地址不为空且 关键字 != k: 发生了冲突！
3. 处理冲突: 根据设定的方法（如线性探测）计算下一个地址 Hi，重复步骤 2。

```

注：在哈希表的开放定址法中，**删除元素时只能做“删除标记”**，绝对不能物理删除（否则会截断后续同义词的查找路径）；插入元素时遇到空位置或带有删除标记的位置即可插入 。

---

### 链地址法处理冲突的实例与性能 (第31页)

>**通俗讲解：**
上一部分提到算哈希值会“撞车”。链地址法（拉链法）就是：如果好几个人的哈希公式算出来都是同一个座位号（比如位置1），那就不要去抢别人的空座了，直接在位置1这里拉起一条长长的“链子”（链表），把算到这个位置的人按顺序串起来 。找人的时候，先定位到位置1，然后顺着这根链子往下摸。

**严谨知识：**

* **链地址法结构：** 哈希数组中不直接存储记录本身，而是存储指向该地址所属同义词单链表的头指针 。


* **ASL（平均查找长度）计算示例：** 针对给定的12个关键字集合，如果落在第1层的有6个节点，第2层的有4个节点，第3层1个，第4层1个，那么其查找成功的平均查找长度计算过程为： $ASL = (1 \times 6 + 2 \times 4 + 3 \times 1 + 4 \times 1) / 12 = 1.75$ 。


* **优势：** 相比于开放定址法，链地址法绝不会发生“非同义词”之间的冲突，查找效率（ASL）通常更优 。



---

### 哈希查找的算法实现细节 (第32页)

>**通俗讲解：**
在使用“开放定址法”（发现座位被占了，就往后找空座）时，有一个非常重要的工程大坑：**不能直接删人**。
假设A和B算出来的首选座位都是1，A坐了1，B只好去坐2。如果这时候你把A从座位1直接“抹掉”，下次想找B时，电脑一看座位1是空的，就会误以为“B不存在”，从而直接宣告查找失败！所以，要想让B不被误伤，A走的时候只能在座位1放一个“已删除”的牌子。

**严谨知识：**

* **基于线性探测再散列法的实现规范：** 


* **查找过程：** 根据哈希函数计算初始地址，若匹配则成功；若冲突则按步长向后探测，直到遇到**绝对空位置**（说明不存在该记录）才判定查找失败 。


* **删除操作（懒惰删除）：** 只能对被删除元素**作标记**（如置为特定状态码），**绝对不能真正物理删除**（抹为空位），否则会截断后续同义词的查找探查路径 。


* **插入操作：** 在探查过程中，遇到“空位置”或者带有“删除标记的位置”都可以直接进行插入，覆盖原有标记 。




* **外链表（链地址）处理冲突算法：** 其插入通常在表头或表尾进行单链表操作，删除操作则是标准的单链表节点删除逻辑，不需要像开放定址法那样做伪删除标记 。



---

### 核心算法代码总结（线性探测哈希表操作）

根据第32页的严谨知识点，将线性探测哈希表的核心操作逻辑总结如下：

```text
// 状态定义：EMPTY(绝对空), OCCUPIED(被占用), DELETED(带有删除标记)

// 1. 查找算法
输入: 哈希表 HT, 表长 m, 目标键值 k
步骤:
  初始地址 addr = H(k)
  当前地址 i = addr
  只要 HT[i].状态 != EMPTY, 循环执行:
      如果 HT[i].状态 == OCCUPIED 且 HT[i].key == k:
          返回 查找成功, 位置 i
      i = (i + 1) MOD m  // 线性探测下一个位置
      如果 i == addr:
          返回 查找失败 (表已满且遍历一圈没找到)
  返回 查找失败 (遇到了绝对空位)

// 2. 插入算法
输入: 哈希表 HT, 表长 m, 目标记录 R(含键值 k)
步骤:
  初始地址 addr = H(k)
  当前地址 i = addr
  只要 HT[i].状态 == OCCUPIED, 循环执行:
      如果 HT[i].key == k:
          返回 插入失败 (元素已存在)
      i = (i + 1) MOD m
      如果 i == addr:
          返回 插入失败 (表已满)
  // 遇到 EMPTY 或 DELETED 状态，均可插入
  HT[i] = R
  HT[i].状态 = OCCUPIED
  返回 插入成功

// 3. 删除算法 (懒惰删除)
输入: 哈希表 HT, 表长 m, 目标键值 k
步骤:
  调用 查找算法(HT, m, k) 得到位置 i
  如果 查找成功:
      HT[i].状态 = DELETED  // 仅作标记，不置为EMPTY
      返回 删除成功
  否则:
      返回 删除失败 (未找到目标)

```

## DS9 排序


### 一、 排序的基本概念 (第1-5页)

>**通俗讲解**：排序就是把一堆乱七八糟的数据，按照某个关键字（比如学号、成绩）从小到大或从大到小重新排队。


**严谨定义**：假设有 $n$ 个记录的序列 $\{R_1, R_2, ..., R_n\}$，其对应的关键字序列为 $\{K_1, K_2, ..., K_n\}$ 。排序就是确定一种排列，使得关键字满足非递减（或非递增）关系：$K_{p1} \le K_{p2} \le ... \le K_{pn}$ 。


* **基本操作**：比较两个关键字的大小；将记录从一个位置移动到另一个位置 。


* **数据结构表示**：通常使用顺序表 `SqList`，内部包含一个记录数组 `r[MAXSIZE + 1]` 和一个记录长度的整型变量 `length` 。


**分类标准**：
* **按位置**：待排序记录都在内存中称为**内部排序**；排序过程需要对外存进行访问的称为**外部排序** 。


* **按稳定性**：如果序列中有两个相等的关键字 $K_i = K_j$ 且排序前 $R_i$ 领先于 $R_j$，排序后 $R_i$ 依然领先于 $R_j$，则是**稳定**的；反之则是**不稳定**的 。





---

### 二、 插入排序 (第6-15页)

插入排序的核心思想是将一个记录插入到已经排好序的有序表中，得到一个新的有序表 。

#### 1. 直接插入排序 (Direct Insertion Sort)

>**通俗讲解**：就像打扑克牌时摸牌一样，左手拿的牌已经是从小到大排好的，每次右手新摸一张牌，就从右向左和左手的牌比较，找到合适的位置插进去。
  

**严谨定义**：进行 $n-1$ 趟插入，先将第1个记录看作有序子序列，从第2个记录起逐个向前进行比较并插入 。


* **算法代码总结**：
* 使用 `for` 循环从 `i=2` 遍历到 `length` 。


* 如果当前元素小于前一个元素，则将当前元素放入 `L.r[0]`（作为暂存和哨兵）。


* 内层循环向后移动比暂存元素大的记录，最后将暂存元素插入空出的位置 。

**性能评价**：时间复杂度为 $T(n) = O(n^2)$ 。最好情况（正序）比较 $n-1$ 次，移动 0 次；最坏情况（逆序）性能最差 。空间复杂度为 $S(n) = O(1)$ 。



#### 2. 折半插入排序 (Binary Insertion Sort)

>**通俗讲解**：找插入位置时，不再挨个比较，而是用“折半查找（二分法）”来快速定位应该插在哪里，然后再统一挪动数据。


**严谨定义**：在直接插入的基础上，用折半查找方法确定插入位置的排序 。


* **算法代码总结**：
* 暂存当前元素至 `L.r[0]`，设查找区间为 `low = 1` 到 `high = i - 1` 。


* 利用 `while (low <= high)` 计算中点 `m = (low+high)/2` 并缩减区间，最终确定插入位置在 `high + 1` 。


* 统一后移数据并插入元素 。

**性能评价**：时间复杂度依然是 $T(n) = O(n^2)$（因为移动元素的次数没变），空间复杂度为 $S(n) = O(1)$ 。



#### 3. 希尔排序 (Shell Sort / 缩小增量法)

* **通俗讲解**：由于直接插入排序在“基本有序”时效率很高，希尔排序就先按照较大的间隔（增量）把数据分组，组内排序；然后逐步缩小间隔再排，最后间隔为1时，全体数据已经基本有序了，最后来一次插入排序就搞定。
* 
**严谨定义**：先取正整数 $d_1 < n$，将相隔 $d_1$ 的记录分为一组进行直接插入排序；然后取 $d_2 < d_1$ 重复上述操作，直到增量 $d_i = 1$ 为止 。


* 
**算法代码总结**：外层提供一组增量序列（如 `dlta[k]`），内层调用 `ShellInsert` 针对当前增量 `dk` 进行跳跃式的插入排序（步长为 `dk` 而非 1）。


* 
**核心要点**：增量序列的取法需满足：除了1之外没有公因子，且最后一个增量值必须为1 。

### 三、 交换排序 (第16-22页)

交换排序在原表上进行，核心动作是比较后交换元素位置 。

#### 1. 冒泡排序 (Bubble Sort)

* **通俗讲解**：就像水底的气泡往上冒，重（大）的元素沉到底，轻（小）的元素浮上来。相邻两个元素比大小，反了就换，一趟下来最大的肯定到了最后面。
* 
**严谨定义**：将第1个记录与第2个记录比较，若为逆序则交换；继续向后比较直至最后，第一趟冒泡使关键字最大的记录安置在最后一个位置 。重复此过程直到“在一趟排序中没有进行过交换操作”为止 。


* 
**性能评价**：时间复杂度为 $T(n) = O(n^2)$ 。最好情况（正序）比较 $n-1$ 次，移动0次；最坏情况（逆序）需要进行大量比较和移动 。空间复杂度为 $S(n) = O(1)$ 。



#### 2. 快速排序 (Quick Sort)

* **通俗讲解**：在数据里随便挑个“基准老大”，比老大弱（小）的都赶到左边，比老大强（大）的都赶到右边。然后对左右两帮人马分别再选老大重复这个过程，直到每个人都分好位置。
* 
**严谨定义**：通过一趟排序将待排记录分割成独立的两部分，其中一部分关键字均比另一部分小，再分别对这两部分进行排序，达到整体有序 。


* **算法代码总结**：
* 附设双指针 `i = s` 和 `j = t`，取枢轴记录 $p = r[s]$，关键字设为 $x$ 。


* 先从 `j` 向前搜索小于 $x$ 的记录，与枢轴交换；再从 `i` 向后搜索大于 $x$ 的记录，与枢轴交换 。


* 重复交替直到 `i == j`，然后对左右子序列递归进行快速排序 。




* **性能评价**：
* 时间复杂度：最好情况（每次选到中间值）为 $T(n) = O(n \log_2 n)$ ；最坏情况（每次选到极值）退化为 $T(n) = O(n^2)$ 。


* 空间复杂度：需栈空间实现递归。一般情况为 $S(n) = O(\log_2 n)$，最坏情况为 $S(n) = O(n)$ 。

### 四、 选择排序及堆排序先导 (第23-30页)

选择排序的思想是：每一趟在剩余未排序的记录中，选取关键字最小的记录，放到有序序列的末尾 。

#### 1. 简单选择排序 (Simple Selection Sort)

* **通俗讲解**：在乱序区里瞪大眼睛找出一个最小的，然后把它和乱序区的第一个位置交换，这样有序区就多了一个，乱序区少了一个。
* 
**严谨定义**：通过 $n-1$ 次关键字比较，从 $n$ 个记录中找最小的与第1个记录交换；再从剩余 $n-1$ 个中找最小的与第2个交换，共进行 $n-1$ 趟 。


* 
**性能评价**：时间复杂度固定为 $T(n) = O(n^2)$，因为无论初始序列如何，比较次数恒定为 $\frac{1}{2}(n^2-n)$ 。空间复杂度为 $S(n) = O(1)$ 。



#### 2. 树形选择排序 (锦标赛排序 / Tree Selection Sort)

* **通俗讲解**：像体育比赛里的单败淘汰赛（锦标赛）。两两PK，赢的晋级，一直打到总决赛选出总冠军（最小值）。
* 
**严谨定义**：利用含有 $n$ 个叶子结点的完全二叉树表示，两两比较选出较小者，树深度为 $\lceil \log_2 n \rceil + 1$ 。


* 
**核心特性**：时间复杂度优化到了 $O(n \log_2 n)$，但缺点是需要较多辅助存储空间，且需和代表最大值的“无限大”进行多余比较 。



#### 3. 堆排序概念引入 (Heap Sort - 第29、30页)

由于树形选择排序存在空间浪费，第29-30页引入了改良版——堆排序。

* 
**严谨定义（堆）**：一个含有 $n$ 个元素的序列 $\{k_1, k_2, ... , k_n\}$，满足 $k_i \le k_{2i}$ 且 $k_i \le k_{2i+1}$ （小顶堆），或者满足 $k_i \ge k_{2i}$ 且 $k_i \ge k_{2i+1}$ （大顶堆）时，称之为堆 。


* 
**结构特性**：可以将堆序列看成一棵完全二叉树，堆顶元素（根结点）必然是整个序列中的最大值或最小值 。


* 
**堆排序算法流程预告**：将无序序列建成堆（得到最大或最小值） $\rightarrow$ 输出堆顶元素 $\rightarrow$ 将剩余的 $n-1$ 个元素重新调整为堆 $\rightarrow$ 循环往复得到有序序列 。这抛出了后续章节需要解决的两个核心问题：如何建初堆，以及输出堆顶后如何调整堆 。

### 一、 堆排序的核心操作 (第31-37页)

在之前的知识中，堆顶（完全二叉树的根节点）总是最大或最小值 。第31页开始，重点解决堆排序的两个核心难题。

#### 1. 问题一：输出堆顶后，如何调整剩余元素？（“筛选”操作）

* 
**通俗讲解**：老大（堆顶）被调走了，只能让最底层、最后面的一个小弟（最后一个元素）先顶替老大的位置 。但这小弟实力不行，没法服众。于是他要和自己直接管辖的两个堂主（左右子节点）比拼，谁实力强（值更小或更大），谁就上去当老大，这个小弟就被“降级”换到下面。重复这个下放过程，直到他打得过手下（叶子节点），新的帮派秩序（新堆）就建立好了 。


* 
**严谨定义**：输出堆顶元素后，以堆中最后一个元素替代之；然后将根结点值与左、右子树的根结点值进行比较，并与其中小者（或大者）进行交换；重复上述操作直至叶子结点，这个从堆顶至叶子的调整过程称为“筛选” 。



#### 2. 问题二：一开始毫无秩序，怎么凭空建堆？（堆的构造）

* 
**通俗讲解**：不能从最底层的小兵开始管，要从“最底层的带头大哥”（最后一个非终端节点）开始整顿 。从后往前，挨个对这些带头大哥执行一遍“筛选”下放操作。等整顿到总会会长（第一个元素）时，整个堆就建好了 。


* 
**严谨定义**：从无序序列的第 $\lfloor n/2 \rfloor$ 个元素（即对应完全二叉树的最后一个非终端结点）起，至第一个元素止，进行反复筛选 。



#### 3. 算法性能评价

* 
**时间复杂度**：即使在最坏情况下，时间复杂度依然保持在 $T(n) = O(n \log_2 n)$ 。


* 
**空间复杂度**：由于完全在原数组上操作，只需要极少的常数空间，$S(n) = O(1)$ 。

### 二、 归并排序 (第38-40页)

#### 1. 核心原理

* 
**通俗讲解**：有点像淘汰赛的逆过程。假设有8个人，一开始每个人自己就是一个队伍（绝对有序）。然后相邻两个人合并成4个双人队伍（内部排好序）；接着相邻的队伍再合并成2个四人队伍... 这样两两合并，最后变成一个大队伍时，所有人就都排好序了 。


* 
**严谨定义**：归并是指将两个或两个以上的有序表组合成一个新的有序表 。2-路归并排序是将 $n$ 个记录看成 $n$ 个长度为1的有序子序列，两两合并得到 $\lceil n/2 \rceil$ 个长度为2或1的有序序列，重复合并直至得到长度为 $n$ 的序列 。



#### 2. 算法性能评价

* 
**时间复杂度**：每趟归并需要遍历所有元素，共进行 $\log_2 n$ 趟，因此 $T(n) = O(n \log_2 n)$ 。


* 
**空间复杂度**：由于在合并过程中需要一个和原数组一样大的空数组来暂存排好序的元素，所以需要额外的 $n$ 个空间，$S(n) = O(n)$ 。

### 三、 基数排序与多关键字排序 (第41-47页)

这是一种完全不需要比较元素大小的“另类”排序法。

#### 1. 多关键字排序

* 
**通俗讲解**：整理扑克牌时，我们通常要兼顾“花色”和“面值” 。如果先按最高级别（花色）分成四堆，每堆里再按面值排，这叫**最高位优先法 (MSD)** 。反过来，如果先不管花色，把所有牌按面值排好，然后再把这些牌按花色分堆合起来，这叫**最低位优先法 (LSD)** 。


* **严谨定义**：
* 
**MSD**：必须将序列逐层分割成若干子序列，分别对子序列按次级关键字排序 。


* 
**LSD**：不必分成子序列，每个关键字都是整个序列参加排序，通过若干次“分配”与“收集”实现 。





#### 2. 链式基数排序 (使用 LSD 策略)

* 
**算法逻辑总结**：用链表作为存储结构 。


* 准备10个桶（代表数字0-9的队列） 。


* 
**分配**：按数字的最低位（个位），把数据扔进对应的桶里 。


* 
**收集**：把10个桶里的数据首尾相连串成一个新链表 。


* 重复这个过程：个位搞完了搞十位，十位搞完了搞百位... 搞完最高位后，链表自然就有序了 。





#### 3. 算法性能评价

* 
**时间复杂度**：需要 $d$（关键字位数）趟分配和收集。分配需要 $O(n)$，收集需要 $O(rd)$（$rd$ 是关键字取值范围，比如十进制是10），总计 $T(n) = O(d(n+rd))$ 。


* 
**空间复杂度**：需要 $2rd$ 个队列指针和 $n$ 个指针域空间，总体可视为 $S(n) = O(rd)$ 。

### 四、 内部排序方法终极比较 (第48-49页)

文档最后对所有的排序算法进行了大阅兵，这是极其重要的考点汇总：

| 排序方法 | 平均时间复杂度 | 最坏情况时间复杂度 | 辅助存储 (空间复杂度) |
| --- | --- | --- | --- |
| <br>**简单排序** (直接插入、冒泡、简单选择)  | <br>$O(n^2)$  | <br>$O(n^2)$  | <br>$O(1)$  |
| <br> **快速排序** | <br>$O(n \log_2 n)$ | <br>$O(n^2)$  | <br>$O(\log_2 n)$  |
| **堆排序** | <br>$O(n \log_2 n)$  | <br>$O(n \log_2 n)$  | <br>$O(1)$  |
| **归并排序** | <br>$O(n \log_2 n)$  | <br>$O(n \log_2 n)$  | <br>$O(n)$  |
| **基数排序** | <br>$O(d(n+rd))$  | <br>$O(d(n+rd))$  | <br>$O(rd)$  |

#### 核心结论提炼：

1. 
**速度王者**：从平均时间来看，**快速排序最佳**，耗时最省。但它的缺点是在最坏情况下会退化到 $O(n^2)$，此时不如堆排序和归并排序稳健 。


2. 
**空间换时间**：归并排序在数据量 $n$ 较大时比堆排序稍快，但代价是它极其消耗内存（辅助空间最多） 。


3. 
**小规模与基本有序首选**：虽然直接插入排序是 $O(n^2)$，但它极度简单，且当记录“基本有序”或数据量 $n$ 很小时，它是最佳选择，常被用作复杂排序的打底策略 。


4. 
**特殊场景王者**：基数排序适合数据量 $n$ 极大、但关键字很小的场景（比如对几十万个100以内的数字排序） 。


5. 
**稳定性分水岭**：基数排序、归并排序、时间复杂度为 $O(n^2)$ 的简单排序法（不含希尔排序）都是**稳定**的；追求极致性能的快速排序、堆排序、希尔排序全部都是**不稳定**的 。
