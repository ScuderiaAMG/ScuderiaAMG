### 🗣️ 一、 通俗语言讲解（知识点深度提取）

1. **变量与数据类型：生活的“收纳盒”**
   C语言中的基本数据类型（如`int`、`char`、`float`）就像是大小、形状不同的收纳盒，根据你需要存放的不同物品（数字或字母）系统会分配对应大小的空间（例如`char`占1个字节，`int`通常占4个字节）。
2. **数组与字符串：排排坐的“连体盒”**
   数组就是内存里一块连续分配的“连体收纳盒”，里面只能放同一种类的物品，编号（下标）永远从`0`开始。字符串其实就是一种特殊的“字符数组”，唯一不同的是它系统会自动在末尾加一个`0`（或`\0`），用来告诉电脑：“我这句话到这里说完了”。
3. **结构体 (Struct) 与 联合体 (Union)：打包的“大礼包”与“共享单车”**
   * **结构体**：像个杂货大礼包，把不同类型的数据封装在一起。比如描述一个学生，可以把“学号(int)”和“姓名(char数组)”打在一个包里。
   * **联合体**：像一块大家共用的黑板或者共享单车，所有的成员共享同一块内存空间。它同一时刻只能表示一种含义，谁最后被赋值，黑板上就留下谁的内容（这在极度节约内存时非常有用）。
4. **指针 (Pointer)：计算机里的“门牌号”**
   指针是C语言和数据结构的灵魂。指针本身不直接存具体的数据，它存的是数据所在房间的“门牌号（内存地址）”。由于你知道门牌号，所以你就能顺藤摸瓜找到房间内的东西并修改它。甚至连函数也有“门牌号”（也就是函数指针），只要有了函数地址，程序就可以在运行时灵活地调度执行它。
5. **初识数据结构：图书馆找书**
   在第20页引入了数据结构的概念。如果把数据随便堆在一起，找数据就像在没分类的旧书堆里翻书一样痛苦。数据结构就是研究怎么把数据安排一定的规则（如按照书名、作者排成的“线性表”）存起来，从而让计算机存取数据变得规律且高效。

### 🔬 二、 核心知识归纳（严谨学术语言表达）

1. **变量域与生存期 (Scope & Lifetime)**
   * **声明与定义的区别**：`extern` 声明全局变量通常放在头文件中，用于给编译器提供符号指示，**不实际分配内存**；而定义则会实际分配存储空间。
   * **作用域限定**：`static` 变量不仅能保留持久的生存期，还可以限制变量或函数的作用域范围，避免命名空间污染。

2. **内存空间的字节对齐 (Memory Alignment)**
   * 结构体成员在内存中的存储为了适应不同硬件总线的快速读取，编译器通常有“字对齐”、“双字对齐”等策略。
   * 可通过编译预处理指令 `#pragma pack(n)` 强制修改对齐方式（如强制 `pack(1)` 字节对齐），这在解决网络协议包解析与内存空间极度敏感的操作中至关重要。

3. **类型别名机制 (Typedef vs Macro)**
   * `typedef` 不同于 `#define` 宏定义的简单文本替换，它是在编译时对数据类型创建**强类型的等价别名**，它属于新数据类型的封装，能够让编译器在编译期进行违例和类型检查。

4. **指针与高级内存寻址 (Pointer Semantics)**
   * **数组与指针等价性**：数组的引用本质上是 `首地址 + 偏移量` 的表现形式。
   * **空指针与泛型指针**：空指针 (`NULL`，本质为 `0`) 用于避免野指针引发的内存违例(`Exception`)；`void` 指针提供了一种丢失了步长类型的泛型内存地址抽象。
   * **指针结构体**：为了实现复杂数据结构（如链表、树），结构体内部必须允许包含指针成员，它是构成自引用（self-referential）拓扑结构的底层基石。

### 🗣️ 一、 通俗语言讲解（知识点深度提取）

1. **什么是数据结构？**
   * **通俗理解**：如果把写程序比作“做菜”，数据就是“食材”，算法就是“菜谱”，那么数据结构就是“怎么科学地存放食材的容器”。比如，你不能把鸡蛋和西瓜全堆砌在一起（因为要拿最底下的西瓜时非常麻烦），你需要用“网兜”、“格子盒”或“串串”把它们按某种规律排列起来。
   * 数据结构研究的就是：**数据的对象** + **它们之间的关系** + **能对它们做些什么（操作）**。

2. **数据结构的四大门派（逻辑结构）**
   * **集合**：所有数据装在一个大麻袋里，除了“都在袋子里”没有其他关系。
   * **线性结构**：大家像排队买奶茶一样，一个挨一个，**一对一**。比如：前面回顾的数组、以后要学的栈和队列。
   * **树形结构**：像公司的组织架构图或者族谱，一个老板管多个员工，**一对多**。
   * **图状结构**：像城市的交通路线网或者朋友圈，四通八达，每个人都可能连着多个人，**多对多**。

3. **大脑里的想法 vs 现实的实现（逻辑结构 vs 物理结构）**
   * **逻辑结构**：单纯的数学模型，也就是你脑子里思考它“应该排成什么样”。
   * **物理/存储结构**：数据在电脑内存里“真正是怎么存的”。有两种典型方式：
     * **顺序存储**：霸占一块连续的座位，用**相对位置**来排排坐（例如数组）。
     * **链式存储**：座位乱坐，但是每个人手里拿着下一张座位的“号码牌（也就是**指针**）”形成一条链。

4. **抽象数据类型 (ADT)**
   * 它就像是给数据定义的一份“黑盒说明书”。ADT只在乎“这个东西里面有什么”、“它支持按什么按钮（操作）”，完全不关心它在机器底部代码是怎么敲出来的。比如我们说了一个“栈(Stack)”，你只需要知道它“先进后出”，不需要管底层它是数组实现的还是链表实现的。

5. **算法的终极奥义：算得快、占得少**
   * 程序要在电脑上跑，有两个致命限制：**CPU算力**和**内存大小**。
   * **时间复杂度**：指程序运行花费的“算力”。我们不拿秒表掐时间（因为不同电脑快慢不一样），而是数代码里面的“基本操作循环了多少次（比如比较次数）”，用符号 `O(f(n))` 表达。
   * **空间复杂度**：指这个算法有没有产生过多“中间垃圾”导致过度占用内存。如果空间消耗是个常数（不随着数据变大而无限吃内存），那叫做“**原地工作 (In-place)**”。

### 🔬 二、 核心知识归纳（严谨学术语言表达）

1. **数据与数据元素的分层体系**
   * **分层概念**：数据(Data) $\rightarrow$ 数据对象(Data Object) $\rightarrow$ 数据元素(Data Element) $\rightarrow$ 数据项(Data Item，具有独立定义的原子或聚合粒度)。
   * **形式化定义**：`Data Structure = (D, S)`，其中 $D$ 是数据元素的有限集，$S$ 是定义在 $D$ 上的关系集合。

2. **存储映像映射 (Storage Mapping)**
   * **顺序映像 (Sequential Mapping)**：逻辑关系邻接 $\Leftrightarrow$ 物理地址连续（寻址方程为线性叠加）。
   * **非顺序映像 (Non-Sequential Mapping)**：依赖指针(Pointer)作为元数据显式建立邻接节点的拓扑关系。

3. **抽象数据类型三元组表述 (Abstract Data Type, ADT)**
   * 采用三元组表述：`ADT = (D, S, P)`。其中 $P$ 为操作元(Operations)。
   * 高质量代码通常实施**模块化隔离**：将定义（接口说明）、逻辑表示及底层物理实现三个层级分离。

4. **算法的五大核心特性**
   * `有穷性` (Finiteness)：在有限步骤后可终止。
   * `确定性` (Definiteness)：每一步的操作语义精确，无二义性（歧义）。
   * `可行性` (Effectiveness)：操作本身可被有限次指令执行并确保结果精准。
   * `输入` 与 `输出` (Input & Output)。

5. **大 O 渐进表示法分析 (Asymptotic Complexity)**
   * **事后统计**依赖环境不具备客观性；故引入**事前分析估计**。
   * **时间复杂度 $T(n) = O(f(n))$**：描述随着问题规模规模 $n$ 的趋于无穷大，基础语句频度的理论上界（最高阶增长率）。
   * **空间复杂度 $S(n) = O(f(n))$**：算法执行期间额外申请的附加物理缓存对规模 $n$ 的极限分布。

### 💻 三、 基础算法与核心代码总结

本节给出了量化评估算法效能的代码分析案例，重点在于**如何算出时间复杂度的阶数**。

**案例：三个嵌套循环的 $n \times n$ 矩阵乘法**

```c
// 分析：求矩阵乘法 c = a * b (全为 n*n 的方阵)
for(i = 1; i <= n; i++)        // 外层循环执行 n 次
{           
    for(j = 1; j <= n; j++)    // 中层循环对于外层的每一次都会执行 n 次
    {       
        c[i][j] = 0;           // {初始化内层：此处频次为 n * n 次}
        
        for(k = 1; k <= n; k++) // 内侧核心循环，针对外两层的每一次，再执行 n 次
        {
            // 核心计算语句，总执行次数: n * n * n = n^3
            c[i][j] = c[i][j] + a[i][k] * b[k][j]; 
        }
    }
}
```

**复杂度求解结论**：
最内层核心累加语句的频度为 $n^3$，即函数 $f(n) = n^3$。
根据大 $O$ 标记法取最高项的原则，该算法的时间复杂度为：$T(n) = O(n^3)$。

### 🗣️ 一、 通俗语言讲解（知识点深度提取）

1. **什么是线性表？**
   **通俗理解**：线性表就像是在食堂打饭排队。
   * 每个队伍都有一个排第一的人（唯一有后驱没前驱），也有一个排最后的人（唯一有前驱没后驱）。
   * 中间的所有人，前面都只有一个人，后面也只有一个人。
   * **要求**：排队的必须都是人类（不能插一条狗进去，数据元素类型要相同），且队伍中间不能出现断层（不能缺项）。

2. **顺序表（顺序存储）**
   **通俗理解**：大家去看电影，买了一排连号的座位。
   * **优点**：找人特别快（随机存取）！如果你知道第一个座位是5排1号，你想找第10个人，直接算一下就知道他在5排10号，1秒钟揪出来。另外座位挨在一起，不浪费空间。
   * **缺点**：如果中间强行加一个人（插入），或者一个人退场了（删除），后面所有的人都要跟着往后挪或者往前补位，非常费劲。而且你得提前跟影院包场，要是来的人比包的位置多，就坐不下了（扩容困难）。

3. **单链表（链式存储）**
   **通俗理解**：去游乐园玩“寻宝游戏”，每个人都不用坐在一起（随便在内存里找位置），但是每个人的口袋里都揣着一张小纸条，写着“下一个人在哪里找”。
   * **特点**：为了存这个“纸条”（即指针 Next），每个数据在内存里分成了两半部分：**数据域**（真实的信息）和**指针域**（纸条）。
   * **头结点**：为了找人方便，会在第一个真正持宝人前面安排一个“向导（头结点）”，他自己身上不带宝物，但他手里拿着“第一号持宝人”的位置纸条。这样就算链表是空的，向导也还在。
   * **优点**：插入删除太方便了！有个新人来，只需要改两张纸条（指针）指向即可，任何人都不用搬家。随时来随时发纸条（动态分配）。
   * **缺点**：找人特别慢。你要找第10个人，只能从向导开始，问第1个，再问第2个，依次顺藤摸瓜找下去。

4. **双向链表**
   **通俗理解**：单链表的进阶版。单链表只能“往前找下家”，一旦走回头路就蒙了。双向链表就是每个人兜里揣**两张纸条**，一张写着上家在哪（prior），一张写着下家在哪（next）。
   * 删除某个人的时候，直接让他“上家的下家纸条”指向他的“下家”，让他“下家的上家纸条”指向他的“上家”，完美踢出。

5. **线性表的实际应用：一元多项式相加**
   **通俗理解**：比如求 $(3x^1 + 9x^8 + 17x^{17}) + (8x^1 + 22x^7 - 9x^8)$。
   因为中间缺了很多项（比如没有 $x^2, x^3$ 等），如果按照 0~17 挨个排顺序表会浪费大量内存。因此只存有用的，用链表存两个值：**系数**和**指数**。按指数大小排好队，两个链表像车链子齿合一样挨个比较合并。

### 🔬 二、 核心知识归纳（严谨学术语言表达）

1. **线性表的数学定义**
   * $Linear\_List = (D, R)$
   * 若 $n > 0$，除了唯一的首元素 $a_1$ 和尾元素 $a_n$ 外，所有的 $a_i (1 < i < n)$ 均有且仅有一个直接前驱 $a_{i-1}$，有且仅有一个直接后继 $a_{i+1}$。

2. **顺序存储 (Sequential Mapping)**
   * **寻址方程**：$LOC(a_i) = LOC(a_1) + (i-1) \times L$。（以基地址 $LOC(a_1)$ 开始计算偏移量，$L$ 为单个节点内存开销）。
   * 具有强烈的**随机存取特性** (Random Access)，时间复杂度为 $O(1)$。
   * **插入操作与删除操作**：需要大批量进行内存区块移动操作，平均循环次数为 $n/2$，因此修改的时间复杂度为 $O(n)$。

3. **链式存储 (Linked List)**
   * 属于**非顺序映像**。元素不仅存储物理信息 `data`，还需要存储元数据指针 `next` 指示拓扑方向。
   * **动态空间分配管理**：无需预先请求内存连续大区块，依靠堆区动态调度（`malloc` / `free` 操作）。
   * **时空复杂度**：插入与删除仅需改动局部指针，物理改动的时间复杂度为 $O(1)$，但因为需要扫描定位，整体带有访问定位开销的增删操作依然是 $O(n)$。不支持随机访问。
   * 为了编程规范与边缘情况的处理，通常设置隐式的**头结点 (Head Node)**，当 `head->next == NULL` 时，即代表空链表。

4. **双向循环链表 (Doubly Linked List)**
   * 数据结构：包含两个拓扑指针域 `prior` 与 `next`。
   * 必须满足环式拓扑等价方程：`p->prior->next == p == p->next->prior`。
   * 处理插入与删除时，需要同时维护前向链路与后向链路。

5. **静态链表 (Static Linked List)**
   * 在缺乏指针类型的高级语言（或规避动态堆内存碎片的严苛环境）中，通过**大段数组**来模拟链表。
   * 结构体内包含 `data` 以及整型游标 `cur`，游标记录的是下个节点在数组中的**下标**索引，从而兼顾顺序表的局部紧凑性和链表免移动元素的插入优势。

### 💻 三、 基础算法与核心代码总结

这里提炼出课件中展示的最核心的链式结构增、删算法：

**1. 单链表节点的定义框架**
```c
typedef struct LNode {
    ElemType data;           // 数据域
    struct LNode *next;      // 指针域
} LNode, *LinkList;          // 别名机制
```

**2. 单链表定位与插入 (指针操纵核心)**
```c
// 在单链表 L 的第 i 个位置之前插入元素 e
Status ListInsert_L(LinkList &L, int i, ElemType e) {
    p = L; j = 0;
    while(p && j < i - 1) { 
        p = p->next; ++j;    // 将游标; // O(n)的定位过程
    }
    if(!p || j > i - 1) return ERROR; // 越界报错
    
    // 生成新节点，建立新链路
    s = (LinkList)malloc(sizeof(LNode));
    s->data = e; 
    
    // 【修改指针顺序必须非常严谨：先接后卫，再断前锋！】
    s->next = p->next; 
    p->next = s;
    
    return OK;
}
```

**3. 双向链表的精准截断与删除**
```c
// 删除双向链表中的节点 p
Status ListDelete_DuL(DuLinkList &L, int i, ElemType &e) {
    // 假设 GetElemP_DuL 已经帮我们定位到了第 i 位的指针 p
    if(!(p = GetElemP_DuL(L, i))) return ERROR;
    e = p->data;
    
    // 双向截断与越级重连
    p->prior->next = p->next;  // 让 p的前面的后继 指向 p的后面
    p->next->prior = p->prior; // 让 p的后面的前驱 指向 p的前面
    
    free(p); // 释放内存
    return OK;
}
```

**4. 多项式相加密集归并算法摘要 (MergeList 思路)**
算法逻辑非常清晰的分步判断（类似于归并排序的核心）：
* 令指针 `p` 扫 $A$，`q` 扫 $B$。
* 如果 `p->exp < q->exp`：$p$ 节点指数小，$p$ 移入结果链表，$p$ 往前走一步。
* 如果 `p->exp > q->exp`：$q$ 节点指数小，$q$ 移入结果链表（插在 $p$ 前面），$q$ 往前走一步。
* 如果 `p->exp == q->exp`：将两人系数相加。如果相加不为零，更新 $p$ 系数，删除/释放 $q$；如果相加为 0，则连 $p$ 一并删除。

### 第一部分：顺序表（顺序存储）完整解析
**核心思想**：用一块连续的数组内存来存储。为了防止容量不够，通常使用**动态分配**机制。

#### 1. 顺序表类型定义
```c
#define LIST_INIT_SIZE 100   // 线性表存储空间的初始分配量
#define LISTINCREMENT  10    // 线性表存储空间的分配增量

typedef struct {
    ElemType *elem;  // 存储空间基址（本质是一个动态数组的头指针）
    int length;      // 当前表内有效元素的个数
    int listsize;    // 当前分配的存储容量（以sizeof(ElemType)为单位）
} SqList;
```
> **详解**：这里不用静态数组 `ElemType elem[100]`，而是用指针 `*elem`，是为了后续可以使用 `realloc` 进行内存扩容（极为严谨的做法）。`length` 是当前用到的长度，`listsize` 是总容量。

#### 2. 在第 i 个位置插入元素 (ListInsert)
```c
Status ListInsert_Sq(SqList &L, int i, ElemType e) {
    // 1. 检查插入位置的合法性（i 的取值范围应在 1 到 length+1 之间）
    if(i < 1 || i > L.length + 1) return ERROR; 
    
    // 2. 如果当前长度等于总容量，说明装满了，需要动态扩容
    if(L.length >= L.listsize) {
        // 使用 realloc 扩充内存块
        ElemType *newbase = (ElemType *)realloc(L.elem, (L.listsize + LISTINCREMENT) * sizeof(ElemType));
        if(!newbase) exit(OVERFLOW); // 内存分配失败，强制退出
        L.elem = newbase;            // 重置基址
        L.listsize += LISTINCREMENT; // 更新最大容量
    }
    
    // 3. 准备移动元素。q 是插入位置，p 是最后一个元素的位置
    ElemType *q = &(L.elem[i-1]); 
    for(ElemType *p = &(L.elem[L.length-1]); p >= q; --p) {
        *(p+1) = *p;  // 从尾部开始，所有 i 之后的元素全部统统后移一位
    }
    
    // 4. 将新元素 e 放入预留出的位置 q，并更新表长
    *q = e;         
    ++L.length;
    return OK;
}
```
> **代码精讲**：顺序表插入最耗时的步骤就在于 `for` 循环中的“倒序后移”。必须**倒着移**（也就是最后一个先退一格），如果正着移后面的数据会被直接覆盖。时间复杂度：**$O(n)$**。

### 第二部分：单链表（链式存储）完整解析
**核心思想**：不强求内存物理相邻，只靠指针维持下一家的逻辑关系（纸条找人法）。

#### 1. 节点与单链表定义
```c
typedef struct LNode {
    ElemType data;       // 数据域：存储真正的数据
    struct LNode *next;  // 指针域：存储下一个节点在哪里
} LNode, *LinkList;      // LNode为节点体，LinkList为指向该节点体的指针类型
```

#### 2. 单链表的读取 (GetElem_L)
```c
// 获取第 i 个位置的元素值，通过引用 e 返回
Status GetElem_L(LinkList L, int i, ElemType &e){
    LinkList p = L->next; // p 跨过头结点，指向第一个真实数据节点
    int j = 1;            // 计数器
    
    // 只要 p 不为空，且还没数到第 i 个，就继续顺藤摸瓜
    while (p && j < i) {
        p = p->next; 
        ++j;
    }
    // 如果 p走到最后变空了（没那么长），或者 i 不合法(i<=0)
    if (!p || j > i) return ERROR; 
    
    e = p->data; // 提取对应的数据
    return OK;
}
```
> **代码精讲**：链表无法像数组那样 `elem[i]` 一步寻址，只能硬着头皮写 `while` 循环一个个往下找。查询的时间复杂度为 **$O(n)$**。

#### 3. 单链表的插入 (ListInsert_L)
```c
// 在第 i 个数据 前面 插入元素 e
Status ListInsert_L(LinkList &L, int i, ElemType e) {
    LinkList p = L; // 从头结点开始
    int j = 0;
    
    // 1. 寻找第 i-1 个节点（需停留在被插位置的前一个节点上）
    while(p && j < i - 1) { 
        p = p->next; 
        ++j; 
    }
    if(!p || j > i - 1) return ERROR; // 越位检查
    
    // 2. 生成新节点 s 并赋值
    LinkList s = (LinkList)malloc(sizeof(LNode));
    s->data = e; 
    
    // 3. 构建链条（极其关键的这2句，绝对不能颠倒！）
    s->next = p->next; // 先让 s 的"下家纸条" 继承 p 原本的"下家纸条"（接后卫）
    p->next = s;       // 再让 p 的"下家纸条" 指向刚来的 s（断前锋）
    
    return OK;
}
```
> **防错重点**：如果先写了 `p->next = s;`，那 `p` 原本的后继节点就凭空丢失了，后面整个链表全部会造成严重内存泄漏（俗称掉链子）。

#### 4. 从尾到头逆向建立单链表 (CreateList_L 头插法)
```c
void CreateList_L(LinkList &L, int n) {
    L = (LinkList)malloc(sizeof(LNode)); // 造出头结点
    L->next = NULL;                      // 先设置为空链表
    
    for(int i = n; i > 0; --i) {
        LinkList p = (LinkList)malloc(sizeof(LNode));
        scanf(&p->data); // 获取用户输入数据
        
        // 头插法：每次新进来的节点，都强制塞在头结点的正后方
        p->next = L->next; 
        L->next = p;
    }
}
```
> **效果解读**：如果用户输入顺序是 1, 2, 3，由于每次都往头结点后面挤，链表里存的顺序是 3 -> 2 -> 1。

#### 5.单链表中删除节点
```c
Status ListDelete_L(LinkList &L, int i, ElemType &e) {
    p = L; j = 0; 
    // 1. 初始化：p指向头结点（或虚拟头结点），j是计数器。
    while(p->next && j < i-1) { p = p->next; ++j; }
    // 2. 遍历寻找：只要还没到链表尾部，且还没走到第 i-1 个结点，就一直往后找。
    // 目标是让 p 停在被删结点的前一个位置（第 i-1 个位置）。
    if(!(p->next) || j > i-1) return ERROR;
    // 3. 异常处理：如果 p 的下一个结点为空（说明位置 i 超出了链表长度），
    // 或者 j > i-1（通常发生在 i 给出的是不合法的负数或0），则返回错误。
    q = p->next; 
    // 4. 暂存：把要删除的结点（第 i 个结点）暂时存给指针 q，防止一会弄丢了它的地址。
    p->next = q->next; 
    // 5. 核心跨越：也就是图里的 p->Next = p->Next->Next; 让前一个结点指向后一个结点。
    e = q->data; 
    // 6. 备份数据：把要删除结点里的数据取出来，赋值给参数 e 
    free(q); 
    // 7. 释放内存
    return OK;
}
```

#### 6.单链表的动态建立
```c
void CreateList_L(LinkList &L, int n) {
    L = (LinkList)malloc(sizeof(LNode)); 
    // 1. 建立头结点：向系统申请一块内存给头结点 L。
    
    L->next = NULL; 
    // 2. 初始化：目前链表是空的，所以头结点后面什么都没有（指向 NULL）。
    
    for(i=n; i>0; --i) { 
    // 3. 开始循环：要建立 n 个结点，就循环 n 次。
    
        p = (LinkList)malloc(sizeof(LNode)); 
        // 4. 捏一个新结点：每次循环，先申请一块新内存给指针 p。这相当于拿到了一个空盒子。
        
        scanf(&p->data); 
        // 5. 装入数据：从键盘读入一个数据，放到 p 的数据域里。
        
        /* 下面两句是头插法的灵魂，顺序绝对不能错！ */
        p->next = L->next; 
        // 6. 新人牵旧人：让新结点 p 指向 L 原本指着的那个结点（如果此时是第一个结点，L->next 就是 NULL）。
        
        L->next = p; 
        // 7. 头牵新人：让头结点 L 重新指向新来的结点 p。
    }
}
```

### 第三部分：双向链表代码详解
单链表缺点是没法倒着找（找前驱）。双向链表通过增加一枚 `prior` 指针彻底解决这一痛点。

#### 1. 双向循环链表节点的定义
```c
typedef struct DuLNode {
    ElemType data;
    struct DuLNode *prior; // 头指前驱方向
    struct DuLNode *next;  // 尾指后继方向
} DuLNode, *DuLinkList;
```

#### 2. 双向链表的精准截断与删除 (ListDelete_DuL)
```c
// 将双向链表的第 i 个节点删除，并返回删除的值 e
Status ListDelete_DuL(DuLinkList &L, int i, ElemType &e) {
    DuLinkList p;
    if(!(p = GetElemP_DuL(L, i))) return ERROR; // 获取指向第 i 节点的指针 p
    
    e = p->data; // 扣留数值
    
    // 核心拆排逻辑：让上家和下家直接建立连接，跳过 p
    p->prior->next = p->next; // 1. 让 p的前一个节点的后继，越过p，直接指向p的后继
    p->next->prior = p->prior;// 2. 让 p的后一个节点的前驱，越过p，直接指向p的前驱
    
    free(p); // 将架空的 p 彻底从内存抹除
    return OK;
}
```

#### 3. 双向链表的插入 (ListInsert_DuL)
```c
// 在第 i 个节点 之前 插入元素 e
Status ListInsert_DuL(DuLinkList &L, int i, ElemType e) {
    DuLinkList p, s;
    if(!(p = GetElemP_DuL(L, i))) return ERROR; // 获取第 i 节点 p
    
    if(!(s = (DuLinkList)malloc(sizeof(DuLNode)))) return ERROR;
    s->data = e;
    
    // 核心安插逻辑：4步建立4根指针
    s->prior = p->prior;      // 1. 新人 s 认 p 的前驱为自己的前驱
    p->prior->next = s;       // 2. 老前驱把 s 认作自己的新后继
    s->next = p;              // 3. 新人 s 认 p 为自己的后继
    p->prior = s;             // 4. p 认 s 为自己新的前驱
    
    return OK;
}
```

### 第四部分：高级应用：一元多项式相加算法

#### 1. 为什么用链表？多项式的特定结构定义
如果多项式是 $A = 3x^{1} + 9x^8 + 17x^{17}$，如果用数组，数组要开到 18个格子，且绝大部分格子存0，极度浪费。因此使用链表，**只保存非 0 项**。
```c
typedef struct node {   
    float coef;         // coefficient: 系数
    int exp;            // exponent: 指数
    struct node *next;
} Node;
```

#### 2. 多项式求和的运行规则与逻辑
课件的核心算法其实就是**归并排序中合并两有序数组的逻辑变体**。我们设置三个指针：`pre` 表示操作后最终链表的最后一个节点，`pa` 是 A 的游标，`pb` 是 B 的游标。

**对比 `pa->exp` 与 `pb->exp` 的三种结局：**
* **情况 1: `pa->exp < pb->exp`** 
  此时 A 这项比较小，直接将 `pa` 的这个节点纳入最终序列：`pa` 向后游走一格（`pa = pa->next`）。
* **情况 2: `pa->exp > pb->exp`**
  此时 B 这项比较小，我们把 `pb` 这个节点剪切下来，插进主表的当前位置前。`pb` 往后游走。
* **情况 3: `pa->exp == pb->exp` (同类项合并)**
  此时系数应该相加。
   - `sum = pa->coef + pb->coef`。
   - 判断 `sum`：
     - 若 `sum != 0`，修改 `pa` 的系数域记录下该数，释放 `pb` 这个冗余节点；并让 `pa` 和 `pb` 都向后游走。
     - 若 `sum == 0`（相互抵消），则这整个项都没存在的必要了，把 `pa` 和 `pb` 的节点通通释放并且从表里除名，两者指针同步后退。

> **尾声处理**：当 `A` 的所有节点或者 `B` 的节点某一个被掏空时，直接把另一个尚未掏空的链表剩余部分整串接在新链表的尾巴即可（相当于直接嫁接后面的残存节点群），从而能在理论极限 $O(m+n)$ 的一次遍历内完成两浩大代数式的相加。

##### 代码实现一元多项式相加

存储两个数据：系数coef和指数exp

```c
typedef struct node 
{ 
    float coef;     // 1. 系数 (Coefficient)：可以是小数
    int exp;            // 2. 指数 (Exponent)：通常是整数
    struct node *next;  // 3. 指针域 (Next)：指向下一个数
} Node;
```
给出了两个多项式 A 和 B 相加得到 C 的具体例子：

$A(x) = 7 + 3x + 9x^8 + 5x^{17}$

$B(x) = 8x + 22x^7 - 9x^8$

**合并同类项的计算机逻辑（双指针遍历法）**：

设定两个指针 pa 和 pb，分别指向 A 和 B 链表的第一个实际数据结点。

对比它们的指数 (exp)：

如果 pa->exp < pb->exp：

说明 A 的当前项比较小，按照指数从小到大的顺序，把 pa 指向的结点直接接在结果链表 C 的后面，然后 pa 往后挪一步。

如果 pa->exp > pb->exp：

同理，把 pb 指向的结点接在 C 后面，pb 往后挪一步。

如果 pa->exp == pb->exp（高光时刻！）：

这就是遇到了“同类项”。将两个系数相加。

$A$ 有一个 $9x^8$，$B$ 有一个 $-9x^8$。两者指数都是 8，系数相加为 $9 + (-9) = 0$。由于系数变成了 0，这一项被彻底抵消。 算法会将这两个结点直接丢弃（释放内存），绝不能把系数为 0 的项接到结果 C 中。

合并完成后，把剩下的尾巴一并接上，就得到了完美的结果链表 C：$C(x) = 7 + 11x + 22x^7 + 5x^{17}$
## DS3 栈和队列

### 🗣️ 一、 通俗语言讲解（核心原理降维打击）

**1. 它们是什么？“憋屈”的排队结构 (Page 2)**
栈和队列的本质依然上一章学的“队伍（线性表）”，但给它们加上了严苛的“规矩”——不能再随便插队或者从队伍中间拉人了（操作受限的线性表）。

**2. 栈 (Stack)：单口羽毛球筒 (Page 3-13)**
* **原理**：想象一个只有一个口的羽毛球筒，最先放进去的球压在最底下。你想拿球，只能从上面拿最后放进去的那一颗。这就叫 **LIFO (后进先出)**。
* **找位置**：底部叫`栈底(base)`封死了，上面那个唯一的活动口叫`栈顶(top)`。
* **版本分化**：
  * **顺序栈 (Page 5)**：拿一段定长的管子当栈。如果管子塞满了，还想塞，就得用 `realloc` 换根更大的管子（扩容）。如果单片机内存太小，还可以搞个“**共享栈(Page 11)**”，一根管子两头往中间塞，能极大节约空间。
  * **链栈 (Page 12)**：用纸条（链表）当栈，要多少有多少不用扩容。为了方便，“入栈”和“出栈”全部在**链表的第一号位（头插法/头删法）** 解决。

**3. 队列 (Queue)：超市结账的队伍 (Page 22-31)**
* **原理**：必须是一边进，另一边出。新来的人只能去队尾，要走的人只能从队头离开。这就叫 **FIFO (先进先出)**。
* **假溢出灾难 (Page 29)**：用数组排队时，如果不挪动队伍，头长椅前面走空了，后面新人又坐到了长椅末端，系统会误报队伍满了排不下了！
* **循环队列 (Page 30)**：为了解决长椅没满却说满的“假溢出”笑话，我们把队列头尾接起来，做成一个“**旋转木马**”。队尾走到编号 99 的木马后，只要 1 号木马是空的，直接环绕回去继续坐。

### 🔬 二、 核心知识与七大经典应用（严谨学术表达）

#### (一) 物理特性与寻址时态边界条件
1. **栈的指针漂移 (Page 5)**：数组实现时，`top` 指针指向实栈顶的**极近上方悬空位**。`top == base` 发生时栈极度空虚，称为下溢 (Underflow)；`top - base >= MAXSIZE` 时称为上溢 (Overflow)。
2. **环形拓扑同余运算 (Page 31)**：为甄别循环队列的满与空（它俩如果自然重叠，条件居然都是 `front == rear`），需主动实施**空间降维牺牲法**：强制废弃数组内最后一个存储空间，将满域检测定义为拓扑追尾，公式为：`((rear + 1) % MAXQSIZE) == front`。

#### (二) 栈的 7 大经典硬核应用 (Page 14-21)
栈不仅仅是个容器，更是计算机编译架构的最底层逻辑：
1. **过程的嵌套调用 (Page 15)**：程序发生函数跳转时，用栈记录当前的运行现场地址与局部变量，子程序跑完后弹栈，完美恢复原现场继续跑。
2. **数制转换 (Page 16)**：10 进制转 8 进制，不断做 `%8` 连除，产生的余数本应倒序读，我们把余数全部 `Push` 压入，再全员 `Pop` 弹出，实现了极其优美的完美颠倒。
3. **括号匹配 (Page 17)**：遇到左向 `[(` 就压入，遇到右向 `)]` 就从栈顶弹一个。但凡有一对型号不匹配，或者最后栈没清空，立马报警（现代各类 IDE 除错功能的雏形）。
4. **回文游戏验证 (Page 18)**：过滤非法字符后压入，利用进出必然颠倒的逆序特性比对源文本进行校验。
5. **DFS回溯法：走迷宫 与 地图着色 (Page 19-20)**：用 7x7 邻接矩阵求解四色问题时，选条路压进栈（踩下足迹）；一旦走入死胡同，就立刻**弹栈（也就是退后一步，即回溯机制）**，换条新路再压下去继续探索。
6. **算术表达式求值 (Page 21)**：遇到 `2+4-3*6`，利用两栈协同：一个“操作数栈”，一个“运算符栈”。后来的运算符若比栈顶的弱（比如准备压入 `-` 发现下面是 `*`），将立刻触发连环弹栈执行现算逻辑。

#### 1.顺序栈的存储表示结构体

#### 2.基本操作函数原型 (Slide 2)
这组 API 覆盖了栈的完整生命周期：
```c
//生命周期管理
```

#### 3.初始化顺序栈
1. 初始化栈 (InitStack) —— 定制一个空圆筒

当你决定开始存数据时，你必须先向操作系统“申请”一块内存地盘。
找系统要空间：系统给你分配了一个标准大小（STACK_INIT_SIZE）的连续空位。
立规矩：你把 base（底座）定在这块空间的开头，把 top（当前顶端）也定在开头（因为现在还是空的），并拿个小本子记下这个筒的最大容量（stacksize）。如果系统说没内存了，程序就只能强制退出。

```c
Status InitStack(SqStack &S) {
    // 1. 使用 malloc 申请初始容量大小的内存块，将起始地址赋给栈底指针 base
    S.base = (SElemType*)malloc(STACK_INIT_SIZE * sizeof(SElemType));
    
    // 2. 检查内存是否分配成功，若失败则程序异常退出
    if(!S.base) exit(OVERFLOW); 
    
    // 3. 栈初始为空，栈顶指针和栈底指针指向同一位置
    S.top = S.base; 
    
    // 4. 记录当前栈的容量
    S.stacksize = STACK_INIT_SIZE; 
    
    return OK; // 初始化成功
}
```
#### 4.顺序栈入栈与出栈算法 
入栈 往筒里放薯片

当你拿到一片新薯片（元素 e）准备放进去时，你得先做个检查：

检查是否满了：看看目前放了多少片（top - base），是不是等于最大容量了。

满了怎么办（扩容）：如果满了，你就找系统说“把我的筒加长一点”（使用 realloc 函数增加 STACKINCREMENT 大小的空间）。系统加长后交给你，你更新好最大容量记录，并且要把 top 指针重新对齐到新的顶端（因为加长过程中，系统可能把你的整个筒搬到了另一个更大的仓库，底座 base 的地址变了，top 也得跟着变）。

放入薯片：如果没满（或者刚刚扩容完毕），就把薯片放在当前 top 指着的位置，然后让 top 往上挪一格，准备接纳下一个。
```c
Status push(SqStack &S, SElemType e) {
    // 1. 判断是否栈满 (当前元素个数 >= 栈容量)
    if(S.top - S.base >= S.stacksize) {
        // 2. 栈满，使用 realloc 追加内存空间
        S.base = (SElemType *)realloc(S.base, 
                 (S.stacksize + STACKINCREMENT) * sizeof(SElemType)); // 注：原图此处有拼写错误
                 
        // 3. 检查扩容是否成功
        if(!S.base) exit(OVERFLOW); 
        
        // 4. 重新计算并定位栈顶指针 top 的位置 (非常关键的一步)
        S.top = S.base + S.stacksize; 
        
        // 5. 更新栈的最大容量记录
        S.stacksize += STACKINCREMENT; 
    }
    
    // 6. 将新元素 e 存入 top 所指的当前位置，然后将 top 指针加 1
    *S.top++ = e; 
    
    return OK; // 入栈成功
}
```
出栈 (Pop) —— 把最上面的薯片拿出来吃掉

先看筒空没空：如果你想拿薯片，第一步永远是低头看看筒里还有没有（S.top == S.base 代表空筒）。如果是空的，你再去掏就会掏个寂寞，系统直接报错（返回 ERROR）。

往下挪一格再拿：top 指针（你的手）永远悬空指着下一个可以放薯片的空位置。所以，要拿最上面的薯片，你的手必须先往下降一格，摸到真正的薯片，然后再把它拿出来交给你（存入变量 e）。拿完之后，你的手就停在当前位置了，相当于筒里的薯片少了一片。
```c
Status Pop(SqStack &S, SElemType &e) {
    // 1. 边界检查：若栈顶指针等于栈底指针，说明栈为空，发生下溢
    if(S.top == S.base) return ERROR; 
    
    // 2. 核心操作：
    //    ① --S.top：将栈顶指针下移一个元素单位，指向真正的栈顶元素
    //    ② * 运算：解引用该地址，取出数据
    //    ③ = 赋值：将取出的数据赋值给 e 返回
    e = *--S.top; 
    
    return OK; // 出栈成功
}
```
取栈顶 (GetTop) —— 只看一眼最上面的薯片是什么口味，不拿走

同样要检查空没空：空筒连看都没得看，直接报错。

目光下移，但手不动：你只是顺着 top 指针的视线往下看一格（S.top - 1），看清楚那片薯片是什么，并把信息记录下来（存入变量 e）。但在此过程中，你并没有真正把手（top 指针）挪下去。看完之后，筒里的薯片数量和原先一模一样。
```c
Status GetTop(SqStack S, SElemType &e) {
    // 1. 边界检查：与 Pop 完全一致，空栈不可取值
    if(S.top == S.base) return ERROR; 
    
    // 2. 核心操作：
    //    计算 S.top 下方一个元素的内存地址，直接解引用取值并赋给 e。
    //    注意：S.top 本身的值并未发生改变！
    e = *(S.top - 1); 
    
    return OK; // 取值成功
}
```

下面我为你分层次深度拆解队列的核心知识。

### 一、 通俗语言讲解：什么是“队列”？

想象一下在**食堂打饭排的队伍**。

* **入队（EnQueue）**：新来的人只能排在队伍的最后面（队尾）。
* **出队（DeQueue）**：打完饭的人只能从队伍的最前面（队头）离开。
* 
**绝对规则**：谁先排队，谁就先吃上饭。这在计算机里叫作**先进先出（FIFO - First In, First Out）** 。



**排队遇到的两个现实问题与计算机的解法：**

1. **链队列**：就像一个**随时可以延长的队伍** 。每来一个人，食堂大妈就发个号码牌（向系统动态申请内存 `malloc`），大家通过号码牌上的指示（指针 `next`）认准自己前面是谁。这种队伍没有长度限制，只要食堂场地够大就行。


2. **顺序队列的“假溢出”与“循环队列”**：假设食堂规定大家必须坐在一条固定长度的长凳上排队 。


* 前面的人打完饭走了，凳子前面空出了位置，但后面的人按照死规定不准往前挪。
* 当队尾的人坐到长凳的最后一格时，即便长凳最前面还有空位，新来的人也坐不下了。这就叫“假溢出（False Overflow）” 。

**怎么解决？** 把长凳首尾相接，做成一个**圆环（循环队列）** ！当后面满了，只要前面有空位，新来的人就绕到最前面去坐。





---

### 二、 核心知识严谨描述

在计算机科学中，队列是限定只能在表的一端进行插入（队尾 `rear`），在表的另一端进行删除（队头 `front`）的线性表 。

* **链队列（Linked Queue）**

**结构**：带有队头指针 `front` 和队尾指针 `rear` 的单链表 。
 
**特性**：为了操作方便，通常带有头结点 。`front` 始终指向头结点，而 `rear` 始终指向实际的最后一个元素结点 。

**空队条件**：`front == rear` 。




* **循环队列（Circular Queue）**
  
**核心机制**：利用模运算（取余数 `%`）来实现逻辑上的环形空间 。


* **指针移动**：
* 入队：$rear = (rear + 1) \% M$ 


* 出队：$front = (front + 1) \% M$ 




* **队满与队空的冲突与解决**：
* 在纯粹的环形数组中，队空是 `front == rear` 。如果不做特殊处理，当队列全部装满时，`rear` 绕了一圈追上 `front`，此时依旧是 `front == rear`，这就导致无法区分是空还是满 。


  
**解决方案（牺牲一个空间）**：规定当队列还剩一个空位时，就认为队列已经满了 。


  
**队满条件判定公式**：$(rear + 1) \% M == front$ 。

### 【核心知识点】
1. **串的定义**：串是由零个或多个字符组成的有限序列（也称字符串）。记为 $s = ‘a_1a_2a_3…a_n’$。
2. **术语解析**：
   - **串名**：记号 $s$。
   - **空串 (null)**：零个字符组成的串（在C语言中表现为 `NULL`）。
   - **子串与主串**：串中任意个**连续**的字符组成的子序列称为“子串”，包含该子串的串称为“主串”。
   - **位置索引**：字符在序列中的序号为主串位置。子串的位置以其**第一个字符**在主串中的位置来表示。
3. **串相等条件**：当且仅当两个串的**长度相等**，且**各个对应位置的字符都相等**时，两串相等。
   - 例：`'WU'` $\neq$ `'WUHAN'`，`'WUHAN'` $\neq$ `'WU HAN'` (空格也是字符)。

#### 
串就是平常用的字符串（像一串羊肉串一样，把字母、数字或者符号穿起来）。只要顺序、内容、甚至空格有一点不同，或者长度不同，它们就是两串不同的字符串。注意，讲义里的单引号 `''` 只是把它括起来避免跟变量名搞混，并不算在字符串长度里。

### --- Page 12：串的模式匹配算法 (朴素匹配) ---

#### 【核心知识点】
- **模式匹配**：在主串中寻找子串（模式串）起始位置的过程。
- **基本思路**：利用双指针。从主串的指定位置开始，与模式串的第1位逐一对齐比较。如果所有字符吻合，则找到；一旦期间发现字符不同，则将**主串的指针回退，移动到下一位重新起头**，模式串指针归1重来。这就是经典的暴力匹配（[Brute-Force] / 双循环匹配）。

#### 【算法代码：定长顺串的暴力模式匹配】
*(该代码利用 0 号位置存放真实长度，1 号开始存储字符)*
```c
int Index(SString S, SString T, int pos) {
    int i = pos; // 主串游标
    int j = 1;   // 模式串游标
    
    while(i <= S[0] && j <= T[0]) {
        if(S[i] == T[j]) {      
            ++i; 
            ++j;  // 字符相同时，游标同步前进
        } else {
            // == 核心逻辑：回溯 ==
            i = i - j + 2; // 主串游标退回至 这一轮起点的下一位置
            j = 1;         // 模式串游标 强行重置为首位
        }
    }
    
    // 如果 j走完了模式串的长度，说明完全匹配成功
    if(j > T[0]) 
        return i - T[0]; // 返回当初首位匹配对上的索引
    else 
        return 0; // 找不到
}
```


#### 一、 通俗语言讲解：什么是“模式匹配”？

简单来说，模式匹配就是你在 Word 里按 `Ctrl+F` 查找文字的过程。

* **主串（S）**：整篇 Word 文档。
* **模式串（T）**：你输入在查找框里、想要找的那个词。
* **定位操作（Index）**：找出这个词在文档中第一次出现的位置。

**BF 算法的底层逻辑（暴力破解）：**
想象你拿着一把带有锯齿的钥匙（模式串），去开一个很长的锁孔（主串）。

1. 你把钥匙对准锁孔的最开头，一个锯齿一个锯齿地往里推进去比对。
2. 如果所有的锯齿都对上了，恭喜你，找到了！
3. 如果比对到第 3 个锯齿发现对不上，怎么办？**退出来，把钥匙整体往右挪一格，然后从头开始，再次一个锯齿一个锯齿地比对。**
这种“一旦失败，彻底重来”的笨办法，就是 BF 算法。

#### 二、 核心知识严谨描述

* **数据结构依赖**：代码使用的是**定长顺序存储结构**。注意这里的首位隐藏逻辑：`S[0]` 和 `T[0]` 存放的是字符串的实际长度，真正的字符是从下标 `1` 开始存放的（1-based indexing）。
* **核心动作：回溯（Backtracking）**：当发现字符不匹配时，主串的指针 `i` 和模式串的指针 `j` 都必须往回倒退。这种倒退会引发大量重复的比较。
* **时间复杂度**：
* 最好情况：一找就找到，时间复杂度为 $O(n)$。
* 最坏情况：每次都比对到模式串的最后一个字符才发现失败（比如主串是 "AAAAAAB"，模式串是 "AAB"）。此时的时间复杂度高达 $O(n \times m)$，其中 $n$ 和 $m$ 分别是主串和模式串的长度。





这段代码虽然短，但里面的指针计算非常容易让人头晕。我们逐句拆解：

```c
int Index(SString S, SString T, int pos) {
    int i = pos; // i 是主串的扫描指针，从指定的 pos 位置开始找
    int j = 1;   // j 是模式串的扫描指针，永远从 1 开始

    // 只要主串和模式串都没走到头，就继续循环比对
    while(i <= S[0] && j <= T[0]) { 
        
        // 【情况 A：当前字符匹配成功】
        if(S[i] == T[j]) { 
            ++i; // 主串指针往后走一步
            ++j; // 模式串指针往后走一步
        } 
        
        // 【情况 B：当前字符匹配失败（核心难点）】
        else { 
            i = i - j + 2; // 主串指针回溯到下一个起点的精准位置！
            j = 1;         // 模式串指针乖乖回到起点 1
        }
    }
    
    // 循环结束。如果 j 走出了模式串的长度 (j > T[0])，说明模式串里的字符全比对成功了
    if(j > T[0]) 
        // 此时的 i 已经停在了主串匹配子串的下一个位置。
        // 用 i 减去模式串的长度 T[0]，正好就是匹配成功的起始位置！
        return i - T[0]; 
    else 
        // 如果是因为 i 走完了 (i > S[0]) 而结束循环，说明没找到
        return 0; 
}

```

####  烧脑点攻克：为什么是 `i = i - j + 2`？

为什么匹配失败后，主串的指针要这么算？我们通过简单的代数推导一下：

1. **刚才这一轮是从哪里开始的？**
假设在匹配失败前，我们已经成功匹配了 `j - 1` 个字符。那么当前这一轮匹配的起点，其实是在主串的 `i - (j - 1)` 这个位置，化简一下就是 `i - j + 1`。
2. **下一轮应该从哪里开始？**
按照 BF 算法的逻辑，当前这轮失败了，下一轮的起点就应该在当前起点的**右边挪一格**。
也就是：`(当前起点) + 1` = `(i - j + 1) + 1` = **`i - j + 2`**。

这就是这个公式的真实含义：**“主串指针，请退回到你刚才出发位置的右边一格，准备重新开始。”**

### --- Page 1 - Page 3：数组的定义与顺序存储 ---

#### 【核心知识点】
1. **数组的定义**：数组可以看成是一种特殊的线性表。即线性表中的数据元素本身也是一个线性表。
2. **数组的特点**：
   - **结构固定**：一旦定义好维度和界限，就不再发生改变。
   - **数据元素同构**：所有元素都具有相同的数据类型。
3. **数组的基本运算**：
   - 给定一组下标，存取相应的数据元素。
   - 给定一组下标，修改数据元素的值。
4. **顺序存储的次序约定（多维映展到一维）**：
   - **以行序为主序**（C/C++、Java等采用）：先排第一行，再排第二行...
   - **以列序为主序**（FORTRAN等采用）：先排第一列，再排第二列...
   - **核心公式（以列序为主序的二维数组为例）**：若矩阵有 $m$ 行，每个元素占 $l$ 个字节空间，则位置公式为：
     $Loc(a_{ij}) = Loc(a_{11}) + [(j - 1)m + (i - 1)] \times l$

#### 【大白话讲解】
数组你可以把它想象成分了格子的储物大柜。比如一个二维数组（表格），但在电脑内存里，存储空间是一条直直的单行道（一维线性的）。你怎么把表格塞进单行道？要么你“一行一行”地按顺序塞（行序为主），要么你“一列一列”地按顺序塞（列序为主）。只要规定好了怎么塞，只要给我个行号列号，我就能用一个简单的加法乘法公式瞬间算出它在单行道里的绝对位置。

### --- Page 4 - Page 7：特殊矩阵的压缩存储 ---

#### 【核心知识点】
为了节省空间，对规律性极强的矩阵进行“压缩”（即：只存那些不重复的或者非零的元素，通过下标映射公式来找位置）。
1. **对称矩阵**：$a_{ij} = a_{ji}$。只需存储下三角（或上三角）部分。
   - 按行序为主序存储下三角，存放在大小为 $n(n+1)/2$ 的一维数组中。
   - 映射公式（存下三角时）转化为一维坐标 $k$：
     当 $i \ge j$ 时：$k = i(i-1)/2 + j - 1$
     当 $i < j$ 时：$k = j(j-1)/2 + i - 1$
2. **三角矩阵**：除对角线外的上半或下半全是常数（如0）。
   - 下三角矩阵公式：$Loc(a_{ij}) = Loc(a_{11}) + [i(i-1)/2 + (j-1)] \times l$
3. **对角矩阵**：所有非零元素集中在主对角线及其附近的几条斜线上（例如三对角矩阵）。
   - 按行序映射公式：$Loc(a_{ij}) = Loc(a_{11}) + [2(i-1) + (j-1)] \times l$

### --- Page 8 - Page 12：稀疏矩阵与三元组表 ---

#### 【核心知识点】
1. **稀疏矩阵定义**：非零元较零元少，且分布**没有一定规律**的矩阵。
2. **压缩存储原则**：只存矩阵的行数、列数、以及每个非零元的**行下标、列下标和它的值**。
3. **三元组表(Triple)**：将每个非零元素表示为一个三元组 `(i, j, v)`。通常第0号位置存矩阵共有多少行、多少列、多少非零元。所占空间从原来的 $m \times n$ 缩减为 $3(t+1)$。

#### 【算法代码：三元组表的结构体定义】
```c
#define MAXSIZE 12500 // 假设最大能存12500个非零元

typedef struct {
    int i, j;         // 行下标，列下标
    ElemType e;       // 元素值
} Triple;

typedef struct {
    Triple data[MAXSIZE+1]; // 三元组数组 (0号单位通常不用作非零元实际数据)
    int mu, nu, tu;         // mu行数，nu列数，tu非零元总数
} TSMatrix;
```
4. **伪地址表示法 / 带辅助行向量的三元组表**：
   为了更快查找每行的非零元，增加一个辅助数组 `NRA` 记录每一行“首个非零元”在三元组表中的起始地址起始下标。
   - 推导关系：$NRA[i] = NRA[i-1] + (第i-1行的非零元个数)$。

### --- Page 13 - Page 21：稀疏矩阵的转置（经典算法重点） ---

#### 【核心知识点】
- **常规矩阵转置**的时间复杂度是 $O(m \times n)$。但在稀疏矩阵存储下（三元组），我们需要设计特殊算法进行高效转置（即把 $(i, j, v)$ 变为 $(j, i, v)$）。
- **思路一：按 M 的列序进行转置（朴素转置）**
  - 反复遍历原来的三元组表。第一遍只找列号=1的，第二遍找列号=2的...依此类推，这样存进新三元组时就能严格保证“新矩阵按行序递增”。
  - **性能**：$O(n \times t)$（$n$ 是列数，$t$ 是非零元个数）。如果非零元数量 $t$ 很大，这甚至不如常规矩阵转置快！

- **思路二：快速转置 (Fast Transpose)**
  - 核心思想：提前“排好雷”。建立两个数组 `num[col]` (记录原矩阵第 `col` 列有几个非零元) 和 `cpot[col]` (指示第 `col` 列第一个非零元在目标转置三元组中的**应该放置的准确起始位置**)。
  - **预处理公式**：
    `cpot[1] = 1;` 
    `cpot[col] = cpot[col -1] + num[col- 1];`
  - **性能**：只需扫表两三遍。复杂度极降为 $O(n + t)$，堪称提速神兵。

#### 【算法代码：稀疏矩阵的快速转置】
```c
Status FastTransposeSMatrix(TSMatrix M, TSMatrix &T) {
    T.mu = M.nu;    // 转置后行数 = 原矩阵列数
    T.nu = M.mu;    // 转置后列数 = 原矩阵行数
    T.tu = M.tu;    // 非零元总数不变
    
    if(T.tu) {
        // 第一步：清零并统计 M中每一列各自有多少个非零元
        for(col = 1; col <= M.nu; ++col) num[col] = 0;
        for(t = 1; t <= M.tu; ++t) ++num[M.data[t].j];
        
        // 第二步：计算 M中每一列首个非零元在转置矩阵T中的正确位置
        cpot[1] = 1;
        for(col = 2; col <= M.nu; ++col) 
            cpot[col] = cpot[col - 1] + num[col - 1]; // 前一列的位置 + 前一列的总个数
            
        // 第三步：将 M中的每个非零元，精标准确地“飞”到目标槽位里
        for(p = 1; p <= M.tu; ++p) {
            col = M.data[p].j;     // 提列号
            q = cpot[col];         // 查该列当前该放在转置坐标表的哪个确切下路(q)
            
            // 执行复制跳跃
            T.data[q].i = M.data[p].j; 
            T.data[q].j = M.data[p].i;
            T.data[q].e = M.data[p].e;  
            ++cpot[col]; // 这个坑已经被占了，下一次同列的元素往后顺延一个位置！
        }
    }
    return OK;
}
```

### --- Page 22 - Page 25：稀疏矩阵的链式存储结构 ---

#### 【核心知识点】
三元组属于顺序存储，当矩阵的非零元数量有增删时，会像挤牙膏一样要搬动大量后面的数据。所以引入链式：
1. **带行指针向量的单链表**：
   - 每行的非零元串成一个链表。设置一个一维数组当“车头”用来存放每行链表的头指针。
2. **十字链表 (Cross List)（极其重要！！！）**：
   - 因为只按行连起来的话，顺着列找又很麻烦。所以，干脆让每个非零元长出**两个**指针：`down` 和 `right`。
   - `right` 指向同一行的下一个非零元，`down` 指向同一列的下一个非零元。每个节点像大网缝合处的结一样。

#### 【算法代码：十字链表的数据结构】
```c
typedef struct OLNode {
    int i, j;               // 自身所在矩阵的行标和列标
    ElemType e;             // 自身的值
    struct OLNode *down, *right; // 列方向的下指针与行方向的右指针
} OLNode, *OLink;

typedef struct {
    OLink *rhead, *chead;   // 一个存所有行头部的指针数组，一个存所有列头部的指针数组
    int mu, nu, tu;         // 行数、列数、非零元总数
} CrossList;
```
*大白话：就像一张经纬线编织的渔网，横向的线是 `right` 串起的行，纵向的是 `down` 串起的列，遇到有非零元的地方就打个“结”(Node)。这样从无论行还是列出发走动极快。建立时间复杂度为 $O(t \times \text{max}(m, n))$。*

### 一、 通俗语言讲解：什么是“广义表”？

如果说普通的线性表（比如数组）是一个“只能装文件的普通文件夹”**，那么广义表就是一个**“既能装文件，也能装子文件夹的超级文件夹”。

* **原子（Atom）**：普通的文件。它是不可再分的基本数据。
* **子表（Sublist）**：文件夹里的子文件夹。
* **表头（Head）与表尾（Tail）**：这是广义表最特别的设定！
* 当你打开一个非空的超级文件夹时，你看到的**第一个东西**（不管是文件还是子文件夹），就叫作“表头”。
* 除了第一个东西之外，**剩下的所有东西打包组成的一个新文件夹**，统称为“表尾”。



**三个神奇的现实特性：**

1. **可以嵌套**：文件夹里套文件夹，可以套无穷多层（多层次结构）。
2. **可以共享**：类似于电脑上的“快捷方式”，同一个子文件夹可以存在于多个不同的广义表里，不用重复占用硬盘空间。
3. **可以无限循环**：一个广义表里面，居然可以包含它自己！就像你打开一个叫 E 的文件夹，发现里面竟然还有一个 E 文件夹，永远点不到头（递归表）。

### 二、 核心知识严谨描述

从计算机科学的严谨角度来看，广义表 $LS = (a_1, a_2, ..., a_n)$ 是一种递归定义的数据结构。

1. **基本概念**：
* $LS$ 是表名，$n$ 是表的**长度**（即最外层包含的元素个数）。
* $a_i$ 可以是不可分割的**原子**，也可以是另一个广义表（**子表**）。


2. **表头与表尾的绝对定律**：
* **表头 $GetHead(LS)$**：非空广义表的第一个元素 $a_1$。表头**可能是原子，也可能是列表**。
* **表尾 $GetTail(LS)$**：除去表头后，由其余元素 $(a_2, ..., a_n)$ 构成的表。**表尾必定是一个列表（广义表）！**


3. **经典易错点（空表辨析）**：
* $A = ()$：这是一个空表，长度为 0。
* $B = (())$：这不是空表！这是一个长度为 1 的表，它的里面装了一个空表。它的表头是 $()$，表尾也是 $()$。

### 三、 算法代码与存储结构总结

由于广义表中的数据元素可以具有不同的结构（有的是原子，有的是表），且长度极其灵活，因此**通常采用链式存储结构**。

文档中给出了两种经典的广义表 C 语言结构体定义：

#### 1. 头尾链表存储表示法

这是最直观的表示法。任何一个节点，我们要么把它当“原子”看，要么把它当“表”看。通过一个标志位 `tag` 来区分。

```c
typedef enum {ATOM, LIST} ElemTag; // tag=0表示原子，tag=1表示子表

typedef struct GLNode {
    ElemTag tag; // 标志位
    union {
        AtomType atom; // 如果是原子节点，这里存真正的数据
        struct {
            struct GLNode *hp; // 表头指针：指向列表真正的第一个元素
            struct GLNode *tp; // 表尾指针：指向剩下的元素组成的表
        } ptr; // 如果是表节点，这里存两个指针
    };
} *GList;

```

* **特点**：最高层的表结点个数，正好等于这个广义表的长度。如果表尾为空，`tp` 指针就为 `NULL`。

#### 2. 扩展的线性链表存储表示法

这种方法把广义表看作是普通的单链表，只不过单链表里的元素可以是一个子表。

```c
typedef struct GLNode {
    ElemTag tag; // 标志位 (0为原子, 1为子表)
    union {
        AtomType atom;     // 原子结点的数据域
        struct GLNode *hp; // 表结点的表头指针（指向子表的内部）
    };
    struct GLNode *tp; // 注意！这里的 tp 被移到了外面！相当于单链表的 next 指针
} *GList;

```

* **特点**：所有结点（不管是原子还是表）都有一个 `tp` 指针，它只负责串联起同一层次的“兄弟结点”（就像普通链表的 `next`）。
