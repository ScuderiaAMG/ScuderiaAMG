## 题目一：用户菜单权限管理系统

### 1. 程序功能

一个带角色权限的菜单管理系统。不同用户登录后，根据其角色看到不同的菜单树，双击菜单项时检查是否有操作权限。权限分两级：可见性（菜单是否显示在树上）和可操作性（能否执行该功能）。主界面右下角有注销按钮，注销后回到登录界面，可换账号重新登录，不退出程序。

### 2. 数据结构

**MenuItem（菜单项）**
```c
typedef struct {
    int id;           // 菜单唯一编号
    int parentId;     // 父菜单id，0表示根节点
    char name[64];    // 菜单显示名称
    char action[128]; // 功能描述（根菜单为空）
} MenuItem;
```
14个菜单项通过parentId形成树形结构。系统管理、数据管理、报表中心、个人设置是4个根节点，各带若干子节点。

**Role（角色）**
```c
typedef struct { int id; char name[32]; } Role;
```
预置3个角色：0-系统管理员、1-操作员、2-普通用户。

**User（用户）**
```c
typedef struct { int id; char name[32], password[32]; int roleId; } User;
```
预置3个用户，roleId指向Role。

**Permission（权限）**
```c
typedef struct { int menuId, roleId, visible, enabled; } Permission;
```
核心数据结构。每条记录描述"某角色对某菜单的可见性和可操作性"。程序启动时硬编码了42条权限记录（14个菜单 × 3个角色）。

### 3. 核心算法

**权限查找** — hasPermission() 和 isVisible() 两个函数结构相同：
1. 遍历users数组，根据userId找到User结构体，取出roleId
2. 遍历permissions数组，匹配(roleId, menuId)组合
3. 返回对应的enabled或visible字段值
4. 时间复杂度O(n+m)，n为用户数，m为权限数

**递归建树** — buildMenuTree()：
1. 从parentId=0的根菜单开始
2. 遍历所有菜单，找出parentId匹配且isVisible()返回1的菜单项
3. 对每个满足条件的菜单，先插入TreeView节点，再递归查找它的子节点
4. 不可见的菜单项及其整个子树都不会出现在界面上

**登录验证流程**：
1. 登录窗口：ComboBox下拉选用户名，Edit输入密码
2. 点"登录"按钮，GetWindowText获取用户名和密码文本
3. 遍历users数组，strcmp比较用户名和密码
4. 匹配成功 → 设置全局变量currentUserId，DestroyWindow销毁登录窗口，CreateWindow创建主窗口
5. 主窗口WM_CREATE触发 → buildMenuTree根据currentUserId构建菜单树 → 状态栏显示用户和角色名
6. 匹配失败 → SetWindowText在登录窗口显示"用户名或密码错误"

**注销流程**：
1. 主窗口右下角"注 销"按钮，ID为205
2. 点击后设置全局标志loggingOut=1，DestroyWindow销毁主窗口
3. 主窗口WM_DESTROY判断loggingOut标志：
   - 若为1：重置currentUserId=-1，重新CreateWindow创建登录窗口，回到登录界面
   - 若为0：PostQuitMessage退出程序
4. 登录窗口的WM_DESTROY中，若currentUserId==-1（关掉登录窗口）则退出程序；若已登录成功则不做退出处理
5. 通过这个标志位区分"注销"和"关闭窗口"，实现换号重登不退出

**双击菜单处理**：
1. TreeView的WM_NOTIFY捕获NM_DBLCLK
2. TreeView_GetSelection获取选中节点
3. TVM_GETITEM取回节点的lParam（存的是菜单id）
4. 用菜单id去menus数组找到MenuItem
5. parentId==0的根菜单不响应双击
6. 叶子菜单调用hasPermission()判断权限 → 有权限弹信息框，无权限弹警告框

### 4. 预设数据说明

| 用户名 | 密码 | 角色 | 可见菜单 | 可操作菜单 |
|--------|------|------|---------|-----------|
| admin | admin123 | 系统管理员 | 全部14项 | 全部14项 |
| operator | oper123 | 操作员 | 数据管理3项+报表中心3项+个人设置2项 | 数据管理3项+报表中心3项+个人设置2项 |
| user | user123 | 普通用户 | 报表中心3项+个人设置2项 | 同上 |

### 5. 运行方式

编译：
```bash
gcc Q1.c -o Q1.exe -lcomctl32 -mwindows -fexec-charset=GBK
```

- `-lcomctl32` 链接Common Controls库（TreeView和StatusBar控件需要）
- `-mwindows` 不显示控制台黑窗
- `-fexec-charset=GBK` 中文编码，源文件是UTF-8时必加，否则界面中文乱码

运行：直接双击Q1.exe，弹出登录窗口 → 选用户输密码 → 进入主界面 → 展开树节点 → 双击叶子菜单测试权限。

### 6. 测试方法

1. 用admin登录，展开所有树节点，确认14个菜单全部可见
2. 双击"用户管理"，应弹出"操作成功完成"对话框
3. 点击右下角"注 销"，确认回到登录界面
4. 换用user登录，确认菜单树只剩报表中心和个人设置
5. 再次点"注 销"，换回admin登录，确认菜单恢复完整
6. 在登录界面点X关闭窗口，确认程序正常退出

## 题目二：路网最短路径计算系统

### 1. 程序功能

随机生成一个包含55个节点的连通路网图，用户选择起点、终点和途径点后，用Dijkstra算法计算最短路径，在图上高亮显示，并输出完整路径序列和总权重。

### 2. 数据结构

**Point（节点坐标）**
```c
typedef struct { double x, y; } Point;
Point pos[MAX_NODES];  // 55个节点的画布坐标
```

**Edge（边）**
```c
typedef struct { int from, to, weight; } Edge;
Edge edges[MAX_EDGES];  // 最多300条边
int edgeCount;           // 实际边数
```

**邻接矩阵**
```c
int adj[MAX_NODES][MAX_NODES];
// adj[i][j] = 0 (i==j时)
// adj[i][j] = 边权重 (i和j直接相连)
// adj[i][j] = INF=999999 (i和j不直接相连)
```
用邻接矩阵而不是邻接表，因为N=55、N²=3025的规模完全可以接受，且矩阵查询O(1)比链表遍历更直接。

**并查集**
```c
int parent[MAX_NODES];
int find(int x);    // 路径压缩查找
void unite(int a, int b);  // 合并两个集合
```
用在路网生成阶段，确保生成的图是连通的。

**Dijkstra辅助数组**
```c
int dist[MAX_NODES];    // 从起点到各节点的最短距离
int prev[MAX_NODES];    // 最短路径上各节点的前驱
int visited[MAX_NODES]; // 是否已确定最短距离
```

### 3. 核心算法详解

**3.1 随机路网生成 generateRoadNetwork()**

第一步：节点布局。55个节点按10列×6行网格排列：
```c
pos[i].x = 60 + (i % 10) * 72 + (rand() % 30 - 15);  // 列间距72，随机偏移±15
pos[i].y = 40 + (i / 10) * 72 + (rand() % 30 - 15);  // 行间距72，随机偏移±15
```
这样节点大致均匀分布在画布上，但坐标有随机偏移，看起来自然。

第二步：随机连边。循环最多N×8=440次：
```c
i = rand() % N;  j = rand() % N;
if (i != j && adj[i][j] == INF) {   // 不能自环，不能重复连边
    double dist = sqrt((pos[i].x-pos[j].x)² + (pos[i].y-pos[j].y)²);
    // 判断是否该连边
}
```
连边条件有两个：
- 前N×3=165次尝试，**无论距离多远都连边**（保证早期有足够多的边）
- 之后只对距离<120像素的节点对连边（模拟真实路网：近的地方路多，远的地方路少）

边权计算：`weight = (int)(距离/8) + (rand()%20) + 1`。距离远的边权重大，带随机波动。每加一条边就unite(i,j)合并并查集。

第三步：连通性保证。遍历所有节点：
```c
for (i = 1; i < N; i++)
    if (find(i) != find(0)) {  // 节点i和节点0不在同一个连通分量
        addEdge(i, 0);         // 强制连一条边到节点0
        unite(i, 0);
    }
```
这一步确保生成的图一定是连通图，Dijkstra不会遇到不可达的情况。

**3.2 Dijkstra最短路径 dijkstra()**

O(N²)实现，不做堆优化（N=55时堆优化的常数开销反而更大）：

```c
// 初始化
for (i = 0; i < N; i++) { dist[i] = INF; visited[i] = 0; prev[i] = -1; }
dist[start] = 0;

// 主循环
for (i = 0; i < N; i++) {
    // 选未访问节点中dist最小的
    int u = -1, minD = INF;
    for (j = 0; j < N; j++)
        if (!visited[j] && dist[j] < minD) { minD = dist[j]; u = j; }
    if (u == -1 || u == end) break;  // 终点已确定，提前终止

    visited[u] = 1;
    // 松弛u的所有邻居
    for (j = 0; j < N; j++)
        if (!visited[j] && adj[u][j] < INF && dist[u] + adj[u][j] < dist[j]) {
            dist[j] = dist[u] + adj[u][j];
            prev[j] = u;
        }
}
```

路径回溯：
```c
int cur = end;
while (cur != -1) { path[idx++] = cur; cur = prev[cur]; }  // 从终点往前推到起点
// 反转得到正序路径
for (i = 0; i < idx; i++) outPath[i] = path[idx - 1 - i];
```

**3.3 多段路径拼接 computeFullPath()**

场景：用户选了起点A、途径点W1 W2、终点B。需要计算 A→W1→W2→B 的最短路径。

处理方式：
1. 构建目标序列：`[A, W1, W2, B]`
2. 对每对相邻目标调用dijkstra，得到各段路径
3. 拼接时跳过重复节点：
   - 第一段(A→W1)：路径节点全部加入结果
   - 第二段(W1→W2)：跳过segPath[0]（等于W1，已在结果中），从segPath[1]开始加入
   - 以此类推
4. 总权重 = 各段边权之和

**3.4 双缓冲绘图 drawGraph()**

如果直接在屏幕DC上画，每画一条线就刷新一次，画面会闪烁。双缓冲方案：
```
memDC = CreateCompatibleDC(hdc)         // 创建内存DC
memBmp = CreateCompatibleBitmap(...)     // 创建内存位图
SelectObject(memDC, memBmp)              // 位图选入DC

// 所有绘制都在memDC上做（用户看不到）
画背景 → 画边 → 标权重 → 画节点 → 标编号

BitBlt(hdc, ..., memDC, ...)            // 一次性拷贝到屏幕
DeleteDC(memDC); DeleteObject(memBmp)    // 清理
```

绘图中使用的颜色约定：
- 普通边：灰线 width=1
- 路径边：红线 width=3
- 起点：绿色大圆 r=8
- 终点：蓝色大圆 r=8
- 途径点：橙色大圆 r=8
- 路径经过的节点：红色小圆 r=5
- 其他节点：灰色小圆 r=5
- 边权重：灰色小字标在边中点
- 节点编号：深色小字标在节点右下方

### 4. GUI交互说明

程序窗口分为两部分：

**上部（路网图区域）**：显示随机生成的55个节点及其连接边的可视化图。随窗口大小自适应缩放。

**下部（控制面板，高度160像素）**：
- 第一行：起点下拉框 | 终点下拉框 | 途径点下拉框 | [添加] [移除] [重置] [重载]
- 第二行：途径点列表（显示已添加的途径点）| [计算最短路径]按钮
- 第三行：结果文本框（显示计算出的路径和总权重）

操作流程：
1. 从"起点"下拉框选起始节点（默认0）
2. 从"终点"下拉框选目标节点（默认10）
3. 可选：从"途径点"下拉框选节点，点"添加"加入途径点列表（最多10个）
4. 可选：在途径点列表中选中某项，点"移除"
5. 点"计算最短路径" → 图上红色加粗路径 + 文本框显示结果
6. 点"重置" → 终点复位到节点0，途径点和路径结果清空
7. 点"重载" → 重新随机生成全新路网，所有下拉框刷新，起点保持原选中值

### 5. 运行方式

编译：
```bash
gcc Q2.c -o Q2.exe -lcomctl32 -mwindows -fexec-charset=GBK
```

参数说明同Q1。不需要单独链接math库（MinGW-w64默认包含）。

注意：每次运行路网随机生成，节点位置和边连接都不同，路径结果也不同。如果想固定路网，可以把 `srand((unsigned)time(NULL))` 改成 `srand(固定值)`。

### 6. 测试方法

1. 默认起点0、终点10，不加途径点，点计算 → 应显示红色路径和权重
2. 添加途径点（如节点5、节点20），再计算 → 路径应强制经过这些点
3. 把起点和终点选成同一个值 → 应提示"起点和终点不能相同"
4. 点"重置" → 终点复位、途径点清空、高亮路径消失
5. 点"重载" → 路网完全变样，下拉框刷新
6. 检查节点颜色：起点绿、终点蓝、途径点橙、路径经过的红、其余灰色

## 编译说明

两个程序都是Win32 GUI程序，需要Windows环境，用MinGW-w64或MSVC编译。

MinGW-w64：
```bash
gcc Q1.c -o Q1.exe -lcomctl32 -mwindows -fexec-charset=GBK
gcc Q2.c -o Q2.exe -lcomctl32 -mwindows -fexec-charset=GBK
```

MSVC（Developer Command Prompt）：
```bash
cl Q1.c /link comctl32.lib user32.lib gdi32.lib
cl Q2.c /link comctl32.lib user32.lib gdi32.lib
```

关键参数：
- `-lcomctl32`：必须，提供TreeView、StatusBar、InitCommonControlsEx等Common Controls
- `-mwindows`：GUI程序不弹出控制台窗口
- `-fexec-charset=GBK`：处理中文界面文本编码，如果源文件已经是GBK编码则可省略
